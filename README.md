# 인디언즈 ERP 클래스 (indeans-erp-class)

회사를 운영하는 대표가 **자기 회사 운영 앱(ERP)** 을 AI(Claude Code·Codex)로 직접 만들 수 있도록 인디언즈가 제작한 교육용 번들입니다. 외부 오픈 스킬 모음이 아니라, 인디언즈가 자체 앱을 만들고 운영하면서 정리한 방식을 교육용으로 새로 쓴 것입니다. 인테리어 회사가 만들었지만 업종을 가리지 않습니다 — 첫 질문은 "회사(사업자) 이름과 대표님을 어떻게 부르면 될까요?"입니다.

이 저장소 하나에 **스킬 17종 · 에이전트 4종(감독·검증·감사) · 훅 4종(검수·명령 보호·배포 전 확인·주간 점검 알림)과 도우미 스크립트 · 디자인 선택창 · 회차 자료**가 모두 들어 있습니다. 1회차에 한 번 설치하면 끝이고, 회차마다 새 저장소를 받지 않습니다.

스킬·에이전트·훅은 인디언즈가 자체 운영 앱에서 실제로 쓰는 것을 **업종과 무관하게 넓히고 보강한 판**입니다. 줄인 교육용이 아니라, 같은 규칙을 초보도 따라갈 수 있는 순서와 말로 옮겼습니다.

수업은 **주 2회 × 3시간, 본 4회 + 최종 회 1회**입니다. 최종 회는 본 과정이 끝나고 2주 뒤, 2주 동안 실제로 써 본 결과를 시연하는 자리입니다.

## 설치 — 가장 쉬운 방법: AI에게 이 문장을 붙여 넣기

Claude Code 또는 Codex에서 **내 ERP 프로젝트 폴더**를 연 상태에서 아래를 그대로 붙여 넣습니다.

```text
https://github.com/indeans6633/indeans-erp-class 를 내 프로젝트 바로 위 폴더에 git clone --depth 1 로 받고,
받은 폴더의 install.mjs 를 node 로 실행해서 지금 이 프로젝트 폴더(--project ".")에 --target both 로 설치해 줘.
설치가 끝나면 설치기가 마지막에 알려 주는 다음 단계를 그대로 보여 줘.
```

`{ }` 로 바꿀 것도 없습니다. 저장소 주소는 문장 안에 이미 들어 있습니다.

## 설치 — 직접 실행

Git과 Node.js 18 이상이 필요합니다. 내 ERP 프로젝트 폴더에서:

```powershell
# 반드시 내 ERP 프로젝트 폴더에서 실행합니다 — 지금 어디인지 pwd 로 먼저 확인하세요.
pwd
git clone --depth 1 https://github.com/indeans6633/indeans-erp-class.git "../indeans-erp-class"
node "../indeans-erp-class/install.mjs" --project "." --target both
```

- `--project "."` 은 **지금 있는 폴더**에 설치한다는 뜻입니다. 내려받은 강의 자료 폴더 안에서 실행하면 설치기가 멈추고 알려 줍니다(그 폴더에 설치되는 일은 없습니다).
- 이미 받아 둔 `../indeans-erp-class` 폴더가 있으면 clone 이 영어 오류(`destination path ... already exists`)로 멈춥니다. 그 폴더에서 `git pull` 하거나, 폴더를 지우고 다시 받으세요.
- `--target claude` → Claude Code 자리에만, `--target codex` → Codex 자리에만, `both` → 둘 다(같은 내용). 두 도구를 같이 켜야 한다는 뜻은 아닙니다.
- `--dry-run` 을 붙이면 **아무것도 바꾸지 않고** 무엇이 설치될지만 보여 줍니다.
- 회차를 고르는 인자는 없습니다. 이 저장소에 든 것이 전부 설치됩니다.

내용이 같은 파일은 건너뛰고, 직접 만든 파일은 덮어쓰지 않습니다(충돌이 나면 파일 이름을 알려 주고 멈춥니다). 설치기가 넣었던 파일에 새 버전이 있으면 손대지 않은 파일만 갱신하고, **워크시트처럼 체크·메모를 적어 둔 파일은 그대로 두고 새 버전을 같은 자리에 `.new` 로 저장**해 알려 줍니다.

**설치기는 네트워크 호출·원격 추적·수강생 코드 수집 기능이 없습니다.** 설치 기록은 내 프로젝트의 `.owner/install-state.json` 에만 남습니다.

## 설치한 뒤

설치가 끝나면 설치기가 다음에 부를 스킬 이름을 알려 줍니다. 새 대화를 열고 그 문장을 그대로 넣으세요.

```text
indeans-erp-setup 스킬을 읽고 시작해 줘
```

**스킬 이름을 직접 불러야 그 절차대로 움직입니다.** 회차마다 말할 문장 원문은 설치된 `course/session-0N/prompts.md` 에 전부 있습니다. 오늘 확인할 것은 `outcomes.md`, 적어 가며 할 것은 `worksheet.md`, 다음 회차까지 해 올 것은 `homework.md` 입니다.

## 스킬 17종

`1~`·`2~` 는 그 회차부터 계속 쓴다는 뜻입니다. 전부 1회차에 설치되고, 회차 열은 주로 쓰는 시점입니다. **1·2회차 배치는 확정이고, 3·4회차 배치는 가안입니다 — 2회차를 정리한 뒤 확정합니다.**

| 회차 | 스킬 이름 | 무엇을 하나 |
|---|---|---|
| 1~ | `indeans-erp-setup` | 도구·번들 설치·계정 가입(GitHub·Supabase·Vercel 필수)·작업 습관 점검, 회차마다 30초 점검 |
| 1·2 | `indeans-erp-interview` | 1차(회사·업종) → 2차(일의 흐름·막히는 곳) → 3차(화면·만들지 않을 것·로드맵), 한 번에 한 질문 |
| 1 | `indeans-erp-design` | 선택창에서 화면 구조 → 스타일 → 색·밝기를 고르고 앱에 적용 |
| 1(앞선 트랙)~ | `indeans-erp-rebuild` | 다른 도구로 만들어 온 앱이 있을 때 — 백업 → 자동 진단 → 5축 개선 방향 제안(대표가 고름) → 디자인 통일·화면 3개 재배치 → 검수 → 전후 비교 보고서(설치기가 앱을 알아보면 안내한다). 여러 앱이 든 저장소(`apps/*`)·`src/` 아래 7단계보다 깊은 화면은 자동으로 알아보지 못한다(지원 범위 밖 — 앱 폴더 하나를 프로젝트로 지정) |
| 2 | `indeans-erp-draft` | 설계 선언 → 모바일 설계 순서 → 스스로 점검 → 검수 → 대표 확인으로 초안 만들기, 끝나면 저장·배포로 |
| 2~ | `indeans-erp-report` | 작업이 끝날 때 전·후·왜·설계 선언 요약·바꾸지 않은 것을 보고서로 만들어 열기 |
| 2~ | `indeans-erp-check` | 위험 등급에 맞는 감독 판정 → 실측(바꾸기 전 시험 포함) → 감사 → 보고(검수 훅이 자동으로 부른다) |
| 2 | `indeans-erp-data` | 백업 먼저 → 번호 붙은 표 변경·실행 전 점검 → Supabase 저장 → Vercel 배포 → 직원이 넣고 다시 보기 |
| 3~ | `indeans-erp-review` | 써 보고 온 앱의 막힌 지점을 진단해 개선 + 디자인 감사(찾기만) |

## 에이전트 4종

인디언즈가 자체 앱에 쓰는 감독·검증·감사 구조를 업종과 무관하게 옮긴 것입니다. 수강생이 직접 부를 일은 거의 없고, `indeans-erp-check`·`indeans-erp-routine` 이 순서대로 부릅니다.

| 이름 | 역할 |
|---|---|
| `erp-supervisor` | 권한·돈·표 구조·삭제·배포 설정이 바뀌면 회사 문서를 기준으로 승인 / 조건부 승인 / 반려로 판정 |
| `erp-design-supervisor` | 고른 디자인 방향을 지키는지, 모바일과 PC 양쪽이 괜찮은지 판정 |
| `erp-verifier` | 판정하지 않고 실측만 — 화면 캡처(375·1280), 빌드, 저장·재접속, 역할별 접근 차단, 배포 뒤 확인, 휴대폰 확인표 |
| `erp-auditor` | 데이터베이스를 읽기만 하는 감사 — 고아·중복·규칙 구멍·노출·돈 맞춤을 건수와 번호로만 보고(고치지 않음) |

들어왔는지 확인하는 법은 두 가지입니다(목록을 내주는 명령은 따로 없습니다).

1. `.claude/agents/` (Codex 는 `.codex/agents/`)에 파일 4개가 있는지 봅니다.
2. AI에게 `erp-supervisor 에이전트로 이 변경을 검토해 줘.` 라고 시켜 실제로 떠지는지 봅니다.

## 훅 4종과 도우미

훅은 도구가 정해진 때에 스스로 부르는 확인입니다. 넷 다 네트워크를 쓰지 않고, `.owner/hooks/` 에서 열어 보면 무엇을 보는지 그대로 읽을 수 있습니다.

| 훅 | 언제 | 하는 일 |
|---|---|---|
| `erp-check.mjs` | 작업이 끝날 때 | **영향이 있는 변경**(화면·데이터 구조·권한·배포 설정·삭제 조건)이면 검수를 받고 끝내라고 요구합니다. 문서·문구·주석·색만 바뀐 수정은 생략하고, **줄 수로 판단하지 않습니다.** 검수를 마치면 표식(`.owner/last-check.json`)이 남아 같은 변경에 다시 요구하지 않고, 같은 작업에서 두 번 요구해도 검수가 없으면 세 번째부터는 경고만 냅니다 |
| `erp-guard.mjs` | 터미널 명령 바로 전 | 이름으로 프로그램을 통째로 끄는 명령(taskkill /IM · pkill · killall · Stop-Process -Name)을 멈추고, 자기가 띄운 서버만 번호(PID)로 끄는 법을 보여 줍니다 |
| `erp-predeploy.mjs` | 배포 명령 바로 전 | `vercel` 배포, 그리고 배포가 이어진 뒤의 `git push` 직전에 커밋 여부·빌드·고정 검사를 다시 돌려, 걸리면 배포를 멈추고 이유를 보여 줍니다. 되돌리기(`vercel rollback`)는 막지 않습니다. 실수를 막는 안전장치라 일부러 우회하는 것까지 막지는 못합니다 |
| `erp-reminder.mjs` | 새 대화를 열 때 | 주간 점검을 정해 둔 뒤 7일이 넘게 밀렸으면 한 줄로 알립니다. 막지 않습니다 |

도우미 스크립트(`open`·`capture`·`report`·`design-pick`)는 스킬이 부르는 열기·화면 캡처·보고서·디자인 선택창이고, 도구에 등록하지 않습니다.

훅을 끄고 싶으면 `.claude/settings.json`(또는 `.codex/hooks.json`)의 `hooks` 에서 그 항목을 지우면 됩니다. 스킬은 그대로 씁니다 — "검수해 줘" 라고 말하면 같은 절차가 돕니다. Codex 는 프로젝트 훅을 한 번 신뢰해야 돌고, 등록이 바뀌면 다시 신뢰해야 합니다(설치기가 알려 줍니다). Codex 훅 등록에는 내 프로젝트 폴더 경로가 들어가므로, **폴더를 옮기거나 다른 컴퓨터에서 받았으면 설치기를 한 번 더 실행**하세요.

## 디자인 선택창

1차 인터뷰가 끝나면 `indeans-erp-design` 스킬이 선택창을 엽니다(이 컴퓨터 안에서만 뜨는 화면입니다). **화면 구조 → 스타일 → 색·밝기** 순서로 고르면, 같은 예시 데이터로 그린 화면 3개가 그 자리에서 다시 그려져 휴대폰 폭과 PC 폭으로 비교할 수 있습니다. '이걸로 하기'를 누르면 색 설정과 화면 뼈대가 `src/styles/` 에 만들어지고, 이후 모든 화면이 그 방향을 따릅니다.

```powershell
node .owner/hooks/design-pick.mjs
```

브라우저가 안 열리면 터미널에 찍힌 주소를 브라우저에 붙여 넣습니다. 자세한 것은 설치된 `.owner/design/README.md` 에 있습니다.

## 필요한 것

- Node.js 18 이상, Git
- Claude Code 또는 Codex 중 하나(둘 다 있어도 됩니다)
- GitHub·Supabase·Vercel 계정 — 1회차에 `indeans-erp-setup` 과 함께 가입합니다(전부 무료 요금제로 시작). 디스코드·텔레그램은 선택입니다.
- 화면 캡처를 쓰려면 프로젝트에 playwright 설치(`npm i -D playwright` 뒤 `npx playwright install chromium`). 설치기가 대신 설치하지 않고, `indeans-erp-setup` 이 확인해 안내합니다.
