# 최종 회 — 오늘 반드시 끝내는 것

시연과 다음 방향 · 3시간 · 본 과정 종료 2주 뒤 · 전원 참석

오늘의 완료선은 하나다. **2주 사용 결과를 보여 주고, 다음 개선 순서를 정해서 나가는 것.**

만드는 자리가 아니다. **보여 주고 방향을 정하는 자리**다.

---

## 오늘의 완료선

| 항목 | 완료로 보는 기준 |
|---|---|
| **시연** | 실제로 도는 화면으로 10분을 마쳤다(시연 5 · 2주 결과 3 · 다음 순서 2) |
| **직원 사례** | 직원이 실제로 처리한 업무 1건을 흐름대로 보여 줬다 |
| **다음 순서** | 받은 의견이 `company/plan-30d.md` 에 **그날 안에** 반영됐다 |
| **운영 규칙** | 예상 운영비와 "한도를 넘으면 무엇을 멈출지"가 적혀 있다 |

안 되는 것은 안 된다고 말하면 된다. **그게 감점이 아니다.**

---

## 가져오는 것

- 실제로 도는 앱(노트북 + 충전기, 폰)
- 직원이 실제로 처리한 업무 **1건**
- `company/log.md` 의 2주치 세 줄 기록
- 주간 점검 기록 2회분, 개선 2건 반영 결과
- `company/plan-30d.md` 의 개선 3건과 순서
- 가장 크게 막힌 문제 1건 — **다시 일으키는 순서(1, 2, 3)까지**

---

## 시연 10분의 구성

| 구간 | 시간 | 내용 |
|---|---|---|
| 시연 | 5분 | 일이 흘러가는 순서대로. 화면 3개 이하. **직원이 처리한 1건**을 끝까지 |
| 2주 사용 결과 | 3분 | 몇 건 처리했나 / 예전 방식으로 돌아간 순간 / 직원이 한 말 하나 |
| 다음 개선 순서 | 2분 | 30일 계획 3건과 그 순서를 정한 이유 |

정원이 8명이면 1인 10분 그대로, 6명이면 뒤의 방향 이야기가 길어진다.

**말할 때 지킬 것**

- 화면을 켜 두고 시작한다. 화면 전환에 시간을 쓰지 않는다.
- **안 되는 것은 안 된다고 말한다.** "이 화면은 아직 껍데기입니다"가 좋은 시연이다.
- 실패하거나 되돌린 이야기를 하나 넣는다. 다른 사람에게 가장 도움이 되는 대목이다.
- 앱이 안 열리면 고치지 말고 캡처로 진행한다.
- 화면에 고객 실명·연락처·계좌·금액이 보이면 **미리 가린다.**

---

## 확인 기준

### 시연 전

- [ ] 지금 **실제로 도는 화면**과 안 되는 화면을 나눠서 안다
- [ ] 시연 순서 세 줄이 정해져 있다
- [ ] 화면에 고객 이름·연락처·금액이 없다
- [ ] 발표용 계정으로 미리 로그인해 뒀다

### 시연 중

- [ ] 10분 안에 끝냈다
- [ ] 직원이 처리한 1건을 흐름대로 보여 줬다
- [ ] 안 되는 것을 안 된다고 말했다
- [ ] 막힌 자리는 고치지 않고 **한 줄로 원인만** 듣고 넘어갔다

### 시연 뒤 (그날 안에)

- [ ] 받은 의견을 그대로 옮겨 적었다
- [ ] `company/plan-30d.md` 의 3건과 대조해 **이미 있는 것 / 새로 넣을 것 / 하지 않기로 할 것**으로 나눴다
- [ ] 3건을 넘으면 무엇을 뺄지 정했다
- [ ] 다음 주 점검 요일이 달력에 들어가 있다

## 오늘 이후

- 주간 점검은 정한 요일에 계속 돈다(`company/routine.md`).
- 급한 것 하나는 루틴을 기다리지 않는다 — `indeans-erp-routine` 의 문제 하나 잡는 순서를 그대로 따른다.
- **스킬·감독 에이전트·검수 훅은 내 프로젝트 안에 그대로 남는다.** 수업이 끝나도 계속 돈다.
- **카카오톡 단톡방은 오늘로 닫는다.** 오늘 이후의 질문은 각자 앱 안의 스킬과 주간 루틴으로 해결한다.

## 오늘 하지 않는 것

- 시연을 위해 앱을 급히 고치기 — 방금까지 되던 것이 깨진다
- 새 기능 만들기 — 오늘은 만드는 날이 아니다
- 다른 사람 앱과 비교해 자기 것을 낮춰 말하기 — 업종이 다르면 필요한 것도 다르다
