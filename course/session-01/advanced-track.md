# 1회차 앞선 트랙 — 이미 해 보고 오신 분

설치와 초안을 이미 해 본 분을 위한 **1회차 대체 과제**다. 기본 트랙과 **같은 시간에 다른 목표**를 잡는다. 진도를 앞서가는 것이 아니라 **깊이를 더한다** — 2회차 내용(Supabase 저장·배포)을 미리 하지 않는다.

이 카드를 받았다고 다른 수강생을 도와야 하는 것은 아니다. 하고 싶을 때만 한다.

---

## 언제 이 카드를 쓰나

아래 중 둘 이상에 해당하면.

- Claude Code 또는 Codex를 이미 써 봤다
- 회사 문서가 이미 있고 빈칸이 거의 없다 — 또는 **문서는 없지만 돌아가는 앱을 만들어 왔다**
- 초안 앱이 이미 돌아간다
- 수업 시작 30분 만에 기본 트랙 항목을 다 채웠다

---

## 설치·점검 시간에 할 것

### A1. 두 도구 비교 (권장)

같은 요청을 Claude Code와 Codex에 각각 넣고 결과를 비교한다.

```
company/flows.md 를 읽고, 우리 회사 업무 흐름에서 지금 문서에 빠져 있을 법한 단계를
세 가지만 짚어 주세요. 고치지는 말고 짚기만 해 주세요.
```

`company/flows.md` 가 아직 없으면(앱만 만들어 오신 분) 이렇게 바꿔 말한다: **"지금 이 앱의 화면을 읽고, 우리 회사 일에서 앱에 빠져 있을 법한 단계를 세 가지만 짚어 주세요. 고치지는 말고 짚기만 해 주세요."**

- 어느 쪽이 내 회사를 더 잘 읽었나
- 어느 쪽이 내 말투를 더 잘 알아듣나
- 결과를 세 줄로 적어 둔다

과정 내내 이 감각이 필요하다. **어느 도구가 좋은가**가 아니라 **어떤 일에 어느 쪽을 부를까**를 정하는 연습이다.

### A2. 개인 스킬 자리 세팅

`indeans-erp-setup` 스킬의 절차를 따라, 앞으로 만들 다른 폴더에서도 같은 스킬이 뜨게 해 둔다.

- Claude Code: `~/.claude/skills/`
- Codex: `~/.agents/skills/`
- 복사한 뒤 새 빈 폴더를 하나 만들어 거기서 스킬이 보이는지 확인한다

### A3. 되돌리기 연습

일부러 부숴 보고 되돌린다. 과정 내내 가장 많이 쓰게 될 안전장치다.

1. `git add -A && git commit -m "연습 전"`
2. `src/` 안의 파일 하나를 열어 아무 줄이나 지운다
3. 앱이 깨지는 것을 확인한다
4. `git status` 로 무엇이 바뀌었는지 본다
5. `git restore .` 로 되돌린다
6. 앱이 다시 도는 것을 확인한다

## 인터뷰 시간에 할 것 (둘 중 하나)

### B1. 재인터뷰 — 빈틈 찾기

```
indeans-erp-interview 스킬을 읽고 재인터뷰 모드로 진행해 주세요.
회사 문서는 이미 있습니다. 실제로 써 보니 빠진 단계나 실제와 다른 부분이 있는지
빈틈부터 찾아 주세요. 처음부터 다시 묻지는 마세요.
```

찾을 것:

- 문서에는 있는데 실제로는 안 쓰는 단계 → 뺀다
- 실제로는 하는데 문서에 없는 단계 → 넣는다
- 앱에 적으려다 적을 자리가 없어서 못 적은 것 → `company/structure.md` 의 항목 표에 넣는다

### B2. "이번에 만들지 않을 것" 확정 + 두 번째 흐름은 문서까지만

첫 흐름의 **앞** 또는 **뒤**에 붙는 흐름 하나를 정한다.

- 앞 — 일이 들어와서 시작되기까지(문의·견적·주문 접수)
- 뒤 — 끝난 뒤(정산·후속 연락·재구매)

```
indeans-erp-interview 스킬로 두 번째 흐름의 시작·끝·단계·담당·완료 증거만 물어봐 주세요.
company/flows.md 의 '두 번째 흐름' 절만 채우고, 앱에는 아직 넣지 마세요.
그리고 이번에 만들지 않을 것 목록을 company/structure.md 에 확정해 주세요.
```

**주의** — 두 번째 흐름을 앱에 넣는 것은 오늘이 아니다. 문서까지만. 첫 흐름이 안 끝난 채로 두 번째를 붙이면 첫 흐름이 영구히 안 끝난다.

## 마무리 시간에 할 것 (하나 고른다)

### C1. 디자인 조합 A/B

토큰 파일만 다른 조합으로 바꿔 보고 같은 화면을 비교한다.

```
indeans-erp-design 스킬을 읽고 조합 바꾸기로 진행해 줘.
지금 src/styles/tokens.css 를 tokens.{지금 조합 이름}.css 로 복사해 두고, 다른 조합의 토큰만 tokens.css 로 바꿔 줘.
화면 코드는 건드리지 마.
바꾼 뒤 PC(가로 1280)와 휴대폰(가로 375) 크기로 한 장씩 캡처해서 전·후를 나란히 보여 줘.
```

화면 코드를 하나도 안 고쳤는데 인상이 바뀌면, 색을 토큰으로 뺀 설계가 제대로 된 것이다. 안 바뀌는 부분이 있으면 그 화면에 색 값이 직접 박혀 있다는 뜻이다 — 찾아서 토큰으로 바꾼다.

`src/styles/tokens.css` 가 없는 앱(직접 만들어 오신 경우)이면 먼저 **색 값을 토큰 한 파일로 모으는 것**부터 한다. 그게 C1의 절반이다.

### C2. 목록 다듬기 (건수가 많은 회사)

월 100건이 넘는 회사면 1회차부터 필요하다.

- 검색창 하나 (이름으로 찾기)
- 기간 고르기 (이번 주 / 이번 달)
- 상태별 묶어 보기

셋 중 **하나만** 넣는다.

**목록을 불러올 때 정렬과 개수 제한을 반드시 같이 건다.** "전부 가져오기"는 건수가 늘면 조용히 잘린다 — 나중에 "왜 최근 것이 안 보이지"로 나타난다.

### C3. 내보내기 버튼

목록을 CSV로 내려받는 버튼 하나. 엑셀을 완전히 놓기 어려운 회사에서 반응이 가장 좋다.

```
목록 화면에 지금 보이는 목록을 CSV 파일로 내려받는 버튼을 만들어 주세요.
열 이름은 company/structure.md 의 항목 표에 적힌 우리 회사 말 그대로 써 주세요.
엑셀에서 한글이 깨지지 않게 저장해 주세요.
```

## 과제 (앞선 트랙)

기본 과제(직원과 함께 눌러 보고 세 줄)에 더해 하나만.

- B1을 했으면 → 고친 문서로 앱을 다시 맞춰 온다. 무엇이 바뀌었는지 한 줄로 적어 온다.
- B2를 했으면 → 두 번째 흐름은 **문서만** 준비해 온다. 앱에는 아직 넣지 않는다.
- C1을 했으면 → 두 조합의 캡처를 나란히 가져와 2회차에 의견을 받는다.

## 하지 않는 것

- 2회차 내용(Supabase 연결·Vercel 배포)을 미리 하기. 순서가 엉키면 2회차에 되돌려야 한다.
- 화면 4개 이상 만들기. 세 개로 끝내는 연습이 이 과정의 핵심이다.
- 다른 수강생 노트북을 대신 만져 주기. 말로 알려 주는 것까지만.
- 실제 회사 데이터 넣기. 2회차에 저장할 자리를 만들면서 같이 한다.
