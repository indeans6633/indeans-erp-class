# 1회차 앞선 트랙 — 이미 해 보고 오신 분

설치·가입을 이미 해 봤거나 앱을 만들어 온 분을 위한 **오늘의 대체 과제**다. 기본 트랙과 **같은 시간에 다른 목표**를 잡는다.

진도를 앞서가는 것이 아니라 **깊이를 더한다** — 2회차의 초안·저장·배포를 미리 하지 않는다.

이 카드를 받았다고 다른 수강생을 도와야 하는 것은 아니다. 하고 싶을 때만 한다.

---

## 언제 이 카드를 쓰나

아래 중 둘 이상에 해당하면.

- Claude Code 또는 Codex를 이미 써 봤다
- GitHub · Supabase · Vercel 계정이 이미 있다
- 회사 문서가 이미 있다 — 또는 **문서는 없지만 돌아가는 앱을 만들어 왔다**
- 설치·계정 블록의 기본 항목을 20분 안에 다 채웠다

---

## 설치·계정 시간에 할 것 (하나 이상)

### A1. 두 도구 비교 (권장)

같은 요청을 Claude Code와 Codex에 각각 넣고 결과를 비교한다.

```
이 폴더에 설치된 스킬 이름과 각각 무엇을 하는지 표로 정리해 주세요.
그중 1회차와 2회차에 쓰는 것만 따로 표시해 주세요. 아무것도 고치지 마세요.
```

- 어느 쪽이 내 질문을 더 잘 알아듣나
- 어느 쪽이 더 짧고 정확하게 정리하나
- 결과를 세 줄로 적어 둔다

**어느 도구가 좋은가**가 아니라 **어떤 일에 어느 쪽을 부를까**를 정하는 연습이다. 과정 내내 이 감각이 필요하다.

### A2. 선택 계정 미리 — 디스코드 · 텔레그램

운영 보고 단계에서 쓰는 창구 둘을 미리 가입해 둔다. 서버·채널 이름과 텔레그램 사용자 이름만 `.owner/accounts.md` 에 적는다. **웹후크 주소와 봇 열쇠는 오늘 만들지 않는다** — 그 단계의 스킬이 만들고, 둘 다 비밀값이다.

### A3. 되돌리기 연습

일부러 고치고 되돌린다. 과정 내내 가장 많이 쓰게 될 안전장치다.

1. `git add -A` → `git commit -m "연습 전"`
2. `README.md` 처럼 지워도 괜찮은 파일 하나를 열어 아무 줄이나 지운다
3. `git status` 로 무엇이 바뀌었는지 본다
4. `git restore .` 로 되돌린다
5. 지운 줄이 돌아왔는지 확인한다

### A4. 다른 폴더에서도 같은 스킬 쓰기

`indeans-erp-setup` 스킬의 앞선 분기(「다른 폴더에서도 쓰기」)를 따라, 앞으로 만들 다른 폴더에서도 같은 스킬이 뜨게 해 둔다.

- Claude Code: `~/.claude/skills/`
- Codex: `~/.agents/skills/`
- 복사한 뒤 새 빈 폴더 하나에서 스킬이 보이는지 확인한다

## 1차 인터뷰 시간에 할 것 (둘 중 하나)

### B1. 앱을 만들어 온 분 — 리빌딩으로 시작한다

다른 도구(다른 AI·바이브코딩·노코드)로 만들어 온 앱이 이 폴더에 있으면, 1차 인터뷰를 따로 열지 않고 **`indeans-erp-rebuild`** 로 시작한다. 설치기가 앱을 알아보면 마지막에 이 스킬 이름을 알려 준다. **새 대화를 열고** 넣는다.

```
indeans-erp-rebuild 스킬을 읽고 시작해 주세요.
이 폴더의 앱은 제가 다른 도구로 만들어 온 것입니다. 먼저 되돌릴 지점과 백업을 만들고,
앱을 진단해서 개선 방향을 제안해 주세요. 제가 고르기 전에는 아무것도 고치지 마세요.
```

이 대화에서 일어나는 일:

1. **되돌릴 지점 + 전체 백업** — 지금 모습을 저장 기록과 `.owner/backup/` 두 곳에 남긴다. 접속 정보 파일(`.env`)은 열지 않는다.
2. **자동 진단** — 화면 수·저장 방식·로그인·디자인·회사 말·휴대폰 폭·비밀값 노출 등 열 가지를 보고, 앱 화면을 휴대폰·PC 폭으로 찍어 둔다(전 사진).
3. **1차 인터뷰(짧게)** — 회사·업종은 그대로 묻고, 화면에 이미 있는 것은 "이렇게 부르시는 것 맞죠?"로 확인만 한다. 두 가지를 더 묻는다: 이 앱으로 풀려던 문제 하나 · 지금 제일 아쉬운 것.
4. **개선 방향 제안서** — 구조 · 디자인 · 데이터·권한 · 검수·보고 · 운영 보고 다섯 가지를 "지금 → 바꾸면 → 달라지는 것 → 언제"로 보여 주고 권장안 하나를 낸다. **대표님이 고른다.**
5. **오늘 바꾸는 것(권장안)** — 디자인 선택창으로 모양을 하나로 통일 · 화면을 목록 / 상세·입력 / 오늘 현황 셋으로 묶기(오늘 현황이 없으면 더한다) · 검수 통과. 저장 방식과 로그인은 오늘 바꾸지 않는다 — 2회차에 백업을 먼저 만들고 한다.
6. **전후 비교 보고서** — `reports/<날짜>-리빌딩-전후.html` 에 전·후 화면을 나란히, 바뀐 것과 바꾸지 않은 것, 남은 순서까지.

디자인 선택창은 제안을 고른 뒤 이 대화 안에서 열린다(기본 트랙의 P5와 같은 화면이다).

**시간** — 제안서까지는 1차 인터뷰 시간 안에 끝난다(되돌릴 지점·진단·짧은 인터뷰·제안, 10~15분). 제안을 고른 뒤 리빌딩(디자인 연결·화면 셋·검수·전후 보고서)은 **AI 혼자 20~30분** 일한다 — 창을 닫지 말고 기다린다. 수업 안에 안 끝나면 "여기까지"라고 말하고, 집에서 새 대화에 `indeans-erp-rebuild 스킬을 읽고 이어서 진행해 주세요.` 라고 넣으면 저장된 자리에서 이어진다. 중간에 "대표님 직접 확인" 다섯 줄이 나오면 **직접 눌러 보고** 답한다 — 건너뛰지 않는다.

회사 문서까지 이 번들로 이미 써 온 분(앱을 만든 뒤 1차 문서가 있는 분)은 리빌딩 대신 재인터뷰로 빈틈만 찾는다.

```
indeans-erp-interview 스킬을 읽고 재인터뷰 모드로 진행해 주세요.
회사 문서는 이미 있습니다. 실제로 써 보니 빠진 단계나 실제와 다른 부분이 있는지
빈틈부터 찾아 주세요. 처음부터 다시 묻지는 마세요.
```

### B2. 1차가 일찍 끝난 분 — 2차 인터뷰 미리

디자인까지 고른 뒤 시간이 남으면 **새 대화에서** 2차 인터뷰(일의 흐름·막히는 곳)를 미리 해도 된다. 직원 확인 과제는 그다음 차수 첫머리에 받는다.

```
indeans-erp-interview 스킬을 읽고 2차 인터뷰를 시작해 주세요.
과제(직원에게 1차 요약 읽어 주기)는 아직 못 했습니다. 그건 다음 차수 첫머리에 받아 주세요.
한 번에 하나씩만 물어봐 주세요. 앱은 아직 만들지 마세요.
```

**주의** — 3차(화면·범위 확정)와 초안은 오늘 하지 않는다. 직원 이야기를 듣기 전에 화면을 정하면 2회차에 다시 정하게 된다.

## 디자인 시간에 할 것 (하나 고른다)

### C1. 두 조합 나란히 보기

선택창에서 마음에 드는 조합 두 개를 휴대폰 폭·PC 폭으로 번갈아 보고, 둘을 화면 사진으로 남긴다.

```
디자인 선택창에서 제가 고른 조합과 {두 번째 조합 코드} 를 PC 폭과 휴대폰 폭으로 한 장씩 찍어서 나란히 보여 주세요.
고른 디자인은 바꾸지 마세요.
```

두 사진을 직원에게 보여 주고 **어느 쪽이 빨리 읽히는지** 묻는다(과제와 같이 하면 된다). 답을 `company/design.md` 에 한 줄 적는다.

### C2. 감독 에이전트 한 번 불러 보기

고른 디자인 문서를 디자인 감독에게 검토받아 본다. 검수 체계가 어떻게 말하는지 미리 겪어 두면 2회차 검수가 쉬워진다.

```
erp-design-supervisor 에이전트로 company/design.md 를 검토해 줘.
판정과 이유만 보여 주고, 아무것도 고치지 마.
```

### C3. 직접 만든 앱의 색 모으기 (앱을 만들어 온 분 — 리빌딩을 하지 않을 때)

B1 리빌딩을 하면 이 일은 리빌딩 안에서 한다. 리빌딩 없이 디자인만 고른 분이 화면 파일에 색·글자 크기가 여기저기 적혀 있으면, 고른 토큰(`src/styles/tokens.css`)으로 **화면 하나만** 먼저 바꿔 본다. 디자인 스킬이 그 순서를 안다 — 한꺼번에 바꾸지 않는다.

## 과제 (앞선 트랙)

기본 과제(1차 요약을 직원에게 읽어 주고 세 줄)에 더해 하나만.

- B1(리빌딩)을 했으면 → 전후 비교 보고서를 직원에게 보여 주고, 직원 폰에서 가장 먼저 달라진 것 한 줄을 적어 온다. 재인터뷰를 했으면 고친 문서를 직원에게 읽어 주고 바뀐 것 한 줄.
- B2를 했으면 → 2차 요약을 직원에게 읽어 주고, 빠진 단계를 한 줄 적어 온다.
- C1을 했으면 → 직원이 고른 쪽과 이유를 한 줄 적어 온다.

## 하지 않는 것

- 2회차 내용(초안 만들기 · Supabase 연결 · Vercel 배포)을 미리 하기. 순서가 엉키면 2회차에 되돌려야 한다.
- 3차 인터뷰(화면·범위 확정)를 오늘 하기. 직원 확인을 거친 뒤에 정한다.
- 다른 수강생 노트북을 대신 만져 주기. 말로 알려 주는 것까지만.
- 실제 회사 데이터 넣기. 2회차에 저장할 자리를 만들면서 같이 한다.
