# 1회차 과제 — 1차 요약을 직원에게 읽어 주고 빠진 것 세 줄 적어 오기

다음 회차까지 할 일은 하나다. **`company/profile.md` 끝의 1차 요약을 직원에게 읽어 주고, 빠진 것을 세 줄 적어 온다.**

권장 시간: 20~30분. 앱을 만들어 오는 과제가 아니다 — 앱은 2회차에 만든다.

왜 직원인가. 1차 요약은 대표님 머릿속의 회사다. 매일 그 일을 하는 사람이 들으면 "그거 말고 이것도 있어요"가 거의 반드시 나온다. 그 한마디가 2회차 2차 인터뷰의 첫 질문이 된다.

---

## 하는 일

### 1. 1차 요약을 연다

프로젝트 폴더의 `company/profile.md` 맨 끝 「1차 요약 (직원에게 읽어 줄 것)」 절이 읽어 줄 부분이다. 파일을 여는 게 낯설면 AI에게 이렇게 말한다.

```
company/profile.md 끝의 1차 요약을 화면에 그대로 보여 주세요.
아무것도 고치지 마세요.
```

### 2. 직원 한 명에게 읽어 준다

- 이 일을 **실제로 하는 사람** 한 명. 컴퓨터를 잘 다루는 사람 말고.
- 1인 회사면 자주 함께 일하는 사람(외주처·가족)이나 회사 사정을 아는 지인에게 읽어 준다.
- 설명을 덧붙이지 말고 읽어 준 뒤 한 문장만 묻는다.

> "여기서 빠진 거나 실제와 다른 거 있어요?"

### 3. 세 줄을 적는다

들은 말을 **그대로** 적는다. 대표님이 정리한 문장으로 바꾸지 않는다. 종이·휴대폰 메모 어디든 된다 — 2회차 2차 인터뷰 첫 질문에 그대로 읽어 주면 AI가 `company/profile.md` 에 옮겨 적는다.

```markdown
## <날짜> · 1차 요약을 들은 사람: <역할 — 실명 말고>
1. <빠진 것 또는 다른 것 — 들은 말 그대로>
2. <…>
3. <…>
```

- 세 줄이 안 나와도 된다. 하나만 나와도, "없다"는 대답도 그대로 적는다.
- "이거 어디에 적어요?", "그건 제가 따로 챙겨요" 같은 짧은 말이 가장 쓸모 있다.
- 고객 이름·금액·연락처는 적지 않는다.

---

## 계정 3종 — 2회차 시작 전까지 필수

1회차에 GitHub · Supabase · Vercel 가입을 다 못 했다면 **이번 주 안에 끝낸다.** 과제 중에 이것만 마감이 있다.

- 없으면 2회차에 저장과 배포를 못 한다. 2회차의 끝(직원이 자기 폰으로 넣는 앱)이 이 세 계정 위에서 돌고, 계정 없이 가는 다른 길이 없다.
- 순서: **GitHub 먼저**, 그다음 "GitHub로 계속"으로 Supabase · Vercel.
- 셋 다 무료 요금제로 가입한다. **카드 입력 화면이 나오면 멈추고 한 화면 뒤로** 간다.
- Supabase는 **조직까지만** 만든다. 프로젝트는 2회차에 같이 만든다(무료 프로젝트는 일주일 넘게 안 쓰면 잠시 멈추고, 동시에 두 개까지다).

AI에게 이렇게 말하면 남은 줄부터 돕는다.

```
indeans-erp-setup 스킬을 읽고 계정 가입을 마저 도와주세요.
.owner/accounts.md 에서 (아직)으로 남은 줄부터 한 단계씩 안내해 주세요. 비밀번호와 인증 코드는 제가 직접 넣겠습니다.
앱은 아직 만들지 마세요.
```

가입 화면에서 막히면 1회차 `prompts.md` 의 「가입 화면에서 막혔을 때」 문장을 쓴다. 그래도 안 되면 막힌 화면을 사진으로 남겨 두고 2회차 전에 강사에게 알린다 — 당일 아침에 말하면 2회차 시간이 가입으로 간다.

---

## 확인 — 이게 되면 과제 끝

- [ ] 1차 요약을 직원(또는 함께 일하는 사람) 한 명에게 읽어 줬다
- [ ] 들은 말을 세 줄 이내로 그대로 적었다
- [ ] `.owner/accounts.md` 의 GitHub · Supabase · Vercel 세 줄이 채워져 있다

다 못 채워도 온다. **하나도 못 했어도 온다.** 2차 인터뷰가 요약을 다시 읽어 주고 그 자리에서 받는다.

---

## 하지 않아도 되는 것

- 앱 만들기. 2회차에 2·3차 인터뷰로 화면을 정한 다음에 만든다. 미리 만들면 2회차에 되돌리게 된다.
- 디자인 다시 고르기. 마음이 바뀌었으면 2회차 3차 인터뷰 때 말한다 — 그때 정한 화면과 맞는지 같이 본다.
- Supabase 프로젝트 만들기 · GitHub에 올리기. 2회차에 같이 한다.
- 디스코드 · 텔레그램. 시간이 남을 때만 한다(운영 보고 단계에서 쓴다).

## 2회차에 가져올 것

1. 노트북 + 충전기
2. **세 줄**(직원이 한 말 그대로)
3. **GitHub · Supabase · Vercel 에 로그인되는 상태** — 없으면 2회차를 끝낼 수 없다
4. 휴대폰 — 2회차 마지막에 내 앱 주소를 폰으로 연다
5. **직원 한 명과 연락되는 시간** — 2회차 끝에 직원이 자기 폰으로 한 건을 넣어 본다. 수업 자리에 없어도 주소와 계정을 보내 그 자리에서 넣게 한다
