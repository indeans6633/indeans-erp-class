# 1회차 과제 — 직원과 함께 눌러 보고 세 줄 적어 오기

다음 회차까지 할 일은 하나다. **직원과 함께 초안을 눌러 보고, 세 줄을 적어 온다.**

권장 시간: 30~40분. 앱을 더 만들어 오는 과제가 아니다.

**이번에는 대표님 노트북에서 한다.** 아직 인터넷 주소가 없어서(2회차에 만든다) 직원 기기로는 접속할 수 없다. 직원을 옆에 앉히고 **대표님 화면을 직원이 직접 누르게** 한다.

---

## 하는 일

### 1. 앱을 켠다

프로젝트 폴더에서 AI를 켜고, 어디까지 됐는지부터 확인한다.

```
이 프로젝트를 읽고 지금 어디까지 만들어졌는지, 다음에 무엇을 하면 되는지 세 줄로 알려 주세요.
아직 아무것도 고치지 마세요.
```

그다음 앱을 띄운다.

```powershell
npm run dev
```

터미널에 나오는 주소를 브라우저에서 연다.

### 2. 직원 한 명을 옆에 앉힌다

- 이 일을 **실제로 하게 될 사람**으로 고른다. 컴퓨터를 잘 다루는 사람 말고.
- 한 명이면 충분하다. 두세 명이면 무엇 때문에 막혔는지 구분이 안 된다.
- 마땅한 사람이 없으면 가족·지인에게 **그 역할인 척** 써 보게 한다.

### 3. 설명하지 말고 한 문장만 말한다

> "이번 주에 실제로 있었던 건 하나만 넣어 보세요."

그리고 **대신 눌러 주지 않는다.** 대표님이 손을 대는 순간 얻을 정보가 사라진다. 어디서 멈추는지, 무엇을 먼저 찾는지만 본다.

- 예시 데이터로 눌러 본다. **실제 고객 이름·연락처·금액은 아직 넣지 않는다.** 저장할 곳이 브라우저 안뿐이라 2회차에 옮기면서 지워진다.

### 4. 세 줄을 적는다

수업에서 나온 형식 그대로다. 잘 쓰려고 하지 않는다.

```markdown
## <날짜> · 1회차 뒤
- 시도한 업무: <이 앱으로 하려 한 일>
- 막힌 지점: <손으로 하거나 그만둔 자리>
- 원하는 변화: <어떻게 되면 되겠는가>
```

AI에게 그대로 적게 해도 된다.

```
오늘 직원과 함께 앱을 눌러 봤어. 아래 세 줄을 company/log.md 맨 위에 그대로 적어 줘.
시도한 업무: {이 앱으로 하려 한 일}
막힌 지점: {손으로 하거나 그만둔 자리}
원하는 변화: {어떻게 되면 되겠는가}
내 말을 요약하거나 다듬지 말고 그대로 넣어 줘. 앱은 고치지 마.
```

**직원이 한 말은 그대로 옮긴다.** "이거 어디로 들어가요?" 같은 짧은 말이 가장 쓸모 있다. 대표님이 정리한 문장으로 바꾸면 사실이 흐려진다.

---

## 확인 — 이게 되면 과제 끝

- [ ] `npm run dev` 로 앱이 켜진다
- [ ] 목록 화면에 예시 데이터가 보인다
- [ ] 한 건을 열어 상세로 넘어간다
- [ ] 새로 하나 만들어 저장하면 목록에 늘어난다
- [ ] 휴대폰 크기(가로 360)로 줄여도 글자가 잘리거나 가로로 밀리지 않는다
- [ ] `company/log.md` 에 세 줄이 적혀 있다
- [ ] 1회차 작업 보고서가 `reports/` 에 한 장 있다

다 못 채워도 온다. **하나도 못 했어도 온다.** 2회차 첫 시간에 같이 잡는다.

## 집에서 막힐 때 쓰는 문장

### 앱이 안 켜질 때

```
npm run dev 를 실행했는데 이렇게 나옵니다: {터미널 글자 그대로 붙여넣기}
원인을 찾아 고치기 전에, 무엇 때문인지 한 줄로 먼저 알려 주세요.
```

### 화면이 하얗게 나올 때

```
앱 주소를 열었는데 화면이 하얗습니다.
브라우저 개발자 도구(F12)에 이런 빨간 글씨가 있습니다: {그대로 붙여넣기}
원인을 찾아 고쳐 주세요.
```

### 만들다가 더 이상해졌을 때

```
방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 상태로 되돌려 주세요.
되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```

### 화면 내용이 우리 회사와 다를 때

```
company/structure.md 를 읽어 주세요.
목록 화면에 {무엇}이 보여야 하는데 지금은 {무엇}이 보입니다.
문서와 화면 중 어느 쪽이 틀렸는지 먼저 알려 주고, 문서가 틀렸으면 문서부터 고쳐 주세요.
```

## 하지 않아도 되는 것

- 화면을 예쁘게 다듬기. 2회차에 같이 본다.
- 기능 추가. 화면 3개에서 멈춘다. 더 만들고 싶은 것은 세 줄 기록의 "원하는 변화"에 적어만 둔다.
- 실제 회사 데이터 입력. 2회차에 저장할 자리를 만든 뒤에 넣는다.
- GitHub에 올리기. 2회차에 같이 한다.
