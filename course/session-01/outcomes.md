# 1회차 — 오늘 반드시 끝내는 것

설치·계정 가입·1차 인터뷰·디자인 선택 · 3시간

오늘의 완료선은 하나다. **설치·계정 가입 + 1차 인터뷰(회사·업종)로 쓴 회사 문서 + 고른 디자인.**

진도 기록(`.owner/progress.json`)의 1회차 문구와 같은 말이다. AI는 아래 세 줄이 **모두 실제로 확인됐을 때만** 1회차를 끝난 것으로 적는다.

"어디까지 배웠나"가 아니라 **무엇이 손에 남았나**로 판정한다. 오늘은 앱을 만들지 않는다 — 앱의 설계도가 될 회사 문서를 쓰고, 앱이 입을 옷(디자인)을 고르는 날이다.

---

## 오늘의 완료선

| 항목 | 완료로 보는 기준 |
|---|---|
| **계정 가입** | GitHub(계정 + 비공개 빈 저장소) · Supabase(GitHub로 로그인 + 조직) · Vercel(GitHub로 로그인) 세 줄이 `.owner/accounts.md` 에 있다 — 계정 이름만, 비밀값 없음 |
| **1차 인터뷰 문서** | `company/profile.md` 에 회사·업종이 있고, 끝에 **디자인 힌트**(일곱 줄)와 **1차 요약**이 있다 |
| **디자인 선택** | 디자인 코드(예: `board-soft-teal-auto` · 내 색이면 `board-indeans-custom-2a6f9e-auto`)가 정해졌고, `src/styles/tokens.css` 첫 줄에 그 코드가 적혀 있다 |

이 셋이 되면 오늘은 끝난 것이다. 계정 하나가 오늘 안 끝났으면 `(아직)` 으로 두고 **2회차 시작 전까지** 만든다(과제).

## 손에 남는 것

### 1. 도구와 번들 — 한 번만 설치

- Claude Code 또는 Codex 중 **하나 이상**이 돈다(`claude --version` / `codex --version` 에 숫자).
- 저장소 하나를 받아 **스킬 15종 · 에이전트 4종(감독 2 · 검증 1 · 감사 1) · 훅 3종(검수 · 배포 전 확인 · 주간 점검 알림)과 도우미 4종 · 디자인 선택창 · 수업 자료**를 한 번에 넣는다. 2회차부터는 저장소를 다시 받지 않는다.

| 자리 | 무엇 |
|---|---|
| `company/` | 회사 문서(오늘은 `profile.md` · `design.md`) |
| `course/session-01/` | 오늘 자료 |
| `.owner/` | 설치 기록 · 상태 문서 · 계정 기록(`accounts.md`) · 훅 · 디자인 선택창 |
| `.claude/skills/` · `.agents/skills/` | Claude Code 쪽 · Codex 쪽 스킬 |

### 2. 계정 3종 (+ 선택 2종)

| 서비스 | 하는 일 | 오늘 만드는 것 | 처음 쓰는 때 |
|---|---|---|---|
| GitHub | 만든 앱을 보관하는 창고 | 계정 + **비공개(Private) 빈 저장소** 1개(이름 = 프로젝트 폴더 이름) | 2회차 — 올리기 |
| Supabase | 앱에 넣은 내용을 두는 곳 | GitHub로 로그인 + 조직(Free). **프로젝트는 만들지 않는다** | 2회차 — 저장 연결 |
| Vercel | 앱을 인터넷 주소로 띄우는 곳 | GitHub로 로그인(Hobby). 가져오기는 하지 않는다 | 2회차 — 배포 |
| 디스코드(선택) | 쌓이는 보고 창구 | 계정 · 서버 · 채널 — 시간이 남을 때만 | 운영 보고 단계 |
| 텔레그램(선택) | 바로 아는 보고 창구 | 폰 앱 가입 — 시간이 남을 때만 | 운영 보고 단계 |

`.owner/accounts.md` 에는 **서비스 · 계정 이름(아이디·저장소·조직·팀) · 만든 날** 세 가지만 적는다. 비밀번호·복구 코드·키·토큰·메일 주소·휴대폰 번호는 적지 않는다 — 이 파일은 저장소에 같이 올라간다.

### 3. 1차 인터뷰 문서 — `company/profile.md`

| 절 | 무엇이 적혀 있나 |
|---|---|
| 대표와 회사 | 회사 이름 · 대표 호칭 · 업종(대분류 > 소분류 — 회사를 소개하는 한 줄) · 규모 · 주 고객 |
| 상품·서비스 · 돈 · 사람 | 파는 것 · 한 건 기간 · 돈 받는 방식(금액 없이) · 사업장(주소 없이) · 인원과 밖에서 일하는 사람 · 주로 쓰는 기기 |
| 관리 단위 | "이거 하나"라고 셀 때의 회사 말 — 후보 1~2개(2회차 2차 인터뷰에서 하나로 정한다) |
| 디자인 힌트 | 고객이 화면을 보나 · 기기 · 밖 근무 · 월 건수 · 동시 진행 · 예상 단계 수 · 구조 추천 — **일곱 줄**. 디자인 선택창이 이것으로 추천을 붙인다 |
| 1차 요약 | 직원에게 읽어 줄 요약 — 오늘 과제의 재료 |

질문은 업종에 맞춰 바뀐다. 카페면 재료·마감·근무표, 교습소면 레슨·보강·발표회, 부품 공장이면 수주·납기·검사로 묻는다.

### 4. 디자인 — 선택창에서 고른 조합

화면 구조 3 · 스타일 7(인디언즈 스타일 포함) · 색 10 + 내 색 · 밝기 자동/밝게/어둡게 중에서 고른 조합. 대표님이 꼭 고르는 것은 구조와 스타일 둘이고, 색·밝기(기본 자동)·모서리·밀도는 접힌 세부 조절에서 필요할 때만 바꾼다. 같은 예시 회사(○○상사)·같은 예시 데이터로 그린 화면 3개(목록 · 상세·입력 · 오늘 현황)를 보면서 골랐다.

- `company/design.md` — 고른 조합 · 고른 이유(대표님 말 그대로) · 바꾸면 안 되는 것
- `src/styles/tokens.css` · `base.css` · `layout.css` · `fonts/` — 색 설정·화면 뼈대·글꼴(라이선스 파일 포함 — 지우지 않는다). 2회차 초안이 이것을 그대로 입는다
- `.owner/design/choice.json` — 선택창이 저장한 조합과 시각

나중에 바꿀 수 있다. 다만 바꾸면 화면 인상이 전부 달라지므로 2회차 3차 인터뷰 때 맞는지 한 번 더 본다.

### 5. 상태 문서

`.owner/state.md` — 미해결 문제(미가입·미설치 항목) · 선택한 디자인 · 다음 행동. 다음 회차는 여기서 시작한다. `.owner/progress.json` 은 같은 내용의 기계용 기록이다.

## 확인 기준 — 집에 가기 전에 직접 본다

### 설치·계정

- [ ] `.claude/skills/` 와 `.agents/skills/` 에 스킬 폴더가 15개씩 있다
- [ ] `.owner/accounts.md` 에 GitHub · Supabase · Vercel 세 줄이 있다 — 계정 이름과 만든 날만, 비밀번호·메일·전화번호·코드는 없다
- [ ] GitHub 저장소 이름 옆에 `Private` 표시가 있다
- [ ] Supabase 에는 **조직만** 있다(프로젝트는 2회차에 만든다)

### 1차 인터뷰 문서

- [ ] `company/profile.md` 의 업종이 "대분류 > 소분류 — 회사 말 한 줄"로 적혀 있다
- [ ] 관리 단위 후보가 **회사에서 실제로 쓰는 말**로 1~2개 있다
- [ ] 끝에 디자인 힌트 일곱 줄이 있고, 구조 추천이 비어 있지 않다
- [ ] 끝에 1차 요약이 있고, 소리 내어 읽었을 때 **내 회사 얘기로 들린다**
- [ ] 문서 어디에도 고객 실명·연락처·금액·계좌·사업장 주소가 없다

### 디자인

- [ ] `src/styles/tokens.css` 첫 줄 주석에 고른 조합 코드가 있다
- [ ] `company/design.md` 에 고른 조합과 고른 이유가 있다

### 기록

- [ ] `.owner/state.md` 의 "선택한 디자인" · "미해결 문제" · "다음 행동"이 오늘 것으로 고쳐졌다
- [ ] `git log` 에 오늘 커밋이 3개 이상 있다(시작 점검 · 회사 문서 · 디자인)

## 오늘 한 문장으로 설명할 수 있어야 하는 것

집에 가서 직원에게 말할 수 있으면 된다.

1. 우리 회사는 열 가지 업종 중 어디이고, 회사를 소개하는 한 줄은 무엇인가.
2. 앱에서 "이거 하나"라고 셀 것(관리 단위 후보)은 무엇인가.
3. 고른 화면 구조는 무엇이고, 왜 그것인가.

셋에 막힘없이 답하면 오늘 수업은 성공이다.

## 알아 둘 것 — 검수는 오늘부터 돈다

번들을 설치한 순간부터 **검수 체계가 작동한다.** 화면·저장 항목·권한·배포 설정이 바뀌면 작업 끝에 "검수가 필요합니다"라는 말이 나온다. 그때는 `indeans-erp-check` 스킬을 부르면 된다(오늘 자료 `prompts.md` 의 P6).

글자만 바꾼 수정은 검수를 요구하지 않는다. **줄 수가 아니라 영향으로 판단한다.** 첫 검수 때 바뀐 파일 목록이 길게 나오는 것은 정상이다.

- 디스코드·텔레그램 보고 연결 — 운영 보고 단계(오늘은 시간이 남을 때 가입만)
