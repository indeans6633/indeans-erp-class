# 1회차 — 오늘 반드시 끝내는 것

첫 흐름 초안과 첫 보고 · 3시간

오늘의 완료선은 하나다. **회사의 핵심 업무 흐름 하나를 눌러 볼 수 있는 초안(디자인 포함) + 그것을 설명하는 첫 작업 보고서.**

"어디까지 배웠나"가 아니라 **무엇이 손에 남았나**로 판정한다. 설치가 덜 됐어도 초안이 돌면 성공이고, 설치가 다 됐어도 초안이 없으면 다음 회차 앞 시간에 이어서 만든다.

---

## 오늘의 완료선

| 항목 | 완료로 보는 기준 |
|---|---|
| **초안 앱** | `npm run dev` 로 열리고, 목록 → 상세 → 새로 만들기가 **끝까지 눌린다** |
| **디자인** | 고른 구조·색이 화면에 실제로 적용돼 있다(`src/styles/tokens.css`) |
| **첫 작업 보고서** | `reports/` 에 HTML 한 장이 있고 브라우저로 열린다 |

이 셋이 되면 오늘은 끝난 것이다.

---

## 손에 남는 것

### 1. 도구와 계정 (사전 안내로 이미 마친 상태)

- Claude Code 또는 Codex 중 **하나 이상**이 돈다(`claude --version` / `codex --version` 에 숫자).
- GitHub · Supabase · Vercel 가입. 오늘은 **가입 확인만** 한다.
- 개강 전 안내로 미리 끝내 오는 항목이다. 못 하고 왔으면 당일 앞 30분에 따라잡는다.

### 2. 번들 설치 — 한 번만

저장소 하나를 받아 **스킬 14종 · 감독 에이전트 3종 · 검수 훅 · 디자인 이미지 세트 · 수업 자료**를 한 번에 넣는다.

```
my-erp/
  company/           회사 문서
  course/session-01/ 오늘 자료
  reports/           작업 보고서가 쌓이는 곳
  .owner/            설치 기록·상태 문서·훅·디자인 이미지
  .claude/skills/    Claude Code 쪽 스킬
  .agents/skills/    Codex 쪽 스킬
```

2회차부터는 저장소를 다시 받지 않는다.

### 3. 회사 문서 4종 — 초안의 재료

| 파일 | 무엇이 적혀 있나 |
|---|---|
| `company/profile.md` | 사업자명·대표 호칭·근무자 현황·사업 규모·업태·주 고객·**관리 단위** |
| `company/flows.md` | 첫 업무 흐름의 시작·끝·중간 단계·누가 하나·끝났다는 증거 |
| `company/scope.md` | 이번에 만들 것과 **이번에 만들지 않을 것** |
| `company/structure.md` | 화면 목록 3개·한 건에 적는 항목표 |

### 4. 디자인 방향 하나

구조 3종(목록·표형 / 진행 보드형 / 카드·상세형) 중 하나를 먼저 고르고, 그 구조의 색 4종 중 하나를 고른다. 결과는 `company/design.md` 와 `.owner/state.md` 에 적힌다. 나중에 바꿀 수 있다.

### 5. 초안 앱 (화면 3개)

목록 · 상세/입력 · 오늘 할 일(또는 현황). 이 셋으로 첫 흐름 하나를 끝까지.

### 6. 첫 작업 보고서

`reports/<날짜>-<제목>.html`. 어느 화면이 무엇을 하는 화면인지, 왜 그렇게 만들었는지가 대표가 읽을 수 있는 말로 적혀 있다. **내 컴퓨터에만 만들어지고 어디로도 보내지지 않는다.**

## 확인 기준 — 집에 가기 전에 직접 눌러 본다

### 초안 앱

- [ ] `npm run dev` 로 앱이 켜진다
- [ ] 목록 화면에 예시 데이터가 보이고, 그 데이터가 **우리 회사 말**로 적혀 있다
- [ ] 한 건을 열어 상세로 넘어간다
- [ ] 새로 하나 만들어 저장하면 목록에 늘어난다
- [ ] 휴대폰 크기(가로 360)로 줄여도 글자가 잘리거나 가로로 밀리지 않는다

### 디자인

- [ ] `src/styles/tokens.css` 가 있고, 고른 조합이 `company/design.md` 에 적혀 있다
- [ ] 화면 인상이 고른 이미지와 크게 다르지 않다

### 회사 문서

- [ ] `company/profile.md` 의 **관리 단위**가 회사에서 실제로 쓰는 말로 적혀 있다
- [ ] `company/flows.md` 에 단계가 3~5개 있고, 각 단계에 **누가**와 **끝났다는 증거**가 있다
- [ ] `company/structure.md` 의 항목표가 6~10줄이고, 각 줄이 실제로 적어 두는 것이다
- [ ] `company/scope.md` 에 **이번에 만들지 않을 것**이 적혀 있다
- [ ] 문서 어디에도 고객 실명·연락처·금액·계좌가 없다
- [ ] 소리 내어 읽었을 때 **내 회사 얘기로 들린다**

### 보고서·기록

- [ ] `reports/` 에 오늘 보고서 한 장이 있고 브라우저로 열린다
- [ ] `.owner/state.md` 에 현재 기능·고른 디자인·다음 행동이 적혀 있다
- [ ] `git log` 에 오늘 커밋이 2개 이상 있다

## 오늘 한 문장으로 설명할 수 있어야 하는 것

집에 가서 직원에게 말할 수 있으면 된다.

1. 우리 회사의 **관리 단위**는 무엇이고 한 달에 몇 건쯤 생기는가.
2. 앱에 먼저 담기로 한 **업무 흐름 하나**는 어디서 시작해 어디서 끝나는가.
3. 이번에 **만들지 않기로 한 것**은 무엇인가.

셋에 막힘없이 답하면 오늘 수업은 성공이다. 반대로 초안은 돌아가는데 이 셋이 흐릿하면, 다음 회차 앞 시간에 인터뷰부터 다시 본다.

---

## 알아 둘 것 — 검수는 오늘부터 돈다

번들을 설치한 순간부터 **검수 체계가 작동한다.** 화면·저장 항목·권한·배포 설정이 바뀌면 작업 끝에 "검수가 필요합니다"라는 말이 나온다. 그때는 `indeans-erp-check` 스킬을 부르면 된다(오늘 자료 `prompts.md` 의 P8).

글자만 바꾼 수정은 검수를 요구하지 않는다. **줄 수가 아니라 영향으로 판단한다.**

## 오늘 하지 않는 것

- 실제 고객 데이터 입력 — 2회차에 저장할 자리를 만들고 나서
- 인터넷 주소로 열기 — 2회차
- 직원·고객 계정 나누기 — 2회차
- 보고 채널·알림 — 3회차
- 화면 4개 이상 만들기 — 세 개로 끝내는 연습이 이 과정의 핵심이다
