# 1회차 — 이렇게 말하세요

AI에게 넣을 문장 원문이다. **글자 그대로** 복사해서 쓴다. 각 문장 아래 한 줄은 "왜 그렇게 말하는지"다.

`{ }` 안은 대표님 것으로 바꾼다. 나머지는 바꾸지 않는다.

**스킬은 이름으로 부른다.** "`indeans-erp-setup` 스킬을 읽고 시작해 줘" 처럼 이름을 직접 불러야 그 절차대로 움직인다. 설치만 해 두면 알아서 쓰지 않는 경우가 많다.

오늘 여는 대화는 셋이다.

| 순서 | 대화 | 넣는 문장 |
|---|---|---|
| 1 | 설치 | P1 · P2 |
| 2 | 점검·계정 가입 (새 대화) | P3 |
| 3 | 1차 인터뷰 → 디자인 선택 (새 대화) | P4 — 인터뷰가 끝나면 같은 대화에서 선택창이 열린다(P5) |

---

## P1 — 첫 대화 (도구가 살아 있는지 확인)

```
안녕하세요. 저는 개발을 해 본 적이 없는 회사 대표입니다.
지금부터 제 회사 운영 앱을 만들 예정인데, 오늘은 도구가 제대로 설치됐는지만 확인하려고 합니다.
지금 이 폴더의 파일 목록을 보여 주고, 제 컴퓨터에 node와 git이 설치돼 있는지 확인해 주세요.
아직 아무것도 만들지 마세요.
```

> **왜 이렇게 말하나** — "아직 만들지 마세요"를 넣어야 AI가 확인만 하고 멈춘다. 첫 대화에서 앱이 통째로 생겨 버리면 뒤가 엉킨다.

---

## P2 — 번들 설치 (한 번만)

내 ERP 프로젝트 폴더를 연 상태에서 아래를 그대로 붙여 넣는다.

```
https://github.com/indeans6633/indeans-erp-class 를 내 프로젝트 바로 위 폴더에 git clone --depth 1 로 받고,
받은 폴더의 install.mjs 를 node 로 실행해서 지금 이 프로젝트 폴더(--project ".")에 --target both 로 설치해 줘.
설치가 끝나면 설치기가 마지막에 알려 주는 다음 단계를 그대로 보여 줘.
```

> **왜 이렇게 말하나** — 저장소 주소가 문장 안에 글자 그대로 들어 있어서, AI가 "비슷한 이름의 다른 저장소"를 대신 받아 오는 일이 없다. 바꿀 `{ }` 도 없다.
>
> 이 설치는 **1회차 한 번뿐**이다. 2회차부터는 저장소를 다시 받지 않는다. 번들이 고쳐졌을 때만 같은 문장을 한 번 더 넣는다. 직접 명령을 치고 싶으면 내려받은 폴더의 `README.md` 에 같은 내용이 명령 형태로도 있다.
>
> 한 번에 들어오는 것: 스킬 15종 · 에이전트 4종(감독 2 · 검증 1 · 감사 1) · 훅 3종(검수 · 배포 전 확인 · 주간 점검 알림)과 도우미 4종 · 디자인 선택창 · 회차 자료.

## P3 — 설치 점검과 계정 가입

설치가 끝나면 설치기가 다음에 부를 스킬 이름을 알려 준다. **새 대화를 열고** 그 문장을 그대로 넣는다.

```
indeans-erp-setup 스킬을 읽고 시작해 줘
```

수업 시간에는 여기에 세 가지를 더 붙여 말한다 — 내 컴퓨터 종류, 계정 가입 도움, "아직 만들지 마세요".

```
indeans-erp-setup 스킬을 읽고 시작해 줘.
제 컴퓨터는 {윈도우 / 맥}입니다. 저는 개발을 해 본 적이 없는 회사 대표입니다.
도구·설치를 점검한 다음, GitHub·Supabase·Vercel 가입을 한 단계씩 도와주세요. 비밀번호와 인증 코드는 제가 직접 넣겠습니다.
앱은 아직 만들지 마세요.
```

> **왜 이렇게 말하나** — 스킬 이름을 직접 불러야 그 절차대로 움직인다. 가입 화면의 입력과 인증은 대표님이 하고, AI는 화면 순서를 한 단계씩 불러 준다. 비밀번호·인증 코드는 AI에게 불러 주지 않는다 — 대화 기록에 남는다.
>
> 세 서비스는 하는 일이 다르다. **GitHub는 만든 앱을 보관하는 창고, Supabase는 앱에 넣은 내용을 두는 곳, Vercel은 그 앱을 인터넷 주소로 띄우는 곳이다.** 오늘은 가입하고 이름까지만 만든다 — 실제로 쓰는 것은 2회차다. GitHub를 먼저 만들고, Supabase·Vercel은 "GitHub로 계속(Continue with GitHub)"으로 가입한다.
>
> 가입이 끝나면 AI가 `.owner/accounts.md` 에 **서비스 · 계정 이름 · 만든 날만** 적는다. 비밀번호·메일 주소·전화번호·코드는 적지 않는다. **결제 카드를 넣는 화면이 나오면 멈추고 한 화면 뒤로 간다** — 이 과정의 가입은 전부 무료 요금제로 된다.
>
> 점검 끝에 AI가 「작업 습관」 여섯 줄(이 문서 맨 아래)을 한 번 읽어 준다.

### 가입 화면에서 막혔을 때

```
계정 가입을 도와주세요. 지금 {GitHub / Supabase / Vercel} 가입 화면에 "{화면에 보이는 글자 그대로}"가 있습니다.
다음에 무엇을 누르면 되는지 한 단계만 알려 주세요. 비밀번호와 인증 코드는 제가 직접 넣겠습니다.
```

> **왜 이렇게 말하나** — 가입 화면의 글자와 버튼 이름은 자주 바뀐다. 짐작으로 누르지 말고 **지금 보이는 글자**를 그대로 알려 주면 AI가 거기에 맞춘다.
>
> 한 서비스에서 5분 넘게 막히면 붙잡지 않는다 — `미가입`으로 적고 다음 서비스로 간다. 다만 **세 계정은 2회차 시작 전까지 꼭 만들어 온다.** 2회차에 이 셋으로 저장과 배포를 하고, 계정 없이 가는 다른 길이 없다.

## P4 — 1차 인터뷰 「회사·업종」 (약 20분)

**새 대화를 열고** 넣는다.

```
indeans-erp-interview 스킬을 읽고 1차 인터뷰를 시작해 주세요.
저는 개발을 모르는 회사 대표입니다. 한 번에 하나씩만 물어봐 주시고,
제가 모르는 용어는 쓰지 말고 쉬운 말로 바꿔서 물어봐 주세요.
답이 짧으면 예를 들어서 다시 물어봐 주세요.
1차가 끝나면 같은 대화에서 디자인 선택창을 바로 열어 주세요.
```

> **왜 이렇게 말하나** — "한 번에 하나씩"을 명시하면 질문 세 개가 한꺼번에 오는 것을 막는다. 대표가 답을 고르지 않고 자기 말로 말하게 하는 장치다.
>
> 1차는 **회사와 업종만** 묻는다. 첫 질문은 회사 이름과 대표님 호칭이고, 업종을 크게(열 가지 중 하나) → 작게 → 세부로 좁힌 다음부터는 **그 업종의 말로** 묻는다 — 카페면 재료·마감 이야기로, 교습소면 레슨·보강 이야기로, 부품 공장이면 수주·납기 이야기로. 일의 순서·화면·이번에 만들지 않을 것은 2회차 2·3차 인터뷰에서 정한다.
>
> 끝나면 AI가 `company/profile.md` 를 쓰고(끝에 **디자인 힌트**와 **1차 요약**), **같은 대화에서 디자인 선택창을 연다.** 넘어갈지 묻지 않는 것이 정상이다(P5). 중간에 "여기까지 하고 다음에"라고 하면 멈추고, 못 한 질문은 2회차 첫머리에 다시 묻는다.

## P5 — 디자인 선택창 (자동으로 열린다)

1차 인터뷰가 끝나면 브라우저에 **선택창**이 저절로 열린다. 명령을 칠 필요가 없다. 위에서부터 고른다.

1. **화면 구조** 셋 중 하나 — 목록·표형 / 진행 보드형 / 카드·상세형
2. **스타일** — 추천 조합 일곱 중 하나: 차분한 기본 / 에디토리얼 미니멀 / 소프트 / 선명한 대비 / 따뜻한 종이 / 인디언즈 스타일 / 단단한 기업형. 칸마다 작은 견본이 있다.
3. (원할 때만) 접혀 있는 **세부 조절**을 연다 — 색 10가지 + **내 색**(색 칩을 움직이거나 간판·로고의 색 코드 `#RRGGBB` 를 적는다) · 밝기(자동·밝게·어둡게 — 기본 자동) · 모서리 · 밀도. 열지 않으면 그 스타일의 기본값이다.
4. 오른쪽(휴대폰에서는 아래) 미리 보기에서 화면 3개(목록 · 상세·입력 · 오늘 현황)와 폭 2개(휴대폰 · PC)를 바꿔 본다. 밝기가 자동이면 밝게·어둡게를 둘 다 본다.
5. 맨 아래 **'이걸로 하기'** 를 누르고, AI에게 이렇게 말한다.

```
골랐어요.
```

> **왜 이렇게 말하나** — 선택창이 고른 조합을 저장해 두고 기다린다. "골랐어요"를 들으면 AI가 저장된 조합을 소리 내어 확인하고, `company/design.md` 와 색 설정 파일(`src/styles/tokens.css`)을 만든다. AI가 '추천' 표시를 붙여 둘 수 있지만 **고르는 것은 대표님**이다. 나중에 바꿀 수 있으니 오래 고민하지 않는다.

선택창이 안 열렸으면(AI가 열지 않고 끝냈거나, 대화를 새로 열었으면) 이렇게 말한다.

```
indeans-erp-design 스킬을 읽고 디자인 선택창을 열어 주세요.
추천은 한 번만 해 주시고, 고르는 것은 제가 하겠습니다.
```

브라우저가 저절로 안 뜨면 터미널에 크게 찍힌 주소(`http://127.0.0.1:…`)를 주소창에 붙여 넣는다. 그래도 안 되면 AI에게 `.owner/design/index.html` 을 열어 달라고 한다. 이 판은 저장 기능이 없어서 '이걸로 하기'를 누르면 **조합 코드**가 크게 나온다. 화면에 나온 코드를 그대로 말한다.

```
디자인은 {화면에 나온 조합 코드} 로 할게요.
```

> **왜 이렇게 말하나** — 조합 코드는 `<구조>-<스타일>-<색>-<밝기>`이고, 모서리·밀도를 바꿨으면 그 뒤에 붙는다. 색 자리는 열 가지 이름 중 하나이거나 내 색이면 `custom-RRGGBB`(예: 내 색 #2A6F9E → `custom-2a6f9e`), 밝기 자리는 `auto`(자동 — 기본)·`light`·`dark` 다. 예: `board-soft-teal-auto` · `board-indeans-custom-2a6f9e-auto`. 이 코드 하나면 선택창과 같은 파일이 만들어진다. 선택창은 이 컴퓨터 안에서만 뜨는 화면이라 보안 프로그램이 막는 일이 있다 — 그때 쓰는 길이다.

## P6 — 검수를 요구받았을 때

작업을 끝내려 할 때 "검수가 필요한 변경이 있습니다"라는 말이 나오면 이 문장을 넣는다.

```
indeans-erp-check 스킬을 읽고 검수를 진행해 줘.
무엇이 바뀌었는지 먼저 목록으로 보여 주고, 감독이 반려하면 고친 뒤 다시 판정받아 줘.
끝나면 결과를 보고서에 더해 줘.
```

> **왜 이렇게 말하나** — 검수는 나중에 켜는 것이 아니라 **설치한 그 순간부터** 돌고 있다. 화면·저장 항목·권한·배포 설정이 바뀌면 요구하고, 글자만 바꾼 수정은 넘어간다. 줄 수로 판단하지 않는다.
>
> 오늘은 디자인을 고르면 화면 뼈대 파일(`src/styles/`)이 생겨서 요구가 뜰 수 있다. 첫 검수 때 바뀐 파일 목록이 길게 나오는 것은 정상이다 — 아직 검수를 마친 적이 없어 번들을 설치한 시점부터 세기 때문이다.

## P7 — 막혔을 때 (오류 전달)

```
(1) 하려던 것: {무엇을 하려 했는지}
(2) 기대한 결과: {무엇이 되기를 바랐는지}
(3) 실제 결과: {무엇이 됐는지}
(4) 오류 원문: {화면의 빨간 글씨를 그대로 붙여넣기}

원인을 찾아 고치기 전에, 무엇 때문인지 한 줄로 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — 네 가지를 나눠 적으면 AI가 추측하지 않는다. "고치기 전에 원인부터"는 엉뚱한 파일을 여러 개 고쳐 놓는 일을 막는다.

## P8 — 되돌리기 (뭘 잘못 건드렸을 때)

```
방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 상태로 되돌려 주세요.
되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — "무엇이 지워지는지 먼저"를 넣으면 되돌리다가 오늘 작업한 것까지 날리는 일을 막는다.

## 작업 습관 — 말할 때의 공통 규칙 여섯 가지

AI와 일하는 방식이다. P3 점검 끝에 AI가 한 번 읽어 주고, 모든 스킬이 스스로도 지킨다. 다섯 회차 내내 같다.

1. **작업 하나 = 새 대화 하나.** 한 작업이 보고서·커밋까지 끝나면 대화를 닫고 다음 작업은 새 대화에서 연다(1차 인터뷰 → 디자인 선택처럼 스킬이 이어서 여는 것은 한 작업이다). 이어 갈 것은 대화 기억이 아니라 `.owner/state.md` 의 "다음 행동"에 있다.
2. **기록은 한 곳.** 한 일은 작업 보고서(`reports/`), 지금 상태는 상태 문서(`.owner/state.md`)에만 둔다. 메모장·대화창·다른 문서에 흩지 않는다.
3. **화면 사진은 기능당 한 번.** 새 기능은 휴대폰·PC 한 번씩, 고친 뒤에는 바뀐 화면만 휴대폰 폭으로. 글자 몇 개 바꾼 것은 찍지 않는다.
4. **결정은 대표가, AI는 권장안 하나.** 고를 것을 여러 개 늘어놓으면 "권하는 것 하나와 이유만 말해 줘"라고 한다.
5. **"아직 만들지 마세요"를 같이 말한다.** 확인이나 계획만 원할 때는 하지 말 것을 같이 말하고, 계획을 먼저 본 뒤 "그대로 해 주세요"로 시작한다.
6. **오류는 원문 그대로.** 요약하지 않고 화면의 글자를 그대로 붙여 넣는다(P7).

## 말하지 않는 것

- 고객 실명·연락처·계좌·금액. AI에게 말할 필요가 없고, 문서에 남으면 지우기 번거롭다.
- 비밀번호·인증 코드·키·토큰. 가입할 때도 AI에게 불러 주지 않는다 — 대표님이 직접 넣는다.
