# 2회차 앞선 트랙 — 먼저 끝났다면

기본 트랙(2·3차 인터뷰 → 초안 → 저장 → 배포 → 직원 폰 확인)이 끝났고 시간이 남는 분용이다.
**새 화면을 늘리지 않는다.** 같은 시간에 다른 목표로 간다 — 있는 것을 깊게 만든다.

먼저 아래 세 가지가 **이미 되어 있어야** 이 카드로 간다. 하나라도 안 되면 그것부터 한다.

- 배포 주소가 있고, 로그인하지 않은 채 목록 주소를 열면 로그인 화면이 나온다
- 명단에 없는 계정으로 로그인하면 목록이 비어 있다
- 직원이 자기 폰으로 한 건을 넣었고, 백업 파일을 한 번 받아서 열어 봤다

1회차에 2차 인터뷰를 미리 해 온 분은 오늘 3차부터 시작한다. 인터뷰 스킬이 어디까지 했는지 읽고 알아서 이어 간다.

아래 여섯 중 **하나만** 고른다. 오늘 끝나는 크기다.

## 가져온 앱의 2회차 — 리빌딩 2단계

1회차에 `indeans-erp-rebuild` 로 바꿔 둔 앱(다른 도구로 만들어 온 앱)은 2회차 순서가 조금 다르다: **2·3차 인터뷰 → 리빌딩 2단계(저장·배포)**. 초안(`indeans-erp-draft`)은 새로 만들지 않는다 — 리빌딩이 묶어 둔 화면 셋이 그대로 출발점이다. 상태 문서의 "다음 행동"에도 그렇게 적혀 있다.

저장·배포는 `indeans-erp-data` 의 「기존 DB가 있을 때」로 한다. 앱에 이미 데이터베이스 표가 있으면 **다시 만들지 않고 다음 번호로 이어 붙인다**(명단·잠금·변경 기록만 더한다). 예전에 Supabase 프로젝트를 지웠어도 `supabase/migrations/` 파일이 남아 있으면 같다 — 파일을 옮기거나 0001 부터 다시 시작하지 않는다. 저장 단계의 '백업'에는 **앱 안 내려받기 버튼**이 들어간다(화면 파일이 조금 바뀐다 — 기능은 그대로). 3차 인터뷰가 끝난 뒤 **새 대화를 열고** 넣는다.

```
indeans-erp-data 스킬을 읽고 리빌딩 2단계(저장·배포)를 시작해 주세요.
이 앱은 다른 도구로 만들어 와서 1회차에 리빌딩한 앱입니다. 기존 표가 있으면 다시 만들지 말고
다음 번호로 이어 붙여 주세요. 초안은 새로 만들지 마세요.
```

완료선은 기본 트랙과 같다 — 직원이 자기 폰으로 넣고 다시 보기. 위 여섯 과제는 그 뒤에 시간이 남으면.

## A. 목록 다듬기 (건수가 많은 회사)

데이터가 이미 50건을 넘거나 한 달에 수백 건이 생기는 회사면 이것부터.

- 검색 칸 하나 · 기간 고르기(이번 주 / 이번 달) · 상태별 묶어 보기 중 **하나만** 넣는다.
- **정렬과 개수 제한을 같이 건다.** "전부 가져오기"는 건수가 늘면 조용히 잘린다.

```
목록에서 {거래처 이름}으로 찾을 수 있게 검색 칸 하나만 넣어 줘.
정렬과 개수 제한은 그대로 두고, 다른 화면은 건드리지 마.
```

확인: 30건이 있다고 치고 원하는 한 건을 5초 안에 찾으면 통과.

## B. 입력 줄이기

직원이 가장 많이 쓰는 화면에서 한 건 넣는 데 손이 몇 번 가는지 세고, 기본값·최근 값 불러오기로 줄인다. 줄인 뒤 그 화면의 설계 선언(`company/screens.md`)을 고친다.

```
상세·입력 화면에서 한 건을 넣을 때 몇 번 누르고 몇 칸을 채우는지 세어 줘.
그중 기본값이나 최근 값으로 줄일 수 있는 것을 하나만 골라 고쳐 주고, 설계 선언도 같이 고쳐 줘.
```

## C. 내보내기 버튼

목록을 CSV로 내려받는 버튼 하나. 엑셀을 완전히 놓기 어려운 회사에서 반응이 가장 좋다. 백업용 **전체 내려받기**와는 다른 버튼이다 — 이름에 그 차이가 드러나게 한다.

```
목록 화면에 지금 보이는 목록을 CSV 파일로 내려받는 버튼을 만들어 주세요.
열 이름은 company/structure.md 의 항목 표에 적힌 우리 회사 말 그대로 써 주세요.
백업용 전체 내려받기 버튼과 헷갈리지 않게 이름을 지어 주세요.
```

## D. 앱 안 표시 1종

사람이 잊어서 새는 지점 하나를 고른다.

- 예: 예정일이 지났는데 다음 단계로 안 넘어간 건, 며칠째 상태가 그대로인 건.
- 오늘은 **앱 안 배지나 목록 맨 위 줄**로만 표시한다. 채널로 보내는 것은 운영 보고 단계에서 한다.

```
{예정일이 지났는데 완료가 안 된 건}을 목록 맨 위에 모아서 보여 줘. 건수도 같이.
문자나 푸시, 다른 곳으로 보내는 것은 아직 하지 마. 앱 안에서만 표시.
```

> 알림이 사람을 대신하지는 않는다. 많아지면 아무도 안 본다. 그래서 오늘은 **한 종류**만 만든다.

## E. 파일 잠금 (사진·서류를 올리는 앱)

사진·서류를 올리는 앱이면 여기가 가장 자주 새는 자리다.

1. 데이터가 닿는 경로를 전부 적는다: 목록 · 상세 · 파일 주소 · 내보내기.
2. 파일 저장소(Storage)에도 표와 같은 규칙(명단에 있으면 본다)이 걸렸는지 하나씩 표시한다.
3. 명단에 없는 계정으로 파일 주소를 직접 열어 본다 → 막혀야 한다.

> 목록은 막았는데 파일은 열려 있는 일이 실제로 있다. **목록에 안 보인다고 막힌 게 아니다.** 목록과 파일은 별개의 문이다.

## F. 바뀐 기록 남기기

상태·날짜처럼 덮어쓰면 이전 값이 사라지는 칸에 변경 이력 표를 붙인다(무엇에서 무엇으로 · 누가 · 언제). 표를 하나 더하는 일이므로 **다음 번호 파일**(`0002_…`)로 만들고, 실행 전에 고정 검사를 통과시킨다.

```
indeans-erp-data 스킬의 앞선 분기 '바뀐 기록 남기기'로 진행해 줘.
{상태} 칸이 바뀔 때마다 이전 값·새 값·누가·언제를 남기는 표를 다음 번호 파일로 만들어 줘.
실행하기 전에 고정 검사와 잠금을 먼저 보여 줘.
```

## 고르는 기준

| 지금 상황 | 추천 |
|---|---|
| 데이터가 이미 50건을 넘는다 | A |
| 직원이 한 건 넣는 데 오래 걸린다 | B |
| 엑셀로 다시 옮겨 쓰는 일이 남아 있다 | C |
| 놓쳐서 손해 본 적이 있다 | D |
| 사진·서류를 올린다 | E |
| 상태를 잘못 바꿔 되돌린 적이 있다 | F |

## 앞선 트랙에서도 지키는 것

- 되돌릴 지점(커밋)을 먼저 만든다. 앞서 있을수록 잃을 게 많다.
- 한 번에 하나만 바꾸고 그때마다 확인한다.
- 표를 바꾸는 일은 **다음 번호 파일**로만 한다. 실행한 파일은 고치지 않는다.
- 잠금과 관련된 작업은 **명단에 없는 계정으로 직접 확인**해야 끝난 것이다.
- 누가 무엇을 보는지 나누는 일(역할별 화면)은 오늘 하지 않는다 — 권한 단계에서 한다.
- 바꾼 뒤에는 검수를 받는다.

```
indeans-erp-check 스킬을 읽고 방금 바꾼 것을 검수해 줘.
저장이나 잠금과 관련된 변경이면 명단에 없는 계정으로 실제로 막히는지까지 확인해 줘.
```

- 과제는 기본 트랙과 같다(`homework.md`). 앞서 있어도 **직원이 자기 기기로 넣어 보는 것**은 건너뛰지 않는다 — 여기서 나오는 문제는 진도와 무관하다.
