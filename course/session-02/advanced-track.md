# 2회차 앞선 트랙 — 먼저 끝났다면

기본 트랙(개선 1~2건 + 저장·백업·배포 + 역할 둘)이 끝났고 시간이 남는 분용이다.
**새 화면을 늘리지 않는다.** 같은 시간에 다른 목표로 간다 — 있는 것을 깊게 만든다.

먼저 아래 세 가지가 **이미 되어 있어야** 이 카드로 간다. 하나라도 안 되면 그것부터 한다.

- 배포 주소가 있고, 로그아웃 상태에서는 아무것도 안 보인다
- 직원 계정으로 로그인하면 대표와 다른 화면이 뜬다
- 백업 파일을 한 번 받아서 열어 봤다

아래 다섯 중 **하나만** 고른다. 오늘 끝나는 크기다.

---

## A. 검색·재입력·인계 병목 없애기

건수가 늘면 제일 먼저 무너지는 자리다. 1번(검색·필터)은 **데이터가 이미 50건을 넘을 때만** 한다. 건수가 적으면 건너뛰고 2번·3번만 해도 A를 한 것이다.

1. 목록에 검색 칸 하나 또는 상태 필터 하나를 넣는다(둘 다 말고 하나).
2. 같은 값을 두 번 넣는 자리를 찾아 한 곳에서만 입력하게 바꾼다.
3. 일이 다음 사람에게 넘어갈 때 **같이 넘어가야 하는 것**을 한 줄 적는다(4회차 흐름 확장의 입력물).

```
목록에서 {거래처 이름}으로 찾을 수 있게 검색 칸 하나만 넣어 줘.
그리고 지금 같은 값을 두 화면에서 각각 입력하는 곳이 있는지 찾아서 알려 줘.
고치기 전에 어디가 원본인지 먼저 말해 줘.
```

확인: **(1번을 했다면)** 30건이 있다고 치고 원하는 한 건을 5초 안에 찾을 수 있으면 통과. **(2번만 했다면)** 같은 값을 두 번 넣는 자리가 없어졌으면 통과.

## B. 팀·담당별 읽기 범위

회사 안에서도 "우리 팀 것만" 보여야 하는 데이터가 있을 때.

1. 담당 팀(또는 담당자) 칸을 표에 넣는다.
2. 읽기 규칙에 팀 조건을 더한다.
3. **다른 팀 계정으로 로그인해 비어 있는지** 확인한다. 이 확인 없이는 안 한 것과 같다.

```
{담당 팀·지점·담당자}별로 나눠 보여야 하는 데이터가 있어.
표에 담당 칸을 넣고 읽기 규칙에 그 조건을 더해 줘.
소속이 양쪽 다 비어 있는 경우도 정상으로 처리해야 해.
그리고 다른 담당 계정으로 로그인했을 때 안 보이는지 확인하는 순서를 알려 줘.
```

주의 두 가지

- 역할 이름만 보고 통과시키는 규칙("직원이면 본다")은 팀이 갈리는 순간 무너진다. **연결**로 판정한다.
- 소속이 양쪽 다 비어 있는 경우(본사 사람이 본사 건을 보는 경우)를 단순 비교(`=`)로 쓰면 **판정 불가**가 되어 아무것도 안 보인다.

## C. 읽기 전용 계정

경리·외부 회계처럼 보기만 해야 하는 사람이 있을 때.

1. 읽기 규칙과 쓰기 규칙을 따로 둔다.
2. 읽기 전용 계정을 하나 만들어 **쓰기가 실제로 막히는지** 확인한다.
3. 화면에서 버튼을 숨기는 것만으로는 막은 게 아니라는 점을 기록에 남긴다.

확인: 읽기 전용 계정으로 저장을 눌렀을 때 저장이 안 되면 통과. 버튼이 안 보이는 것은 통과가 아니다.

## D. 앱 안 표시 1종

사람이 잊어서 새는 지점 하나를 고른다.

- 예: 예정일이 지났는데 다음 단계로 안 넘어간 건, 며칠째 상태가 그대로인 건.
- 오늘은 **앱 안 배지나 목록 맨 위 줄**로만 표시한다. 채널로 보내는 것은 3회차에 한다.

```
{예정일이 지났는데 완료가 안 된 건}을 목록 맨 위에 모아서 보여 줘. 건수도 같이.
문자나 푸시, 다른 곳으로 보내는 것은 아직 하지 마. 앱 안에서만 표시.
```

> 알림이 사람을 대신하지는 않는다. 많아지면 아무도 안 본다. 그래서 오늘은 **한 종류**만 만든다.

## E. 파일 잠금

사진·서류를 올리는 앱이면 여기가 가장 자주 새는 자리다.

1. 데이터가 닿는 경로를 전부 적는다: 목록 · 상세 · 파일 주소 · 내보내기 · 공유 링크.
2. 각 경로에 같은 규칙이 걸렸는지 하나씩 표시한다.
3. 목록에서 안 보이는 파일의 주소를 직접 열어 본다 → 막혀야 한다.

> 목록은 막았는데 파일은 열려 있는 일이 실제로 있다. **목록에 안 보인다고 막힌 게 아니다.** 목록과 파일은 별개의 문이다.

## 앞선 트랙에서도 지키는 것

- 되돌릴 지점(커밋)을 먼저 만든다. 앞서 있을수록 잃을 게 많다.
- 한 번에 하나만 바꾸고 그때마다 확인한다.
- 잠금 관련 작업은 **명단에 없는 계정 또는 다른 팀 계정으로 직접 확인**해야 끝난 것이다.
- 새 규칙을 기존 표에 붙였으면 **그 표를 쓰는 다른 화면까지** 다시 열어 본다. 권한을 조이다가 멀쩡하던 화면이 통째로 죽는 일이 가장 흔하다.
- 바꾼 뒤에는 검수를 받는다.

```
indeans-erp-check 스킬을 읽고 방금 바꾼 것을 검수해 줘.
권한과 관련된 변경이니 다른 역할 계정으로 실제로 막히는지까지 확인해 줘.
```

- 과제는 기본 트랙과 같다(`homework.md`). 앞서 있어도 **직원이 자기 기기로 넣어 보는 것**은 건너뛰지 않는다 — 여기서 나오는 문제는 진도와 무관하다.
