# 2회차 과제 — 직원이 자기 기기로 넣어 보기

다음 회차까지 할 일. **직원이 자기 폰이나 자기 컴퓨터로 접속해서 실제 업무 건을 직접 넣는다.** 그리고 세 줄을 적어 온다.

권장 시간: 40분. 앱을 더 만들어 오는 과제가 아니다.

지난 회차와 달라진 것은 하나다 — **이제 주소가 있다.** 대표님 노트북 앞에 앉힐 필요가 없다. 그리고 주소가 생겼다는 것은 **주소를 아는 사람은 누구나 열어 본다**는 뜻이기도 하다. 그래서 잠금 확인도 같이 한다.

---

## 하는 일

### 1. 직원 한 명에게 계정을 준다

- 역할은 **직원**으로 만든다. 대표 계정을 빌려주지 않는다. 역할이 다르면 보이는 게 다르다는 것을 확인하는 게 절반이다.
- 비밀번호는 문자나 메신저로 보내고, 받은 사람이 바로 바꾸게 한다.
- 주소(`...vercel.app`)를 보내고 **폰에서 열게** 한다.

### 2. 실제 업무 건 3건을 넣게 한다

설명을 길게 하지 않는다. **딱 한 문장만** 보낸다.

> "이 주소 열어서 오늘 들어온 건 하나 등록해 주세요."

- 이번 주에 **실제로 있었던 일**로 넣는다. 지어낸 데이터로 하지 않는 것이 이 과제의 전부다. 제조라면 들어온 가공 의뢰, 서비스라면 방문, 유통이라면 납품, 예약업이라면 예약.
- 3건이면 충분하다. 많이 넣으면 나중에 표가 바뀔 때 다시 넣어야 한다.
- **옆에서 보지 않는다.** 대신 눌러 주는 순간 얻을 정보가 사라진다.

### 3. 잠금을 한 번 확인한다 (3분)

수업에서 한 것을 집에서 한 번 더 한다. 배포본에도 그대로 적용됐는지 보는 것이다.

- 배포 주소에서 **로그아웃한 상태**로 목록 화면 주소를 직접 열어 본다 → 아무것도 안 보여야 한다.
- 직원 계정으로 로그인해 **대표만 봐야 하는 것**이 안 보이는지 본다.
- 보이면 다음 회차에서 가장 먼저 말한다. 혼자 고치지 않아도 된다.

### 4. 백업 파일을 한 번 받아서 연다

- 내려받기 버튼으로 파일을 받는다.
- **파일을 열어 본다.** 빈 파일이 만들어지는 실수가 흔하다. 한글이 깨지면 그것도 고칠 목록이다.
- 회사 드라이브에 `<날짜>_<화면이름>` 으로 저장한다. 노트북 바탕화면은 백업이 아니다.

### 5. 세 줄을 적는다

```markdown
## <날짜> · 2회차 뒤
- 시도한 업무: <이 앱으로 하려 한 일>
- 막힌 지점: <손으로 하거나 그만둔 자리 — 직원이 겪은 것이면 (직원 말 전달)>
- 원하는 변화: <어떻게 되면 되겠는가>
```

AI에게 그대로 적게 해도 된다.

```
직원이 앱을 써 봤어. 아래 세 줄을 company/log.md 맨 위에 그대로 적어 줘.
시도한 업무: {이 앱으로 하려 한 일}
막힌 지점: {손으로 하거나 그만둔 자리}
원하는 변화: {어떻게 되면 되겠는가}
직원이 한 말은 (직원 말 전달) 이라고 표시해 줘. 요약하거나 다듬지 말고 그대로 넣어 줘. 앱은 고치지 마.
```

**직원이 한 말 중 가장 뼈아팠던 한마디를 꼭 그대로 옮긴다.** "이거 어디로 들어가요?" 같은 짧은 말이 다음 회차 개선 1번이 된다.

## 다음 회차에 가져올 것

- [ ] 백업 파일 1개 (열어 본 것)
- [ ] `company/log.md` 의 세 줄
- [ ] 잠금 확인 결과 (로그아웃 상태에서 안 보였나 / 보였나)
- [ ] 노트북 + 충전기

## 하지 않아도 되는 것

- 데이터를 많이 넣어 채우기. **3건이면 충분하다.**
- 혼자 새 기능 만들기. 화면을 늘리는 것은 흐름을 정한 뒤가 낫다.
- 디자인 다듬기.
- 실제 고객에게 계정 주기. 아직 이르다.

## 막히면

- 앱이 아예 안 열리면 되돌린다.

```

되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```
