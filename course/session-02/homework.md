# 2회차 과제 — 직원이 자기 기기로 넣어 보기

다음 회차까지 할 일. **직원이 자기 폰이나 자기 컴퓨터로 접속해서 실제 업무 건을 직접 넣는다.** 그리고 세 줄을 적어 온다.

권장 시간: 40분. 앱을 더 만들어 오는 과제가 아니다.

지난 과제와 달라진 것은 하나다 — **이제 주소가 있다.** 대표님 노트북 앞에 앉힐 필요가 없다. 그리고 주소가 생겼다는 것은 **주소를 아는 사람은 누구나 열어 본다**는 뜻이기도 하다. 그래서 잠금 확인도 같이 한다.

수업 안에 주소나 직원 폰 확인까지 못 갔으면 그것부터 마친다 — 2회차 `prompts.md` 의 P5 · P6 을 새 대화에서 이어서 넣는다.

---

## 하는 일

### 1. 직원 한 명에게 계정을 준다

- 수업에서 만든 직원 계정을 쓴다. 대표 계정을 빌려주지 않는다.
- 비밀번호는 문자나 메신저로 따로 보내고, 받은 사람이 처음 로그인한 뒤 바꾸게 한다.
- 주소(`…vercel.app`)를 보내고 **폰에서 열게** 한다.

### 2. 실제 업무 건 3건을 넣게 한다

설명을 길게 하지 않는다. **딱 한 문장만** 보낸다.

> "이 주소 열어서 오늘 들어온 건 하나 등록해 주세요."

- 이번 주에 **실제로 있었던 일**로 넣는다. 지어낸 데이터로 하지 않는 것이 이 과제의 전부다. 부품 공장이라면 들어온 가공 의뢰, 카페라면 재료 발주, 교습소라면 보강 일정, 방문 서비스라면 방문 예약.
- 3건이면 충분하다. 많이 넣으면 나중에 표가 바뀔 때 다시 넣어야 한다.
- **옆에서 보지 않는다.** 대신 눌러 주는 순간 얻을 정보가 사라진다.
- 지금은 회사 명단에 있는 사람이 모두 같은 것을 본다. **대표만 봐야 할 내용(금액 같은 것)은 넣지 않는다** — 누가 무엇을 보는지 나누는 것은 권한 단계에서 한다.

### 3. 잠금을 한 번 확인한다 (3분)

수업에서 한 것을 집에서 한 번 더 한다. 배포한 주소에도 그대로 걸려 있는지 보는 것이다.

- 휴대폰 브라우저의 시크릿(사생활 보호) 창에서 배포 주소의 목록 화면을 직접 연다 → 데이터가 아니라 **로그인 화면**이 나와야 한다.
- 이상하면 다음 회차에서 가장 먼저 말한다. 혼자 고치지 않아도 된다.

### 4. 백업 파일을 한 번 받아서 연다

- 앱의 **전체 내려받기** 버튼으로 파일을 받는다.
- **파일을 열어 본다.** 빈 파일이 만들어지는 실수가 흔하다. 한글이 깨지면 그것도 고칠 목록이다.
- `company/backup.md` 에 정한 곳(회사 드라이브 등)에 `<날짜>_<화면이름>` 으로 둔다. 노트북 바탕화면은 백업이 아니다.

### 5. 세 줄을 적는다

```markdown
## <날짜> · 2회차 뒤
- 시도한 업무: <이 앱으로 하려 한 일>
- 막힌 지점: <손으로 하거나 그만둔 자리 — 직원이 겪은 것이면 (직원 말 전달)>
- 원하는 변화: <어떻게 되면 되겠는가>
```

AI에게 그대로 적게 해도 된다.

```
직원이 앱을 써 봤어. 아래 세 줄을 company/log.md 맨 위에 그대로 적어 줘.
시도한 업무: {이 앱으로 하려 한 일}
막힌 지점: {손으로 하거나 그만둔 자리}
원하는 변화: {어떻게 되면 되겠는가}
직원이 한 말은 (직원 말 전달) 이라고 표시해 줘. 요약하거나 다듬지 말고 그대로 넣어 줘. 앱은 고치지 마.
```

**직원이 한 말 중 가장 뼈아팠던 한마디를 꼭 그대로 옮긴다.** "이거 어디로 들어가요?" 같은 짧은 말이 다음 개선 1번이 된다.

---

## 확인 — 이게 되면 과제 끝

- [ ] 직원이 자기 기기로 실제 건 3건을 넣었다
- [ ] 시크릿 창에서 목록 주소를 열면 로그인 화면이 나온다
- [ ] 백업 파일 1개를 받아서 열어 봤다
- [ ] `company/log.md` 에 세 줄이 있다

다 못 채워도 온다. 못 한 이유가 다음 회차의 첫 개선 후보다.

## 다음 회차에 가져올 것

- [ ] 실제 건 3건이 들어간 앱(주소)
- [ ] 백업 파일 1개(열어 본 것)
- [ ] `company/log.md` 의 세 줄
- [ ] 잠금 확인 결과(로그인 화면이 나왔나)
- [ ] 노트북 + 충전기

다음 회차(3회차)의 내용은 2회차를 정리한 뒤 확정한다(가안). 바뀌면 미리 알린다.

## 하지 않아도 되는 것

- 데이터를 많이 넣어 채우기. **3건이면 충분하다.**
- 혼자 새 기능·새 화면 만들기. 화면을 늘리는 것은 흐름이 안정된 뒤가 낫다.
- 디자인 다듬기.
- 실제 고객에게 계정 주기. 아직 이르다.

## 막히면

- 오류 문장을 그대로 AI에게 붙여 넣는다(`prompts.md` 아래쪽 「막혔을 때」 형식).
- 30분 넘게 같은 자리에 있으면 멈추고 **무엇이 안 됐는지 한 줄로 적어** 온다. 다음 회차 시작 때 다룬다.
- 회차 사이에 앱이 갑자기 데이터를 못 불러오면, 무료 Supabase 프로젝트가 일주일 넘게 안 쓰여 잠시 멈춘 것일 수 있다. Supabase 대시보드에서 그 프로젝트의 다시 켜기(Restore)를 누르고 몇 분 기다린다 — 데이터는 그대로다.
- 앱이 아예 안 열리면 되돌린다.

```
방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 상태로 되돌려 주세요.
되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```
