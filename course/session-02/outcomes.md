# 2회차 — 오늘 반드시 끝내는 것

2·3차 인터뷰·초안·저장·배포 · 3시간

오늘의 완료선은 하나다. **2·3차 인터뷰로 정한 첫 흐름이 초안 → 실제 저장 → 인터넷 주소로 열리는 앱 + 작업 보고서.**

한 줄로 확인하면 이렇다 — **실제 주소에서 직원이 자기 폰으로 넣으면 저장되고, 다시 열어도 남아 있다.**

진도 기록(`.owner/progress.json`)의 2회차 문구와 같은 말이다. 2회차 완료는 직원 폰 확인까지 끝났을 때 `indeans-erp-data` 가 적는다.

---

## 수업 전 확인

- **계정 3종** — `.owner/accounts.md` 에 GitHub · Supabase · Vercel 세 줄이 채워져 있다. 비었으면 수업 시작 전에 강사에게 알린다. 오늘 저장과 배포가 이 세 계정 위에서 돈다.
- **과제 세 줄** — 직원에게 1차 요약을 읽어 주고 들은 말. 못 적어 왔어도 2차 인터뷰가 그 자리에서 받는다.
- 번들 재설치 공지를 받았으면 1회차 P2 설치 문장을 같은 명령으로 한 번 더 실행한다 — 이미 고친 파일은 지워지지 않고 새 버전이 같은 자리에 `.new`로 저장되니, 비교해서 옮길 것이 있으면 옮기고 `.new`는 지운다.

## 오늘의 완료선

| 항목 | 완료로 보는 기준 |
|---|---|
| **2·3차 인터뷰** | `company/flows.md`(첫 흐름 하나) · `structure.md`(화면 3개 · 한 건에 적는 항목 · 이번에 만들지 않을 것) · `scope.md` · `roadmap.md` 가 있다 |
| **초안** | 화면 3개(목록 · 상세·입력 · 오늘 현황)가 끝까지 눌린다 — 대표님이 확인 표를 직접 눌러 봤다. 화면마다 설계 선언이 `company/screens.md` 에 있다 |
| **작업 보고서** | `reports/` 에 초안 보고서 한 장이 있고 브라우저로 열린다 |
| **저장** | 입력하고 새로고침해도, 다른 기기에서 열어도 그대로 있다 |
| **주소** | `…vercel.app` 주소가 휴대폰과 PC에서 열린다 |
| **직원 폰 확인** | **직원이 자기 폰으로 넣고 다시 보기** — 직원 계정으로 로그인 → 실제 업무 한 건 입력 → 다시 열어도 그 건이 보인다 |

수업 안에 끝까지 못 가면 최소선은 **새로고침해도 남는 저장**이다. 주소와 직원 폰 확인은 과제로 이어서 하고, 다음 회차 시작 전까지 끝낸다.

## 손에 남는 것

### 1. 회사 문서 — 2·3차 인터뷰의 결과

| 파일 | 무엇이 적혀 있나 |
|---|---|
| `company/flows.md` | 앱에 먼저 담을 **흐름 하나** — 시작 · 끝 · 단계(회사 말) · 단계마다 누가 · 끝났다는 증거 · 안 되는 날 |
| `company/profile.md` (보강) | 과제로 들은 직원의 말 · 관리 단위 확정 · 지금 쓰는 도구 · 가장 귀찮은 일 세 가지 |
| `company/structure.md` | 화면 3개 · 한 건에 적는 항목 표 · **이번에 만들지 않을 것**(언제 꺼낼지 함께) |
| `company/scope.md` · `roadmap.md` | 이번 회차 성공 기준 · 앞으로의 순서(2회차 밖은 가안) |

### 2. 초안 앱 — 화면 3개

- 목록 · 상세·입력 · 오늘 현황. 이 셋으로 첫 흐름 하나를 끝까지.
- 1회차에 고른 디자인(`src/styles/`)을 그대로 입는다. 새 색·새 모양을 섞지 않는다.
- `company/screens.md` — 화면마다 설계 선언 다섯 줄(목적 · 주 사용자 · 기기 · 가장 중요한 행동 하나 · 쓰지 않을 것)과 스스로 점검 결과.

### 3. 작업 보고서

`reports/<날짜>-<제목>.html` — 어느 화면이 무엇을 하는지, 왜 그렇게 만들었는지, 일부러 바꾸지 않은 것, 화면 사진 1~3장. 내 컴퓨터에만 만들어지고 어디로도 보내지지 않는다.

### 4. 백업 — 저장보다 먼저

- `company/backup.md` — 무엇을 잃으면 아픈가 · 누가 얼마나 자주 내려받나 · 어디에 두나 · **되돌리는 순서**
- 앱 안에 **전체 내려받기 버튼** — 받은 파일을 **열어 봤다**(빈 파일이 아니고 한글이 안 깨진다)

### 5. 저장할 자리

- `supabase/migrations/0001_init.sql` — 표는 세 개 이하(회사 · 쓰는 사람 명단 · 업무 표 하나). 칸 이름은 영문, 회사 말은 주석으로.
- 잠금(행 수준 보안)을 **표를 만들 때 같이** 걸었다 — "로그인했고 우리 회사 명단에 있으면 본다".
- `scripts/migration-gate.mjs` + `npm run check` — 실행 전 고정 검사(잠금 없는 표 · 정책 없는 표 · 파일에 적힌 비밀값 등을 막는다).
- `company/data.md` — 표와 회사 말 대응 · 표를 바꾼 기록(실행한 날·결과) · 잠금 확인 · 배포 주소.

### 6. 인터넷 주소

- 1회차에 만든 **비공개** GitHub 저장소에 올렸다 — `.env.local` 은 올라가지 않았다.
- Vercel 가져오기 → 환경 변수 두 줄 → 배포. 배포 직전에 훅이 커밋·빌드·고정 검사를 다시 돌린다.
- 배포 뒤 세 가지를 읽기만 해서 봤다 — 폰·PC에서 열린다 · 목록이 보인다 · 로그인 없이 목록 주소를 열면 로그인 화면이 나온다.

### 7. 오늘 것 검수

- 초안 뒤(화면) · 저장·배포 뒤(표·잠금·배포 설정) 각각 감독 판정 → 실측 → 보고서.
- `.owner/last-check.json` 이 오늘 날짜로 갱신돼 있다.

## 확인 기준 — 내가 직접 눌러 본다

AI의 "완료했습니다"는 확인이 아니다. 아래는 전부 **대표가 손으로** 확인하는 것이다.

### 인터뷰·문서

- [ ] `company/flows.md` 의 첫 흐름이 **하나**이고, 단계가 회사에서 쓰는 말로 적혀 있다
- [ ] `company/structure.md` 에 화면이 세 개이고, **이번에 만들지 않을 것**이 적혀 있다
- [ ] 문서 어디에도 고객 실명·연락처·금액·계좌가 없다

### 초안

- [ ] 목록에 예시 데이터가 보이고, 한 줄만 봐도 어느 건인지·지금 어느 단계인지 안다
- [ ] 새 건을 만들어 저장하면 목록에 늘어난다 · 필수 칸을 비우면 그 칸 아래에 무엇이 비었는지 나온다
- [ ] 휴대폰 크기(가로 375)에서 글자가 잘리거나 가로로 밀리지 않는다
- [ ] 화면 인상이 1회차에 고른 디자인과 같다

### 저장·주소

- [ ] 한 건을 입력하고 **새로고침**해도 그대로 있다
- [ ] **명단에 없는 계정**으로 로그인하면 목록이 비어 있다
- [ ] 배포 주소가 휴대폰에서도 열린다 · 로그아웃 상태로 목록 주소를 열면 로그인 화면이 나온다
- [ ] 저장소에 `.env.local` 이 없다

### 직원 폰

- [ ] 직원이 **자기 폰으로** 로그인해 실제 업무 한 건을 넣었다
- [ ] 다시 열었을 때(또는 대표님 폰에서) 그 건이 보인다

### 백업·기록

- [ ] 내려받은 파일을 **열어 봤다**
- [ ] `reports/` 에 오늘 보고서가 있다
- [ ] `.owner/state.md` 의 현재 기능·미해결 문제·다음 행동이 오늘 것으로 고쳐졌다

## 오늘 알아 두는 생각 세 가지

1. **화면에서 숨기는 것과 데이터가 막힌 것은 다르다.** 메뉴를 감춰도 주소를 직접 치면 열린다. 막는 자리는 데이터를 가져오는 쪽이고, 막혔다는 증거는 다른 계정으로 열었을 때 비어 있는 것뿐이다.
2. **표를 바꾸는 일은 번호 붙은 파일로만.** 한 번 실행한 파일은 고치지 않고 다음 번호 파일을 만든다. 실행하기 전에 고정 검사를 통과시킨다.
3. **제한 없는 목록은 조용히 잘린다.** 오류도 안 나고 최근 것이 사라진다. 정렬과 개수 제한을 같이 건다.

## 오늘 하지 않는 것

- 누가 무엇을 보는지 나누기 · 대표만 보는 칸(금액) — 권한 단계(가안)
- 보고 채널·정해진 시각의 운영 보고 — 운영 보고 단계(가안)
- 돈 계산 — 돈 흐름 단계 / 두 번째 업무 흐름 — 두 번째 흐름 단계
- 고객에게 계정 주기 — 아직 이르다
- 화면 4개 이상 — 세 개로 끝내는 연습이 이 과정의 핵심이다
