# 2회차 — 이렇게 말하세요

AI에게 넣을 문장 원문이다. **글자 그대로** 복사해서 쓰고 `{ }` 안만 우리 회사 말로 바꾼다. 각 문장 아래 한 줄은 "왜 그렇게 말하는지"다.

오늘 끝내야 하는 것은 하나다. **직원 계정으로 입력하고 다시 접속해도 내용이 남아 있는 앱(실제 주소).**

저장소를 다시 받지 않는다. 번들은 1회차에 설치돼 있고, 스킬은 **이름으로 부른다.**

---

## P1 — 써 보고 온 것부터 (오늘의 시작)

```
indeans-erp-review 스킬을 읽고 시작해 줘.
company/log.md 에 적어 온 세 줄부터 읽어 주고, 그 막힌 자리를 앱에서 같이 다시 해 보자.
고치기 전에 되돌릴 지점을 먼저 만들어 줘. 무엇을 고칠지는 내가 고를게.
```

> **왜 이렇게 말하나** — 오늘 고칠 것은 AI가 찾은 문제가 아니라 **대표와 직원이 실제로 막힌 자리**다. 기록을 먼저 읽게 하지 않으면 AI가 자기 눈에 띄는 것부터 고친다.

---

## P2 — 고칠 것 한 건 정하기

```
지금 나온 것 중에 오늘 고칠 것을 한 건만 정하자. 한 번에 하나씩 물어봐 줘.
정해지면 company/improve-plan.md 에 전·후·확인 방법·데이터 영향을 적어 줘.
아직 고치지는 마.
```

> **왜 이렇게 말하나** — "확인 방법"을 먼저 적게 해야 나중에 됐는지 안 됐는지를 대표가 판단할 수 있다. 확인 방법이 없는 개선은 끝난 줄 알고 넘어간다.

---

## P3 — 개선 적용

```
계획서 1번만 고쳐 줘. 2번은 아직 하지 마.
디자인(색·모양)은 건드리지 말고, 화면에 보이는 말은 우리 회사가 쓰는 말로.
다 되면 무엇을 바꿨는지 두 줄로 알려 주고 커밋해 줘.
```

> **왜 이렇게 말하나** — 두 개를 같이 고치면 문제가 생겼을 때 어느 쪽 때문인지 알 수 없다.

---

## P4 — 내가 직접 확인

```
계획서에 적은 확인 방법을 순서대로 읽어 줘. 내가 직접 눌러 볼게.
내가 "안 보인다"고 하면 원인을 찾기 전에 먼저 되돌려 줘.
```

> **왜 이렇게 말하나** — AI의 "완료했습니다"는 확인이 아니다. 내 손으로 눌러 본 것만 된 것이다.

---

## P5 — 백업 먼저 (저장으로 넘어가기 전)

```
indeans-erp-data 스킬을 읽고 시작해 줘.
데이터를 옮기기 전에 백업과 되찾는 방법부터 정하고 company/backup.md 에 적어 줘.
내려받은 파일을 내가 직접 열어서 확인하는 순서까지 알려 줘.
```

> **왜 이렇게 말하나** — 순서가 핵심이다. "저장 먼저, 백업은 나중에"로 가면 그 나중은 대개 오지 않는다. 백업은 **되찾아 본 적이 있을 때만** 있는 것이다.

---

## P6 — 표 만들기 (잠금은 같이)

```
company/structure.md 의 항목 표를 보고, 우리 일을 담는 표 하나부터 supabase/migrations/0001_init.sql 로 만들어 줘.
표와 칸 이름은 영문으로 두고, 우리 회사가 부르는 말은 주석으로 붙여 줘.
잠금(행 수준 보안)은 표를 만들 때 같이 걸어 줘. 나중에 켜는 건 안 해.
```

> **왜 이렇게 말하나** — "나중에 켜자"로 미룬 잠금은 대개 안 켜진다. 사람이 늘어난 뒤에 알게 된다.

---

## P7 — 진짜 데이터로 갈아타기

```
앱이 예시 데이터 대신 데이터베이스를 쓰게 바꿔 줘. 한 화면씩, 목록부터.
이메일·비밀번호로 로그인하는 최소 화면도 넣어 줘. 역할 나누기는 이따가 할 거야.
목록 조회에는 정렬과 개수 제한을 꼭 넣어 줘.
한 화면 끝날 때마다 멈추고 내가 확인할 시간을 줘.
```

> **왜 이렇게 말하나** — 제한 없는 목록은 데이터가 쌓이면 **오류 없이 조용히 잘린다.** 나중에 "왜 최근 것이 안 보이지"로 나타난다.

---

## P8 — 인터넷 주소 만들기

```
GitHub 비공개 저장소에 올리고 Vercel 로 배포하는 순서를 알려 줘.
올리기 전에 .env.local 이 올라가지 않는지 먼저 확인해 줘.
Vercel 환경 변수에 무엇을 넣어야 하는지도 화면 순서대로 알려 주고, 값은 화면에 출력하지 마.
```

> **왜 이렇게 말하나** — 환경 변수를 빼먹어서 "내 컴퓨터에선 되는데 주소로는 빈 화면"이 되는 경우가 가장 많다. 비밀값은 화면에 찍지 않는다 — 대화 기록에 남는다.

---

## P9 — 사람·권한 인터뷰

```
indeans-erp-people 스킬을 읽고 시작해 줘.
질문은 한 번에 하나씩. 다 묻기 전에는 코드를 만들지 마.
'절대 보이면 안 되는 것'을 물을 때는 내가 '없다'고 해도 넘어가지 말고,
금액·단가·다른 고객 건·직원끼리 안 보였으면 하는 것을 하나씩 짚어서 다시 물어봐.
작업 전에 되돌릴 지점(커밋)을 먼저 만들어 줘.
```

> **왜 이렇게 말하나** — 권한 설계의 출발점은 "무엇을 보여 줄까"가 아니라 "무엇은 절대 안 된다"이다. 이 목록이 나중에 확인할 체크리스트가 된다.

---

## P10 — 권한을 앱에 반영

```
인터뷰 내용을 company/people.md 로 저장하고 앱에 반영해 줘.
1) 로그인을 붙이고, 아무나 가입되는 화면은 만들지 마
2) 대표와 직원 두 역할로 나누고, 역할마다 첫 화면을 정해 줘
3) 내가 말한 '보면 안 되는 것'은 어느 화면에서도 안 보이게 해 줘

--- 아래는 AI에게 주는 규칙입니다. 뜻을 모르셔도 됩니다. 지우지 말고 그대로 두세요 ---
· 역할 칸은 비워 둘 수 없게 하고 활성 여부 칸을 둘 것
· 역할 판정 함수의 실행 권한은 절대 회수하지 말 것
· 모든 표를 먼저 잠그고 필요한 것만 역할별로 다시 열 것
· 권한 검사는 '이 역할이면 허용'으로 쓰고 '이 역할이 아니면 거부'로 쓰지 말 것
· 화면에서 숨기는 것으로 끝내지 말고 데이터를 가져오는 자리에서 막을 것
· 내가 고른 두세 가지 행동에만 누가 언제 했는지 기록을 남길 것
· 기존 마이그레이션 파일은 고치지 말고 새 번호로 만들 것
```

> **왜 이렇게 말하나** — "이 역할이 아니면 거부"로 쓰면 역할이 비어 있는 계정이 검사를 그냥 통과한다. 빈칸은 "아니오"가 아니다.

---

## P11 — 권한 확인 — 가장 권한 낮은 자리에서

```
역할별 테스트 계정을 만들어 주고, 내가 직접 로그인해서 확인할 순서를 알려 줘.
company/people.md 의 '보면 안 되는 것' 목록을 한 줄씩 대조할 수 있게 표로 정리해 줘.
목록 화면뿐 아니라 상세·검색·사진이나 파일까지 확인할 곳을 알려 줘.
역할 칸이 빈 계정도 하나 만들어 줘. 그 계정으로는 아무것도 안 보여야 맞는 거지?
테스트 계정은 가짜 이름으로 만들고, 비밀번호는 화면에 출력하지 마.
```

> **왜 이렇게 말하나** — 권한은 가장 권한이 낮은 사람의 자리에서 확인해야 한다. 관리자 화면에서 규칙만 보는 것은 확인이 아니다.
>
> 로그아웃한 상태로 목록 화면 주소를 직접 열어 보는 것도 같이 한다. **화면에서 안 보이는 것과 데이터가 막힌 것은 다르다.**

---

## P12 — 오늘 것 검수·보고

```
indeans-erp-check 스킬을 읽고 오늘 바꾼 것을 검수해 줘.
무엇이 바뀌었는지 먼저 목록으로 보여 주고, 감독이 반려하면 고친 뒤 다시 판정받아 줘.
저장이 되는지, 다시 접속해도 남아 있는지, 다른 역할로는 막히는지까지 실제로 확인해 줘.
끝나면 보고서로 만들어 열어 줘.
```

> **왜 이렇게 말하나** — 오늘은 저장 구조와 권한이 둘 다 바뀌었다. 되돌리기 어려운 쪽이라 배포 전에 한 번 보고 간다.

---

## 막혔을 때 (오류 전달)

```
(1) 하려던 것: {무엇을 하려 했는지}
(2) 기대한 결과: {무엇이 되기를 바랐는지}
(3) 실제 결과: {무엇이 됐는지}
(4) 오류 원문: {화면의 빨간 글씨를 그대로 붙여넣기}

원인을 찾아 고치기 전에, 무엇 때문인지 한 줄로 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — 네 가지를 나눠 적으면 AI가 추측하지 않는다. 요약하면 어느 줄에서 났는지가 사라진다.

## 되돌릴 때

```
방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 상태로 되돌려 주세요.
되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — 되돌리는 것은 실패가 아니라 절차다. 되돌릴 수 있으면 더 과감하게 시도할 수 있다.
