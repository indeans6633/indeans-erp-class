# 3회차 과제 — 하루 받아 보고 문구 고치기

다음 회차까지 할 일. **정해진 시각에 오는 보고를 며칠 받아 보고, 항목과 문구를 한 번 고친다.** 그리고 세 줄을 적어 온다.

권장 시간: 첫날 10분 + 고치는 데 20분. 직원은 계속 자기 기기로 앱을 쓴다.

---

## 하는 일

### 1. 보고를 실제로 받는다 (필수)

- 정한 시각에 폰으로 오는지 본다. **첫날 아침이 가장 중요하다.**
- 안 왔으면 그날 안에 확인한다. 하루 미루면 원인이 두 개로 늘어난다.

```
오늘 보고가 안 왔어. 발송 기록부터 보여 줘.
예약이 돌았는지, 돌았는데 보내기에서 실패했는지, 아예 안 돌았는지 순서대로 짚어 줘.
원인을 찾기 전에 고치지 마.
```

### 2. 숫자를 한 번 대조한다 (필수, 3분)

- 보고에 적힌 숫자와 앱 화면의 숫자를 눈으로 맞춰 본다.
- 다르면 **어느 쪽이 맞는지**부터 적어 둔다. 대개 세는 기준이 다르다(오늘의 기준이 자정인가, 영업 시작인가).

### 3. 항목·문구를 한 번 고친다 (필수)

며칠 받아 보면 안 보게 되는 줄이 생긴다. 그 줄을 뺀다.

```
받아 보니 {무엇}이 빠졌고 {무엇}은 필요 없어.
보고 항목을 고치고 company/digest.md 도 같이 고쳐 줘.
예약은 다시 걸지 말고 보내는 내용만 바꿔 줘.
```

**줄이는 쪽으로 고친다.** 보고가 길어지면 안 읽게 되고, 안 읽으면 없는 것과 같다.

### 4. 직원용 보고도 받아 본다 (해당되면)

- 직원에게 가는 보고가 따로 있으면, 직원에게 **"오늘 온 거 봤어요?"** 라고만 물어본다.
- 안 봤다고 하면 그 이유가 다음 회차 고칠 목록이다(시각이 안 맞나, 내 일이 아닌 것 같나, 알림이 꺼져 있나).

### 5. 세 줄을 적는다 (필수)

```markdown
## <날짜> · 3회차 뒤
- 시도한 업무: <이 앱으로 하려 한 일 / 보고를 보고 실제로 한 행동>
- 막힌 지점: <손으로 하거나 그만둔 자리>
- 원하는 변화: <어떻게 되면 되겠는가>
```

```
이번 주 앱과 보고를 써 봤어. 아래 세 줄을 company/log.md 맨 위에 그대로 적어 줘.
시도한 업무: {이 앱으로 하려 한 일}
막힌 지점: {손으로 하거나 그만둔 자리}
원하는 변화: {어떻게 되면 되겠는가}
내 말을 요약하거나 다듬지 말고 그대로 넣어 줘. 앱은 고치지 마.
```

## 다음 회차에 가져올 것

- [ ] 실제로 받은 보고 화면(폰 사진 한 장이면 된다)
- [ ] 보고 숫자와 앱 숫자를 대조한 결과
- [ ] 고친 항목 한 가지
- [ ] `company/log.md` 의 세 줄
- [ ] 노트북 + 충전기

## 하지 않아도 되는 것

- 보고 종류 늘리기. **한 종류를 쓸 만하게 만드는 것**이 먼저다.
- 알림을 여러 채널로 동시에 보내기. 둘 다 오면 둘 다 안 보게 된다.
- 고객에게 가는 알림. 아직 이르다. 내부에서 한 달은 돌려 본 뒤 대표님 판단으로.

## 막히면

- 보고가 안 오는 것과 앱이 안 되는 것은 다른 문제다. 섞어서 말하지 않는다.
- 30분 넘게 같은 자리에 있으면 멈추고 한 줄로 적어 온다. 다음 회차 시작 15분에 다룬다.
- 비밀값(웹훅 주소·봇 토큰)이 화면이나 저장소에 노출된 것 같으면 **그것부터 새로 만든다.** 새 값으로 바꾸는 것이 가장 빠르다.
