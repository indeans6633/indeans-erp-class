# 4회차 과제 — 2주 실사용

기간: 최종 회까지 2주. 목표는 기능을 늘리는 것이 아니라 **실제로 쓰면서 무엇이 불편한지 알아내는 것**이다.

최종 회에서 각자 10분씩 시연한다. 그 재료가 이 2주에 쌓인다.

---

## 1. 앱을 실제 업무에 쓴다

- 하루에 한 번 이상 연다. 들어오는 건을 앱에도 넣는다.
- **기존 방식(엑셀·수첩·메신저)을 버리지 않는다.** 최소 한 달은 같이 돌린다. 앱만 믿고 원장을 버리면 잘못됐을 때 되돌릴 것이 없다.
- 적어도 **5건**은 처음부터 끝까지 앱으로 처리해 본다. 그중 **직원이 직접 처리한 1건**은 최종 회 시연에서 보여 줄 사례가 된다.

## 2. 세 줄을 계속 적는다

고치려 하지 말고 **적어만 둔다.** 주간 점검 때 한꺼번에 본다. 한 주에 한 건씩, 2주면 두 건이면 충분하다.

```markdown
## <날짜> · 4회차 뒤
- 시도한 업무: <이 앱으로 하려 한 일>
- 막힌 지점: <손으로 하거나 그만둔 자리 — 직원이 겪은 것이면 (직원 말 전달)>
- 원하는 변화: <어떻게 되면 되겠는가>
```

```
이번 주 앱을 써 봤어. 아래 세 줄을 company/log.md 맨 위에 그대로 적어 줘.
시도한 업무: {이 앱으로 하려 한 일}
막힌 지점: {손으로 하거나 그만둔 자리}
원하는 변화: {어떻게 되면 되겠는가}
내 말을 요약하거나 다듬지 말고 그대로 넣어 줘. 앱은 고치지 마.
```

**"그래서 어떻게 했나"가 가장 중요하다.** 앱 대신 쓴 방법이 있다는 것은 **그 방법이 앱보다 빨랐다**는 뜻이고, 거기에 고칠 것이 있다.

## 3. 주간 루틴 2회 실행

정한 요일에 두 번 돌린다.

```
이번 주 점검을 실행 모드로 한 번 돌려 줘.
이번 주에 불편했던 것부터 하나씩 물어보고, 그중 한 건만 골라서 고치자.
고치기 전에 되돌릴 지점을 먼저 만들고, 내가 말한 요구와 네 계획을 표로 대조해서 보여 줘.
내 요구 중에 빼거나 다르게 바꾼 것이 있으면 진행하기 전에 먼저 알려 줘.
```

- 한 주에 **개선 1건만** 한다. 더 하고 싶어도 다음 주로 넘긴다.
- 못 하는 단계는 "해당 없음 — 이유"로 적는다.
- 두 AI 교차 검토를 두 번 다 해 본다. 두 번째부터 익숙해진다.

## 4. 보고를 계속 받는다

- 정한 시각에 계속 오는지 본다. 중간에 끊기면 그것도 기록이다(언제부터 안 왔는지).
- 며칠 안 보게 되는 줄이 있으면 뺀다. 줄이는 쪽으로 고친다.

## 5. 백업을 한 번 더 내려받아 열어 본다

- 2주 사이에 표가 바뀌었을 수 있다. **바뀐 뒤에도 백업이 제대로 나오는지** 확인한다.
- 파일을 어디에 둘지 정한다. 노트북 바탕화면은 백업이 아니다.

---

## 최종 회에 가져올 것

시연은 10분이고 구성은 정해져 있다 — 시연 5분 / 2주 사용 결과 3분 / 다음 개선 순서 2분.

- [ ] **직원이 실제로 처리한 업무 1건** (시연에서 흐름대로 끝까지 보여 줄 것)
- [ ] `company/log.md` 의 2주치 세 줄 기록
- [ ] 주간 점검 기록 2회분
- [ ] 개선 2건(주당 1건)을 실제로 반영한 결과
- [ ] `company/plan-30d.md` 의 개선 3건과 순서
- [ ] 가장 크게 막힌 문제 1건 — **다시 일으키는 순서(1, 2, 3)까지**
- [ ] 노트북 + 충전기

**다시 일으키는 순서가 있는 문제**가 가장 빨리 해결된다. 없으면 다음에 나올 때 화면을 사진으로 찍어 둔다.

시연 준비는 최종 회 전에 한 번 돌린다.

```
indeans-erp-showcase 스킬을 읽고 시연 준비를 마저 해 줘.
2주 동안 쌓인 기록으로 빈칸을 채우고, 직원이 실제로 처리한 1건을 시연 순서에 넣어 줘.
지금 안 되는 것은 안 된다고 그대로 적어 줘. 시연을 위해 앱을 고치지는 마.
캡처에 고객 이름·연락처·금액이 없는지 먼저 확인해 주고, 있으면 어디에 있는지 알려 줘.
```

## 막히면

- 2주 동안은 **단톡방**이 열려 있다. 막힌 것은 거기서 묻거나, 최종 회 안건으로 가져온다.
- 앱이 아예 안 열리면 되돌린다. 되돌리는 것은 실패가 아니다.
- 무엇을 고칠지 모르겠으면 `company/plan-30d.md` 의 개선 1번을 그냥 시작한다.
- 혼자 안 되면 막힌 화면과 오류 글자를 캡처해 두고 그 사이엔 손으로 처리해도 된다.
