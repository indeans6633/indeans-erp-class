# 4회차 — 이렇게 말하세요

> 3·4회차 배치는 가안 — 2회차 정리 뒤 확정(2026-10-08)

AI에게 넣을 문장 원문이다. **글자 그대로** 복사해서 쓰고 `{ }` 안만 우리 회사 것으로 바꾼다. 각 문장 아래 한 줄은 "왜 그렇게 말하는지"다.

오늘 끝내야 하는 것은 하나다. **검수와 복구를 직접 눈으로 확인하고, 2주 실사용 준비를 마치는 것.**

검수 체계는 오늘 켜는 것이 아니다. **1회차에 설치한 순간부터 돌고 있었다.** 오늘은 그것이 언제 무엇을 하는지 이해하고, 무너졌을 때 되돌리는 것을 한 번 해 본다.

---

## P1 — 지금까지 무엇이 돌고 있었나 (검수 체계 이해)

```
indeans-erp-check 스킬을 읽고 시작해 줘.
오늘은 고치는 게 아니라, 지금 이 프로젝트에서 검수가 언제 어떻게 도는지 이해하려고 해.
1회차부터 지금까지 검수를 요구했던 기록과 그때 무엇을 봤는지 보여 주고,
어떤 변경은 검수를 하고 어떤 변경은 넘어가는지 표로 정리해 줘.
오늘은 설명만. 아무것도 고치지 마.
```

> **왜 이렇게 말하나** — "어떤 변경은 넘어가는지"를 같이 묻는 것이 핵심이다. 검수는 **줄 수가 아니라 영향**으로 판단한다. 한 줄만 고쳐도 권한이 바뀌면 검수하고, 백 줄을 고쳐도 문구뿐이면 넘어간다. 이 기준을 대표가 알아야 AI가 검수를 건너뛸 때 알아챈다.

---

## P2 — 복구 실습 (한 번은 직접 해 본다)

```
indeans-erp-routine 스킬을 읽고 복구 실습을 해 보자.
지금 상태를 먼저 백업하고, 연습용으로 한 건을 지운 다음 백업에서 그 한 건만 되돌려 줘.
내가 무엇을 눌러야 하는지 단계마다 알려 주고, 끝나면 company/backup.md 에 해 본 날짜를 적어 줘.
실제 업무 데이터 말고 연습용 한 건으로만 해 줘.
```

> **왜 이렇게 말하나** — 백업이 있다는 말은 **되찾아 본 적이 있을 때만** 사실이다. 실제로 사고가 났을 때 처음 해 보면 그때 되돌리는 법을 배우게 된다.
>
> "연습용 한 건으로만"을 넣는 이유: 실습하다가 실제 데이터를 지우는 일이 실제로 생긴다.

---

## P3 — 업무 흐름 확장

```
indeans-erp-workflow 스킬을 읽고 시작해 줘.
먼저 지금 첫 흐름이 안정된 상태인지 판정해서 한 문장으로 알려 줘.
질문은 한 번에 하나씩. 다 묻기 전에는 코드를 만들지 마.
작업 전에 되돌릴 지점(커밋)을 먼저 만들어 줘.
```

> **왜 이렇게 말하나** — **두 번째 흐름은 첫 흐름이 안정된 사람만** 한다. 첫 흐름에 미해결 문제가 남은 채로 두 번째를 붙이면 첫 흐름이 영구히 안 끝난다. 그래서 판정을 먼저 시킨다.

---

## P4 — 흐름을 앱에 반영하고 내가 확인

```
정한 흐름을 앱에 반영해 줘.
1) 단계 값과 화면에 보이는 글자를 따로 두고 한 파일에 정의할 것
2) 어느 단계에서 어디로 갈 수 있는지 표를 코드 한 곳에만 둘 것
3) 목록에 단계별 필터를 넣되 기본은 '끝난 것 빼고'로 할 것
4) 상세 화면 맨 위에 '다음 할 일' 한 줄과 넘기는 버튼을 둘 것
5) 단계 칸은 비워 둘 수 없게 하고 기본값을 첫 단계로 할 것
6) 목록을 불러올 때 정렬과 개수 제한을 반드시 넣을 것
다 되면 내가 직접 눌러서 확인할 순서를 알려 줘. 한 건을 처음부터 끝까지 옮기기,
한 번 되돌리기, 하면 안 되는 이동을 눌러 보기까지.
```

> **왜 이렇게 말하나** — 단계 값과 화면 글자를 나누지 않으면, 나중에 단계 이름만 바꿔도 과거 기록이 목록에서 사라진다.
>
> 확인이 끝나면 **앞서 잘 되던 화면을 한 번 더 열어 본다.** 새 규칙을 붙이면 멀쩡하던 화면이 죽는 일이 잦다.

---

## P5 — 주간 루틴 정하기

```
indeans-erp-routine 스킬로 우리 회사 주간 점검 루틴을 세워 줘.
나는 매주 {요일} {시각}에 30분을 쓸 수 있어. {혼자 한다 / 직원 1명과 같이 한다}.
company/routine.md 를 만들고, 요일과 시각을 비워 두지 마.
```

> **왜 이렇게 말하나** — "시간 날 때 하겠다"는 안 하게 된다. **요일과 시각을 문장에 박아 넣는 것**이 루틴의 전부다.

---

## P6 — 첫 주간 점검 한 번 돌리기

```
이번 주 점검을 실행 모드로 한 번 돌려 줘.
지난 회차 이후 불편했던 것부터 하나씩 물어보고, 그중 한 건만 골라서 고치자.
고치기 전에 되돌릴 지점을 먼저 만들고, 내가 말한 요구와 네 계획을 표로 대조해서 보여 줘.
내 요구 중에 빼거나 다르게 바꾼 것이 있으면 진행하기 전에 먼저 알려 줘.
```

> **왜 이렇게 말하나** — AI가 요구를 조용히 줄이는 것이 가장 흔한 사고다. **대조표를 요구하면** 그 자리에서 드러난다.

---

## P7 — 두 AI 교차 검토

만든 도구가 아닌 **다른 도구**에서 실행한다(Claude Code로 만들었으면 Codex에서).

```
이 프로젝트의 최근 변경을 검토만 해 줘. 파일은 고치지 마.
요구 원문: "{내가 한 말 그대로}"
바뀐 파일: {git diff --name-only HEAD~1 HEAD 결과}
(1) 요구 중 빠진 것 (2) 요구와 다르게 해석한 것 (3) 누가 무엇을 보는지에 영향이 가는 변경
이 세 가지만 목록으로 알려 줘. 더 좋은 방법은 제안하지 마.
각 항목에 맞음 / 빠짐 / 바뀜 판정을 붙여 줘.
```

검토자가 못 읽었다고 하면 `git diff HEAD~1 HEAD > 바뀐내용.txt` 를 만들어 붙여 넣는다.

> **왜 이렇게 말하나** — 만든 AI에게 "잘 됐냐"고 물으면 거의 "잘 됐다"고 한다. 만든 과정을 모르는 쪽에 **요구와 결과만** 주고 대조시킨다.
>
> "바뀐 파일" 줄이 없으면 검토자가 파일을 스스로 찾아야 하는데, 도구에 따라 그 명령이 막혀 있어 세 항목 전부 "판정 불가"로 끝난다.

## P8 — 30일 계획 채우기

```
indeans-erp-routine 스킬로 다음 30일 계획을 채워 줘.
개선 3건을 정할 건데, 각각 한 주 안에 끝나는 크기인지 봐 주고 크면 쪼개 줘.
항목마다 "무엇이 되면 끝인지"를 내 말로 적게 질문해 줘.
백업과 비용 칸은 비워 두지 말고, 내가 모르면 "모름 — 다음 주 확인"이라고 적어 줘.
```

> **왜 이렇게 말하나** — "무엇이 되면 끝인지"가 없으면 한 달 뒤에 끝났는지 아닌지를 판단할 수 없다.

## P9 — 시연 대본 틀 잡기

```
indeans-erp-showcase 스킬을 읽고 최종 회 시연 대본의 틀만 잡아 줘.
2주 동안 쓰면서 채울 칸은 비워 두고, 지금 채울 수 있는 것만 채워 줘.
시연은 10분이고, 실제로 도는 화면만 보여 줄 거야. 발표를 위해 앱을 고치지는 마.
```

> **왜 이렇게 말하나** — "실제로 도는 것만"이라고 먼저 못 박아야 시연 중에 안 되는 화면을 누르는 사고가 없다. 안 되는 것은 안 된다고 말하는 것이 이 자리의 기준이다.

## 막혔을 때 (오류 전달)

```
(1) 하려던 것: {무엇을 하려 했는지}
(2) 기대한 결과: {무엇이 되기를 바랐는지}
(3) 실제 결과: {무엇이 됐는지}
(4) 오류 원문: {화면의 빨간 글씨를 그대로 붙여넣기}

원인을 찾아 고치기 전에, 무엇 때문인지 한 줄로 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — 네 가지를 나눠 적으면 AI가 추측하지 않는다. 이 문장은 수료 후에도 계속 쓴다.

## 되돌릴 때

```
방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 상태로 되돌려 주세요.
되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.
```

> **왜 이렇게 말하나** — 되돌리는 것은 실패가 아니라 절차다. 되돌릴 수 있으면 더 과감하게 시도할 수 있다.

---

## 4회 동안 반복한 원칙 네 가지

1. **한 번에 하나씩 시킨다.** 한꺼번에 시키면 엉뚱한 것이 나온다.
2. **"이렇게 해 줘"보다 "지금 이게 불편하다"**를 먼저 말한다. 방법은 AI가 더 많이 안다.
3. **고치기 전에 되돌릴 지점**을 만들라고 말한다.
4. **"확인했다"는 말이 아니라 화면에서 눈으로 본 것**이 확인이다.
