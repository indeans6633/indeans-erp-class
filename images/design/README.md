# 디자인 선택 이미지 세트

앱을 만들기 전에 **화면 구조 3가지 × 색 4가지 = 12가지**를 눈으로 비교해 고르는 자료다.
12장 모두 **같은 가상 회사(○○상사)·같은 예시 데이터·같은 문구·같은 정보량**으로 그렸다. 달라진 것은 구조와 색뿐이다 — 그래야 디자인만 비교된다.

## 고르는 방법 (수강생·대표)

```
node .owner/hooks/open.mjs .owner/design/index.html
```

1. 먼저 **줄(구조)** 을 하나 고른다. 3줄이 구조 3가지다.
2. 고른 줄에서 **색** 4가지를 비교해 하나 고른다.
3. 그림을 누르면 원래 크기(폭 1280)로 크게 볼 수 있다.

12장을 한 번에 늘어놓고 고르지 않는다. 구조를 먼저 정하면 볼 것이 4장으로 줄어든다.

| 구조 | 화면 모양 | 이런 회사에 맞음 |
|---|---|---|
| 목록·표형 `list` | 좌측 메뉴 + 표 | 건이 많아 표로 훑는 회사. 한눈에 세기·찾기가 중심일 때 |
| 진행 보드형 `board` | 상단 탭 + 단계 열 | 지금 어느 단계까지 왔는지가 중요한 회사. 단계별로 밀어 가는 일 |
| 카드·상세형 `card` | 카드 목록 + 상세 패널 | 건 하나하나를 자세히 보는 회사. **고객이 직접 보는 화면에 적합** |

색 4가지: 남색 `navy` · 진회색(차콜) `charcoal` · 녹색 `green` · 갈색 `brown`. 넷 다 무채색 바탕에 강조색 하나만 쓰는 절제 톤이다.

## 고른 다음 (색·글자 값 옮기기)

고른 조합의 토큰 파일 하나를 앱으로 복사한다.

```
tokens/<구조>-<색>.css  →  src/styles/tokens.css
```

예: 진행 보드형 + 녹색 → `tokens/board-green.css`를 `src/styles/tokens.css`로 복사한다.
토큰 파일에는 **CSS 변수만** 들어 있다(색·글자 크기·굵기·간격·모서리·누르는 곳 높이). 값은 회사에 맞게 바꿀 수 있지만 **강조색(`--primary`)은 하나만 유지**한다.

- 화면 구조(표·보드·카드)를 만드는 CSS는 토큰 파일에 없다. 구조는 `src/`의 목업 HTML을 참고해 앱 코드로 만든다.
- 같은 색의 토큰 4벌(`list-navy`·`board-navy`·`card-navy`)은 **지금 값이 같다.** 구조가 달라도 색·글자·간격 규칙은 같기 때문이다. 파일을 조합마다 둔 이유는 복사 절차를 하나로 유지하려는 것이고, 어떤 구조만 값을 달리하고 싶으면 그 파일만 고치면 된다.
- `--ok`·`--warn`·`--danger` 세 개는 목업 화면에 나오지 않는다(목업에 경고·삭제 버튼을 넣지 않았다). 앱에서 필요하므로 파일에는 들어 있다. **면(배경)이 아니라 글자로만** 쓴다.

## 파일

```
images/design/
  index.html              비교 갤러리(3줄 × 4칸) — 생성물
  <구조>-<색>.png         12장, 폭 1280 — 생성물(높이는 내용에 맞춰 자른다. 같은 줄 4장은 같은 높이)
  tokens/<구조>-<색>.css  12벌, :root 변수만
  src/                    목업 원본(캡처의 입력)
    base.css              12장 공통 바탕(상단 바·버튼·요약 칸·폼 기본·좁은 화면 뼈대)
    layout-list.css       구조별 레이아웃 3개(구조마다 좁은 화면 뼈대 포함)
    layout-board.css
    layout-card.css
    <구조>-<색>.html      12개 — 토큰 + 공통 바탕 + 구조 CSS 를 불러 쓴다
  README.md               이 문서
```

파일명은 영문(`list-navy.png`), 화면에 보이는 라벨은 한글이다.

## 다시 만들기 (제작 쪽)

강의 자료 저장소에서 실행한다. playwright는 이 저장소의 개발 의존성이다(`npm install` → 없으면 `npx playwright install chromium`).

```
node scripts/build-design-images.mjs                 12장 캡처 + 갤러리 다시 쓰기
node scripts/build-design-images.mjs --only board     한 구조만 다시 캡처
node scripts/build-design-images.mjs --check-only      캡처 없이 점검만
```

스크립트가 같이 확인하는 것(하나라도 걸리면 목록을 내고 exit 1):

- 같은 구조의 색 4장이 **글자 하나까지 같은지**(색만 달라야 한다)
- 12장 전부에 공통 예시 데이터·문구가 들어 있는지(회사명·건 번호 6개·담당 3명·단계 4개·받은 날·마감일·날짜 11개·요약 문구)
- **12장 교차** — 구조가 달라도 날짜·담당 문구가 모두 있는지. 넘길 값을 적는 `CROSS_EXEMPT` 는 **지금 비어 있다**(세 구조가 같은 날짜를 모두 보여 준다). 한 구조에만 있는 날짜를 만들면 여기서 막힌다.
- 1280 폭에서 가로로 밀리지 않는지, 800 높이 안에 들어오는지(넘치면 캡처에서 아래가 잘린다)
- **375 폭(폰)** 에서 가로가 밀리지 않는지, 말줄임 없이 잘린 글자가 없는지(`scrollWidth > clientWidth`)
- **색 대비** — 토큰 12벌의 글자색이 바탕 4종(화면 바탕·표/카드 바탕·머리줄 바탕·**선택된 줄·카드 바탕**) 위에서 4.5:1 이상인지, 강조색 글자와 버튼 위의 글자까지(한 벌 27짝 × 12벌 = 324짝)
- 본문 글자 크기가 14px인지, 누르는 곳이 40px보다 낮지 않은지
- 토큰 파일이 실제로 적용됐는지(`--primary`가 비어 있지 않은지), PNG가 1MB를 넘지 않는지

## 고칠 때 지키는 것

- **문구·데이터를 한 장만 고치지 않는다.** 같은 구조의 4장을 같이 고친다(점검이 막는다).
- **구조가 달라도 정보량을 같게 둔다.** 세 구조 모두 6건에 담당·단계·받은 날·마감일이 보인다. 한 구조에만 있는 날짜를 새로 만들면 12장 교차 점검이 막는다.
- **글자색은 바탕과 4.5:1 이상**을 지킨다 — 날짜·보조 글자(`--text-3`)와 **선택된 줄·카드 바탕(`--primary-soft`) 위**까지 포함. 스크립트가 계산해서 막는다.
- **375 에서는 표 머리줄 대신 날짜 라벨이 붙는다.** 목록형 날짜 칸의 `.d-in`·`.d-due` 클래스를 지우면 폰에서 두 날짜가 라벨 없이 나란히 보인다(680 이하에서만 CSS `::before` 로 "받은 날 "·"마감 " 을 붙인다. 1280 에서는 표 머리줄이 라벨을 맡는다).
- **좁은 화면 뼈대를 지운 채 값만 옮기지 않는다.** 목업 CSS의 `@media (max-width: 680px)`(구조 접힘)·`@media (max-width: 900px)`(카드 상세를 아래로)·`@media (pointer: coarse)`(누르는 곳 44px)가 폰에서 세로쓰기·겹침을 막는다. 토큰 파일에는 이 뼈대가 없다.
- 예시 데이터는 전부 가상이다. **인디언즈 운영 데이터·고객 정보·실제 회사명·금액을 넣지 않는다.** 금액 항목 자체를 두지 않는다.
- 업종을 특정하는 말을 쓰지 않는다(○○상사·건·단계 4개처럼 어느 업종에나 읽히는 말만).
- 절제 톤을 지킨다: 무채색 바탕, 강조색 하나, 장식·그림자·이모지 없음, 시스템 글꼴, 단계마다 다른 색을 쓰지 않음(단계는 위치와 글자로 구분).
- 색을 더하려면 `tokens/`에 조합만 늘리지 말고 `scripts/build-design-images.mjs`의 목록(`COLORS`)과 칸마다의 "이런 회사에 맞음" 한 줄(`FIT`)도 같이 늘린다. 목업 HTML은 구조 3개 × 새 색만큼 더 만든다.
