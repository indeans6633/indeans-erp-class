# 인디언즈 알림 채널 연결

**이 스킬의 역할은 "보고를 받을 창구 만들기"다.** 무엇을 언제 보낼지 정하고 서버에 예약하는 일은 `indeans-erp-digest` 가 한다. 여기서는 **보낼 곳**을 만들고, 그 곳으로 글자 한 줄이 실제로 도착하는 것까지 확인한다.

3회차 앞 실습. 창구가 없으면 운영 보고를 만들 수 없으니 이 스킬이 먼저다.

## 언제 쓰나

- 앱이 보내는 보고·알림을 폰으로 받고 싶을 때(3회차 본 실습).
- 창구를 하나 더 늘리거나, 받는 사람을 바꾸고 싶을 때.
- 보내던 것이 갑자기 안 올 때(주소가 무효가 됐는지 확인).

쓰지 않는 경우: 무엇을 언제 보낼지 정하는 일(→ `indeans-erp-digest`), 작업이 끝날 때 보여 주는 보고서(→ `indeans-erp-report`), 앱 화면 안 배지·표시(→ `indeans-erp-review`).

## 시작 전 상태 진단

먼저 읽고 판정한다. 읽기 전에 말을 걸지 않는다.

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` | 현재 기능 · 미해결 문제 · 다음 행동 |
| `.owner/progress.json` | `channel.discord` · `channel.telegram` 값, 저장·배포가 끝났는지 |
| `company/channel.md` | 창구를 이미 만들었나(있으면 아래 '진행 중' 분기) |
| `company/people.md` | 역할 — 누가 보고를 받아야 하나 |
| `company/profile.md` | 회사 이름·업태(보고 첫 줄에 쓴다) |
| `.env.local` · `.gitignore` | 비밀값을 둘 자리가 있나, 커밋에서 빠져 있나 (**값은 화면에 출력하지 않는다**) |
| `supabase/migrations/` | 비밀값을 서버 쪽에 둘 표가 이미 있나 |

**상태 문서가 실제와 다르면 문서를 믿지 않는다.** `company/channel.md` 에 "연결됨"이라고 적혀 있어도 테스트 발송이 도착하지 않으면 연결된 것이 아니다.

판정과 분기:

- **처음** — `company/channel.md` 없음 → 절차 0부터 순서대로(둘 다 만든다).
- **진행 중** — 한쪽만 있음 → 있는 쪽은 테스트 발송으로 살아 있는지 확인만 하고, 없는 쪽을 만든다.
- **완료** — 둘 다 있고 테스트가 도착함 → 「앞선 수강생 분기」로 간다.

판정을 한 문장으로 먼저 알린다. 예: "창구가 아직 없습니다. 디스코드와 텔레그램 두 곳을 만들고 각각 한 줄씩 보내 보겠습니다."

## 절차

### 0. 되돌릴 지점과 비밀 파일 확인

```bash
git add -A
git commit -m "알림 채널 연결 전 상태"
```

`git check-ignore -v .env.local` 을 실행해 한 줄이 나오는지 본다. 아무것도 안 나오면 `.gitignore` 에 `.env.local` 을 먼저 추가하고 커밋한다. **웹훅 주소나 봇 열쇠가 한 번 올라가면 파일을 지워도 기록에 남는다.**

### 1. 왜 둘 다 만드나 (2분, 세 문장)

대표에게 이렇게 설명한다.

> 디스코드는 **쌓이는 쪽**입니다. 지난 보고를 찾아보고 파일도 올려 둘 수 있습니다.
> 텔레그램은 **바로 아는 쪽**입니다. 폰에 즉시 뜨고 대표님 혼자 보기에 편합니다.
> 둘 중 하나는 회사 사정에 따라 막히거나 안 쓰게 됩니다. 오늘 둘 다 만들어 두고, 쓰다가 한쪽을 고르시면 됩니다.

슬랙을 이미 쓰는 회사면 `references/slack.md` 를 읽고 그쪽을 셋째 창구로 안내한다. **슬랙을 기본으로 바꾸지는 않는다**(수업에서 절차를 다루지 않는다).

### 2. 누가 받나 (질문 하나)

> "이 보고를 대표님만 받으시겠어요, 직원도 같이 받는 방이 필요하세요?"

판단 기준:

- "대표만" → 방은 하나다. 대표용(`owner`) 창구만 만든다.
- "직원도" → 방을 **둘로 나눈다**(대표용 · 직원용). 직원 방에는 금액·다른 사람 평가·아직 확정 안 된 일정을 보내지 않는다. 무엇을 보낼지는 `indeans-erp-digest` 에서 정하고, 지금은 **받을 곳 두 개**만 만든다.
- 답이 애매하면 대표용 하나로 시작한다. 늘리는 것은 나중에 5분이면 된다.

### 3. 디스코드 웹훅 만들기 — 대표가 직접 누른다

대신 해 줄 수 없는 단계다. `references/discord.md` 를 열어 화면 순서대로 읽어 주고 대표가 누른다. 뼈대만 옮기면:

1. 디스코드 앱에서 **서버 만들기**(없으면) → 보고를 받을 **채널** 하나 만들기(예: `운영보고`).
2. 그 채널 오른쪽의 **톱니(채널 편집)** → **연동** → **웹후크** → **새 웹후크**.
3. 이름을 알아보게 바꾸고(예: `우리회사 보고`), **웹후크 URL 복사**.
4. 직원용 방을 만들기로 했으면 **채널을 하나 더** 만들어 같은 순서로 하나 더 받는다.

이 주소가 곧 열쇠다. **주소를 아는 사람은 누구나 그 채널에 글을 쓸 수 있다**(읽지는 못한다). 화면 공유·캡처·문서에 붙이지 않는다.

### 4. 텔레그램 봇 만들기 — 대표가 직접 누른다

`references/telegram.md` 를 열어 순서대로. 뼈대:

1. 텔레그램에서 `@BotFather` 를 찾아 대화 시작 → `/newbot`.
2. 봇 이름(사람이 보는 이름) → 봇 아이디(`_bot` 으로 끝나야 한다) 입력.
3. **봇 열쇠(토큰)** 를 받는다. 이 한 줄이 전부다 — 새지 않게 둔다.
4. 방금 만든 봇과의 대화방을 열고 **`/start` 를 보낸다.** 이걸 안 하면 봇이 먼저 말을 걸 수 없어 보고가 오지 않는다.
5. 받을 방 번호(`chat_id`)를 확인한다. `references/telegram.md` 의 방법 그대로 한다.

직원도 함께 받기로 했으면 텔레그램 **그룹**을 만들어 봇을 초대하고, 그 그룹의 방 번호를 하나 더 받는다(그룹 번호는 음수로 나온다 — 정상이다).

### 5. 비밀값을 두는 곳은 두 군데뿐이다

| 어디 | 무엇을 | 왜 |
|---|---|---|
| `.env.local` | 내 컴퓨터에서 테스트 발송할 때 쓰는 값 | 커밋되지 않는다 |
| Supabase 의 설정 표 `app_secret` | 서버가 정해진 시각에 보낼 때 쓰는 값 | 내 컴퓨터가 꺼져 있어도 서버가 읽어야 한다 |

`.env.local` 에 넣을 이름은 아래로 고정한다.

```
DIGEST_DISCORD_URL=<복사한 웹후크 주소>
DIGEST_TELEGRAM_TOKEN=<봇 열쇠>
DIGEST_TELEGRAM_CHAT_ID=<방 번호>
```

- **`VITE_` 를 붙이지 않는다.** `VITE_` 로 시작하는 값은 앱을 쓰는 사람 화면까지 따라 내려간다. 이 셋은 앱 화면이 아니라 테스트 스크립트와 서버만 쓴다.
- 서버 쪽 저장은 `indeans-erp-digest` 의 `references/cron-sql.md` 2절 순서를 따른다. 이번 회차에 같이 넣어 두면 다음 스킬이 바로 쓴다.
- **소스 파일·마이그레이션 파일·회사 문서에는 값을 적지 않는다.** 문서에는 "이름"만 적는다(`DIGEST_DISCORD_URL`).
- 값이 새면(캡처·화면 공유·실수 커밋) 디스코드는 웹후크를 지우고 새로 만들고, 텔레그램은 `@BotFather` 에서 `/revoke` 로 열쇠를 새로 받는다. 지우면 옛 주소는 바로 죽는다.

### 6. 테스트 발송 — 도착을 눈으로 본다

`assets/channel-test.template.mjs` 를 `scripts/channel-test.mjs` 로 복사하고 실행한다. 다른 준비물은 없다(Node 18 이상).

```bash
node scripts/channel-test.mjs
```

- 두 창구에 각각 한 줄을 보내고, 어디에 성공·실패했는지 화면에 찍는다. **비밀값은 찍지 않는다.**
- 실패하면 `references/discord.md`·`references/telegram.md` 의 "안 올 때" 절을 순서대로 본다.
- 대표가 **폰에서 실제로 도착한 것을 보고 "왔다"고 말할 때까지** 이 단계를 끝내지 않는다. 명령이 오류 없이 끝난 것은 도착의 증거가 못 된다.
- **도착을 본 뒤, 일부러 주소 한 글자를 바꿔 한 번 더 보내 실패가 어떻게 보이는지 미리 본다.** `.env.local` 의 주소 끝 한 글자를 바꾸고 같은 명령을 다시 돌린다. 화면에 어떤 글자가 뜨는지(어느 창구가 실패했는지·응답 번호) 대표가 직접 보게 하고, **확인한 뒤 주소를 원래대로 되돌린다.** 되돌린 다음 한 번 더 보내 도착까지 확인하고 끝낸다.
  - 실패 모양을 성공한 날에 미리 봐 두는 것이 목적이다. 3회차 뒤 보고가 안 오는 날, 이 화면을 본 적이 있으면 어디부터 볼지 안다.
  - 되돌리는 것을 절차에서 빼지 않는다 — 바꾼 주소를 그대로 두면 이후 보고가 전부 조용히 실패한다.

보내는 글자에는 규칙이 있다.

- 디스코드는 한 번에 2,000자, 텔레그램은 4,096자까지다. 넘으면 잘리거나 거부된다 — 보고는 **10줄 이내**로 잡는다.
- 짧은 시간에 여러 번 보내면 잠시 막힌다. 테스트는 한 번씩만.
- **고객 실명·연락처·금액·계좌는 보내지 않는다.** 채널은 회사 밖 서비스다. 건수와 관리 단위 이름까지만 보낸다.

### 7. 문서로 남긴다

`assets/channel.template.md` 를 그대로 채워 `company/channel.md` 로 저장한다. 절 제목과 순서를 바꾸지 않는다 — `indeans-erp-digest` 가 이 문서를 읽는다.

들어가는 것: 창구 목록(디스코드·텔레그램) · 받는 사람 · 비밀값 **이름**과 둔 곳 · 테스트 발송 날짜와 결과 · 글자 수 상한 · 보내지 않는 것 · 주소가 새면 무엇을 하나.

### 8. 상태 문서 갱신과 커밋

`.owner/state.md` 를 고친다.

- **현재 기능** — "디스코드·텔레그램 창구 있음(테스트 도착 확인)".
- **미해결 문제** — 남은 것(예: "직원용 방은 아직 없음").
- **다음 행동** — "운영 보고 만들기(`indeans-erp-digest`)".

`.owner/progress.json` 의 `channel.discord`·`channel.telegram` 을 `true` 로, `updated_at` 을 지금 시각으로 적는다.

```bash
git add -A
git commit -m "알림 채널: 디스코드·텔레그램 연결과 테스트 발송"
```

화면·저장 구조·권한을 바꾸지 않았으면 검수는 생략한다. 검수 훅이 요구하면 `indeans-erp-check` 를 부른다.

## 하지 않는 것

- 웹훅 주소·봇 열쇠·방 번호를 소스·문서·커밋·화면에 적지 않는다. 대표가 화면을 공유 중이면 값을 띄우지 않는다.
- `VITE_` 로 시작하는 이름에 이 값들을 넣지 않는다.
- 대표를 대신해 디스코드·텔레그램 계정을 만들지 않는다. 계정과 방은 회사 것이어야 한다.
- 무엇을 언제 보낼지 여기서 정하지 않는다(`indeans-erp-digest`).
- 고객 실명·연락처·금액·계좌를 보내는 문장을 만들지 않는다.
- 도착을 확인하지 않고 "연결했습니다"라고 보고하지 않는다.
- 슬랙·카카오·문자 연동을 이번 회차에 벌이지 않는다. 슬랙은 `references/slack.md` 의 선택 안내까지다.

## 앞선 수강생 분기

창구 둘이 이미 살아 있으면 하나만 고른다.

1. **직원용 방 분리** — 대표용과 직원용 방을 나누고, 직원 방에 **보내지 않을 항목**을 `company/channel.md` 에 목록으로 적는다. 목록이 없으면 언젠가 섞여 나간다.
2. **한쪽이 죽었을 때** — 보고가 실패하면 다른 창구로 한 번 더 보내는 규칙을 정한다. 규칙만 문서에 적고, 실제 구현은 `indeans-erp-digest` 의 실패 기록과 함께 붙인다.
3. **소음 줄이기** — 오는 것이 많아 안 보게 됐으면 창구를 늘리지 말고 **보내는 항목을 줄인다.** "매일 오는데 아무 행동도 안 하게 되는 줄"을 찾아 뺀다.

## 자주 막히는 지점

- **디스코드에 아무것도 안 온다** — 주소를 끝까지 복사했는지, 채널이나 웹후크를 지우지 않았는지 본다. 웹후크를 지우면 옛 주소는 즉시 죽는다.
- **텔레그램에 안 온다** — 대개 봇에게 `/start` 를 안 보낸 것이다. 봇은 먼저 말을 걸 수 없다.
- **방 번호를 못 찾는다** — 봇에게 아무 말이나 한 줄 보낸 뒤 다시 확인한다. 대화가 없으면 번호가 나오지 않는다.
- **그룹에 초대했는데 안 온다** — 그룹 번호는 음수다(`-100...`). 개인 방 번호를 그대로 쓰고 있지 않은지 본다.
- **한글이 깨져 온다** — 보내는 쪽에서 글자 형식을 지정하지 않은 것이다. 테스트 스크립트를 그대로 쓰면 생기지 않는다.
- **오류 없이 끝나는데 안 온다** — 보내기만 하고 결과를 안 읽는 방식이면 이렇게 된다. 테스트 스크립트는 응답 번호를 찍는다. 200대가 아니면 도착하지 않은 것이다.
