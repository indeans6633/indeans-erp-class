# 두 번째 AI 교차 검수 — 프롬프트 틀

`indeans-erp-crosscheck` 절차 2에서 쓴다. 이 틀은 두 부분이다.

- **「보낼 글」** — `.owner/tmp/crosscheck-<날짜>.txt` 로 옮겨 `{ }` 칸만 채운다. **「코드 —」 줄까지만 옮긴다.** 그 아래 네 줄은 모양을 보여 주는 자리이고, `references/commands.md` 1절 명령이 실제 파일을 같은 모양으로 이어 붙인다(파일마다 `===== FILE: 경로 =====` 와 줄 번호, 끝에 `===== END =====` 와 "한국어로 답한다."). 코드를 손으로 옮기지 않는다 — 옮기다 줄이거나 빠뜨린다.
- **「보내기 전 점검표」** — 보내는 파일에 넣지 않는다. 확인한 결과를 `reports/<날짜>-교차검수.md` 머리에 한 줄로 남긴다.

넣지 않는 것: 우리 AI 의 결론·가설("여기가 의심된다"·"잘 고쳤다")·감독 판정·대화 내용·어떻게 고쳤는지. 넣으면 검수자가 따라 말한다.

---

## 보낼 글

당신은 이 코드를 처음 보는 독립 검수자다. 만든 쪽의 설명과 결론은 일부러 주지 않았다. 아래 문제 서술과 코드만 보고 판단한다.

규칙
1. 결함만 적는다. 칭찬·총평·취향·더 나은 설계 제안은 쓰지 않는다.
2. 발견 하나마다 아래 형식을 지키고, 치명 → 중요 → 경미 순서로 쓴다.
3. 확실하지 않으면 심각도 앞에 '추정'을 붙이고(예: [추정·중요]), 무엇을 보면 확정되는지 '확인' 줄에 적는다.
4. 발견이 없으면 "발견 없음" 한 줄과, 무엇을 봤는지 한 줄만 쓴다.
5. 파일을 고치거나 명령을 실행하지 않는다. 붙여 넣은 코드 밖의 일은 짐작으로 단정하지 말고 '추정'으로 적는다.
6. 한국어로 답한다.

형식
[치명|중요|경미] 파일:줄 — 한 줄 제목
- 재현: 누가 무엇을 어떤 순서로 하면 드러나는지 (원인을 찾는 일이면 원인을 확인하는 방법)
- 수정: 고칠 방향 한 줄
- 확인: ('추정'일 때만) 무엇을 보면 확정되는지

심각도
- 치명: 보면 안 되는 사람이 보거나 바꿀 수 있다 · 돈이 틀리게 저장된다 · 데이터가 지워지거나 되돌릴 수 없다
- 중요: 어떤 조건에서 틀린 결과·두 번 처리·조회 실패가 난다
- 경미: 지금 해는 없지만 곧 실수를 부른다

문제 서술
{이 코드가 할 일을 업무 말로 2~3줄. 예: "직원이 예약을 취소하면 받은 예약금을 돌려준 기록을 남기고 예약을 취소 상태로 바꾼다. 금액은 대표만 본다."}
{원인이 안 잡히는 버그면 덧붙인다: 무엇을 하면 / 무엇이 나와야 하는데 / 실제로 무엇이 나온다 / 오류 원문. 이 줄이 필요 없으면 지운다}

지켜야 하는 규칙 (회사 문서에서 옮김)
{company/*.md 에서 이 코드에 걸리는 줄만 원문 그대로 1~5줄. 없으면 "없음"}

검수 관점 — 다섯 가지를 차례로 본다 (해당 없으면 건너뛴다)
1. 권한 누수 — 역할(대표·직원·고객)이 다르거나 비었을 때 보거나 바꿀 수 있는 것이 생기는가. 화면에서 숨겼을 뿐 데이터는 열려 있지 않은가
2. 돈 제약 — 금액이 0·음수·소수·아주 큰 값일 때, 합계가 넘칠 때 데이터베이스가 막는가. 계산을 화면에서만 하지 않는가
3. 두 번 실행 — 버튼을 두 번 누르거나 요청이 다시 가거나 예약 작업이 두 번 돌면 줄이 두 개 생기거나 두 번 빠지지 않는가
4. 삭제 조건 — 조건이 비었을 때 전부 지워지지 않는가. 지운 뒤 되돌릴 길이 있는가. 딸린 기록이 주인 없이 남지 않는가
5. 화면 동작 — 빈 목록·실패·느린 응답·휴대폰 폭에서 멈추거나 틀린 값을 보여 주지 않는가

코드 — 바뀐 파일 전문, 줄 번호 붙음
===== FILE: {경로} =====
   1| {코드 한 줄}
===== END =====
한국어로 답한다.

## 보내기 전 점검표 (보내는 파일에 넣지 않는다)

`references/commands.md` 2절 점검 명령을 먼저 돌리고, 명령이 못 찾는 것(이름·실제 금액)은 눈으로 본다. **하나라도 "있음"이면 보내지 않는다.** 지우거나 가짜 값(홍길동 · ○○상사 · 010-0000-0000 · 10,000원)으로 바꾸고 다시 점검한다. 검수자는 외부 서비스다 — 보낸 글은 그 회사의 서버로 간다.

| # | 항목 | 어디를 보나 | 결과 |
|---|---|---|---|
| 1 | 고객·직원 실명 | 예시 데이터·시드·시험 파일·주석 — 가짜 이름만 있어야 한다 | 없음 / 있음 |
| 2 | 전화·이메일·주소 | 점검 명령 + 예시 데이터 | 없음 / 있음 |
| 3 | 실제 금액·계좌 | 예시 데이터의 금액이 실제 거래 값인지 | 없음 / 있음 |
| 4 | 토큰·키·웹훅 주소·비밀번호 | 점검 명령(키 모양·웹훅 주소·비밀값 이름) | 없음 / 있음 |
| 5 | `.env`·`.env.local` 내용, `.owner/`·`reports/`·`company/` 파일 | 「코드」의 FILE 줄 — 이 경로가 하나도 없어야 한다 | 없음 / 있음 |
| 6 | 우리 쪽 결론 | 문제 서술에 "의심된다"·"고쳤다"·"괜찮다"·감독 판정이 없는지 | 없음 / 있음 |
