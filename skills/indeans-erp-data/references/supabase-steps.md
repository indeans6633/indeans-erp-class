# Supabase 화면 단계별 안내

대표가 직접 누르는 단계만 모았다. 화면의 메뉴 이름은 바뀔 수 있다 — 안 보이면 **"지금 화면에 이런 메뉴들이 보인다"** 고 AI에게 말하면 맞춰 준다.
(2026년 9월 기준 화면. 영문 메뉴 이름은 그대로 두고 괄호로 뜻을 적었다.)

---

## 1. 가입과 프로젝트 만들기

1회차에 가입하고 조직까지 만들었으면(`.owner/accounts.md` 의 Supabase 줄) 1·2번은 건너뛰고 로그인만 한다. 무료 프로젝트는 **동시에 두 개까지**이고 **일주일 넘게 안 쓰면 잠시 멈춘다**(대시보드에서 Restore 로 다시 켠다 — 데이터는 그대로다). 연습용으로 여러 개 만들지 않는다.

1. `supabase.com` → **Start your project** / **Sign in**. GitHub 계정으로 로그인하면 계정이 하나로 줄어 편하다.
2. 조직(Organization)이 없으면 하나 만든다. 이름은 회사 이름, 요금제는 **Free**.
3. **New project**(새 프로젝트) 를 누른다.
4. 입력하는 것 세 가지
   - **Name**: 프로젝트 이름. 회사 영문 약자 + 용도(예: `hansung-erp`).
   - **Database Password**: 데이터베이스 비밀번호. **이 화면에서만 보인다.** 비밀번호 관리 앱에 저장하거나 종이에 적어 금고에 둔다. 앱을 쓸 때 이 비밀번호를 넣을 일은 없다 — 데이터를 통째로 다룰 때만 쓴다.
   - **Region**: 지역. 회사와 가까운 곳(한국이면 서울 계열)을 고른다. 멀면 화면이 느려진다.
5. **Create new project** → 1~3분 기다린다. 왼쪽 메뉴가 활성화되면 준비 완료.

## 2. 접속 정보 복사하기

1. 왼쪽 아래 **Settings**(톱니) → **API Keys**.
2. **Project URL** 복사 → `.env.local`의 `VITE_SUPABASE_URL`.
3. 공개용 키 복사 → `.env.local`의 `VITE_SUPABASE_ANON_KEY`.
   - 화면에 `anon` 또는 `publishable`(sb_publishable_... 로 시작) 로 표시된다. **보이는 것을 쓴다.** 두 이름이 같이 쓰이는 중이고, 예전 이름(`anon`)은 2026년 말까지 유지된다고 공지돼 있다.
4. `service_role` / `secret` 키는 **복사하지 않는다.** 이 키는 모든 잠금을 지나간다. 수업에서 쓸 일이 없다.

> 키를 남에게 보여 줬거나 실수로 올렸다면 같은 화면에서 새로 발급(회전)할 수 있다. 발급 후 `.env.local`과 배포 화면의 값을 같이 바꾼다.

## 3. 표 만들기 (SQL Editor)

1. 왼쪽 **SQL Editor** → **New query**.
2. `supabase/migrations/0001_init.sql` 내용을 전부 붙여 넣는다.
3. 오른쪽 아래 **Run**. 초록색 성공 메시지가 나오면 된 것이다.
4. 빨간 오류가 나오면 **메시지를 그대로 복사해** AI에게 준다. 요약하지 않는다 — 오류 문장 안에 어느 줄인지가 들어 있다.
5. 왼쪽 **Table Editor** 에서 만든 표가 보이는지 확인한다.

> SQL Editor는 **관리자 권한**으로 돈다. 여기서 데이터가 보이는 것은 "누구나 볼 수 있다"는 뜻이 아니다. 잠금 확인은 반드시 앱에서 한다.

알아 둘 것 두 가지:

- **결과 칸에는 마지막 한 문장의 결과만 나온다.** 여러 개의 확인 질의를 한꺼번에 붙이면 앞의 결과는 안 보인다. 확인 질의는 한 덩어리(한 결과 표)로 만든 것을 쓴다. 정책을 실제로 바꾸기 전에 시험해 보는 방법(롤백 시뮬)은 `indeans-erp-check` 스킬의 `references/rollback-sim.md` 에 있다 — 일부러 오류를 내서 결과를 보여 주고 바꾼 것을 전부 취소하는 방식이라, 빨간 글씨가 나오는 것이 정상이다.
- 새 표·칸·함수를 만든 뒤 앱에서 **"Could not find … in the schema cache"** 가 나오면 `notify pgrst, 'reload schema';` 한 줄을 실행한다. 마이그레이션 파일 끝에 이 줄을 넣어 두면 생기지 않는다.

## 4. 로그인 계정 만들기 (Authentication)

1. 왼쪽 **Authentication** → **Users** → **Add user** → **Create new user**.
2. 이메일과 비밀번호를 넣는다. **Auto Confirm User**(확인 메일 없이 바로 사용) 를 켠다.
3. 만들어진 사용자의 **User UID**(긴 문자열)를 복사한다.
4. SQL Editor에서 그 사람을 우리 회사 사람으로 등록한다. 명령은 `0001_init.sql` 아래쪽 주석에 그대로 들어 있다.

## 5. 잠금 확인 — 두 번째 계정으로

1. 4번과 같은 방법으로 **두 번째 계정**을 만든다. 단, `app_users` 표에는 **넣지 않는다.**
2. 앱에서 그 계정으로 로그인한다.
3. 목록이 **비어 있어야** 정상이다. 한 줄이라도 보이면 잠금이 안 걸린 것이니 AI에게 "두 번째 계정에서 데이터가 보인다"고 그대로 말한다.
4. 확인이 끝나면 **Authentication > Users** 에서 그 계정을 지운다.

## 6. 데이터 내려받기 (CSV)

- **표 단위**: Table Editor → 표 선택 → 내보낼 행을 고르면 오른쪽에 점 세 개 메뉴가 뜬다 → **Export to CSV**.
- **조회 결과 단위**: SQL Editor에서 원하는 조회를 실행한 뒤 결과 위쪽의 내려받기 버튼으로 CSV 저장.
- 내려받은 파일은 엑셀에서 바로 열린다. 한글이 깨지면 엑셀에서 "데이터 → 텍스트/CSV 가져오기"로 UTF-8을 골라 연다.

## 7. 자동 백업 확인 (Database > Backups)

1. 왼쪽 **Database** → **Backups**.
2. **무료 요금제에는 자동 백업이 없다.** 목록이 비어 있거나 유료 안내가 보이면 그 상태다.
3. 유료 요금제면 최근 며칠치 일일 백업이 보인다. 며칠치인지 `company/data.md`에 적는다.
4. 어느 쪽이든 앱 안 CSV 버튼과 6번 내려받기는 계속 쓴다. 자동 백업은 사고용이고, CSV는 대표가 언제든 확인할 수 있는 사본이다.

---

## 요금제에 대해 미리 알아 둘 것

- 무료 요금제는 수업과 초기 실사용에 충분하다. 다만 **자동 백업이 없고**, 일정 기간 아무도 접속하지 않으면 프로젝트가 일시 정지될 수 있다(대시보드에서 다시 켠다).
- 직원이 실제로 쓰기 시작하고 데이터가 회사 자산이 되는 시점이 유료 전환 시점이다. 기능이 모자라서가 아니라 **백업 때문에** 올린다.
- 비용은 바뀌므로 수업에서 금액을 말하지 않는다. 대시보드의 요금 안내를 그때 확인한다.

## 안 될 때 AI에게 주는 말

```
Supabase에서 <무엇을> 하려는데 <어느 화면>에서 막혔다.
화면에 보이는 문구는 이렇다: "<그대로 복사>"
지금 보이는 메뉴는 <목록>이다. 다음에 무엇을 누르면 되나?
```

오류 문장을 그대로 붙여 넣는 것이 가장 빠르다. "안 된다"만 말하면 AI가 되묻는 데 시간이 간다.
