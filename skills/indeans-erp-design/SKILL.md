# 인디언즈 디자인 고르기 — 2단계 선택창 (1일 차 · 11-17 개정)

> **11-17 리허설 반영 개정판.** 공개 번들 v3.2 의 옛 선택창(구조 3 × 스타일 7 × 색 10, 코드 `<구조>-<스타일>-<색>-<밝기>`)을 2단계 선택창으로 바꿨다. 옛 원본: `proposed-skills/_원본/indeans-erp-design/`. 옛 코드도 그대로 읽힌다(이미 고른 수강생).

3차 인터뷰가 끝나면 대표가 **테마 하나 → 세부 설정**을 화면을 보며 고른다. 말로 묻지 않고 선택창을 연다. 대표가 하는 결정은 두 번이다 — **① 테마 ② 세부(밝기·메뉴 위치·본문 모양, 우리 회사 색이면 그 색)**. 대표에게도 이 말 그대로 쓴다.

| 고르는 것 | 값(id) |
|---|---|
| ① 테마 | `shop` 따뜻한 매장 · `large` 큰 글씨 · `list` 촘촘한 목록 · `brand` 우리 회사 색 |
| ② 밝기 | `light` 밝게 · `dark` 어둡게 (테마마다 기본값 — 우리 회사 색은 어둡게) |
| ② 메뉴 위치 | `side` 왼쪽 · `top` 위쪽 · `bottom` 아래 탭(휴대폰에서 화면 아래) |
| ② 본문 모양 | `cards` 카드 · `table` 목록 · `board` 보드(단계 칸) |
| ② 회사 색 | 우리 회사 색 테마만 — 색 코드 `#RRGGBB` |

테마마다 기본 배치가 있다: 따뜻한 매장 위쪽+카드 · 큰 글씨 아래+카드 · 촘촘한 목록 왼쪽+목록 · 우리 회사 색 위쪽+보드.

**조합 코드**: `theme-<테마>-<RRGGBB>-<밝기>-<메뉴>-<본문>` 예) `theme-large-CA8A04-light-bottom-cards` · `theme-list-0F766E-light-side-table`.
코드는 `src/styles/tokens.css` 첫 줄 주석과 `.owner/design/choice.json` 에 들어간다. 본문 모양이 화면 뼈대(구조)를 정한다 — cards → `card` · table → `list` · board → `board`. 메뉴 위치는 `src/styles/layout.css` 끝의 메뉴 위치 절이 맡는다.

**업종 → 추천 테마**(인터뷰 업종 가지, 선택창과 같다): B1 집 공사·수리·설치 → 큰 글씨 · B2 가게·쇼핑몰 → 따뜻한 매장 · B3 식당·카페·음식 → 따뜻한 매장 · B4 예약·방문 서비스 → 큰 글씨 · B5 공장·제작·도매·유통 → 촘촘한 목록 · B6 학원·교습·강의 → 따뜻한 매장 · B7 사무 서비스 → 촘촘한 목록 · B8 그 밖 → 우리 회사 색.

**색은 엔진이 계산한다** — 고른 색 하나에서 바탕·글자·선을 만들고 글자가 4.5:1, 입력 칸 테두리가 3:1 로 읽히게 명도만 옮긴다(선택창의 "색을 조금 옮겼어요"). 대비를 못 맞추면 저장이 막힌다.

## 언제 쓰나

- **3차 인터뷰가 끝난 직후**(인터뷰가 「테마 고르기로 넘어갑니다」로 끝남) 또는 카드 D1 「디자인 테마 골라 줘.」.
- 카드 D2 「골랐어요.」·「디자인은 theme-… 로 할게요.」 — 결과 받기(절차 4).
- **1차·2차 인터뷰 끝에는 쓰지 않는다.** 1차 끝은 2차로, 2차 끝은 3차로 간다. 3차 전에 대표가 "디자인부터 보고 싶다"고 하면 추천 없이 열 수는 있다.
- 써 보고 "글자가 작다·색이 안 맞다·메뉴가 불편하다"가 나왔을 때(손보기 또는 다시 고르기).

## 시작 전 상태 진단

같은 대화에서 이어 불렸어도 **아래 파일을 지금 다시 읽는다.**

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/progress.json` | `interview.round`(3이면 인터뷰 끝) · `company.industry` 의 `가지 {번호}` · `design.code` |
| `company/profile.md` | 「대표와 회사」의 업종 분류 줄 `가지 {번호} {이름}` · `## 디자인 힌트` 의 간판·로고 색 |
| `.owner/design/choice.json` | 선택창이 마지막으로 저장한 조합·시각 |
| `src/styles/tokens.css` | 첫 줄 주석의 조합 코드 |
| `.owner/hooks/design-pick.mjs` · `.owner/design/index.html` | 선택창이 설치돼 있는지 |

| 상태 | 판정 기준 | 분기 |
|---|---|---|
| A. 처음 | `design.code` 없음 · `tokens.css` 없음 | **확인 질문 없이** 절차 1→2→3 으로 바로 연다 |
| B. 같은 조합 손보기 | 조합이 있고 "조금만 고치자" | 선택창을 열지 않는다. `tokens.css` 값만 손보고 `company/design.md` "값을 바꾼 곳"에 적는다 |
| C. 다시 고르기 | 조합이 있는데 다시 고르려 함 | 먼저 한 번 확인: "지금 {테마 이름}입니다. 다시 고르면 화면 인상이 전부 달라집니다. 선택창을 열까요?" |
| D. 결과 받기 | 대표가 "골랐어요"·코드 문장을 말함 | 절차 4 부터 |
| E. 선택창 없음 | `design-pick.mjs` 또는 `index.html` 없음 | 설치기를 다시 돌리게 안내한다. 말로 고르게 하지 않는다 |
| F. 인터뷰 전·업종 없음 | `가지 {번호}` 를 못 찾음 | 추천 없이 연다(`--branch` 빼기) |

판정을 한 문장으로 먼저 알린다. 예: "인터뷰가 끝났고 디자인은 아직입니다. 선택창을 바로 열겠습니다."

## 절차

### 1. 되돌릴 지점 (묻지 않고)

`git add -A` → `git commit -m "디자인 고르기 전"`. 커밋할 게 없으면 넘어간다.

### 2. 추천 (속으로 — 대표에게 묻지 않는다)

`company/profile.md`(없으면 `progress.json` 의 `company.industry`)에서 `가지 {번호}` 를 읽어 **B{번호}** 로 연다. 추천은 테마 하나뿐이다 — 색·밝기·배치는 테마 기본값으로 시작하고 대표가 세부 설정에서 바꾼다. **옛 추천(`list-bold`·`card-bold-custom-…` 같은 구조-스타일 코드)을 쓰지 않는다** — 2단계 선택창은 그 코드를 모른다.

### 3. 선택창 열기 — 확인 질문 없이 바로

아래 안내를 **한 번만** 하고, 같은 차례에 바로 명령을 실행한다(대표가 명령을 치지 않는다).

> 선택창을 엽니다. 인터뷰에서 고르신 업종에 맞춰 「{추천 테마 이름}」을 먼저 골라 두었어요 — 다른 테마를 고르셔도 됩니다.
> ① 테마 하나를 고르고 「이 테마로 세부 설정」 → ② 밝기·메뉴 위치·본문 모양을 보고 맨 아래 「이걸로 하기」를 누르세요. 누르면 저장되고 창을 닫으셔도 됩니다.

```
node .owner/hooks/design-pick.mjs --branch B{번호}
```

- **대표에게 하는 말은 명령이 찍는 「대표님께 그대로 전할 말」 블록을 줄이지 않고 옮긴다**(11-17 r2 반영). 추천 테마 이름 한 줄 + ① 줄 + ② 줄은 하나도 빠지면 안 된다 — **주소만 알리고 끝내지 않는다.** 명령을 백그라운드로 돌렸으면 그 출력에서 블록을 읽어 같은 차례에 전한다.
- 업종 번호가 없으면(분기 F) `--branch` 없이 실행하고 첫 줄을 "네 가지 테마 중 하나를 골라 주세요"로 바꾼다.
- 브라우저가 저절로 열린다. 안 열리면 터미널에 크게 찍힌 주소(`http://127.0.0.1:포트/?branch=B…`)를 대표에게 그대로 보여 준다. 그래도 안 되면 `.owner/design/index.html?branch=B…` 를 파일로 열게 한다(저장 기능이 없는 판 — 고른 뒤 나오는 문장을 대표가 말한다).
- 명령은 대표가 「이걸로 하기」를 누를 때까지 끝나지 않는다(30분 동안 반응이 없으면 스스로 닫힌다). **명령에 제한 시간을 줄 수 있으면 허용되는 가장 긴 값으로, 또는 백그라운드로 실행한다.** 기다리는 동안 더 권하지 않는다.

### 4. 결과 받기

- 명령이 `골랐습니다: …` 와 만든 파일을 찍고 끝났으면 → `.owner/design/choice.json` 을 읽는다(`theme`·`seed`·`scheme`·`nav`·`body`·`code`).
- 명령이 먼저 끊겼고 대표가 "골랐어요"라고 하면 → `choice.json` 의 `chosen_at` 이 방금인지 본다. 방금이 아니면 저장되지 않은 것이다 — 화면 아래에 나온 문장을 알려 달라고 한다.
- 대표가 문장이나 코드를 말해 주면 **그 문장 통째로** 넣는다(코드만 골라 읽는다):

```
node .owner/hooks/design-pick.mjs --code "디자인은 theme-large-CA8A04-light-bottom-cards 로 할게요."
```

- 코드를 못 읽는다고 나오면 형식 안내가 같이 찍힌다 — 옮겨 적다 틀린 글자(여섯 자리 색, 하이픈, side·top·bottom, cards·table·board)만 다시 묻는다. **토큰 파일을 손으로 지어 쓰지 않는다**(밝게·어둡게·글꼴·대비·메뉴 위치를 생성기가 맞춘다). **선택창을 같은 대화에서 두 번 넘게 다시 열지 않는다.**
- 조합이 정해지면 소리 내어 확인한다: **"{테마} · 색 {#RRGGBB} · {밝게/어둡게} · 메뉴 {왼쪽/위쪽/아래 탭} · 본문 {카드/목록/보드}({코드})로 하겠습니다."** 엔진이 색을 옮겼으면 한 줄 전한다.

#### 「잘 모르겠어요 / 알아서 해 주세요」라고 하면 (11-17 리허설 반영)

- 설득하지 않고, 선택창을 다시 열지 않고, **AI 가 다른 테마·색을 골라 지어내지도 않는다.** 추천 테마의 기본값으로 정한다: 업종 번호가 있으면 `--code theme-{추천 테마}`(색·밝기·메뉴·본문이 그 테마 기본값으로 채워진다), 없으면 `--code theme-shop`.
- 한 줄로 알린다: "그럼 추천한 「{테마 이름}」 기본 그대로 해 둘게요. 나중에 「디자인 다시 고르기」로 바꿀 수 있어요."
- 그다음은 절차 5~7 만 하고 **멈춘다** — 계획·초안으로 넘어가지 않는다.

### 5. company/design.md 쓰기

`assets/design.template.md` 를 채워 `company/design.md` 로 쓴다. 고른 이유는 대표가 한 말 그대로(「알아서」면 "추천 테마 기본값 — 대표가 맡김"). 추천 테마와 근거(업종 가지) 한 줄. "바꾸면 안 되는 것"에 공통 줄과 메뉴 위치·본문 모양을 적는다.

### 6. 앱이 있으면 불러오기 · 화면 값 토큰으로 (없으면 건너뛴다)

`src/main.tsx` 맨 위에 `import './styles/tokens.css'` · `import './styles/base.css'` · `import './styles/layout.css'`. 앱이 아직 없으면(보통 1일 차) `design.md` "적용 범위"에 "초안 만들 때 불러오기 추가"라고 적는다 — `indeans-erp-draft` 가 `src/styles/` 를 그대로 쓴다. 앱이 있으면 화면 값을 `var(--…)` 로 한 화면씩 바꾼다(v3.2 절차 7 그대로 — `references/structures.md`·`families.md`).

### 7. 상태 문서 갱신하고 커밋 — 그리고 멈춘다

- `.owner/state.md` "선택한 디자인" 절: 테마 · 색 · 밝기 · 메뉴 위치 · 본문 모양 · 조합 코드 · `src/styles/tokens.css`. "다음 행동"은 앱이 없으면 **"새 대화에서 초안 계획 — 모드 Plan, 「초안 계획 세워 줘.」(`indeans-erp-draft`)"**, 앱이 있으면 `indeans-erp-check`.
- `.owner/progress.json` → `design`: `structure`(본문 모양에서 온 구조) · `family`(`theme-{테마}`) · `palette`(`custom`) · `scheme` · `code` · `tokens`(`src/styles/tokens.css`) · `updated_at`. 템플릿에 없는 키를 새로 만들지 않는다(메뉴·본문은 코드와 `choice.json` 에 있다).
- `git add -A` → `git commit -m "디자인 {코드} 적용"`.
- **검수 관문(Stop 훅 `erp-check`)** — 앱이 아직 없을 때 디자인 설정 파일(`src/styles/`)만 바뀐 것은 관문이 스스로 넘긴다(11-17 r2 반영). 그래도 관문이 검수를 요구하면(앱이 이미 있는 경우) `indeans-erp-check` 로 처리하되, 검수 기록 파일(`.owner/last-check.json`)을 갱신한 뒤 **바로 커밋**해 작업 폴더에 남기지 않고, 대표에게는 검수 이야기를 길게 하지 않는다 — **마지막 말은 언제나 아래 「디자인은 여기까지예요 …」 한 줄**이다.
- 대표에게 마지막 한 줄: **"디자인은 여기까지예요. 새 대화를 열고 모드를 Plan 으로 바꾼 뒤 「초안 계획 세워 줘.」라고 말씀해 주세요."** — **같은 대화에서 계획·초안을 이어 만들지 않는다**(Plan 모드에서 파일을 안 바꾸고 계획만 보는 순서를 지킨다).

## 하지 않는 것

- 1차·2차 인터뷰 끝에 선택창 열기. 처음 고를 때 "선택창을 열까요?" 묻기(조합을 바꿀 때만 확인 — 분기 C).
- 옛 추천 코드(`--recommend list-bold` 등)로 열기. 말로만 고르게 하기. 두 번 이상 권하기.
- 대표 대신 다른 테마·색을 골라 지어내기(「알아서」면 추천 테마 기본값만). 선택창을 같은 대화에서 두 번 넘게 다시 열기.
- 토큰 파일을 손으로 지어 쓰기 — `design-pick.mjs`(선택창 저장 또는 `--code`)가 규칙(`.owner/design/app/design-rules.js`·`color-engine.js`)대로 만든 것을 쓴다.
- 디자인을 고른 같은 대화에서 초안 계획·초안 만들기. 화면 코드는 `indeans-erp-draft` 의 일이다.
- 인터넷 글꼴 주소(CDN)·그라데이션·장식 이모지·왼쪽 색 막대. 강조색 둘 이상.

## 자주 막히는 지점

- **브라우저가 안 열린다** — 터미널의 주소를 붙여 넣게 한다. 그래도 안 되면 `.owner/design/index.html` 을 직접 열게 하고, 나온 문장으로 `--code`.
- **명령이 안 끝난다** — 정상이다. 대표가 아직 「이걸로 하기」를 누르지 않았다.
- **「저장하지 못했습니다」·「연결이 끊겼습니다」** — 명령이 제한 시간에 걸려 닫힌 것이다. 화면 아래 문장을 그대로 받아 `--code`.
- **"코드를 못 읽는다"** — 옛 v3.2 규칙 파일이 남은 것이다(`규칙 파일이 옛 판입니다`). 설치기를 다시 돌린다.
- **아래 탭인데 PC 에서 위에 있다** — 정상이다. 아래 탭은 휴대폰 폭(680px 이하)에서만 화면 아래로 간다.
- **"다 마음에 안 든다"** — 어느 쪽이 걸리는지 하나만 묻는다(글자 크기·빽빽함 → 테마, 색 → 우리 회사 색, 메뉴 → 메뉴 위치). 선택창을 한 번만 다시 연다.
