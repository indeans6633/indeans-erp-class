# 인디언즈 디자인 고르기 (선택창)

1차 인터뷰가 끝나면 이 스킬로 바로 넘어온다(인터뷰 전에 대표가 직접 불러도 된다). 말로 묻지 않고 **선택창을 열어** 대표가 화면을 보며 고르게 한다. 선택창은 같은 예시 데이터로 화면 3개(목록 · 상세·입력 · 오늘 현황)를 고른 조합대로 바로 다시 그려 보여 준다 — 폰(375)·PC(1280) 둘 다.

대표가 꼭 내리는 결정은 두 번이다 — **① 화면 구조 ② 추천 조합(스타일)**. 나머지는 접힌 **③ 세부 조절**에서 원할 때만 바꾼다. 대표에게도 이 말 그대로 쓴다.

| 고르는 것 | 가짓수 | id |
|---|---|---|
| ① 화면 구조 | 3 | `list` 목록·표형 · `board` 진행 보드형 · `card` 카드·상세형 |
| ② 스타일(추천 조합) | 7 | `calm` 차분한 기본 · `editorial` 에디토리얼 미니멀 · `soft` 소프트 · `bold` 선명한 대비 · `paper` 따뜻한 종이 · `indeans` 인디언즈 스타일 · `corporate` 단단한 기업형 |
| ③ 색 | 10 + 내 색 | `navy` 남색 · `charcoal` 차콜 · `green` 녹색 · `brown` 갈색 · `teal` 청록 · `wine` 와인 · `terracotta` 테라코타 · `slate` 슬레이트 · `olive` 올리브 · `plum` 자두 · **`custom` 내 색**(색 칩·색 코드로 아무 색) |
| ③ 밝기 | 3 | `auto` 자동(기기 설정을 따름 — 기본) · `light` 밝게 · `dark` 어둡게 |
| ③ 모서리·밀도 | 3 · 3 | 모서리 `sharp` 각지게 · `base` 기본 · `round` 둥글게 / 밀도 `compact` 촘촘 · `base` 기본 · `roomy` 넉넉 |

추천 조합은 스타일마다 기본 색이 있다(차분한 기본 남색 · 에디토리얼 차콜 · 소프트 청록 · 선명한 대비 녹색 · 따뜻한 종이 올리브 · 인디언즈 스타일 브론즈 `#84745C` · 단단한 기업형 슬레이트). 대표가 색을 직접 고르면 스타일을 바꿔도 그 색이 유지된다.

**조합 코드**: `<구조>-<스타일>-<색 또는 custom-RRGGBB>-<밝기>[-<모서리>][-<밀도>]` — 모서리·밀도는 기본이면 생략.
예) `board-soft-teal-auto` · `board-indeans-custom-2a6f9e-auto`(내 색 #2A6F9E) · `list-calm-navy-light-round-compact`.
코드는 `src/styles/tokens.css` 첫 줄 주석에 들어간다. 이 스킬은 **방향과 토큰까지**만 한다. 화면 코드는 `indeans-erp-draft`가 만든다.

**색은 엔진이 계산한다** — 고른 색 하나에서 밝게·어둡게 두 벌을 만들고, 버튼 면(`--primary`)은 고른 색을 되도록 그대로 둔다. 글자가 4.5:1 로 읽히지 않으면 명도만 조금 옮기고 선택창에 "보정됨"이라고 보인다. 바탕 위 강조 글자는 따로 계산한 `--primary-text`, 입력 칸 테두리는 바탕 대비 3:1 의 `--border-input` 이다. 대비 검사를 통과하지 못하면 '이걸로 하기'가 막힌다.

## 언제 쓰나

- 1차 인터뷰(회사·업종) 직후 — 같은 대화에서 "indeans-erp-design 스킬을 읽고 선택창을 연다"로 이어진다. 이때 `company/structure.md`는 아직 없다(`company/profile.md`의 `## 디자인 힌트`만 있다).
- 인터뷰 전이라도 대표가 "디자인부터 보고 싶다"·"선택창 열어 줘"라고 할 때 — 추천 없이 연다.
- 새 대화에서 "디자인 고르기"·"선택창 열기"·"우리 회사 색으로"를 들었을 때.
- 써 보고 "글자가 작다·색이 안 맞다·너무 빽빽하다"가 나왔을 때(손보기 또는 다시 고르기).

## 시작 전 상태 진단

같은 대화에서 이어 불렸어도 **아래 파일을 지금 다시 읽는다** — 인터뷰가 방금 고쳤을 수 있다.

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` · `.owner/progress.json` | 이미 고른 조합(`design.code`)이 있는지 |
| `.owner/design/choice.json` | 선택창이 마지막으로 저장한 조합·시드·시각 |
| `src/styles/tokens.css` | 첫 줄 주석의 조합 코드. `/* 구조: … · 컬러: …`처럼 옛 형식이면 옛 세트로 고른 것 |
| `company/design.md` | 고른 이유·"값을 바꾼 곳" |
| `company/profile.md`의 `## 디자인 힌트` | 추천 근거: 고객이 화면을 직접 보나 · 주로 쓰는 기기 · 밖에서 일하는 사람 · 월 건수 · 동시 진행 건수 · 예상 단계 수 · 간판·로고 색 · **구조 추천** |
| `.owner/hooks/design-pick.mjs` · `.owner/design/index.html` | 선택창이 설치돼 있는지 |
| `package.json` · `src/`의 화면 파일 | 앱이 이미 있는지, 화면에 색·크기를 직접 적은 곳이 많은지 |

| 상태 | 판정 기준 | 분기 |
|---|---|---|
| A. 처음 | `tokens.css` 없음 · `design.code` 없음 | **확인 질문 없이** 절차 1→2→3으로 바로 선택창을 연다 |
| B. 같은 조합 손보기 | 조합이 있고 대표가 "조금만 고치자" | 선택창을 열지 않는다. `tokens.css` 값만 손보고 `company/design.md` "값을 바꾼 곳"에 적는다(색을 바꾸고 싶다면 C) |
| C. 조합 바꾸기 | 조합이 있는데 다시 고르려 함 | **먼저 한 번 확인**: "지금 {조합 이름}입니다. 다시 고르면 화면 인상이 전부 달라집니다. 선택창을 열까요?" 예라고 해야 절차 1부터 |
| D. 직접 적은 색이 많음 | 화면 파일에 색·크기가 여기저기 | 고른 뒤 한꺼번에 바꾸지 않는다. 화면 하나에 먼저 적용해 보여 준다(절차 7) |
| E. 선택창 없음 | `design-pick.mjs` 또는 `index.html` 없음 | 강의 자료의 설치기를 다시 돌리게 안내한다. 말로 고르게 하지 않는다 |
| F. 추천 없음 | `profile.md`가 없음(인터뷰 전) · `## 디자인 힌트` 절이 없음 · **`구조 추천: (미정 — 업종 분류 뒤)`** | 묻지 않고 **추천 없이** 연다(`--recommend` 빼기). 고르는 것은 대표가 한다 |

판정을 한 문장으로 먼저 알린다. 예: "디자인은 아직 고르지 않았습니다. 선택창을 바로 열겠습니다."

## 절차

### 1. 되돌릴 지점 (묻지 않고)

```
git add -A
git commit -m "디자인 고르기 전"
```

커밋할 게 없거나 저장소가 아직 없으면 넘어간다. 앱이 이미 있으면 바꾸기 전 화면을 한 장씩 찍어 둔다(`node .owner/hooks/capture.mjs --url <npm run dev 가 알려 준 주소>`).

### 2. 추천 정하기 (속으로 — 대표에게 묻지 않는다)

분기 F 면 이 절을 건너뛴다(추천 없이 연다). `구조 추천`이 `(미정 — 업종 분류 뒤)`이면 구조뿐 아니라 스타일·색도 추천하지 않는다 — 업종이 정해지지 않은 채 권하면 대표가 그 권유에 묶인다.

`## 디자인 힌트`로 구조·스타일을 하나씩 정한다. 위에서부터 먼저 맞는 줄을 쓴다.

| 구조 | 이럴 때 |
|---|---|
| 제외 규칙 | 예상 단계 수 8개 이상이면 진행 보드형을 빼고, 고객이 화면을 직접 보지 않으면 카드·상세형을 뺀다 |
| `구조 추천` 값 | 인터뷰가 적어 둔 값 — 제외 규칙과 부딪히면 제외가 이긴다 |
| 카드·상세형 | 고객이 화면을 직접 보고 주로 휴대폰으로 쓴다 |
| 진행 보드형 | 단계가 3~6개이고 동시에 진행하는 건이 많다 |
| 목록·표형 | 그 밖(건수가 많다·PC 위주) |

| 스타일 | 이럴 때 |
|---|---|
| 선명한 대비 `bold` | 밖에서 일하는 사람이 있다(햇빛 아래 휴대폰) |
| 소프트 `soft` | 고객이 화면을 직접 본다(서류·계약처럼 종이 느낌이 어울리는 일이면 따뜻한 종이 `paper`) |
| 단단한 기업형 `corporate` | 표·숫자가 많고 PC 에서 여러 건을 맞춰 보는 일(정산·재고·발주) |
| 차분한 기본 `calm` | 건수가 많아 한 화면에 여러 건을 촘촘히 본다 |
| 에디토리얼 `editorial` | 건수가 적고 PC 에서 한 건씩 들여다본다 |
| 차분한 기본 `calm` | 그 밖 |

인디언즈 스타일 `indeans`는 권하지 않는다 — 대표가 "인디언즈처럼"·"인디언즈 스타일로"라고 말했을 때만 추천 칸에 넣는다.

색: `profile.md`에 간판·로고·명함 색이 **색 코드(#RRGGBB)로** 있으면 `custom-RRGGBB`로 그대로 추천한다(엔진이 읽히게 맞춘다). 색 이름만 있으면 10가지 중 가장 가까운 것(파랑 → 남색·슬레이트, 초록 → 녹색·올리브, 민트 → 청록, 빨강·자주 → 와인, 주황·벽돌 → 테라코타, 갈색·베이지 → 갈색, 보라 → 자두, 검정·회색 → 차콜). 없으면 색은 추천하지 않는다(추천 조합의 기본 색). 밝기는 추천하지 않는다(기본 자동).

### 3. 선택창 열기 — 확인 질문 없이 바로

아래 안내를 **한 번만** 하고, 같은 차례에 바로 명령을 실행한다. 대표가 명령을 치지 않는다.

> 선택창을 엽니다. 저는 이렇게 권합니다 — 결정은 대표님이 하십니다.
> - 화면 구조: {구조 이름} — {힌트에서 온 근거 한 줄}
> - 스타일: {스타일 이름} — {근거 한 줄}
> - 색: {색 이름 또는 회사 색 #RRGGBB} — {근거 한 줄}
> 구조와 스타일 두 가지를 고르고, 색·모서리·밀도·밝기는 '세부 조절'을 열어 바꾸실 수 있습니다. 회사 색이 있으면 '내 색'에 넣어 보세요. 다 고르면 맨 아래 '이걸로 하기'를 누르세요.

```
node .owner/hooks/design-pick.mjs --recommend {구조}-{스타일}[-{색 또는 custom-RRGGBB}]
```

- 선택창에 추천한 칸마다 '추천' 표시가 붙고, 그 조합으로 시작한다. 추천이 없으면(분기 F) `--recommend` 없이 실행하고 안내의 세 줄을 빼고 "구조와 스타일을 골라 주세요"만 한다. 구조만 정했으면 `--recommend {구조}` 만 준다.
- 브라우저가 저절로 열린다. 안 열리면 터미널에 크게 찍힌 주소(`http://127.0.0.1:포트/`)를 대표에게 그대로 보여 주고 브라우저 주소창에 붙여 넣게 한다. 그래도 안 되면 `.owner/design/index.html`을 직접 열게 한다(저장 기능이 없는 판 — 고른 뒤 조합 코드가 나온다).
- 이 명령은 대표가 '이걸로 하기'를 누를 때까지 끝나지 않는다(30분 동안 반응이 없으면 스스로 닫힌다). **명령에 제한 시간을 줄 수 있으면 허용되는 가장 긴 값으로 실행한다.**
- 기다리는 동안 더 권하지 않는다. 권하는 것은 위의 한 번뿐이다.

### 4. 결과 받기

- 명령이 `골랐습니다: …`와 만든 파일을 찍고 끝났으면 → `.owner/design/choice.json`을 읽어 조합(`code`·`seed`·`scheme`·`radius`·`density`)을 확인한다.
- 명령이 먼저 끊겼고(제한 시간) 대표가 "골랐어요"라고 하면 → `choice.json`을 읽고 `chosen_at`이 방금인지 본다. 방금이 아니면 저장되지 않은 것이다 — 화면에 나온 조합 코드를 알려 달라고 한다.
- 대표가 코드를 말해 주면(파일로 연 판·연결이 끊긴 판) 그 코드 그대로 — 내 색이 든 코드(`custom-RRGGBB`)도 같다:

```
node .owner/hooks/design-pick.mjs --code board-indeans-custom-2a6f9e-auto
```

- 코드를 못 읽는다고 나오면 형식 안내가 같이 찍힌다 — 대표가 옮겨 적다 틀린 글자(여섯 자리 색 코드, 하이픈)를 찾아 다시 묻는다. 손으로 토큰 파일을 지어 쓰지 않는다(밝게·어둡게·글꼴·대비 보정을 엔진이 한다). 규칙 파일이 깨져 `--code` 도 안 되면 강의 자료의 설치기를 다시 돌린 뒤 `--code` 로 만든다.

조합이 정해지면 소리 내어 확인한다: **"{구조} · {스타일} · {색} · {밝기}({코드})로 하겠습니다. 나중에 바꿀 수 있지만 화면 인상이 전부 달라지니 오늘은 이걸로 갑니다."** 내 색을 엔진이 보정했으면 선택창에 나온 보정 내용(예: "버튼 색 #8A7A62 → #84745C")도 한 줄 전한다. 대표가 추천과 다른 것을 골랐으면 그대로 따른다.

### 5. company/design.md 쓰기

`assets/design.template.md`를 채워 `company/design.md`로 쓴다.

- 고른 이유는 대표가 한 말을 그대로, 추천과 그 근거도 한 줄씩. 추천이 없었으면 "추천 없음(이유)".
- 내 색이면 넣은 색 코드와 엔진이 바꾼 값(버튼 색·바탕 위 강조 글자·어둡게 버튼 색)을 `tokens.css`에서 읽어 적는다.
- "바꾸면 안 되는 것"에 공통 줄과 **고른 스타일의 "지킬 것"**을 옮긴다 — `references/families.md`의 그 스타일 절(`## {id} — …`)과 "모든 스타일 공통"·(어둡게·자동이면) "어둡게" 절만 읽는다.
- 이미 있던 `design.md`에 "값을 바꾼 곳"이 있으면(분기 C) 새 조합에 다시 넣을지 대표에게 묻고 결과를 적는다.

### 6. 앱이 있으면 이 파일들을 불러오게 하기 (없으면 건너뛴다)

`src/main.tsx` 맨 위:

```ts
import './styles/tokens.css'
import './styles/base.css'
import './styles/layout.css'
```

- `./index.css`를 부르고 있으면 그 줄을 위 세 줄로 바꾼다. **빠뜨리면 고른 디자인이 화면에 안 먹는다.** 글꼴은 `tokens.css` 안의 `@font-face` 가 `src/styles/fonts/` 의 파일을 부른다 — 그 폴더를 지우거나 옮기지 않는다(라이선스 파일도 함께 둔다).
- 앱이 아직 없으면(1차 인터뷰 직후) `design.md` "적용 범위"에 "초안 만들 때 불러오기 추가"라고 적는다. `indeans-erp-draft`가 `src/styles/`를 지우지 않고 그대로 쓴다.

### 7. 앱이 있으면 화면 값을 토큰으로 바꾼다 (없으면 건너뛴다)

화면 파일에 적힌 `#333`·`font-size: 14px`·`border-radius: 8px`·`box-shadow: …` 같은 값을 `var(--text)`·`var(--fs-body)`·`var(--radius)`·`var(--shadow)`로 바꾼다. **한 화면씩** 바꾸고 그때마다 눈으로 확인한다. 목록 → 상세·입력 → 오늘 현황 순서.

- 고치기 전에 `references/structures.md`의 고른 구조 절과 `references/families.md`의 고른 스타일 절을 읽는다.
- 강조색 자리: 버튼 면은 `var(--primary)` + 글자 `var(--primary-on)`, **바탕 위 강조 글자·탭 밑줄·선택 카드 테두리·포커스 테두리는 `var(--primary-text)`**. 입력 칸·보조 버튼 테두리는 `var(--border-input)`.
- 화면 뼈대는 `.owner/design/src/<구조>.html`의 클래스·배치를 따른다(화면 3개가 `data-screen`으로 들어 있다 — 시트 `dialog.sheet`·칩 `.chips`·빈 화면 `.empty` 도 있다).
- 표·격자의 모든 열은 `minmax(0, 1fr)`로 시작한다. 빠뜨리면 내용이 긴 건이 들어온 날 화면이 옆으로 밀린다.

### 8. 앱이 있으면 폰·PC 확인 (없으면 건너뛴다)

다른 창에서 `npm run dev`로 앱을 띄우고, 터미널에 찍힌 주소를 그대로 쓴다(짐작하지 않는다).

```
node .owner/hooks/capture.mjs --url http://localhost:5173
```

375·1280 두 장에서 확인한다: 좌우로 밀리는 곳 없음 · 누르는 곳 40px 이상(손가락 기기 44px) · 글자 잘림·겹침 없음 · 글자 크기 4종(입력 칸 제외)·굵기 3종 이하 · 고른 스타일의 그림자·모서리·선 굵기가 지켜짐 · 밝기 자동이면 기기를 어둡게 바꿔 한 장 더(또는 `<html data-theme="dark">`).

### 9. 상태 문서 갱신하고 커밋

- `.owner/state.md` "선택한 디자인" 절을 맞춘다: 화면 구조 · 스타일 · 색(내 색이면 색 코드) · 밝기 · 모서리·밀도(기본이 아닐 때) · 조합 코드 · 색 설정 파일(`src/styles/tokens.css`). "다음 행동"은 앱이 없으면 "2·3차 인터뷰(`indeans-erp-interview`) → 초안(`indeans-erp-draft`)"(인터뷰 전에 골랐으면 "1차 인터뷰"), 앱이 있으면 `indeans-erp-check`.
- `.owner/progress.json` → `design`의 `structure`·`family`·`palette`·`scheme`·`code`·`tokens`(`src/styles/tokens.css`)와 `updated_at`. 템플릿에 없는 키를 새로 만들지 않는다 — 시드·모서리·밀도는 코드와 `choice.json` 에 들어 있다(옛 파일에 `color` 키가 있으면 지우지 말고 `palette`와 같은 값을 넣는다).

```
git add -A
git commit -m "디자인 board-soft-teal-auto 적용"
```

커밋 메시지의 코드는 고른 것으로 바꾼다. 화면이 바뀌었으면 `indeans-erp-check`로 넘긴다(검수 훅이 자동으로 요구한다).

## 산출물

토큰 값은 회사에 맞게 바꿔도 된다. 단 **강조색은 하나**를 유지하고, 바꾼 줄은 `design.md`에 적는다. 색을 바꾸고 싶으면 값을 손으로 고치기보다 선택창의 '내 색'으로 다시 만든다(대비 보정·어둡게까지 함께 바뀐다).

## 하지 않는 것

- 처음 고를 때 "선택창을 열까요?"처럼 묻기. 진단 한 문장 뒤 바로 연다(조합을 바꿀 때만 확인한다 — 분기 C).
- 말로만 고르게 하기, 선택창 없이 색 이름만 묻기. 업종이 정해지지 않았는데(`(미정 — 업종 분류 뒤)`) 추천하기.
- 두 번 이상 권하기, 대표 대신 고르기, 고른 결과를 바꾸기. 인디언즈 스타일을 먼저 권하기.
- 토큰 파일을 손으로 새로 지어 쓰기 — 선택창이나 `--code`가 규칙(`.owner/design/app/design-rules.js`·`color-engine.js`)대로 만든 것을 쓴다.
- 두 조합 섞기 — 스타일 하나, 강조색 하나. `--primary` 를 바탕 위 글자색으로 쓰기(`--primary-text` 를 쓴다).
- 고른 스타일이 허용하지 않는 장식(`references/families.md`). 그라데이션·장식 이모지·왼쪽 색 막대·둥근 아이콘 배경은 어느 스타일에서도 넣지 않는다.
- 인터넷 글꼴 주소(CDN)를 넣거나 동봉 글꼴을 지우기. 강조색을 바탕으로 넓게 깔기, 빨강을 경고·주의에 쓰기(빨강은 지우기에만).
- 글자 크기 4종(입력 칸 제외)·굵기 3종 넘기기. 화면 코드 새로 만들기 — 초안은 `indeans-erp-draft`의 일이다.
- 대표 확인 없이 이미 고른 조합을 바꾸기.

## 앞선 수강생 분기

디자인이 이미 정해져 있으면 아래 중 하나를 제안한다(고르는 것은 대표).

1. **두 조합 나란히 보기** — `--code`로 다른 조합을 만들어 같은 화면을 한 번 더 찍고, 직원에게 어느 쪽이 빨리 읽히는지 묻는다. 앞 파일은 `.owner/tmp/design-backup/`에 남는다. 결정 근거를 `design.md`에 한 줄.
2. **밀도 조절** — 한 화면에서 30건 이상을 보면 세부 조절의 '촘촘'으로 다시 만든다(`-compact`). 누르는 곳은 40px 아래로 내려가지 않는다.
3. **회사 색 정확히 맞추기** — 간판·명함의 색 코드를 '내 색'에 넣는다. 엔진이 바꾼 값(보정됨)을 직원 휴대폰에서 확인한다.
4. **고객이 보는 화면만 다르게** — 토큰은 하나로 두고 고객이 여는 화면 한 장만 카드·상세형 규칙으로 여백·글자 크기를 키운다. `design.md`에 적는다.
5. **인쇄 규칙** — 목록을 종이로 뽑아야 하면 인쇄용 규칙을 따로 둔다(바탕색 빼고 선만 남김).

## 자주 막히는 지점

- **브라우저가 안 열린다** — 터미널의 주소를 붙여 넣게 한다. 그래도 안 되면 `.owner/design/index.html`을 직접 연다(고른 뒤 나오는 코드로 `--code`).
- **명령이 안 끝난다** — 정상이다. 대표가 아직 '이걸로 하기'를 누르지 않았다.
- **선택창에 "연결이 끊겼습니다"가 뜬다** — 명령이 제한 시간에 걸려 닫힌 것이다. 그대로 고르고 '이걸로 하기'를 누르면 코드가 나온다 → `--code`.
- **"선택창을 열지 못했습니다"가 뜬다(빈 포트를 못 연다)** — 보안 프로그램이나 AI 도구의 안전 모드(샌드박스)가 이 컴퓨터 안 주소를 막는 경우다. `node .owner/hooks/design-pick.mjs --check`로 확인하고, `node .owner/hooks/open.mjs .owner/design/index.html`로 파일로 연 판을 띄운다. 고른 뒤 나오는 코드로 `--code`.
- **'이걸로 하기'가 눌리지 않는다** — 아래 줄에 이유가 나온다. 대개 내 색의 색 코드가 덜 적혔다(# 다음 여섯 자리). 고치면 바로 풀린다.
- **내 색을 넣었더니 버튼 색이 조금 다르다** — 글자가 읽히도록 엔진이 명도만 옮긴 것이다("보정됨"). 넣은 색 그대로를 원하면 같은 계열에서 조금 더 진한(또는 밝은) 색을 넣어 본다. 버튼 글자를 지워 가며 맞추지 않는다.
- **"링크를 거치는 경로라 쓰지 않습니다"** — `src/styles` 같은 폴더가 바로 가기(링크·정션)다. 프로젝트 밖으로 쓰는 것을 막는 안전장치다. 그 링크를 지우고 실제 폴더로 만든 뒤 다시 실행한다.
- **글꼴이 바뀌지 않는다** — `src/styles/fonts/` 가 없거나 `tokens.css` 를 안 불렀다(절차 6). 선택창 미리 보기만 시스템 글꼴로 보이면(브라우저 보안 설정) 저장 결과와는 관계없다.
- **적용했는데 화면이 안 바뀐다** — 불러오는 세 줄이 빠졌거나(절차 6), 화면 파일에 값이 직접 적혀 토큰을 덮고 있다(절차 7).
- **어둡게(또는 자동)인데 일부만 밝다** — 화면 파일에 흰색·검은색이 직접 적혀 있다. `var(--surface)`·`var(--text)`로 바꾼다.
- **표가 폰에서 옆으로 밀린다** — 열 폭에 `minmax(0, 1fr)`이 빠졌거나 띄어쓰기 없는 긴 글자가 있다. `references/structures.md`의 말줄임 규칙을 쓴다.
- **"다 마음에 안 든다"** — 어느 쪽이 걸리는지 하나만 묻는다(색인지, 빽빽함인지, 모서리인지, 글자 크기인지). 색이면 세부 조절의 색·내 색만, 빽빽함은 밀도만, 그 밖은 스타일만 다시 고르게 하고 구조는 둔다.
- **테라코타·와인을 골랐더니 지우기 버튼과 헷갈린다** — 지우기는 면을 칠하지 않는 테두리 버튼(`.btn-danger`) 그대로 둔다. 강조 버튼은 면을 칠한다 — 모양으로 구분된다.
