# 구조 3종 적용 규칙 — 화면 3개에 어떻게 넣나

`indeans-erp-design`이 화면을 고치기 전에, `indeans-erp-draft`가 초안을 만들 때 읽는다. 고른 구조의 절만 읽으면 된다.

구조·스타일·색은 **따로** 고른다. 이 문서에는 스타일·색 이름이 나오지 않는다 — 강조색은 버튼 면이면 `var(--primary)`(그 위 글자 `var(--primary-on)`), 바탕 위 강조 글자·선택 표시선이면 `var(--primary-text)`이고, 모서리·선 굵기·그림자는 토큰(`var(--radius)`·`var(--line-w)`·`var(--shadow)`)이라 어느 스타일을 골랐든 쓰는 자리는 같다. 스타일마다 허용·금지되는 것(그림자·모서리·괘선·밀도·서체)은 `families.md`에 있다.

구조마다 목업이 하나씩 있다: `.owner/design/src/<구조>.html`(`list`·`board`·`card`). 한 파일에 화면 3개(목록 · 상세·입력 · 오늘 현황)가 `data-screen="list|detail|today"`로 나뉘어 들어 있다. 초안은 이 파일의 클래스·배치를 그대로 이어받는다(파일 머리의 세 스크립트 `../app/color-engine.js`·`design-rules.js`·`mock.js`는 선택창 미리 보기용이라 가져가지 않는다).

세 구조 모두에 공통인 것부터 본다.

---

## 0. 세 구조 공통

### 폭과 크기

- **가로 375px(휴대폰)에서 먼저 맞춘다.** 넓은 화면은 가운데로 모은다.
- 바깥 여백·요소 사이·묶음 사이는 토큰의 `--sp-1`~`--sp-6` 값만 쓴다. 그 사이의 숫자를 직접 적지 않는다.
- 본문 글자는 14px 아래로 내리지 않는다. 입력 칸 글자는 16px 이상(`--fs-input` — 그보다 작으면 iPhone에서 화면이 확대된다).
- 누를 수 있는 것은 높이 `--tap`(40px) 이상, 서로 8px 이상 떨어뜨린다. 손가락 기기에서는 `base.css`가 `--tap-touch`(44px 이상)로 바꿔 끼운다. 카드·상세형의 고객 화면은 52px 이상.
- 글자 크기 **4종 이하**(입력 칸 `--fs-input`은 셈에서 뺀다), 굵기 **3종 이하**. 한 화면을 열고 세어 본다.

### 가로로 밀리는 것을 막는 세 가지

1. 가로 줄(flex)·격자(grid)의 자식에 `min-width: 0`을 준다. 없으면 긴 글자가 칸을 밀어낸다.
2. 격자의 칸 크기는 `minmax(0, 1fr)`로 준다. 그냥 `1fr`이나 자동은 내용만큼 늘어난다.
3. 한 줄로 유지할 글자에는 말줄임을 같이 준다.

```css
/* 맞음 */
--cols: minmax(0, 2fr) minmax(0, 1fr) minmax(0, 110px);
/* 틀림 — 내용이 길면 그 열이 늘어나 화면이 옆으로 밀린다 */
--cols: 2fr 1fr 110px;
```

```css
/* 한 줄 말줄임 */
.cell { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
/* 띄어쓰기 없는 긴 글자(이메일·주소) */
.cell-wrap { white-space: normal; overflow-wrap: anywhere; }
```

`white-space: nowrap`만 주고 `overflow: hidden; text-overflow: ellipsis`를 빼면 글자가 밖으로 삐져나간다.

### 색과 모양을 쓰는 자리

- 강조색(`var(--primary)`)은 **화면당 두 군데 이하**. 대개 버튼 하나와 선택된 줄 하나다. 상단 바의 등록 버튼은 셈에서 뺀다.
- 빨강(`var(--danger)`)은 삭제처럼 **되돌릴 수 없는 행동**에만. 경고·주의는 `var(--warn)` 글자로("지남").
- 상태는 색 막대가 아니라 **작은 점 + 글자**(`.stage`)로 표시한다. 카드나 줄 왼쪽에 색 막대를 넣지 않는다.
- 그라데이션·둥근 아이콘 배경·장식 이모지는 어느 스타일에서도 넣지 않는다. 그림자·모서리·선 굵기는 고른 스타일 규칙(`families.md`)을 따르고, 값은 토큰으로만 쓴다.
- 선택된 줄·카드는 `aria-current="true"`로 표시한다(색만으로 뜻을 전하지 않게 화면 읽기 프로그램에도 알린다).
- 바탕 위의 강조색 글자·탭 밑줄·선택 카드 테두리·포커스 테두리는 `var(--primary-text)`(바탕 대비 4.5:1). `var(--primary)`를 글자색으로 쓰지 않는다 — 고른 색이 밝으면 읽히지 않는다.
- 입력 칸·보조 버튼·칩의 테두리는 `var(--border-input)`(바탕 대비 3:1 — 경계가 보여야 누를 곳인지 안다). 줄 사이 가는 선만 `var(--border)`.

### 비었을 때

건이 0건인 화면을 반드시 만든다. `.empty` 안에 "아직 없음" 한 줄(`.empty-t`)과 다음에 할 일 한 줄(`.empty-d`)만 쓴다(목업 오늘 현황의 "오늘 들어온 건 0"). 그림을 넣지 않는다.

### 새 창 — 폰에서는 아래에서 올라오는 시트

등록·단계 바꾸기처럼 화면 위에 잠깐 띄우는 창은 `<dialog class="sheet">`(목업의 '건 등록')를 쓴다 — 폰에서는 화면 아래에 붙고 넓은 화면에서는 가운데 창이 된다. 위쪽 잡는 막대(`.sheet-grip`), 머리(`.sheet-head`), 내용(`.sheet-body`), 아래 버튼 줄(`.sheet-acts`). 몇 개 중 하나를 고르는 칸은 칩(`.chips` > `label.chip` > 라디오 + `span`)으로 — 단계·담당처럼. 여닫기(바깥 누르면 닫힘·아래로 끌면 닫힘)는 앱 코드로 만든다.

## 1. 목록·표형 (`list`)

기록과 비교가 일의 중심인 회사. 한 화면에 여러 건을 나란히 놓고 **줄과 숫자를 읽는 것**이 목적이라 색은 거의 쓰지 않고 선과 간격으로 정리한다.

이 구조가 맞는 회사: 하루에 수십 번 같은 목록을 본다 · 수량·날짜·담당이 나란히 보여야 한다 · 쓰는 사람이 주로 내부 직원이고 PC나 태블릿에서 본다.

### 목록 화면 — 이 구조의 중심

- 화면 제목 한 줄, 그 아래 바로 표. 설명 문구는 넣지 않는다.
- 표 머리줄은 가라앉은 바탕(`--surface-2`)에 라벨 크기. 정렬 기준을 머리줄에 표시한다.
- 열은 4~6개까지. 더 필요하면 상세 화면으로 보낸다.
- 숫자 열은 오른쪽 정렬 + `.num`(`--font-num`). 자릿수가 어긋나면 비교가 안 된다.
- 선택된 줄만 연한 강조색 바탕(`--primary-soft`, `aria-current="true"`).
- 건 이름은 링크(`a.name`)로 둔다. 줄 전체에 누르는 동작을 걸지 않는다.

```html
<section class="panel table" style="--cols: minmax(0,2fr) minmax(0,1fr) minmax(0,1fr) minmax(0,110px)">
  <div class="thead"><span>건명</span><span>담당</span><span>단계</span><span class="num">수량</span></div>
  <div class="trow">
    <a class="name ellip" href="/items/24-101">{{건명}}</a>
    <span class="ellip">{{담당}}</span>
    <span class="stage">{{단계}}</span>
    <span class="num">120</span>
  </div>
</section>
```

업종별 열 예시 — 제조: 품목·거래처·상태·수량 / 유통: 품목·입출고·일자·재고 / 서비스: 건명·담당·상태·예정일 / 예약: 고객·예약일시·상태·인원.

### 상세·입력 화면

- 한 열로 세운다. 입력 칸을 좌우로 늘어놓지 않는다(모바일에서 반드시 깨진다). 폭은 `.narrow`(720px)까지.
- 라벨은 칸 위에(`.field > label`), 도움말은 칸 아래(`.hint`).
- 저장 버튼은 화면 아래 오른쪽. 강조색 버튼은 **화면에 하나**.
- 취소는 보통 버튼, 지우기만 `.btn-danger`(왼쪽).
- 읽기 전용 값은 입력 칸처럼 보이지 않게 테두리 없이 글자로만 둔다.

### 오늘 현황 화면

- 하루에 가장 많이 여는 화면이라 **글자 수를 줄인다.** 한 줄에 한 건(`.todo`), 왼쪽에 할 일, 오른쪽에 처리 버튼 하나.
- 건수를 제목 옆에 숫자로 둔다("오늘 할 일 3건"). 큰 숫자 칸 여러 개를 위에 늘어놓지 않는다.
- 마감이 지난 것은 맨 위에 "지남"(`.late`, `--warn` 글자)을 붙인다. 끝낸 것은 아래 구역(`.is-done`)으로 내리고 `--text-3`으로 흐리게. 빨강으로 칠하지 않는다.

### 모바일

표는 **두 칸으로 접는다.** 가로 스크롤을 만들지 않는다. 접는 규칙(`@media (max-width: 680px)`)은 `layout.css`에 이미 있다 — 머리줄은 눈에서만 감추고(화면 읽기 프로그램은 읽는다) 날짜에 "받은 날"·"마감" 라벨을 붙인다. 날짜 칸의 `.d-in`·`.d-due` 클래스를 지우면 폰에서 라벨이 사라진다. 줄 격자에 붙은 표 역할(`role="table"`·`"row"`·`"columnheader"`·`"cell"`)을 지우지 않는다 — 접혀도 표로 읽히게 하는 것이다. 열이 많아 접기 어려운 표(정산표 등)만 `.table-scroll`(`role="region"`·`tabindex="0"`·`aria-label`)에 넣어 가로로 민다.

## 2. 진행 보드형 (`board`)

"지금 어디까지 왔나"와 "다음에 누가 무엇을 하나"가 일의 중심인 회사. 건을 **카드 한 장**으로 보고 카드가 단계를 따라 옮겨 다니는 그림이다.

이 구조가 맞는 회사: 한 건이 3~6단계를 거친다 · 담당자가 여럿이고 "지금 누구 차례인가"를 자주 묻는다 · 건수가 많지 않다(하루 수 건~수십 건).

**단계가 7개를 넘으면 이 구조를 쓰지 않는다.** 칸이 너무 많아진다. 단계 표(`company/flows.md`)가 아직 비어 있으면 보드로 만들 것이 없으니 카드 목록 형태로만 적용한다.

### 목록 화면 = 진행 보드

단계를 열로 세우고 건을 카드로 놓는다. **어느 열에 있는가**가 상태다. 단계마다 색을 달리하지 않는다.

```html
<div class="board">
  <section class="column" aria-label="{{단계1 이름}}">
    <div class="column-head"><span>{{단계1 이름}}</span><span class="n num">6</span></div>
    <article class="card">
      <span class="no num">{{번호}}</span>
      <a class="name ellip" href="/items/{{번호}}">{{건명}}</a>
      <span class="owner ellip">{{담당}}</span>
      <span class="meta"><span>받은 날 <span class="num">{{날짜}}</span></span><span>마감일 <span class="num">{{날짜}}</span></span></span>
    </article>
  </section>
</div>
```

### 카드에 넣을 네 줄

| 줄 | 내용 | 업종 예 |
|---|---|---|
| 1 | 무엇인지(제목) | 제조: 품목·수량 / 서비스: 고객·작업 / 유통: 주문번호·품목 / 예약: 고객·인원 |
| 2 | 담당 | 누구 차례인지 |
| 3 | 판단에 필요한 정보 한 줄 | 거래처 / 주소 요약 / 결제 상태 / 예약 시각 |
| 4 | 날짜 | 예정일. 지났으면 "지남"을 앞에 붙임. **끝난 건(완료·마감)에는 붙이지 않는다** — 예정일이 지났어도 지연이 아니다 |

다섯 줄 이상 넣지 않는다. 더 보여 주고 싶으면 상세 화면으로 보낸다.

### 단계 이름

대표가 쓰는 말을 그대로 쓴다. "대기·처리중·완료" 같은 일반 용어로 바꾸지 않는다. 매일 확인하지 않는 단계는 카드 안 글자로 내린다.

### 열 폭 규칙 (가장 자주 깨지는 곳)

```css
/* 맞음 — 화면이 좁아지면 열이 자동으로 접힌다 */
grid-template-columns: repeat(auto-fit, minmax(min(260px, 100%), 1fr));
/* 틀림 — 좁은 화면에서 260px를 고집해 옆으로 밀린다 */
grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
```

### 상세·입력 화면

- 한 열로 세운다. 맨 위에 **지금 단계**(`.steps`)와 **다음 행동 버튼** 하나(`.next`). 이 화면에서 가장 중요한 것은 "다음에 무엇을 하나"다.
- 다음 행동 버튼에만 강조색을 쓴다(화면에 하나). 그래서 이 구조의 "내용 저장"은 보통 버튼이다.
- 다음 행동은 상태 이름이 아니라 **동작**으로 쓴다. "진행중으로 변경"이 아니라 "작업 시작"·"출고 처리"·"확인 요청".
- 기록(메모·사진)은 아래로. 입력 항목이 여덟 개를 넘으면 구역을 나눈다.

### 오늘 현황 화면

- 보드가 아니라 **한 줄짜리 목록**이다(`.todo-list` — 줄마다 카드 한 장). 오늘 해야 할 건만 모은다.
- 각 줄 오른쪽에 처리 버튼 하나. 끝낸 것은 아래 구역으로 내리고 흐리게.

### 모바일

보드는 **한 화면에 한 열 + 다음 열이 살짝** 보이게 옆으로 넘겨 본다(스냅 스크롤 — `layout.css`에 이미 있다). 위에 열 탭(`.col-tabs` — 단계 이름 + 카드 수, 누르면 그 열로)을 둔다. 넘어가는 것은 보드 칸 안이고 **화면 전체는 좌우로 밀리지 않아야 한다.** 폰에서는 카드를 끌어 옮기지 않는다 — 카드를 눌러 상세에서 단계를 바꾼다(또는 시트의 상태 칩).

## 3. 카드·상세형 (`card`)

**고객이 직접 보거나**, 직원이 고객 앞에서 화면을 돌려 보여 주는 회사. 한 화면에 적은 것을 크게 담고 다음에 할 일 하나를 분명하게 보여 준다.

이 구조가 맞는 회사: 고객이 링크를 받아 직접 연다(확인·신청·일정 보기) · 쓰는 사람의 연령대가 넓다 · 거의 모두 휴대전화로 본다. **모바일이 기준 화면**이다.

고객이 직접 여는 화면이 없으면 이 구조의 효과가 거의 없다. 그럴 때는 다른 구조를 권한다.

### 목록 화면 — 표가 아니라 카드 목록

고객이 보는 목록은 건수가 적다(자기 것만 본다). 표를 쓰지 않고 한 건을 카드 하나로 놓는다. PC 에서는 오른쪽에 고른 건의 상세(`.detail`)를 붙이고, 900px 아래에서는 상세가 목록 아래로 내려간다.

```html
<div class="cards">
  <article class="card">
    <span class="line1"><span class="no num">{{번호}}</span><a class="name ellip" href="/items/{{번호}}">{{지금 상태를 고객의 말로}}</a></span>
    <span class="line2"><span>{{언제·어디서·누가}}</span><span class="due">마감일 <span class="num">{{날짜}}</span></span></span>
  </article>
</div>
```

- 한 카드에 세 가지까지: 무엇인지 · 언제인지 · 다음에 할 일.
- 지난 건은 아래로 내리고 `--text-3`으로 흐리게 둔다.

### 상세·입력 화면 — 한 줄에 한 가지

표 대신 라벨과 값을 나열한다(`.rows`). 모바일에서는 라벨이 값 위로 올라간다.

- 한 화면에 입력 칸 **다섯 개 이하**. 넘으면 화면을 나눈다.
- 라벨은 칸 위에, 필수 여부는 글자로("필수").
- 오류는 빨간 테두리만 두지 말고 무엇을 고치면 되는지 한 줄로 적는다(`.err`).
- 저장 버튼은 폼 맨 아래 폭 가득(`.btn-block`). 엄지가 닿는 자리다.

### 문구 규칙 (이 구조에서 가장 중요하다)

크게 키운 화면에서는 어색한 말이 더 눈에 띈다. 적용 전에 대표에게 한 번 읽히고 고친다. 질문 하나만 한다: **"이 화면을 고객이 봅니다. 여기 적힌 말 중에 고객이 못 알아들을 말이 있나요?"**

| 내부 말 | 고객 화면의 말 |
|---|---|
| 배정 완료 | 담당자가 정해졌습니다 |
| 승인 대기 | 확인 중입니다 |
| 반려 | 다시 확인이 필요합니다 |
| 확인 | (무엇을 하는지 써서) 예약 확정하기 · 내용 저장하기 |
| 건 번호 A-1023 | 화면에서 숨기거나 맨 아래 작은 글자로 |

### 오늘 현황 화면

직원이 고객 앞에서 보여 주는 화면이라면 이 화면도 같은 크기를 유지한다. 맨 위에 오늘 날짜와 건수를 한 줄, 건마다 카드 하나, 카드마다 행동 버튼 하나(폰에서는 버튼이 카드 아래 폭 가득). 끝난 것은 아래로 내리고 흐리게.

### 모바일 — 이 구조의 합격 기준

- 팔을 뻗은 거리에서 본문이 읽히는가
- 누르는 곳이 손가락 한 마디보다 큰가(고객 화면은 최소 52px)
- 좌우로 밀리는 곳이 없는가
- 한 화면에 고객이 할 행동이 **하나**만 강조돼 있는가
