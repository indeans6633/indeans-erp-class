# 구조 3종 적용 규칙 — 화면 3개에 어떻게 넣나

`indeans-erp-design`이 화면을 고치기 전에 읽는다. 고른 구조의 절만 읽으면 된다.

구조와 컬러는 **따로** 고른다. 이 문서에는 색 이름이 나오지 않는다 — 강조색은 항상 `var(--primary)`이고, 어느 컬러를 골랐든 쓰는 자리는 같다.

세 구조 모두에 공통인 것부터 본다.

---

## 0. 세 구조 공통

### 폭과 크기

- **가로 375px(휴대폰)에서 먼저 맞춘다.** 넓은 화면은 가운데로 모은다.
- 바깥 여백·요소 사이·묶음 사이는 토큰의 `--sp-1`~`--sp-6` 값만 쓴다. 그 사이의 숫자를 직접 적지 않는다.
- 본문 글자는 14px 아래로 내리지 않는다. 입력 칸 글자는 16px 이상(그보다 작으면 iPhone에서 화면이 확대된다).
- 누를 수 있는 것은 높이 40px 이상, 서로 8px 이상 떨어뜨린다(카드·상세형은 52px 이상).
- 글자 크기 **4종 이하**, 굵기 **3종 이하**. 한 화면을 열고 세어 본다.

### 가로로 밀리는 것을 막는 세 가지

1. 가로 줄(flex)·격자(grid)의 자식에 `min-width: 0`을 준다. 없으면 긴 글자가 칸을 밀어낸다.
2. 격자의 칸 크기는 `minmax(0, 1fr)`로 준다. 그냥 `1fr`이나 자동은 내용만큼 늘어난다.
3. 한 줄로 유지할 글자에는 말줄임을 같이 준다.

```css
/* 맞음 */
--cols: minmax(0, 2fr) minmax(0, 1fr) minmax(0, 110px);
/* 틀림 — 내용이 길면 그 열이 늘어나 화면이 옆으로 밀린다 */
--cols: 2fr 1fr 110px;
```

```css
/* 한 줄 말줄임 */
.cell { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
/* 띄어쓰기 없는 긴 글자(이메일·주소) */
.cell-wrap { white-space: normal; overflow-wrap: anywhere; }
```

`white-space: nowrap`만 주고 `overflow: hidden; text-overflow: ellipsis`를 빼면 글자가 밖으로 삐져나간다.

### 색을 쓰는 자리

- 강조색(`var(--primary)`)은 **화면당 두 군데 이하**. 대개 버튼 하나와 선택된 줄 하나다.
- 빨강(`var(--danger)`)은 삭제처럼 **되돌릴 수 없는 행동**에만. 경고·주의에 쓰지 않는다.
- 상태는 색 막대가 아니라 **작은 점 + 글자**로 표시한다. 카드나 줄 왼쪽에 색 막대를 넣지 않는다.
- 그림자·그라데이션·둥근 아이콘 배경·장식 이모지는 넣지 않는다.

### 비었을 때

건이 0건인 화면을 반드시 만든다. `.empty`로 한 줄만 쓴다(예: "아직 없습니다. 오른쪽 아래 버튼으로 추가하세요"). 그림을 넣지 않는다.

## 1. 목록·표형 (`list`)

기록과 비교가 일의 중심인 회사. 한 화면에 여러 건을 나란히 놓고 **줄과 숫자를 읽는 것**이 목적이라 색은 거의 쓰지 않고 선과 간격으로 정리한다.

이 구조가 맞는 회사: 하루에 수십 번 같은 목록을 본다 · 수량·날짜·담당이 나란히 보여야 한다 · 쓰는 사람이 주로 내부 직원이고 PC나 태블릿에서 본다.

### 목록 화면 — 이 구조의 중심

- 화면 제목 한 줄, 그 아래 바로 표. 설명 문구는 넣지 않는다.
- 표 머리줄은 가라앉은 바탕(`--surface-2`)에 라벨 크기. 정렬 기준을 머리줄에 표시한다.
- 열은 4~5개까지. 더 필요하면 상세 화면으로 보낸다.
- 숫자 열은 오른쪽 정렬 + `--font-num`. 자릿수가 어긋나면 비교가 안 된다.
- 선택된 줄만 연한 강조색 바탕(`--primary-soft`).

```html
<section class="panel">
  <div class="panel-head">
    <span>진행 중 24건 · 최근 등록 순</span>
    <button class="btn btn-primary">새로 등록</button>
  </div>

  <div class="table" style="--cols: minmax(0,2fr) minmax(0,1fr) minmax(0,1fr) minmax(0,110px)">
    <div class="thead"><span>건명</span><span>담당</span><span>상태</span><span class="num">수량</span></div>
    <div class="trow">
      <span class="cell">{{건명}}</span>
      <span class="cell">{{담당}}</span>
      <span class="status status-ok">{{상태}}</span>
      <span class="cell num">120</span>
    </div>
  </div>
</section>
```

업종별 열 예시 — 제조: 품목·거래처·상태·수량 / 유통: 품목·입출고·일자·재고 / 서비스: 건명·담당·상태·예정일 / 예약: 고객·예약일시·상태·인원.

### 상세·입력 화면

- 한 열로 세운다. 입력 칸을 좌우로 늘어놓지 않는다(모바일에서 반드시 깨진다).
- 라벨은 칸 위에, `--fs-label` · `--text-2`.
- 저장 버튼은 화면 아래. 강조색 버튼은 **화면에 하나**.
- 취소·삭제는 글자 버튼. 삭제만 `--danger`.
- 읽기 전용 값은 입력 칸처럼 보이지 않게 테두리 없이 글자로만 둔다.

### 오늘 현황 화면

- 하루에 가장 많이 여는 화면이라 **글자 수를 줄인다.** 한 줄에 한 건, 왼쪽에 할 일, 오른쪽에 처리 버튼.
- 건수를 제목 옆에 숫자로 둔다("오늘 7건").
- 지난 것은 아래 구역으로 내리고 `--text-3`으로 흐리게. 빨강으로 칠하지 않는다.

### 모바일

표는 **두 칸으로 접는다.** 가로 스크롤을 만들지 않는다. 토큰 파일에는 색·크기 값만 있고 화면이 좁아질 때의 규칙은 없으니, 접는 규칙(`@media (max-width: 640px)`)은 화면 쪽 CSS에 직접 쓴다. 머리줄은 숨기고 두 번째 줄에 보조 정보를 메타 크기로 붙인다. 줄 전체를 누를 수 있게 하면 버튼을 줄일 수 있다.

## 2. 진행 보드형 (`board`)

"지금 어디까지 왔나"와 "다음에 누가 무엇을 하나"가 일의 중심인 회사. 건을 **카드 한 장**으로 보고 카드가 단계를 따라 옮겨 다니는 그림이다.

이 구조가 맞는 회사: 한 건이 3~5단계를 거친다 · 담당자가 여럿이고 "지금 누구 차례인가"를 자주 묻는다 · 건수가 많지 않다(하루 수 건~수십 건).

**단계가 7개를 넘으면 이 구조를 쓰지 않는다.** 칸이 너무 많아진다. `company/flows.md`의 단계 표가 비어 있으면 보드로 만들 것이 없으니 카드 목록 형태로만 적용한다.

### 목록 화면 = 진행 보드

단계를 열로 세우고 건을 카드로 놓는다. **어느 열에 있는가**가 상태다. 단계마다 색을 달리하지 않는다.

```html
<div class="page-head">
  <h1>진행 현황 <span class="count">24건</span></h1>
  <button class="btn btn-primary">새로 등록</button>
</div>

<div class="board">
  <section class="column">
    <div class="column-head"><span>{{단계1 이름}}</span><span class="n">6</span></div>
    <article class="card">
      <div class="card-title">{{건명}}</div>
      <div class="card-line">{{핵심 정보 한 줄}}</div>
      <div class="card-meta"><span>{{담당}}</span><span>{{날짜}}</span></div>
    </article>
  </section>
  <section class="column">
    <div class="column-head"><span>{{단계2 이름}}</span><span class="n">11</span></div>
  </section>
</div>
```

### 카드에 넣을 네 줄

| 줄 | 내용 | 업종 예 |
|---|---|---|
| 1 | 무엇인지(제목) | 제조: 품목·수량 / 서비스: 고객·작업 / 유통: 주문번호·품목 / 예약: 고객·인원 |
| 2 | 판단에 필요한 정보 한 줄 | 거래처 / 주소 요약 / 결제 상태 / 예약 시각 |
| 3 | 담당 | 누구 차례인지 |
| 4 | 날짜 | 예정일. 지났으면 "지남"을 앞에 붙임. **끝난 건(완료·마감)에는 붙이지 않는다** — 예정일이 지났어도 지연이 아니다 |

다섯 줄 이상 넣지 않는다. 더 보여 주고 싶으면 상세 화면으로 보낸다.

### 단계 이름

대표가 쓰는 말을 그대로 쓴다. "대기·처리중·완료" 같은 일반 용어로 바꾸지 않는다. 매일 확인하지 않는 단계는 카드 안 글자로 내린다.

### 열 폭 규칙 (가장 자주 깨지는 곳)

```css
/* 맞음 — 화면이 좁아지면 열이 자동으로 접힌다 */
grid-template-columns: repeat(auto-fit, minmax(min(260px, 100%), 1fr));
/* 틀림 — 좁은 화면에서 260px를 고집해 옆으로 밀린다 */
grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
```

### 상세·입력 화면

- 한 열로 세운다. 맨 위에 **지금 단계**와 **다음 행동 버튼** 하나. 이 화면에서 가장 중요한 것은 "다음에 무엇을 하나"다.
- 다음 행동 버튼에만 강조색을 쓴다(화면에 하나).
- 다음 행동은 상태 이름이 아니라 **동작**으로 쓴다. "진행중으로 변경"이 아니라 "작업 시작"·"출고 처리"·"방문 완료".
- 기록(메모·사진)은 아래로. 입력 항목이 여덟 개를 넘으면 구역을 나눈다.

### 오늘 현황 화면

- 보드가 아니라 **한 줄짜리 목록**이다. 오늘 해야 할 카드만 모은다.
- 오늘 표시(`.card-today`)가 화면에 너무 많아지면 기준이 느슨한 것이다.
- 각 줄 오른쪽에 처리 버튼 하나.

### 모바일

보드를 **가로로 늘어놓지 않고 세로로 쌓는다.** 단계는 접었다 펴는 구역이 된다. 좌우 밀림이 하나도 없어야 한다.

## 3. 카드·상세형 (`card`)

**고객이 직접 보거나**, 직원이 고객 앞에서 화면을 돌려 보여 주는 회사. 한 화면에 적은 것을 크게 담고 다음에 할 일 하나를 분명하게 보여 준다.

이 구조가 맞는 회사: 고객이 링크를 받아 직접 연다(확인·신청·일정 보기) · 쓰는 사람의 연령대가 넓다 · 거의 모두 휴대전화로 본다. **모바일이 기준 화면**이다.

고객이 직접 여는 화면이 없으면 이 구조의 효과가 거의 없다. 그럴 때는 다른 구조를 권한다.

### 목록 화면 — 표가 아니라 카드 목록

고객이 보는 목록은 건수가 적다(자기 것만 본다). 표를 쓰지 않고 한 건을 카드 하나로 놓는다.

```html
<div class="page">
  <h1>{{고객 이름}} 님의 {{건}}</h1>
  <article class="card">
    <div class="headline">{{지금 상태를 고객의 말로}}</div>
    <div class="sub">{{언제·어디서·누가}}</div>
    <button class="btn btn-primary">{{다음에 할 일}}</button>
  </article>
  <article class="card">
    <div class="headline">{{지난 건}}</div>
    <div class="meta">{{완료일}}</div>
  </article>
</div>
```

- 한 카드에 세 가지까지: 무엇인지 · 언제인지 · 다음에 할 일.
- 지난 건은 아래로 내리고 `--text-3`으로 흐리게 둔다.

### 상세·입력 화면 — 한 줄에 한 가지

표 대신 라벨과 값을 나열한다. 모바일에서는 라벨이 값 위로 올라간다.

- 한 화면에 입력 칸 **다섯 개 이하**. 넘으면 화면을 나눈다.
- 라벨은 칸 위에, 필수 여부는 글자로("필수").
- 오류는 빨간 테두리만 두지 말고 무엇을 고치면 되는지 한 줄로 적는다.
- 저장 버튼은 화면 아래 고정. 엄지가 닿는 자리다.

### 문구 규칙 (이 구조에서 가장 중요하다)

크게 키운 화면에서는 어색한 말이 더 눈에 띈다. 적용 전에 대표에게 한 번 읽히고 고친다. 질문 하나만 한다: **"이 화면을 고객이 봅니다. 여기 적힌 말 중에 고객이 못 알아들을 말이 있나요?"**

| 내부 말 | 고객 화면의 말 |
|---|---|
| 배정 완료 | 담당자가 정해졌습니다 |
| 승인 대기 | 확인 중입니다 |
| 반려 | 다시 확인이 필요합니다 |
| 확인 | (무엇을 하는지 써서) 예약 확정하기 · 내용 저장하기 |
| 건 번호 A-1023 | 화면에서 숨기거나 맨 아래 작은 글자로 |

### 오늘 현황 화면

직원이 고객 앞에서 보여 주는 화면이라면 이 화면도 같은 크기를 유지한다. 맨 위에 오늘 날짜와 건수를 큰 글자로 한 줄, 건마다 카드 하나, 카드마다 행동 버튼 하나. 끝난 것은 아래로 내리고 흐리게.

### 모바일 — 이 구조의 합격 기준

- 팔을 뻗은 거리에서 본문이 읽히는가
- 누르는 곳이 손가락 한 마디보다 큰가(최소 52px)
- 좌우로 밀리는 곳이 없는가
- 한 화면에 고객이 할 행동이 **하나**만 강조돼 있는가

- [ ] 화면당 글자 크기 4종 이하, 굵기 3종 이하
- [ ] 강조색이 쓰인 곳이 화면당 두 군데 이하
- [ ] 빨강은 삭제에만
- [ ] 모든 격자·표 열이 `minmax(0, ...)`
- [ ] 가로 375에서 좌우 밀림 없음
- [ ] 그림자·그라데이션·장식 이모지 없음
- [ ] 카드·줄 왼쪽에 색 막대 없음
- [ ] 비었을 때 화면이 있다
- [ ] 누르는 곳 높이 40px 이상(카드·상세형은 52px 이상)
