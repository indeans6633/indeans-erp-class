# 운영 보고 — <회사 이름>

작성 <YYYY-MM-DD> · 작성 `indeans-erp-digest` · 마지막 확인 <YYYY-MM-DD>

이 문서는 **무엇을·언제·누구에게 보내는가**의 기록이다. 보낼 곳(창구)과 받는 사람 라우팅은 `company/channel.md` 에 있다.
절 제목과 순서를 바꾸지 않는다.

## 1. 보고 항목 (세 개까지)

| 순서 | 항목(대표의 말) | 앱에서 무엇을 세나 | 표·칸(저장 값 코드로) | 0이면 |
|---|---|---|---|---|
| 1 | <오늘 해야 할 것> | <예정일이 오늘이고 안 끝난 건수> | `<업무표>.<예정일칸>` · 끝난 상태 `<done>` | 0으로 보낸다 |
| 2 | <기한이 지난 것> | <예정일이 지났고 안 끝난 건수> | `<업무표>.<예정일칸>` | 0으로 보낸다 |
| 3 | <어제 들어온 것> | <어제 만들어진 건수> | `<업무표>.created_at` | 0으로 보낸다 |

**0인 항목도 보낸다.** 안 보내면 "안 온 것"과 "0인 것"을 구분할 수 없다.

다음에 넣을 것(지금은 넣지 않는다):

- <예: 직원별 진행 건수 — 직원용 보고를 나눈 뒤>

## 2. 언제 · 누구에게

| 항목 | 대표용 | 직원용 |
|---|---|---|
| 받는 시각(한국) | 매일 <08:00> | <없음 / 매일 ○○:○○> |
| 요일 | <월~금 / 매일> | |
| 창구 | <디스코드 운영보고> | <직원알림 방> |
| 발송 함수 | `send_owner_digest` | `<send_staff_digest>` |
| 예약 이름 | `owner-daily-digest` | `<staff-daily-digest>` |
| 예약에 적은 값(UTC) | `<0 23 * * 0-4>` | |

- 하루 한 번으로 시작한다. 두 번은 첫 보고가 안정된 뒤에 늘린다.
- 직원용은 **같은 문장을 그대로 보내지 않는다.** 항목을 줄인 다른 문장을 쓴다(`company/channel.md` 라우팅 표의 '보내지 않는 것').

## 3. 보내는 문장 (실제로 온 것을 그대로)

대표용:

```
<회사 이름> 운영 보고 09-22 08:00
오늘 할 <관리 단위>: 4건
기한 지난 <관리 단위>: 1건
어제 들어온 <관리 단위>: 2건
```

직원용(있으면):

```
<회사 이름> 오늘 할 일 09-22
오늘 할 <관리 단위>: 4건
```

| 항목 | 값 |
|---|---|
| 줄 수 | <4>줄 (10줄 이내) |
| 처음 받은 날 | <YYYY-MM-DD> |
| 같은 명령을 두 번 불렀더니 "이미 보냈음" | 예 / 아니오 — <YYYY-MM-DD> |

## 4. 확인이 꼭 필요한 공지 (있을 때만)

| 종류 | 우리 회사에서 | 확인 방법 | 다시 알리기 |
|---|---|---|---|
| 알려 주기만 | 운영 보고 | 필요 없음 | 안 함 |
| 처리가 필요한 일 | <기한 지난 건> | 앱에서 그 건을 처리하면 끝 | 다음 보고에 남은 건수로 |

## 6. 보고가 안 왔을 때 확인 순서

1. 폰에서 창구를 직접 열어 본다(알림만 안 온 것일 수 있다).
2. 발송 기록을 본다.
   ```sql
   select report_date, report_key, channel, status, http_status, left(detail, 80)
     from public.report_log order by created_at desc limit 10;
   ```
3. 줄이 아예 없으면 예약이 안 돈 것이다 — `cron.job` · `cron.job_run_details` 확인.
4. 줄은 있고 `failed` 면 주소·열쇠 문제다 — `company/channel.md` 7절로 갈아 끼운다.
5. 상세 확인 순서는 스킬의 `references/cron-sql.md` 6·7절.

주간 점검에서 확인하기로 한 날: 매주 <요일> (`indeans-erp-routine` 5단계에서 같이 본다)
