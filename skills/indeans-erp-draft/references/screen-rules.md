# 화면 3개 규칙

`indeans-erp-draft`가 화면을 만들기 전에 읽는다. 첫 앱은 이 세 화면으로 끝낸다. 화면마다 **설계 선언을 먼저 쓰고**(`references/design-statement.md`) 이 규칙으로 만든 뒤, 다 만들면 점검표(`references/self-review.md`)로 스스로 본다.

세 화면이 **하나의 업무 흐름을 처음부터 끝까지** 처리할 수 있으면 합격이다. 예쁜지는 다음 문제다.

화면에 무엇을 넣을지는 `company/structure.md`(화면 3개 목록·한 건에 적는 항목표)가 정한다. 이 문서는 **어떻게 만드나**의 규칙이다. 고른 구조(목록·표형 / 진행 보드형 / 카드·상세형)별 배치 규칙은 `indeans-erp-design` 스킬의 `references/structures.md`에, 고른 스타일(패밀리)별 모양 규칙(모서리·선·밀도·그림자)은 같은 스킬의 `references/families.md`에 있다.

- **배치는 구조 규칙이, 모양은 스타일(패밀리) 규칙이 이 문서보다 앞선다.**
- 단, 아래 「공통」 절의 가로 밀림·누르는 크기·글자 대비·입력 칸 글자 규칙은 **어느 규칙도 덮지 못한다.**

## 공통 — 모바일 폭 우선

대표와 직원은 대부분 휴대폰으로 본다. **가로 375px에서 먼저 맞추고**, 넓은 화면은 가운데로 모은다.

- 여백은 토큰 값만 쓴다: 바깥 여백 `var(--sp-4)`, 요소 사이 `var(--sp-3)`, 묶음 사이 `var(--sp-5)`. 그 사이의 숫자를 직접 적지 않는다.
- 본문 글자는 `var(--fs-body)`가 기준이다. 그보다 작게 쓰지 않는다. **입력 칸의 글자는 `var(--fs-input)`로 둔다** — 본문보다 크게 잡힌 값이다. 그보다 작으면 폰(특히 아이폰)에서 입력할 때 화면이 저절로 확대된다. 입력 칸에 글자 크기 숫자를 직접 적지 않는다.
- 누를 수 있는 것은 높이 `var(--tap)` 이상, 서로 `var(--sp-2)` 이상 떨어뜨린다. 고른 구조·스타일에 맞는 값이 토큰에 이미 들어 있다 — 화면에서 숫자로 덮지 않는다.
- 가장 넓은 폭은 **글이 이어지는 화면(상세·입력)에서 720px**로 묶고 가운데 정렬한다. PC에서 글자가 가로로 길게 늘어지지 않게 한다. 목록이 보드(열이 여러 개)인 구조에서는 폭을 묶지 않고 열이 접히게 둔다.
- **가로 스크롤이 생기면 잘못 만든 것이다.** 만들고 나서 375px에서 좌우로 밀어 확인한다.

### 가로로 밀리는 것을 막는 세 가지

1. 가로 줄(flex)·격자(grid)의 자식에 `min-width: 0`을 준다. 이게 없으면 긴 글자가 칸을 밀어낸다.
2. 격자를 쓸 때 칸 크기를 `minmax(0, 1fr)`로 준다. 그냥 `1fr`이나 자동은 내용만큼 늘어난다.
3. 한 줄로 유지할 글자에는 말줄임을 같이 준다. `white-space: nowrap`만 주고 `overflow: hidden; text-overflow: ellipsis`를 빼면 밖으로 삐져나간다.

### 표를 쓸 때

- 휴대폰에서는 표를 쓰지 않는다. **한 건 = 카드 한 장**으로 쌓는다. 목록·표형 목업의 표(줄 격자 + 표 역할 `role="table"`·`"row"`·`"columnheader"`·`"cell"`)는 `layout.css`가 폰에서 이미 두 칸으로 접는다 — 그 격자와 역할을 그대로 쓴다. 역할을 지우면 접혔을 때 화면 읽기 프로그램이 표로 읽지 못한다.
- 열이 많아 접기 어려운 표(정산표 등)만 가로로 미는 상자 `.table-scroll`(`role="region"`·`tabindex="0"`·`aria-label` — 키보드로도 민다)에 넣는다. **화면 전체가 밀리는 대신 표만 밀리게** 한다.
- 열 폭은 정하지 않은 채로 두지 않는다. 각 열에 폭 규칙(`minmax(0, 1fr)` 또는 고정 폭)을 준다.
- 고정 폭은 300px을 넘기지 않는다. 넘겨야 하면 `max-width: 100%`를 같이 준다.

### 색과 글꼴

- 색은 `src/styles/tokens.css`에 정의된 변수만 쓴다(`var(--text)`·`var(--primary-text)`·`var(--border)` 등). 화면 파일에 색 값을 직접 쓰지 않는다. 그래야 디자인 방향을 바꿀 때 토큰만 갈아 끼우면 된다.
- **강조색은 자리마다 이름이 다르다.** 버튼 면은 `var(--primary)`(그 위 글자 `var(--primary-on)`), 바탕 위의 강조 글자·탭 밑줄·선택 테두리·포커스 테두리는 `var(--primary-text)`(바탕 대비 4.5:1). `var(--primary)`를 글자색이나 얇은 선에 쓰지 않는다 — 고른 색(특히 내 색)이 밝으면 읽히지 않는다.
- **테두리 세 가지**: 입력 칸·보조 버튼·칩은 `var(--border-input)`(바탕 대비 3:1 — 경계가 보여야 누를 곳인지 안다), 구역 구분·머리줄 아래는 `var(--border-strong)`, 줄 사이 가는 장식 선만 `var(--border)`.
- **모서리·그림자도 토큰만**: 모서리 `var(--radius)`·`var(--radius-sm)`·`var(--radius-btn)`·`var(--radius-lg)`(시트·큰 상자), 그림자 `var(--shadow)`(상자)·`var(--shadow-md)`(떠 있는 카드)·`var(--shadow-lg)`(시트·창). 고른 스타일이 그림자를 쓰지 않으면 값이 `none`이다 — 그림자 값을 직접 적어 되살리지 않는다.
- 강조색(버튼 면 `var(--primary)`·강조 글자 `var(--primary-text)`)이 쓰이는 곳은 화면당 두 군데 이하로 둔다. 토큰 파일에는 색·크기 값만 있고 화면이 좁아질 때의 규칙은 없으니, 접는 규칙은 화면 쪽 CSS에 직접 쓴다.
- **셀 때 상단바 버튼은 세지 않는다.** 목업의 상단바에는 이미 강조 버튼이 하나 있다. 그것까지 세면 상세 화면에서 "다음 행동 버튼 + 저장"만으로 셋이 되어 규칙이 저절로 깨진다. 세는 대상은 **본문 안의 강조색**이다(상단바·하단 탭 같은 고정 틀은 제외).
- 빨강(`var(--danger)`)은 **삭제와 오류에만** 쓴다. 상태 표시에 빨강을 쓰면 나중에 진짜 경고가 묻힌다.
- 장식용 이모지를 넣지 않는다. 버튼에는 동작을 나타내는 말만 넣는다("저장", "새 ○○ 만들기").
- 왼쪽 색 막대·카드 안 카드·그라데이션·두꺼운 그림자처럼 AI가 만든 티가 나는 모양을 넣지 않는다. 목록은 `references/self-review.md` 5절.
- **글꼴**: 서체는 `var(--font-sans)`·`var(--font-title)`·`var(--font-num)`만 쓴다. 글꼴 파일은 `src/styles/fonts/`에 있고 `tokens.css`의 `@font-face`가 부른다 — 인터넷 글꼴 주소를 더하지 않고, `fonts/`와 그 안의 `LICENSE-*.txt`를 지우지 않는다.

### 목업 부품 — 새로 짓지 않고 이어받는다

고른 구조의 목업(`.owner/design/src/<구조>.html`)과 `src/styles/base.css`·`layout.css`에 아래 부품이 이미 있다. 같은 일을 하는 부품을 새 클래스로 다시 만들지 않는다 — 클래스·속성을 그대로 쓴다.

| 부품 | 클래스·속성 | 쓰는 곳 |
|---|---|---|
| 아래에서 올라오는 시트 | `dialog.sheet` > `.sheet-grip` · `.sheet-head` · `.sheet-body` · `.sheet-acts` | 등록·단계 바꾸기처럼 화면 위에 잠깐 띄우는 창(목업의 '건 등록'). 폰에서는 화면 아래에 붙고 넓은 화면에서는 가운데 창이 된다 |
| 상태 칩 | `fieldset.chips` > `legend` + `label.chip` > 라디오 `input` + `span` | 단계·담당처럼 몇 개 중 하나 고르기(값 4개 이하). 진짜 라디오라 키보드로도 고른다 |
| 빈 화면 | `.empty` > `.empty-t`(아직 없음 한 줄) + `.empty-d`(다음에 할 일 한 줄) | 0건인 목록·오늘 현황 |
| 표 역할 | 줄 격자에 `role="table"` · `"row"` · `"columnheader"` · `"cell"` | 목록·표형의 목록 — 폰에서 접혀도 표로 읽힌다 |
| 가로로 미는 표 | `.table-scroll`(`role="region"` · `tabindex="0"` · `aria-label`) | 열이 많아 접기 어려운 표만 |
| 읽기용 글자 | `.sr-only` | 눈에는 안 보이고 화면 읽기 프로그램만 읽는 글자(접힌 표의 머리줄 등) |
| 열 탭 | `.col-tabs`(단계 이름 + 카드 수, 지금 열은 `aria-current="true"`) | 진행 보드형의 폰 화면 — 누르면 그 열로 넘어간다 |

- 여닫기(바깥을 누르면 닫힘·아래로 끌면 닫힘)·열 이동 같은 동작은 앱 코드로 만든다. 목업 머리의 미리 보기 스크립트(`../app/*.js`)는 가져가지 않는다.
- 선택된 줄·카드는 `aria-current="true"`, 마감이 지난 건은 `.late`, 끝낸 건은 `.is-done` — 표시 방식도 목업 그대로 이어받는다.

### 회사 말 + 조사

화면 문구에 회사 말을 끼워 넣을 때 조사가 어긋난다. `'주문' + '을(를)'` 처럼 괄호로 얼버무린 글자가 그대로 대표에게 보인다.

- **첫째 규칙은 조사를 피하는 것이다.** 조사가 필요 없는 문장으로 바꾼다.

| 이렇게 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| `{항목}을(를) 넣어 주세요` | `{항목} 칸이 비었습니다` (`칸`이 받침을 정해 주므로 어떤 항목이든 맞는다. `{항목}이 비었습니다`는 `메모이`처럼 틀린다) |
| `{단계}(으)로 옮겼습니다` | `{단계} — 옮겼습니다` |
| `{관리 단위}을(를) 지울까요?` | `이 {관리 단위} 지울까요?` |

- 그래도 조사가 필요하면 받침으로 고른다. 한 줄이면 된다.

```ts
const jong = (w: string) => (w.charCodeAt(w.length - 1) - 0xac00) % 28
const eul = (w: string) => w + (jong(w) ? '을' : '를')
const euro = (w: string) => w + (jong(w) === 0 || jong(w) === 8 ? '로' : '으로')
```

- `으로/로`만 예외가 하나 더 있다. 받침이 `ㄹ`이면 `로`다(위 함수의 `8`이 `ㄹ`이다).
- 마지막 글자가 한글이 아니면(영문·숫자) 위 계산이 엉뚱한 값을 낸다 — 그럴 때는 조사를 피하는 문장을 쓴다.

## 화면 1 — 목록

이 회사가 가진 것을 전부 한 줄씩 보여 준다. 가장 많이 보는 화면이다.

- **한 줄에 3~4가지만.** 보통은 `날짜 · 이름 · 담당 · 상태`. 더 넣고 싶으면 상세로 보낸다.
- 상태는 작은 라벨(칩)로. 글자로만 쓰고 색은 은은하게. 상태 하나에 색 하나를 고정한다.
- 정렬은 `structure.md`의 화면 1 절에 적힌 대로. 정하지 않았으면 **최근 것이 위**.
- 줄 전체가 눌려야 한다(작은 화살표만 누르게 만들지 않는다).
- 새로 만드는 버튼은 오른쪽 아래 고정(모바일) 또는 목록 위 오른쪽(PC).
- `structure.md`에 검색·묶어 보기가 필요하다고 적혀 있으면 처음부터 넣는다(월 건수 구간·동시 진행 건수가 근거다).
- 목록을 불러올 때는 **정렬과 개수 제한을 항상 같이** 건다. "전부 가져오기"는 건수가 늘면 조용히 잘린다.

### 비었을 때

데이터가 0건일 때 빈 화면을 그대로 두지 않는다. 목업의 빈 화면(`.empty` > `.empty-t` · `.empty-d`)으로 만든다.

> 아직 등록된 ○○이 없습니다.
> 아래 "새 ○○ 만들기"로 첫 건을 넣어 보세요.

## 화면 2 — 상세 / 입력

새로 만들기와 고치기가 **같은 화면**이다. 화면을 두 개로 나누지 않는다.

- 위에는 이 건이 무엇인지(이름·날짜), 아래에 항목들, 맨 아래 저장.
- 항목 순서는 `structure.md`의 "한 건에 적는 항목" 표 순서 그대로. 대표가 말한 순서가 대표가 생각하는 순서다.
- 필수 항목은 이름 옆에 표시하고, 비어 있으면 저장을 막는다. **막을 때는 무엇이 비었는지 그 항목 바로 아래에 적고, 첫 번째로 비어 있는 칸으로 옮겨 간다.** "입력값을 확인하세요" 같은 뭉뚱그린 말은 쓰지 않는다.
- 모든 입력 칸에 화면에 보이는 이름표를 붙인다. 안내 문구(placeholder)만으로 이름을 대신하지 않는다 — 입력을 시작하면 사라진다.
- 상태 바꾸기는 여기서 한다. 고를 수 있는 값은 `flows.md`의 상태 목록 그대로.
- **단계를 고르는 칸은 처음부터 넣는다.** 새로 만들 때 기본값은 `flows.md`의 **첫 단계**이고, 비워 둘 수 없다. 이 칸을 나중으로 미루면 복구 실습(실사용 준비 단계)에서 되돌린 건의 단계를 고칠 자리가 없어 전원이 같은 곳에서 막힌다.
- 삭제는 맨 아래, 다른 버튼과 떨어뜨려서, 한 번 더 묻고 지운다.
- 저장하면 목록으로 돌아가고, 방금 저장한 줄이 어디 있는지 보이게 한다.
- 뒤로 가기가 항상 있어야 한다. 저장 안 한 변경이 있으면 한 번 묻는다.

### 입력 항목 형식

| `structure.md`의 형식 | 화면에서 |
|---|---|
| 글자 | 한 줄 입력 |
| 여러 줄 | 여러 줄 입력(메모) |
| 숫자 | 숫자 입력. 휴대폰에서 숫자 자판이 뜨게 한다 |
| 날짜 | 날짜 고르기 |
| 고르기 | 값이 4개 이하면 상태 칩(`.chips` — 목업 부품), 많으면 목록에서 고르기 |

## 화면 3 — 오늘 현황

대표가 아침에 이것만 봐도 "오늘 뭘 해야 하는지" 알아야 한다.

두 덩어리로 만든다.

1. **오늘 것** — 오늘 날짜이거나 기한이 지난 것들의 목록(짧게, 5~7건). 누르면 상세로.
2. **단계별 개수** — 상태마다 몇 건인지 숫자. 숫자를 누르면 그 상태로 걸러진 목록으로 간다.

- 아무것도 없으면 "오늘 할 일이 없습니다"라고 분명히 말한다. 빈 화면으로 두지 않는다.
- 회사에 따라 "오늘"이 다르다. `structure.md`의 화면 3 절에 적힌 정의를 따른다(오늘 해야 할 것 / 오늘 나가는 것 / 기한 임박).
- 예시 데이터로 되돌리는 버튼을 이 화면 맨 아래에 둔다. 수업 중에 자주 쓴다. 누르면 한 번 묻고 되돌린다.

## 화면 사이 이동

- 라우터 라이브러리를 쓰지 않는다. `App.tsx`에서 `useState`로 어느 화면인지 들고 있으면 된다.
- 이동은 세 갈래면 충분하다: 목록 ↔ 상세, 오늘 현황 → 목록(걸러진 상태로), 오늘 현황 → 상세.
- 아래 탭(모바일) 또는 위 탭(PC)으로 목록·오늘 현황을 오간다. 탭은 두 개면 된다. 상세는 탭이 아니라 목록에서 들어간다.
- 뒤로 가기는 브라우저 버튼이 아니라 **화면 안의 버튼**으로 만든다. 브라우저 뒤로 가기는 이 구조에서 앱을 벗어난다.

## 만들고 나서 확인하는 순서

1. 375px 폭에서 좌우로 밀어 본다 — 밀리면 안 된다.
2. 목록에서 줄 하나를 누른다 — 상세가 뜬다.
3. 새 건을 만들어 저장한다 — 목록에 늘어난다.
4. 상태를 바꾼다 — 목록의 칩이 바뀐다.
5. 새로고침한다 — 방금 넣은 것이 그대로 있다.
6. 오늘 현황을 연다 — 숫자가 실제 건수와 맞는다.
7. 데이터를 다 지워 본다 — 빈 화면 안내가 뜬다.
8. 예시 데이터로 되돌린다 — 처음 상태로 돌아온다.
