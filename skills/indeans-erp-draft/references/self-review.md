# 만들고 나서 스스로 점검 (초안 점검표)

> **1일 차 라이브 판(11-17 리허설 반영)** — 공개 번들 v3.2 원본에서 수업 단위 말만 바꿨다. 비교용 원본: `proposed-skills/_원본/`.

`indeans-erp-draft` 절차 12가 읽는다. 화면 3개를 다 만든 뒤, **대표에게 보여 주기 전에** AI가 스스로 본다. 코드를 읽어 보는 항목과 화면을 띄워 보는 항목이 섞여 있다. 위에서부터 본다.

결과는 파일별로 묶어 `파일:줄 — 무엇이 걸렸나`로 적는다. 다 통과한 파일은 `통과` 한 줄이다.

```
src/screens/DetailScreen.tsx:42 — 입력 칸 '수량'에 보이는 이름표 없음(안내 문구만)
src/screens/ListScreen.tsx:18 — 목록 정렬은 있는데 개수 상한 없음
src/screens/TodayScreen.tsx — 통과
```

- 걸린 것은 **지금 고친다.** 초안을 만든 쪽이 고친다 — 다음 사람에게 넘기지 않는다.
- 지금 못 고치는 것만 `.owner/state.md`의 "미해결 문제"와 보고서의 "남은 문제"로 보낸다. `company/screens.md`의 "스스로 점검 결과" 표에도 한 줄씩 남긴다.
- 대표에게는 파일·줄이 아니라 **화면의 말**로 전한다("상세 화면의 수량 칸에 이름표를 붙였습니다").

## 1. 접근성 — 누구나 쓸 수 있나

| 본다 | 통과 | 찾는 법 |
|---|---|---|
| 포커스 | 키보드 Tab으로 움직일 때 지금 어디에 있는지 보인다 | `outline: none`·`outline: 0`을 찾는다. 있으면 같은 자리에 `:focus-visible` 표시가 따로 있어야 통과(색은 `var(--primary-text)` — `base.css`에 이미 있다) |
| 라벨 | 모든 입력 칸에 화면에 보이는 이름표(`<label>`)가 있다. 글자 없는 버튼(아이콘만)에는 `aria-label` | `<input`·`<select`·`<textarea`마다 짝이 되는 `label`을 본다. 안내 문구(`placeholder`)만 있는 칸은 걸린다 — 입력을 시작하면 사라져 무슨 칸인지 잊는다 |
| 대비 | 글자와 바탕의 대비가 충분하다(본문 4.5:1 이상) | 토큰의 글자색(`--text`·`--text-2`·`--text-3`, 강조 글자는 `--primary-text`)만 쓰면 맞게 만들어져 있다. 옅은 색을 직접 적었거나 `opacity`로 글자를 흐리게 했으면 걸린다. **`--primary`를 글자·얇은 선·포커스에 쓴 곳**(`color: var(--primary)`·`border-color: var(--primary)`·`outline: … var(--primary)`)도 걸린다 — `--primary`는 버튼 면 전용이다. `base.css`의 `var(--primary-text, var(--primary))`처럼 뒤에 붙은 대체값은 옛 토큰 파일용이라 걸리지 않는다 |
| 테두리 | 입력 칸·보조 버튼·칩의 경계가 바탕과 구분된다(3:1 이상) | 그 테두리가 `--border-input`인지 본다(`base.css` 그대로면 통과). `--border`로 덮었거나 테두리를 지웠으면 걸린다 |
| 표 역할 | 목록·표형이면 줄 격자에 표 역할이 그대로 있다 | `role="table"`·`"row"`·`"columnheader"`·`"cell"`을 지웠으면 걸린다 — 폰에서 접히면 표로 읽히지 않는다. 가로로 미는 표는 `.table-scroll` + `tabindex="0"`·`aria-label` |
| 누르는 것 | 누르는 것은 `<button>`, 옮겨 가는 것은 버튼이나 `<a>` | `<div onClick`·`<span onClick`을 찾는다. 키보드로 못 누르고 화면 읽기 프로그램이 버튼인 줄 모른다 |
| 제목 | 화면마다 제목이 하나(`h1`), 그 아래 묶음은 `h2` | 제목이 없거나 굵은 글자로만 흉내 낸 곳 |

## 2. 폼 — 틀려도 그 자리에서 고칠 수 있나

| 본다 | 통과 |
|---|---|
| 오류 위치 | 오류는 **그 칸 바로 아래**에, 무엇이 문제인지 회사 말로("수량이 비었습니다"). 화면 맨 위에 한꺼번에 모아 쓰지 않는다. 저장을 누르면 첫 번째로 걸린 칸으로 옮겨 간다 |
| 필수 표시 | 필수 칸은 이름 옆에 표시가 있고, 비면 저장이 막힌다. 표시를 색만으로 하지 않는다(글자나 기호를 같이) |
| 입력 칸 크기 | 입력 칸 글자는 `var(--fs-input)`, 높이는 `var(--tap)` 이상. 글자가 이보다 작으면 폰에서 입력할 때 화면이 저절로 확대된다 |
| 자판 | 숫자 칸은 숫자 자판(`inputmode="numeric"`), 날짜는 날짜 고르기, 전화번호는 `type="tel"` |
| 고르는 칸 | 값 4개 이하는 상태 칩(`.chips` — 진짜 라디오를 감싼다, 묶음 이름은 `legend`). `div`·`span`을 눌러 고르게 흉내 냈으면 걸린다 |
| 막지 않을 것 | 붙여넣기를 막지 않는다. 자동 완성을 일부러 끄지 않는다 |
| 두 번 저장 | 저장하는 동안 버튼이 "저장 중"으로 바뀌고 다시 눌리지 않는다 |
| 떠날 때 | 저장 안 한 변경이 있으면 뒤로 가기 전에 한 번 묻는다 |

## 3. 상태 — 네 가지 모습이 다 있나

| 상태 | 통과 |
|---|---|
| 비었을 때(0건) | "아직 등록된 ○○이 없습니다" + 다음에 할 일 한 줄 + 그 버튼 — 목업의 빈 화면(`.empty` > `.empty-t` · `.empty-d`) |
| 불러오는 중 | 불러오는 동안 자리 표시가 있다. 브라우저 저장일 때는 순식간이라 안 보이지만, 데이터베이스로 바꾸면(다음 단계 `indeans-erp-data`) 실제로 생긴다 — 자리를 지금 만들어 둔다 |
| 실패했을 때 | 무엇이 실패했고 무엇을 하면 되는지 말한다("저장하지 못했습니다. 연결을 확인한 뒤 다시 저장해 주세요"). 화면이 하얗게 비지 않는다 |
| 정상 | 저장하면 목록으로 돌아가 방금 그 줄이 보인다 |

## 4. 성능 — 건수가 늘어도 버티나

| 본다 | 통과 |
|---|---|
| 정렬 + 상한 | 목록은 **정렬과 개수 상한을 함께** 건다(예: 최근 것부터 100건). 상한을 넘으면 "더 보기"나 기간 고르기. 전부 가져오기는 건수가 늘면 오류 없이 조용히 잘린다 |
| 찾는 수단 | `structure.md`에 검색·묶어 보기가 필요하다고 적혀 있으면 처음부터 있다 |
| 같은 계산 반복 | 화면이 다시 그려질 때마다 전체 목록을 다시 거르고 세지 않는다. 오늘 현황의 숫자는 한 번 세어 쓴다 |

## 5. 안티-제네릭 — AI가 만든 티가 나지 않나

| 본다 | 걸리는 모습 | 바꾸는 법 |
|---|---|---|
| 왼쪽 색 막대 | 카드·알림 상자 왼쪽에 색 띠(`border-left`에 강조색·상태색) | 은은한 바탕 톤(`--primary-soft` 등)·여백·중립 선으로 구분한다 |
| 카드 안 카드 | 테두리 상자 안에 또 테두리 상자 | 안쪽은 선 한 줄이나 여백으로 나눈다 |
| 장식 | 장식 이모지·그라데이션·두꺼운 그림자·의미 없는 아이콘 동그라미 | 지운다. 그림자는 `--shadow`·`--shadow-md`·`--shadow-lg` 토큰만 — 직접 적은 `box-shadow` 값은 걸린다. 토큰 값이 `none`이면 그림자를 쓰지 않는다 |
| 새로 지은 부품 | 시트·상태 칩·빈 화면·열 탭을 목업과 다른 새 클래스로 다시 만들었다 | 목업·`base.css`의 클래스로 바꾼다(`references/screen-rules.md` 「목업 부품」) |
| 글꼴 | 인터넷 글꼴 주소(`@import url(…)`·글꼴 서비스 `<link>`)를 더했거나 `src/styles/fonts/`를 지웠다 | 주소는 지우고, 폴더는 `node .owner/hooks/design-pick.mjs --code <design.code>`로 되살린다 — 글꼴은 `tokens.css`의 `@font-face`가 `fonts/`에서 부른다 |
| 대시보드 틀 | "큰 숫자 + 작은 라벨" 칸 세 개를 맨 위에 나란히 | 오늘 현황은 **오늘 할 일 목록**부터. 숫자는 단계별 개수로, 누르면 그 목록으로 |
| 뭉뚱그린 말 | "확인"·"제출"·"오류가 발생했습니다"·"입력값을 확인하세요" | 동작을 말하는 버튼("○○ 저장"), 원인을 말하는 오류 |
| 가짜 같은 데이터 | 홍길동·ABC상사·딱 떨어지는 숫자만 | 업태에 맞는 가상 이름과 현실적인 들쭉날쭉한 수량(실제 고객 정보는 여전히 넣지 않는다) |
| 회사 말 | 화면 글자가 `profile.md`의 용어와 다르거나 영문 코드(`assigned`)·`undefined`가 보인다 | 회사 말 그대로. 영문 코드는 코드 안에서만 쓴다 |

## 6. 끝으로 — 빼기

선언의 "쓰지 않을 것"을 다시 읽는다. 들어가 있으면 뺀다. 쓰이지 않는 클래스·주석 처리된 코드·쓰지 않는 파일도 지운다. 더할 것을 찾는 단계가 아니라 뺄 것을 찾는 단계다.
