# 구조안

> 작성: indeans-erp-interview · {날짜} · v{번호}
> 절 제목과 순서를 바꾸지 않는다. `indeans-erp-draft`가 이 문서를 그대로 읽어 초안을 만든다.
> 이 문서가 **"무엇을 만들고 무엇을 만들지 않는가"의 단일 원본**이다. 다른 문서에 같은 목록을 복사하지 않는다.

## 관리 단위

- 우리 회사 말: {}
- 영문 키(앱 코드에서 쓰는 이름): {}
- 한 달 건수 구간 / 동시 진행 건수: {} / {}
- 첫 업무 흐름: {시작} → {끝} (자세한 단계는 `flows.md`)
- 첫 흐름 단계 요약: {단계 1} → {단계 2} → {단계 3}

## 화면 3개

첫 흐름 하나를 끝까지 처리하는 세 화면이다. **네 번째 화면을 만들지 않는다.**

### 화면 1 — 목록

- 우리 회사 말로 부르는 이름: {}
- 한 줄에 보이는 정보: {3~4가지. 예: 날짜 · 이름 · 담당 · 상태}
- 정렬 기준: {최신순 / 날짜순 / 기한 임박순}
- 묶어 보기·검색: {필요 없음 / 상태별 묶기 / 검색창 / 검색+기간 필터}
- 위 판단의 근거: {월 건수 구간 · 동시 진행 건수}

### 화면 2 — 상세 / 입력

- 우리 회사 말로 부르는 이름: {}
- 새로 만들 때와 고칠 때 같은 화면을 쓴다.
- 여기서 하는 일: {항목 입력 · 상태 바꾸기 · 메모}
- 되돌릴 수 없는 행동: {삭제 — 확인을 한 번 받는다}

### 화면 3 — 오늘 현황

- 우리 회사 말로 부르는 이름: {}
- 무엇을 보여 주나: {오늘 해야 할 것 / 오늘 나가는 것 / 기한 임박 / 단계별 개수}
- 대표가 아침에 이 화면만 봐도 되는 내용인가: {예 / 아니오 — 아니면 무엇이 더 필요한지}

## 한 건에 적는 항목

| 항목(우리 회사 말) | 형식 | 필수 | 영문 키 | 고를 값 / 비고 |
|---|---|---|---|---|
| {} | {글자 / 숫자 / 날짜 / 고르기 / 여러 줄} | {예/아니오} | {} | {} |

- 항목은 6~10개가 적당하다. 엑셀을 쓰고 계셨다면 그 열 이름을 그대로 가져온다.
- "고르기" 형식은 고를 값을 함께 적는다. 예: 상태 = 배정됨 / 완료됨
- 영문 키는 AI가 정한다(소문자·밑줄). 대표에게 묻지 않는다.
- 금액 항목은 이름만 적고 1회차 앱에는 넣지 않는다. 아래 "이번에 만들지 않을 것"으로 내린다.

## 예시 데이터

- 몇 건 만들 것인가: {8~12}
- 상태가 섞여 있어야 한다: {각 상태가 최소 1건씩, 오늘 날짜가 최소 2건}
- 이름·연락처는 가상으로 만든다. **실제 고객 정보를 넣지 않는다.**

## 이번에 만들지 않을 것

인터뷰에서 나왔지만 이번에는 담지 않기로 대표가 확정한 것이다. **회차마다 이 표를 꺼내 다시 묻는다.**

| 무엇을 | 대표가 말한 이유·바람 | 언제 |
|---|---|---|
| 로그인·직원별 권한 | | 2회차 |
| 실제 저장·인터넷 주소 | | 2회차 |
| 알림·운영 보고 | | 3회차 |
| 돈 계산 | | 2회차 이후 |
| 두 번째 흐름 | | 4회차 |
| {대표가 원했지만 이번엔 미룬 것} | {} | {} |

- 이 표에 없는 것을 만들지 않는다. 만들고 싶어지면 표를 먼저 고친다.
- 옮겨 온 항목은 지우지 말고 "언제" 칸을 `완료({회차})`로 바꾼다.
