# 저절로 따라오는 것 — 표 틀과 나누는 규칙 (C3-10 · 업종 무관)

> `indeans-erp-interview` 3차에서 C3-1 ~ C3-5 화면을 확인받은 뒤 읽는다. "한 번 누르면 다음이 저절로 따라오는" 모양을 표로 보여 주고 확인받는 자리다(A — 확인받지 못하면 3차를 닫지 않는다). 결과는 `company/structure.md` 끝 절 「자동 연결 (변형판)」에 4절 모양 그대로 쓴다 — `indeans-erp-draft` 가 그 절을 읽는다. (예전에는 인테리어 변형판만 채웠다. 이제 **모든 업종**이 채운다.)

## 1. 표 틀 — 회사 말로 바꿔 채운다

`{ }` 자리는 2차에서 받은 단계 이름·한 건 이름·화면 이름으로 바꾼다. 그 회사에 없는 줄은 빼고 읽는다. 업종마다 「확정 버튼」은 다르다 — 아래 2번째 표에서 그 가지의 것을 고른다.

| 사람이 하는 것 | 저절로 되는 것 | 다음으로 미루는 것(C3-6) |
|---|---|---|
| 손님이 {문의·주문·예약 받는 화면}을 쓴다 (C3-1 에서 받아들였을 때만) | {첫 단계} 카드 생김 · 담당 알림 | 자동 답장 문자(운영 보고 단계 이후) |
| 담당이 메모를 적는다 | 횟수 · 마지막 연락일 표시 | 녹음 정리(나중에) |
| **[{확정 버튼}] 을 누른다** | {한 건} 칸 열림 · 일 순서 틀({회사 순서}) · 날짜 칸 · 돈 받을 차례 표시 칸 | 입금 요청 발송 · 계산서(돈 단계) |
| 진행 체크 · 사진 올림 | 아침 화면의 '다음 할 일' 갱신 · 오늘 현황 집계 | 손님 화면 공유(권한 단계) |
| {끝 단계} 체크 | 다시 연락할 날 · 하자·AS 접수 칸 | 만족도 조사(나중에) |
| (두 번째 일) {두 번째 일의 첫 동작} | 대표 화면 표시 · 한 달 집계 | 돈 단계 연결(두 번째 일 단계) |

| 업종 가지 | 흔한 확정 버튼 (대표 말로 바꿈) | 흔한 「저절로」 |
|---|---|---|
| 1 집 공사·수리·설치 | [계약] · [일정 확정] | 현장 칸 · 공정 틀 · 돈 나눠 받는 칸 |
| 2 가게·쇼핑몰 | [주문 확인] · [보냄] | 포장할 목록 · 남은 수량 줄이기 · 보낸 날 표시 |
| 3 식당·카페·음식 | [예약 확정] · [주문 받음] | 오늘 예약판 · 재료 주문 목록 후보 |
| 4 예약·방문 서비스 | [예약 확정] · [방문 끝] | 다음 방문 날 후보 · 남은 횟수 줄이기 |
| 5 공장·제작·도매·유통 | [주문 받음] · [출고] | 만들 목록 · 남은 재료 줄이기 · 납품 날 칸 |
| 6 학원·교습·강의 | [등록] · [출석] | 반 명단 · 남은 횟수 · 다음 달 수강료 차례 |
| 7 사무 서비스 | [맡기기 확정] · [넘겨 드림] | 할 일 목록 · 마감 날 칸 · 받을 서류 목록 |
| 8 그 밖 | [확정] | {한 건} 칸 · 다음 할 일 |

- 읽어 준 뒤 한 번만 묻는다(C3-10): **"[{확정 버튼}] 누르면 저절로 따라오는 것과 사람이 누르는 것을 이렇게 나눴어요. 이대로 괜찮으세요?"** 대표에게 "자동 연결" 같은 말은 쓰지 않는다. 옮기자고 하면 2절에 맞는지 보고, 맞지 않으면 이유 한 문장 뒤 대표가 정한다(2절 둘째 줄은 바꾸지 않는다).
- **두 번째 일 행은 첫 앱에 넣지 않는다.** 표에 "두 번째 일 단계"로만 적고 `indeans-erp-draft` 는 이 행을 만들지 않는다.
- **한 건이 둘(예: 상담·현장, 문의·주문)로 보이는 회사**에서 대표가 C2-3 에서 앞쪽 하나로 정했으면: 확정 버튼 행의 '저절로'(뒤쪽 칸 열림)를 '미루는 것'으로 옮겨 적고 4절 `상태 전이:` 는 앞쪽 단계만 적는다.

## 2. 나누는 규칙 — 세 줄

1. **저절로**: 기록 · 칸 · 표시 · 알림을 앱 안에서 만드는 것만(카드 생김 · 칸 열림 · 집계 · 담당 알림 · 남은 수량/횟수 줄이기).
2. **사람이 누름**: 고객에게 나가는 것 · 금액 · 계약이나 주문 확정은 **언제나** 사람이 보고 누른다. 대표가 "그것도 저절로"를 원해도 이 줄은 바꾸지 않는다.
3. **다음으로**: 지금 화면 셋 밖이면 미룬다 — C3-6 의 단계 이름(권한 단계 · 운영 보고 단계 · 돈 단계 · 두 번째 일 단계 · 실사용 준비 단계 · 나중에)으로 적는다. 라이브 클래스는 1일 차만이다. 저장·배포·운영 보고·두 번째 일·30일 계획은 오늘 과정이 아니다. 오늘은 내 컴퓨터에서 화면 3개가 열리는 것이 끝이다.

## 3. C1-1 답을 돌려주는 문장

1차 C1-1 「저절로 됐으면」 원문을 표에서 찾아 셋 중 하나로 짚는다(기대와 결과의 간격을 없애는 자리).

- 저절로: **"말씀하신 '{원문}'은 [{확정 버튼}] 한 번 누르면 저절로 돼요."**
- 사람이 누름: **"그건 손님께 가는 거라 실수하면 안 돼서, 사람이 보고 누르게 둘게요."** (금액이면 "금액이 걸린 것이라", 확정이면 "확정하는 것이라")
- 다음으로: **"그건 다음에 붙일게요({단계 이름})."**

C1-1 이 `(미정)` 이면 건너뛰고 4절 `기대하는 자동` 줄에 `(미정)`.

## 4. `company/structure.md` 끝 절에 쓰는 모양

공통 템플릿(`../assets/structure.template.md`) 맨 끝 절. 절 제목·머리 세 줄의 앞말·표 머리를 **글자 그대로** 둔다 — `indeans-erp-draft` 가 이 모양을 읽는다. 템플릿 인용 안내 줄은 이번 개정에서 "모든 업종이 채운다"로 바꾼다(템플릿 수정안: `> 인터뷰 3차 C3-10 에서 채운다. indeans-erp-draft 가 이 절이 채워져 있으면 상태 전이·확정 버튼·공개 접수 폼을 초안에 넣는다.`).

```
## 자동 연결 (변형판)

> 인터뷰 3차 C3-10 에서 채운다. indeans-erp-draft 가 이 절이 채워져 있으면 상태 전이·확정 버튼·공개 접수 폼을 초안에 넣는다.

- 상태 전이: {단계 1} → {단계 2} → {단계 3} → … ({확정 버튼 이름} = 버튼 — 누르면 {한 건} 칸 열림)
- 공개 문의 폼: {있음 / 없음} (로그인 없음 · 링크/QR · 손님이 쓰면 '{첫 단계 이름}' 카드가 생긴다)
- 기대하는 자동: "{대표 원문}" → {저절로 / 사람이 누름 / 다음 단계({단계 이름})}

| 사람이 하는 것 | 저절로 되는 것 | 다음 단계로 미루는 것 |
|---|---|---|
| {} | {} | {} |
```

- 단계는 `company/flows.md` 의 회사 말 그대로, 처음 앱에 담기로 한 것만. 취소·보류는 화살표 끝에 `· {보류 이름}`.
- 공개 문의 폼은 C3-1 에서 대표가 문의·주문·예약 받는 화면을 받아들였으면 `있음`. (G11 「손님이 직접 본다」면 먼저 제안하되 대표가 정한다.)
- 표는 1절 표를 확인받은 그대로(두 번째 일 행은 셋째 칸에 "두 번째 일 단계").

## 5. 사용자·들어가기 — `company/users.md` (U1 · UM · US · UC · UV)

3차 첫머리에서 받은 답을 아래 모양으로 적는다. `indeans-erp-draft`(그리고 설치·권한 안내)가 이 파일을 읽어, 고른 들어가기 방식대로 초안을 세팅한다.

```
## 누가 쓰나

- 쓰는 사람: {대표 / 직원 / 손님 / 거래처 / …}  (U1, 여러 개일 수 있음)
- 대표 들어가기: {카카오 로그인 / 이메일 가입 / 둘 다}  (UM)
- 직원 들어가기: {카카오 로그인 / 이메일 가입 / 둘 다 / 해당 없음}  (US)
- 손님 들어가기: {카카오 로그인 / 이메일 가입 / 가입 없이 링크만 / 둘 다 / 해당 없음}  (UC)
- 거래처 들어가기: {카카오 로그인 / 이메일 가입 / 가입 없이 링크만 / 둘 다 / 해당 없음}  (UV)
- 직원이 하면 되는 일 / 보면 안 되는 것: {원문}
- 손님이 하면 되는 일: {원문}
- 거래처가 하면 되는 일: {원문}
- 짐작으로 채운 줄: {있으면 (짐작) 표시}

> 잘 모르겠어요의 기본값: 혼자면 대표만·카카오 로그인. 직원이 있으면 대표+직원·카카오 로그인. 손님 화면이 있으면 손님은 가입 없이 링크만.
```
