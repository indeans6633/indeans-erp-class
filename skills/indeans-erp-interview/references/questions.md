# 질문 원문·되묻기·분기 (30분 · 18문)

`indeans-erp-interview` 스킬이 질문할 때마다 읽는 파일이다. **굵게 표시된 문장이 원문**이다. 그대로 쓴다.

각 항목 구성: 원문 → 짧게 답할 때 되묻기 → 분기 → 받아 적을 곳.

| 부 | 질문 | 분 |
|---|---|---|
| 0부 대표와 회사 | 1~6 | 5 |
| 1부 무엇을 파나 | 7~8 | 3 |
| 2부 돈이 들어오는 방식 | 9 | 2 |
| 3부 사람·도구·막히는 곳 | 10~12 | 4 |
| 4부 관리 단위 | 13~14 | 3 |
| 5부 첫 흐름 | 15~17 | 7 |
| 6부 이번에 만들지 않을 것 | 18 | 2 |

# 0부 — 대표와 회사 (질문 1~6)

## 1. 회사 이름과 호칭 — 첫 질문

> **회사(사업자) 이름과 대표님을 어떻게 부르면 될까요?**

- 이 문장은 절대 바꾸지 않는다. 인사말 뒤 첫 질문이다.
- 짧게 답할 때(회사 이름만): **"제가 대표님을 어떻게 부르면 편하실까요? 사장님·대표님·원장님 중에 쓰시는 말이 있으실까요?"**
- 분기:
  - 상호가 두 개(법인명과 간판 이름)면 → **"앱 화면에는 어느 쪽 이름이 나오는 게 좋을까요?"** 그 이름을 쓴다.
  - 아직 상호가 없으면(창업 준비 중) → 임시 이름을 받아 적고, 이후 질문은 "하시게 되면"으로 바꿔 묻는다.
- **사업자등록번호는 묻지 않는다.** 대표가 먼저 말해도 적지 않는다.
- 받은 호칭은 **인터뷰 내내, 이후 모든 스킬에서** 그대로 쓴다.
- 받아 적을 곳: `profile.md` → 대표와 회사(회사 이름 / 호칭)

## 2. 사업장 위치 구분

> **사업장이 한 곳인가요, 여러 곳인가요? (본점·지점·창고·작업장 같은 구분이 있으신가요?)**

- 짧게 답할 때: **"그 구분을 회사에서는 뭐라고 부르세요? (본점·지점·지사·창고·현장 같은 말 중에)"**
- **주소는 묻지 않는다.** 몇 곳인지와 어떤 구분인지만 받는다. 문서에는 `○○ 지점`처럼 가려 적는다.
- 분기:
  - 한 곳 → 앱에 장소 구분을 넣지 않는다. 화면이 하나 줄어든다.
  - 여러 곳 → 목록에 "어디 것인지" 한 칸이 생긴다. 다만 **1회차에는 항목 하나로만** 두고 권한 분리는 2회차로 미룬다.
  - 고정 사업장 없이 고객 쪽으로 나가는 형태 → 장소 구분 대신 "누가 나가는가"가 중요해진다(질문 10과 연결).
- 받아 적을 곳: `profile.md` → 대표와 회사(사업장 구분)

## 3. 근무자 현황

> **지금 몇 분이 함께 일하시고, 각각 어떤 일을 맡고 계신가요?**

- **근무 장소를 말하지 않으면 항상 되묻는다**(인원만 답했든, 맡은 일까지 답했든): **"그분들 중에 사무실에 계신 분과 밖에서 일하시는 분이 나뉘나요?"**
  - 이 답이 화면을 휴대폰 기준으로 만들지 말지를 가른다. 사람 수와 맡은 일만 받고 넘어가면 그 근거를 통째로 놓친다. "밖"이라는 말이 답에 한 번도 안 나왔으면 아직 안 받은 것이다.
- 역할별 인원으로 받아 적는다. 이름은 적지 않는다(역할만).
- 분기:
  - 혼자 → 질문 10을 외주 버전으로 바꾼다.
  - 밖에서 일하는 사람이 있음 → 화면은 휴대폰 기준으로 만든다.
  - 아르바이트·외주가 섞임 → "앱을 볼 사람"과 "안 볼 사람"을 가른다. 2회차 권한의 밑그림이다.
- 받아 적을 곳: `profile.md` → 대표와 회사(근무자 현황 표)

## 4. 사업 규모 구간

> **한 달에 일이 몇 건쯤 들어오나요? 한 자리 수인지, 수십 개인지, 수백 개인지만 알려 주세요.**

- 짧게 답할 때: **"정확하지 않아도 됩니다. 지난달을 떠올리시면 어느 쪽에 가까우세요?"**
- **금액·매출액은 묻지 않는다.** 건수 구간만 받는다.
- 분기(목록 화면 설계에 바로 쓴다):
  - 한 자리 수 → 목록 하나로 충분. 검색·필터 없음.
  - 수십 개 → 상태별 묶어 보기가 필요.
  - 수백 개 → 검색·기간 필터가 1회차부터 필요.
- 받아 적을 곳: `profile.md` → 대표와 회사(사업 규모 구간) · `structure.md` → 화면 1 목록

## 5. 업태

> **사업자등록증의 업태·종목이 무엇인가요? 모르시면 지인에게 회사를 소개하실 때 하시는 말로 답해 주셔도 됩니다.**

- 짧게 답할 때 — **답에 나온 갈래로 되묻는다.** 한 단어로 답하면 그 단어가 가리키는 일이 회사마다 전혀 다르다.

| 이렇게 답하면 | 이렇게 되묻는다 |
|---|---|
| "서비스업이요" | **"어떤 서비스인지 한 가지만 예를 들어 주시겠어요?"** |
| "제조업이요" · "만듭니다" | **"무엇을 만드시나요?"** |
| "도소매요" · "판매합니다" | **"어떤 물건을 다루세요?"** |
| "건설이요" · "공사합니다" | **"어떤 공사를 주로 하세요?"** |

- 분기:
  - 두 가지 이상을 한다고 하면 → **"그중에 가장 손이 많이 가는 쪽은 어느 쪽인가요?"** 그쪽을 기준으로 진행한다.
  - 업태와 실제 하는 일이 다르면(등록증엔 도매, 실제는 제작) → **실제 하는 일**을 기준으로 적고 등록증 표기는 괄호로 병기한다.
- 이 답이 예시 데이터·화면 문구의 말투를 정한다. 이후 질문을 그 업태의 말로 다듬는다.
- 받아 적을 곳: `profile.md` → 대표와 회사(업태·종목)

## 6. 주 고객

> **주로 어떤 고객을 상대하시나요? 개인인가요, 회사인가요?**

- 짧게 답할 때: **"그 고객이 대표님 앱 화면을 직접 볼 일이 있을까요?"** (있다고 하면 적어만 두고 지금 파고들지 않는다)
- 분기:
  - 개인 고객 → 고객이 직접 여는 화면의 필요가 커진다. 디자인에서 카드·상세형이 후보가 된다.
  - 회사 고객 → 담당자·발주처 구분이 항목표에 들어갈 가능성이 크다.
  - 둘 다 → **"둘 중에 더 손이 많이 가는 쪽"**을 기준으로 첫 흐름을 고른다.
- 고객 역할을 실제로 만들지는 2회차 `indeans-erp-people`에서 한 문항으로 다시 묻는다.
- 받아 적을 곳: `profile.md` → 대표와 회사(주 고객)

# 1부 — 무엇을 파나 (질문 7~8)

## 7. 대표 상품·서비스

> **고객에게 무엇을 파시나요? 가장 대표적인 것 하나만 말씀해 주세요.**

- 짧게 답할 때: **"그게 대표님 일의 몇 할쯤 되나요?"**
- 분기:
  - 물건 → 재고·입출고가 관리 단위 후보가 된다.
  - 시간·인력 → 일정·배정이 후보가 된다.
  - 프로젝트성 → 진행 단계가 후보가 된다.
- 받아 적을 곳: `profile.md` → 상품·서비스

## 8. 한 건에 걸리는 기간

> **그건 주문받고 바로 끝나나요, 아니면 며칠·몇 주 걸리나요?**

- 짧게 답할 때: **"짧게 끝나는 건과 오래 가는 건이 섞여 있나요?"**
- 분기:
  - 즉시 끝남 → 상태가 두 개(접수·완료)로 충분하다. 단계 표를 짧게 잡는다.
  - 며칠~몇 주 → 단계와 담당이 중요해진다. 질문 14(동시에 열린 건수)를 꼭 묻는다.
- 받아 적을 곳: `flows.md` → 첫 흐름(한 건이 걸리는 기간)

# 2부 — 돈이 들어오는 방식 (질문 9)

## 9. 돈이 들어오는 방식

> **그 돈은 언제, 어떤 식으로 들어오나요?**

- 짧게 답할 때: **"한 번에 다 받으시나요, 아니면 나눠서 받으시나요?"**
- 분기:
  - 나눠 받음(계약금·중도금·잔금) → 첫 흐름 후보로 "입금 확인"이 강해진다.
  - 월정액·구독 → 갱신일 관리가 중요해진다.
  - 판매 즉시 → 돈보다 재고·발송이 중요해진다.
- **금액은 묻지 않는다.** 대표가 말해도 문서에 숫자를 남기지 않는다. 금지되는 것은 **금액 값**이고, '계약금액' 같은 **항목 이름은 적어도 된다** — 1회차 앱에는 넣지 않고 `structure.md`의 "이번에 만들지 않을 것"으로 내린다.
- 받아 적을 곳: `profile.md` → 돈이 들어오는 방식

# 3부 — 사람·도구·막히는 곳 (질문 10~12)

## 10. 한 건이 지나가는 손

> **한 건이 들어왔을 때, 맨 처음 손대는 사람은 누구이고 그다음은 누구인가요?**

- 짧게 답할 때: **"그다음엔 누구 손으로 넘어가나요?"** 끝까지 한 번만 따라간다.
- 혼자 하는 회사면 원문을 바꾼다:
  > **혼자 다 하시는 중에, 밖에 맡기는 일이 있나요? (배송·설치·시공·세무·디자인 같은 것)**
  - 없다고 해도 문제없다. `profile.md`에 "1인 회사, 외주 없음"으로 적는다.
- 분기: 밖에서 일하는 사람이 있으면 "그분들도 이 앱을 볼까요?"를 **적어만 두고 지금 묻지 않는다.** 2회차 질문이다.
- 이름은 적지 않는다. 역할로만 적는다.
- 받아 적을 곳: `profile.md` → 사람과 협업 · `flows.md` → 단계 표(누가)

## 11. 지금 쓰는 도구

> **지금 이 일들을 어디에 적어 두세요?**

- 짧게 답할 때: **"엑셀이면 시트가 몇 개쯤 되나요? 카톡이면 어디에 남기시나요?"**
- 분기:
  - 엑셀 → **"그 엑셀 열 이름을 몇 개만 불러 주시겠어요?"**를 이어 묻는다. 그 열 이름이 `structure.md`의 항목표가 된다.
  - 머릿속·수첩 → 빠뜨리는 일이 무엇인지(질문 12)가 더 중요해진다.
  - 이미 다른 프로그램을 쓰는 중 → **"그 프로그램에서 가장 불편한 것 한 가지"**만 이어 묻는다. 옮겨 오는 이야기는 하지 않는다.
- 받아 적을 곳: `profile.md` → 지금 쓰는 도구

## 12. 가장 귀찮은 일

> **그중에 가장 귀찮거나, 자주 빠뜨려서 문제가 되는 일은 무엇인가요?**

- 짧게 답할 때: **"최근에 '아, 이거 또 놓쳤네' 하셨던 일이 있나요?"**
- 이 답은 질문 15(첫 흐름 고르기)에서 근거로 쓴다. **원문 그대로** 인용할 수 있게 적어 둔다.
- 받아 적을 곳: `profile.md` → 가장 귀찮은 업무

# 4부 — 관리 단위 (질문 13~14)

## 13. 관리 단위

> **회사에서 "이거 하나"라고 셀 때는 무엇을 세시나요? 회사에서 부르시는 말 그대로 알려 주세요.**

- 안 나올 때 보기를 든다(고르라고 하지 말고, 없으면 회사 말을 쓰게 한다):
  > **예를 들면 주문, 예약, 프로젝트, 계약, 건, 의뢰 같은 말을 쓰시는 분들이 있는데요. 대표님 회사에서는 뭐라고 부르세요?**
- 두 개로 보일 때: **"'이번 달 몇 건 했다'고 하실 때는 무엇을 세세요?"** 세는 쪽이 관리 단위다.
- 확정하면 소리 내어 확인한다: **"그럼 앱에서도 '○○'이라고 부르겠습니다."**
- 받아 적을 곳: `profile.md` → 관리 단위 (우리 회사 말 / 영문 키는 AI가 정함) · `structure.md` → 관리 단위

## 14. 동시에 열려 있는 건수

> **지금 동시에 열려 있는 ○○이 몇 개쯤인가요?**

- ○○ 자리에 질문 13의 답(회사 말)을 넣는다.
- 짧게 답할 때: **"오늘 아침에 '아직 안 끝난 것'이 몇 개였을까요?"**
- 질문 4(월 건수 구간)와 합쳐 판단한다:
  - 월 건수도 적고 동시 진행도 적음 → 목록 하나. 검색 없음.
  - 월 건수는 적은데 동시 진행이 많음(한 건이 몇 주 가는 업태) → **상태별 묶어 보기**가 핵심. 검색은 필요 없다.
  - 월 건수도 많고 동시 진행도 많음 → 검색·기간 필터가 1회차부터 필요.
- 받아 적을 곳: `profile.md` → 관리 단위(동시 진행 건수) · `structure.md` → 화면 1 목록

# 5부 — 첫 흐름 (질문 15~17)

## 15. 첫 흐름 고르기

> **○○ 하나가 시작돼서 끝날 때까지 중에, 오늘 딱 한 구간만 앱에 담는다면 어디를 담고 싶으세요?**

- ○○ 자리에 질문 13의 답을 넣는다.
- 안 정해질 때, 질문 12의 답을 근거로 **한 번만** 추천한다:
  > **아까 ○○이 제일 자주 빠진다고 하셨는데, 거기부터 담아 볼까요?**
- 대표가 다른 걸 고르면 그대로 따른다. 설득하지 않는다.
- 받아 적을 곳: `flows.md` → 첫 흐름(이름·고른 이유)

## 16. 시작과 끝

> **그 구간은 무엇으로 시작해서 무엇으로 끝나나요?**

- 끝이 애매할 때: **"무엇을 보시면 '이건 끝났다'고 하시나요?"**
- 시작이 애매할 때: **"그 일이 시작됐다는 걸 대표님은 어떻게 아세요? 전화인가요, 문자인가요, 누가 알려 주나요?"**
- 분기: 시작이 "전화가 온다"면 앱의 첫 화면은 **입력**이 된다. "다른 데서 넘어온다"면 **목록**이 먼저다.
- 받아 적을 곳: `flows.md` → 시작 / 끝

## 17. 중간 단계·담당·증거

> **시작과 끝 사이에, 지금 어디쯤인지 말할 때 쓰시는 단계가 있나요? 그리고 각 단계는 누가 하나요?**

- 단계가 안 나올 때: **"'지금 어디까지 됐어?'라고 물으시면 직원분이 뭐라고 답하나요?"** 그 답들이 단계 이름이다.
- 단계마다 이어서 묻는다(한 번에 하나씩):
  > **그 단계가 끝났다는 건 무엇으로 확인하세요?** (사진·서명·문자 발송·입금 확인·체크 표시)
- 단계가 6개를 넘으면: **"오늘은 이 중 어디까지만 담을까요?"** 3~5단계로 줄인다.
- 확인하지 않는 단계는 넣지 않는다. 쓰지 않는 단계는 앱에서 빈칸으로 남는다.
- 받아 적을 곳: `flows.md` → 단계 표 / 상태 값

# 6부 — 이번에 만들지 않을 것 (질문 18)

## 18. 미룰 것 고르기

먼저 인터뷰 중 나왔지만 첫 흐름 밖인 것을 **목록으로 읽어 준다.** 그다음 한 문장.

> **방금 읽어 드린 것 중에, 이번에는 만들지 않고 다음으로 미룰 것을 골라 주시겠어요? 미룬 것은 잊지 않게 문서에 적어 두고, 회차마다 꺼내서 다시 여쭙겠습니다.**

- "다 해 달라"고 할 때: **"오늘 다 담으면 오늘 안에 돌아가는 것이 없습니다. 한 흐름이 끝까지 돌아가는 걸 먼저 보시고 고르시는 게 빠릅니다."** 그리고 한 번만 다시 묻는다.
- "뭘 미뤄야 할지 모르겠다"고 할 때: **"그럼 오늘 이것만 되면 성공이라고 하실 만한 것 하나를 골라 주세요. 나머지는 제가 미뤄 적겠습니다."**
- 미룬 항목마다 **언제 할지**를 한 단어로 붙인다(2회차 / 3회차 / 4회차 / 나중에).
- 기본으로 미루는 것: 로그인·권한(2회차) · 실제 저장·인터넷 주소(2회차) · 알림·운영 보고(3회차) · 돈 계산(2회차 이후) · 두 번째 흐름(4회차).
- 받아 적을 곳: `structure.md` → 이번에 만들지 않을 것 (**단일 원본**. 다른 문서에 복사하지 않는다)

## 구조안·요약 확인 (질문 아님)

정리해 보여 준 뒤 한 문장만 묻는다.

> **이 중에 틀린 데나 빠진 데가 있을까요?**

고칠 곳이 나오면 그 항목만 다시 묻는다. 전체를 처음부터 하지 않는다.

## 시간이 모자랄 때의 우선순위

30분 안에 다 못 하면 이 순서로 챙긴다.

1. 질문 1 (회사 이름·호칭)
2. 질문 13 (관리 단위)
3. 질문 15~17 (첫 흐름·시작·끝·단계)
4. 질문 12 (가장 귀찮은 일)
5. 질문 18 (이번에 만들지 않을 것)
6. 나머지

1~5번만 있어도 초안 앱은 나온다. 나머지는 `(미정)`으로 적고 다음 회차에 채운다. **5번은 생략하지 않는다** — 미룰 것을 정하지 않으면 초안이 끝나지 않는다.

## 묻지 않는 것

| 묻지 않는다 | 이유 |
|---|---|
| 사업자등록번호·상호 전체 법인명 | 앱에 쓰지 않는다 |
| 사업장 주소 | 몇 곳인지와 구분만 필요하다 |
| 매출액·단가·금액 | 문서에 숫자를 남기지 않는다 |
| 고객 실명·연락처·계좌 | 예시 데이터에도 넣지 않는다 |
| 직원 실명 | 역할로만 적는다 |

대표가 먼저 말해도 받아 적지 않는다. "그건 앱에 쓰지 않으니 적지 않겠습니다"라고 한 줄로 알리고 다음 질문으로 간다.
