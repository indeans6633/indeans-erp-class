# 상태 진단과 상태 기록 — 판정 기준

> **1일 차 라이브 판(11-17 리허설 반영)** — 원본(403518a)에서 수업 단위 말·옛 순서(1차 끝 → 디자인)·꼭 적을 날짜만 바꿨다. 순서는 `SKILL.md` 가 이긴다: 1차 → (새 대화) 2차 → (새 대화) 3차 → 테마 고르기(D1).

`indeans-erp-interview`가 **말을 걸기 전에** 읽는다. SKILL.md 「시작 전 상태 진단」과 절차 6의 자세한 기준이다. 경로는 모두 수강생 프로젝트 루트 기준이다(`.owner/…`·`company/…`).

## 1. 읽을 것

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/progress.json` | `interview.round` · `interview.open_items` · `design.code` · `app.draft_done` · `app.deploy_url` |
| `.owner/state.md` | `인터뷰 진행:` 줄 · 미해결 문제 · 다음 행동 |
| `company/profile.md` | 머리말 `1차 확인:` 줄 · 업종 분류 · `## 디자인 힌트` |
| `company/flows.md` | 머리말 `2차 확인:` 줄 · 첫 흐름(이름·시작·끝) · 단계 표 |
| `company/structure.md` | 머리말 `3차 확인:` 줄 · 화면 3개 · 한 건에 적는 항목 · 이번에 만들지 않을 것 |
| `company/scope.md` · `company/roadmap.md` | 있는지(3차 산출물) |
| `company/design.md` | 고른 디자인(없으면 `design.code`만 본다) |

## 2. 차수의 세 상태

| 상태 | 뜻 | 알아보는 법 |
|---|---|---|
| 끝남 | 그 차수를 닫았다 — 요약 확인을 받았거나 '여기까지'로 멈췄고, 문서·상태·커밋까지 했다 | `interview.round ≥ n` **그리고** 그 차수 문서 머리말 `n차 확인:`이 `확인 {날짜}` 또는 `멈춤 {날짜}` |
| 멈춤 | 끝남의 한 종류 — '여기까지'로 닫았고 빈 칸이 `open_items`에 남았다 | `n차 확인: 멈춤 {날짜}` |
| 진행 중 | 시작했지만 닫지 못했다(대화가 끊김 등) | 그 차수 문서가 있는데 `n차 확인:`이 `아직`이거나 없다, 그리고 `interview.round < n` |

- **확인 줄 모양** — `n차 확인: 확인 {YYYY-MM-DD}` · `멈춤 {YYYY-MM-DD}` · `아직` 셋 중 하나뿐이다. 다른 모양(예: `1차 확인: 2026-11-17 (대표 확인 — …)`)을 만나면 뜻대로(확인·멈춤) 읽고, 그 줄을 정해진 모양으로 고쳐 같은 커밋에 넣는다. 쓸 때도 이 모양만 쓴다.
- `interview.round`는 **마지막으로 닫은 차수**다. 차수를 닫을 때만 올린다.
- 예외 둘 — 멈춰도 닫지 않는다(`n차 확인: 아직`, 진행 중으로 본다):
  - **1차를 업종 분류(1-2·1-3) 전에 멈췄을 때.** 팩도 구조 추천도 정할 수 없으므로 디자인으로 넘길 수 없다. 다음에 분류 불명 재개(4절 ⑩)로 돌아온다.
  - **3차에 초안을 막는 항목(6절의 A)이 남았을 때.**

## 3. round와 파일이 어긋날 때

| 어긋남 | 판정 | 고치는 것 |
|---|---|---|
| round가 n인데 n차 문서의 빈 칸이 모두 `open_items`에 있다 | 정상(멈춤) | 고치지 않는다 |
| round가 n인데 n차 문서에 `open_items`에 없는 빈 칸이 있다 | 기록 누락 | 그 빈 칸을 `open_items`에 더한다. **round는 내리지 않는다** |
| round가 n인데 n차 문서가 없다 | 문서 유실 | round를 n-1로 내리고 그 차수를 진행 중으로 다시 한다(5절) |
| round가 n보다 작은데 n차 문서의 확인 줄이 `확인`·`멈춤` | 상태 갱신 누락 | round를 n으로 올린다 |
| round가 n보다 작고 n차 문서는 있으나 확인 줄이 `아직`·없음 | 진행 중 | 그 차수의 빈 칸부터 이어 간다 |

## 4. 판정 순서 — 위에서부터 처음 맞는 줄

| 순서 | 조건 | 판정 | 할 일 |
|---|---|---|---|
| ① | 하려는 차수의 선행 문서가 빠졌다(5절) | 복구 | 빠진 차수부터. 있는 내용은 다시 묻지 않는다 |
| ② | `app.draft_done` true · 3차 끝남 | 재인터뷰 | SKILL 절차 7 |
| ③ | 3차 끝남 · `blocks_draft` 항목 없음 · `design.code` 있음 | 인터뷰 끝 | 구조안을 읽어 주고 "이대로 초안을 만들까요?"만 묻는다 → 새 대화에서 `indeans-erp-draft` |
| ④ | 3차 끝남 · `design.code` 없음 | 디자인 먼저 | `indeans-erp-design` |
| ⑤ | 3차 진행 중 | 3차 이어 하기 | 남은 항목만 |
| ⑥ | 2차 끝남 | 3차 차례 | SKILL 절차 4 — 첫 질문은 U1 |
| ⑦ | 2차 진행 중 | 2차 이어 하기 | 빈 칸만 |
| ⑧ | 1차 끝남 · `design.code` 없음 | 2차 차례 | SKILL 절차 3 — 디자인은 3차 뒤(④). 첫 질문은 C2-1 |
| ⑨ | 1차 끝남 · `design.code` 있음 | 2차 차례 | SKILL 절차 3 — 첫 질문은 C2-1 |
| ⑩ | 1차 진행 중 · 업종 분류 없음 | 분류 불명 재개 | 1-2·1-3부터. 팩·구조 추천은 그 뒤에 정한다 |
| ⑪ | 1차 진행 중 · 업종 분류 있음 | 1차 이어 하기 | 빈 칸만. 끝나면 새 대화에서 2차로 |
| ⑫ | `company/profile.md` 없음 · `app.draft_done` true 또는 `imported_app.detected` true | 앱 먼저 만들어 온 분 | 1차부터. 화면에 이미 있는 것은 "이렇게 부르시는 것 맞죠?"로 확인만. 가져온 앱이면 축약 모드(`imported-app.md`) — 끝나면 디자인이 아니라 `indeans-erp-rebuild` 로 돌아간다 |
| ⑬ | 아무 문서도 없음 | 1차 처음 | SKILL 절차 2 |

- **앱이 있는지는 `.owner/progress.json`의 `app.draft_done`(이 번들로 만든 앱)과 `imported_app.detected`(가져온 앱 — 블록이 없으면 false)로만 본다.** `src/`·`package.json`만 있는 것(설치 골격)은 앱이 아니다.
- 어느 판정이든 `open_items` 중 `ask_at`이 이번 차수 첫머리인 것과 `state: 약속`인 것을 **첫 질문보다 먼저** 묻는다.

## 5. 선행 문서 — 차수마다 있어야 하는 것

| 하려는 것 | 있어야 하는 것 | 없으면 |
|---|---|---|
| 2차 | `company/profile.md` — 업종 분류 · 관리 단위 후보 · 1차 확인 줄 | 1차로 돌아가 빈 칸만 묻는다 |
| 3차 | 위 + `company/flows.md` — 첫 흐름 이름·시작·끝 · 단계 표 · 2차 확인 줄 | 2차로 돌아가 빈 칸만 |
| 재인터뷰 | 위 + 3차 끝남 | 3차로 돌아가 빈 칸만. 화면에 이미 있는 것은 확인만 |
| 디자인으로 넘기기 | `company/profile.md`의 `## 디자인 힌트` 일곱 줄(업종 분류가 끝났으면 구조 추천까지) | 1차로 돌아가 디자인 힌트 칸만 |

복구할 때도 판정을 한 문장으로 알린다. 예: "업무 흐름 문서는 있는데 회사 소개 문서가 없습니다. 회사 소개의 빈 칸부터 짧게 여쭙겠습니다."

## 6. 3차를 닫는 조건과 초안 인계 조건

3차 항목은 셋으로 나뉜다(`coverage-checklist.md` 3차 표의 '구분' 칸).

| 구분 | 무엇 | 비면 |
|---|---|---|
| A 대표 확인 필수 | 3-0 지난 미정 항목 중 `blocks_draft` · 3-1~3-3 제안에 대한 대표의 확인 · 3-7 만들지 않을 것 · 구조안 요약 확인 | **3차를 닫지 않는다.** `interview.round`는 2에 둔다. 다음에 3차 이어 하기 |
| B 설계 값 | 3-4 꼭 적을 것 · 3-5 고르는 값 · 3-6 화면 이름 · 목록의 정렬·찾기 | AI가 `(권장안)`으로 채우고 **구조안 요약 확인에서 한꺼번에** 확인받는다. 확인받으면 표시를 지운다 |
| C 대표 말 필요 · 초안은 안 막음 | 3-8 성공 기준 · 3-9 실사용 2주 뒤 · 3-9 가치 가설(2주 뒤 직접 잴 숫자) · 3-10 로드맵 바람 | `(미정)` + `open_items`(`blocks_draft: false`, `ask_at` — 3-8은 `오늘 작업 보고서 전`, 3-9·가치 가설·3-10은 `권한 단계 시작 전`) |

- **3차를 닫는다** = A가 모두 답해졌고 B의 `(권장안)`이 구조안 요약 확인에서 확인됐다 → `company/structure.md` 머리말을 `3차 확인: 확인 {날짜}`로 → `interview.round` 3.
- **초안 인계 조건** = `interview.round` 3 · `design.code` 있음 · `open_items`에 `blocks_draft: true`인 항목이 없음. 이때만 "새 대화에서 `indeans-erp-draft`"로 넘긴다.
- 1·2차의 ★ 칸 중 첫 흐름에 걸린 것(2-3 첫 흐름 · 2-4 관리 단위 · 2-5 시작 · 2-6 끝 · 2-7 단계)이 `open_items`에 남아 있으면 `blocks_draft: true`다 — 3-0에서 먼저 받는다.

## 7. open_items 모양

`interview.open_items`는 객체 목록이다.

```json
{ "id": "1-10:밖 근무", "label": "밖에서 일하는 사람", "state": "보류", "round": 1, "ask_at": "2차 첫머리", "blocks_draft": false }
```

| 키 | 값 |
|---|---|
| `id` | 고유 ID(아래 표) |
| `label` | 대표에게 다시 물을 때 쓰는 이름(회사 말) |
| `state` | `보류`(되묻기 3회에 걸림·'여기까지') · `미질문`(멈춰서 못 물음) · `약속`(옆길에서 "그 얘기는 n차에" 한 것) · `권장안`(B를 AI가 채움, 확인 전) |
| `round` | 생긴 차수(1·2·3) |
| `ask_at` | 다시 물을 때 — `1차 이어 하기` · `2차 첫머리` · `3차 첫머리` · `구조안 요약 확인` · `오늘 작업 보고서 전` · `권한 단계 시작 전` |
| `blocks_draft` | 초안을 막는가(6절 A와 첫 흐름 ★ 칸이면 `true`) |

ID 짓는 법 — 같은 질문을 다음 대화에서 정확히 되살릴 수 있어야 한다.

| 종류 | 모양 | 예 |
|---|---|---|
| 뼈대 칸의 세부 항목 | `{칸}:{세부 항목}` | `1-10:밖 근무` · `1-5:고비 수` · `2-9:증거(왔음)` · `3-9:가치 가설` |
| 팩 질문 | `팩{소분류}:{차수}-{번호}` | `팩4.2:2-5` · `팩7.2:1-2` |
| 차수 끝 확인 | `{차수}-끝:{무엇}` | `1-끝:디자인 힌트` · `3-끝:구조안 요약 확인` |
| 옆길 약속 | `약속:{대상 차수}:{주제}` | `약속:2차:보강` |
| 직원 확인 과제 | `과제:{만든 차수}` | `과제:1차` |

- 받은 항목은 목록에서 지운다. 같은 차수에서 `보류`가 된 항목은 **그 차수에서 다시 묻지 않는다.**
- 옛 문자열 항목(`"1-8 돈 받는 방식"`)을 만나면 `{ "id": "1-8", "label": "돈 받는 방식", "state": "보류" }`로 바꿔 적는다.

## 8. progress 키 — 전체 경로

| 차수를 닫을 때 | 적는 키 |
|---|---|
| 1차 | `interview.round` 1 · `company.name` · `company.owner_label` · `company.industry`(`"{대분류} > {소분류} — {회사 말}"`, 복수 업종이면 `"주: … · 보조: …"`) · `company.unit`(후보 둘이면 `"○○/○○ (후보)"`) · `next_action` |
| 2차 | `interview.round` 2 · `company.unit`(확정) · `company.first_flow`(`"{시작} → {끝}"`) · `next_action` |
| 3차 | `interview.round` 3 · `next_action` |
| 차수마다 | `interview.open_items` · `interview.updated_at` · `updated_at` · `updated_by`(`"indeans-erp-interview"`) |

- **없는 키를 새로 만들지 않는다.** 예외 — 알려진 모양의 빠진 키는 채운다: `interview` 블록이 없거나 그 안의 `round`·`open_items`·`updated_at` 중 빠진 것이 있으면 템플릿 기본값(`0` · `[]` · `null`)으로 보충한다.
- 다른 블록(`design`·`app` 등)의 빠진 키는 읽을 때 `null`로 보고 만들지 않는다 — 그 블록을 쓰는 스킬의 몫이다.
- `next_action` 값 — 1차를 마침: `"indeans-erp-interview — 2차 인터뷰(새 대화)"` · 1차를 멈춤: `"indeans-erp-interview — 1차 이어 하기"` · 2차: `"indeans-erp-interview — 3차 인터뷰(새 대화)"` · 3차를 닫음: `"indeans-erp-design — 테마 고르기(D1)"`(디자인이 이미 있으면 `"indeans-erp-draft — 초안 계획(새 대화 · Plan)"`) · 3차가 진행 중: `"indeans-erp-interview — 3차 이어 하기(초안 전 확인 ○개)"`.

## 9. state.md

- `인터뷰 진행:` 줄 — 차수마다 `완료 {날짜}` · `멈춤 {날짜} — 다시 물을 것 ○개` · `진행 중` · `(아직)`.
- `## 다음 행동` — `next_action`과 같은 말. 1차를 닫으면 "수업 뒤 숙제: `company/profile.md` 끝의 1차 요약을 직원에게 읽어 주고 빠진 것 세 줄"을 함께 적는다.
- `## 미해결 문제` — 디자인 맞춤 경고, 초안을 막는 미정 항목이 있으면 그 수.
