# 4. 음식·숙박·매장 — 질문 팩

> 목차·공통 규칙은 `../industry-taxonomy.md`. 칸을 메뉴처럼 읽어 주지 않는다. 질문은 이 업종의 말로 쓴 원문이다 — 대표가 다른 말을 쓰면 대표의 말로 바꿔 묻는다. 모든 칸은 가상의 일반 서술이다.
>
> 이 대분류는 계산대(포스기)·배달 앱·예약 사이트가 판매와 주문을 **이미 세고 있는** 경우가 많다. 그것을 다시 만들지 않는다 — 그 뒤에 사람이 따로 챙기는 일(발주·재고·근무표·마감·예약·청소)에서 관리 단위를 고른다. 매출 **금액**은 묻지 않는다.

### 4.1 식당·주점

예: 한식당 · 고깃집 · 주점 · 분식

- **이 업종의 말**: 한 건 → 예약·발주 · 재료 → 식자재 · 하루 끝 → 마감 · 근무 → 근무표 · 매장이 둘 이상 → 지점(○○점)
- **관리 단위**: 홀 판매는 세지 않는다(포스기가 센다). 예약 · 식자재 발주 · 마감 점검에서 고른다. 두 층: 식자재(계속 있음) / 발주(매번 생김).
- **첫 흐름 후보**: 단체 예약 → 방문 완료 · 식자재 발주 → 입고 확인 · **구조 추천**: list — 날짜·시간순 시간표가 기본이다
- **증거 예**: 예약 확인 메시지 · 입고 확인 · 마감 체크표 · **막히는 곳**: 단체 예약을 겹쳐 받는다 · 재료가 떨어진 걸 장사 중에 안다

**1차 세부**
1. "예약을 받으시나요? 단체 예약도 있나요?"
2. "식자재는 매일 들여오시나요, 며칠에 한 번인가요?"

**2차 흐름**
1. "예약은 어떻게 받고 어디에 적으세요?" [예약 · 시작·도구] — 이어서: "예약은 주로 누가 받으세요?" [예약 · 담당]
2. "단체 예약은 메뉴·인원을 언제 확정하세요?" [예약 · 단계] — 이어서: "확정됐다는 건 무엇으로 남기세요?" [예약 · 증거]
3. "예약 손님이 안 오시거나 인원이 바뀌면 어떻게 하세요?" [예약 · 되돌리기] — 이어서: "쉬는 날이나 대관으로 예약을 못 받는 날은 어떻게 표시하세요?" [예약 · 안 되는 날]
4. "예약 손님이 다녀가셨다는 건 무엇으로 남기세요?" [예약 · 끝]
5. "식자재 발주는 무엇이 보이면 하세요?" [발주 · 시작] — 이어서: "누가 하세요?" [발주 · 담당]
6. "들어온 식자재는 무엇으로 확인하세요?" [발주 · 증거]
7. "마감 때 무엇을 점검하고 어디에 적으세요?" [마감 · 단계·도구]
8. "근무표는 누가, 언제 짜세요?" [근무 · 담당] — 이어서: "갑자기 바뀌면 어떻게 알리세요?" [근무 · 안 되는 날]

**3차 화면·항목 제안**
1. "예약 목록 한 줄에 날짜·시간·인원·자리(룸)·확정 여부를 보이면 될까요?" [3-1]
2. "예약 한 건에는 날짜·시간·인원·메뉴·요청 사항·받은 방법·손님 칸·확정 여부를 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 예약 시간표와 오늘 들어올 식자재가 보이면 될까요?" [3-2]
4. "식자재 재고 계산은 다음으로 미뤄도 될까요?" [3-7]

### 4.2 카페·베이커리

예: 동네 카페 · 빵집 · 디저트 가게 · 매장 여러 곳

- **이 업종의 말**: 한 건 → 발주·예약 주문 · 재료 → 원두·우유·시럽·포장재 · 근무 → 근무표(시프트) · 하루 끝 → 마감 · 매장이 둘 이상 → 지점(○○점)
- **관리 단위**: 계산대에서 바로 끝나는 판매는 세지 않는다(포스기가 센다). 따로 챙기는 일에서 고른다 — 발주 · 예약 주문 · 마감. 두 층: 품목(원두·우유 — 계속 있음) / 발주(매번 생김) → 발주가 관리 단위, 품목·지점은 고르기 칸.
- **첫 흐름 후보**: 발주 → 입고 확인 · 예약 주문 → 픽업 · 하루 마감 점검 · **구조 추천**: list — 날짜·지점·품목을 줄로 견준다
- **증거 예**: 발주 메시지 · 입고 확인 체크 · 마감표 사진 · 픽업 체크 · **막히는 곳**: 재료가 떨어진 걸 영업 중에 안다 · 두 매장이 같은 걸 두 번 시키거나 빠뜨린다 · 지점마다 재고 숫자가 다르다 · 예약 픽업 시간을 놓친다

**1차 세부**
1. "매장이 몇 곳이고, 매장마다 맡는 분(점장)이 따로 계신가요?" [1-9 대신]
2. "커피 말고 빵·디저트를 직접 만드시나요?"
3. "케이크·단체 주문처럼 미리 받는 주문이 있나요?"

**2차 흐름** (매장이 하나면 8번을 빼고, 2번의 '매장마다'를 뺀다)
1. "원두·우유 같은 재료는 무엇이 보이면 주문하세요?" [발주 · 시작] — 이어서: "거래처가 쉬거나 늦게 오는 날은 어떻게 하세요?" [발주 · 안 되는 날]
2. "재료 주문은 매장마다 누가, 어디에 넣으세요?" [발주 · 담당·도구]
3. "주문한 재료가 들어오면 누가 무엇으로 확인하세요?" [발주 · 끝·증거] — 이어서: "수량이 틀리게 오면 어떻게 하세요?" [발주 · 되돌리기]
4. "재고는 언제, 어디에 세어 적으세요?" [재고 · 단계·도구] — 이어서: "유통기한이 지나 버리는 것(폐기)은 어떻게 적으세요?" [재고 · 되돌리기]
5. "근무표(시프트)는 누가, 언제 짜세요?" [근무 · 시작·담당] — 이어서: "갑자기 바뀌면 어떻게 알리세요?" [근무 · 안 되는 날]
6. "하루 마감 때 무엇을 맞춰 보세요? 카드·현금·배달 앱 같은 것이요. 금액은 말씀하지 않으셔도 됩니다." [마감 · 단계·증거]
7. "케이크·단체 주문은 어떻게 받고, 찾아가실 때까지 무엇을 챙기세요?" [예약 · 시작~끝]
8. "두 매장을 견줘 보실 때 무엇을 보세요?" [지점 비교 · 끝·도구] — 이어서: "그건 지금 어떻게 모으세요?"

**3차 화면·항목 제안**
1. "발주 목록 한 줄에 날짜·매장·품목·수량·들어왔는지를 보이면 될까요?" [3-1]
2. "발주 한 건에는 매장·품목·수량·거래처·주문한 사람·주문일·입고 확인을 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 들어올 재료와 아직 안 들어온 발주가 보이면 될까요?" [3-2]
4. "품목은 고르기 칸으로 두고, 품목별 재고 표는 다음으로 미뤄도 될까요?" [3-7]
5. "두 매장 견주기는 이번에는 목록을 매장으로 걸러 보는 것까지만 두고, 견주는 표는 운영 보고 단계로 미뤄도 될까요?" [3-7]

### 4.3 배달·포장 전문

예: 배달 전문점 · 포장 전문 · 공유 주방

- **이 업종의 말**: 한 건 → 발주·문의(리뷰) · 재료 → 식자재·포장재 · 주문 → 배달 앱이 관리하는 것
- **관리 단위**: 주문은 배달 앱이 이미 처리한다 — 다시 만들지 않는다. 이 앱은 뒤에 남는 일에서 고른다 — 식자재·포장재 발주 · 고객 문의·리뷰 답 · 마감.
- **첫 흐름 후보**: 발주 → 입고 확인 · 문의(리뷰) → 답 완료 · **구조 추천**: list — 주문은 배달 앱이 맡고 이 앱은 뒤 일을 줄로 챙긴다
- **증거 예**: 입고 확인 · 답변 완료 표시 · **막히는 곳**: 앱마다 들어온 불만을 놓친다 · 포장재가 떨어진 걸 늦게 안다

**1차 세부**
1. "주문은 배달 앱으로만 받으시나요, 전화로도 받으시나요?"
2. "배달은 대행을 쓰시나요, 직접 하시나요?"

**2차 흐름**
1. "배달 앱 말고 따로 손으로 챙기는 일은 무엇무엇인가요?" [흐름 전부]
2. "식자재·포장재 주문은 무엇이 보이면 하세요?" [발주 · 시작] — 이어서: "누가, 어디에 주문하세요?" [발주 · 담당·도구]
3. "들어온 재료는 무엇으로 확인하세요?" [발주 · 끝·증거] — 이어서: "수량이 틀리거나 상한 게 오면 어떻게 하세요?" [발주 · 되돌리기]
4. "리뷰나 불만 문의는 어디에서 보고, 누가 답하세요?" [문의 · 시작·담당]
5. "답을 했다는 건 무엇으로 남기세요?" [문의 · 끝]
6. "주문이 몰리는 시간에 재료가 떨어지면 어떻게 하세요?" [발주 · 안 되는 날]
7. "하루 마감 때 배달 앱 정산과 무엇을 맞춰 보세요?" [마감 · 단계]

**3차 화면·항목 제안**
1. "문의 목록 한 줄에 받은 날·배달 앱·내용 요약·답 여부를 보이면 될까요?" [3-1]
2. "문의 한 건에는 받은 날·배달 앱·주문 번호·내용·처리·답한 날을 적으면 될까요?" [3-3]
3. "아침 첫 화면에 답 안 한 문의와 오늘 들어올 재료가 보이면 될까요?" [3-2]
4. "배달 앱 주문을 이 앱으로 가져오는 것은 만들지 않아도 될까요?" [3-7]

### 4.4 단체 급식·케이터링

예: 도시락 · 단체 급식 · 출장 뷔페 · 행사 케이터링

- **이 업종의 말**: 한 건 → 납품(주문) · 고객 → 거래처(회사·학교·행사) · 단계 → 수량 확정·조리·출고 · 끝 → 납품 · 뒤처리 → 그릇 회수
- **관리 단위**: 납품. 두 층: 거래처(계속 있음) / 납품(매번 생김) → 납품이 관리 단위, 거래처는 고르기 칸.
- **첫 흐름 후보**: 수량 확정 → 납품 완료 · **구조 추천**: list — 납품일 기준 날짜순이 핵심이다
- **증거 예**: 수량 확정 메시지 · 출고 체크 · 납품 확인 · **막히는 곳**: 전날 수량 변경을 놓친다 · 알레르기 같은 요청 사항을 빠뜨린다

**1차 세부**
1. "정기적으로 넣는 곳과 한 번씩 주문하는 곳이 섞여 있나요?"
2. "식단은 누가, 언제 정하세요?"

**2차 흐름**
1. "주문 수량은 언제까지 확정받으세요?" [납품 · 시작]
2. "수량이 바뀌면 어떻게 연락이 오고, 누가 고치세요?" [납품 · 되돌리기·담당]
3. "알레르기나 따로 빼 달라는 요청은 어디에 적으세요?" [납품 · 도구]
4. "납품 날 조리부터 출고까지 어떤 순서로 가나요? 회사에서 부르시는 이름 그대로요." [납품 · 단계]
5. "출고할 때 무엇을 확인하세요?" [납품 · 증거]
6. "납품이 끝났다는 건 무엇으로 받으세요?" [납품 · 끝]
7. "회수할 그릇이나 남은 음식은 어떻게 챙기세요?" [납품 · 정산·후속]

**3차 화면·항목 제안**
1. "납품 목록 한 줄에 납품일·시간·거래처·수량·확정 여부를 보이면 될까요?" [3-1]
2. "납품 한 건에는 거래처·납품일과 시간·식단·수량·요청 사항·출고 확인·회수 여부를 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘·내일 납품 수량과 아직 확정 안 된 주문이 보이면 될까요?" [3-2]
4. "식단표 관리는 다음으로 미뤄도 될까요?" [3-7]

### 4.5 숙박·공간 대여

예: 펜션 · 게스트하우스 · 소형 호텔 · 연습실 · 파티룸 · 스터디룸

- **이 업종의 말**: 한 건 → 예약 · 방 → 객실·룸 · 시작 → 입실 · 끝 → 퇴실·정리 · 뒤처리 → 청소·점검
- **관리 단위**: 예약. 두 층: 객실·룸(계속 있음) / 예약(매번 생김) → 예약이 관리 단위, 객실은 고르기 칸. 청소가 가장 급하면 "퇴실 뒤 청소 한 번"을 관리 단위로 잡는다.
- **첫 흐름 후보**: 예약 → 이용 완료(퇴실) · 퇴실 → 청소 완료 → 다음 손님 준비 · **구조 추천**: list — 날짜별 객실 예약을 줄로 훑는다
- **증거 예**: 예약 확정 메시지 · 입실 안내 발송 · 청소 완료 사진 · 비품 점검표 · **막히는 곳**: 여러 예약 사이트에서 예약이 겹친다 · 청소가 끝났는지 몰라 손님을 기다리게 한다

**1차 세부**
1. "객실(룸)이 몇 개인가요?"
2. "예약은 어디로 들어오나요? 예약 사이트·전화·메시지 중에요."
3. "시간 단위로 빌려 드리나요, 하룻밤 단위인가요?" [1-5 대신]

**2차 흐름**
1. "예약 사이트가 여러 곳이면 겹치지 않게 무엇으로 맞춰 보세요?" [예약 · 도구] — 이어서: "들어온 예약은 누가 확인하세요?" [예약 · 시작·담당]
2. "예약이 확정되면 손님께 무엇을 보내 드리세요?" [예약 · 단계]
3. "입실하실 때 확인하는 것이 있나요?" [예약 · 증거] — 이어서: "퇴실하셨다는 건 무엇으로 아세요?" [예약 · 끝]
