# 9. 운송·물류·창고 — 질문 팩

> 목차·공통 규칙은 `../industry-taxonomy.md`. 칸을 메뉴처럼 읽어 주지 않는다. 질문은 이 업종의 말로 쓴 원문이다 — 대표가 다른 말을 쓰면 대표의 말로 바꿔 묻는다. 모든 칸은 가상의 일반 서술이다.
>
> 이 대분류는 기사님이 밖에서 일하므로 1-10·1-11을 꼭 받는다. 출발지·도착지는 **문서에 실제 주소를 적지 않는다** — "출발 구분·도착 구분" 같은 칸 이름만 정한다. 택배사·운송 앱이 이미 세는 물량은 다시 만들지 않는다.

### 9.1 화물 운송 (용달·퀵)

예: 용달 · 화물 운송 · 퀵서비스 · 납품 운송 대행

- **이 업종의 말**: 한 건 → 오더(운송 건) · 배정 → 배차 · 사람 → 기사님·차량 · 증거 → 상차·하차·인수증 · 끝 → 하차 완료
- **관리 단위**: 오더. 두 층: 거래처·차량(계속 있음) / 오더(매번 생김) → 오더가 관리 단위, 거래처·차량은 고르기 칸.
- **첫 흐름 후보**: 오더 접수 → 배차 → 하차 확인 · **구조 추천**: board — 접수·배차·운행 중·완료 칸을 하루에 여러 건이 지난다
- **증거 예**: 배차 확인 · 상차·하차 사진 · 인수증 · **막히는 곳**: 기사·차량 배정이 머릿속에만 있다 · 인수증을 모아 정산할 때 빠진다

**1차 세부**
1. "정해진 거래처를 도시나요, 그때그때 오더를 받으시나요?"
2. "차량은 몇 대이고, 기사님은 몇 분인가요?" [1-10 대신 — 밖 근무는 '있음']

**2차 흐름**
1. "오더는 어떻게 들어오나요? 전화·메시지·앱 중에요." [오더 · 시작]
2. "배차는 누가, 무엇을 보고 정하세요?" [오더 · 담당]
3. "기사님께 배차는 어떻게 전달하세요?" [오더 · 도구]
4. "상차·하차는 무엇으로 확인하세요?" [오더 · 단계·증거]
5. "하차가 끝났다는 건 무엇으로 받으세요? 인수증인가요, 사진인가요?" [오더 · 끝]
6. "차가 막히거나 고장 나서 늦어지면 어떻게 하세요?" [오더 · 안 되는 날]
7. "운송비 정산은 언제, 무엇을 모아서 하세요?" [정산 · 정산·후속]

**3차 화면·항목 제안**
1. "오더 목록을 단계별로 묶어서, 한 줄에 날짜·출발 구분·도착 구분·화물·기사를 보이면 될까요?" [3-1]
2. "오더 한 건에는 접수일·거래처·출발 구분·도착 구분·화물·차량·기사·상하차 사진·인수증 여부를 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 배차표와 아직 배차 안 된 오더가 보이면 될까요?" [3-2]
4. "운송비 정산은 돈 흐름 단계로 미뤄도 될까요?" [3-7]

### 9.2 택배·배송 대행

예: 택배 대리점 · 지역 배송 대행 · 당일 배송

- **이 업종의 말**: 한 건 → 문제 배송(반송·파손·분실·주소 오류) · 구역 → 배송 구역 · 사람 → 배송 기사 · 되돌리기 → 반송·재배송
- **관리 단위**: 하루 물량 전부는 세지 않는다(택배사 시스템이 센다). 사람이 따로 챙기는 문제 배송에서 고른다.
- **첫 흐름 후보**: 문제 배송 접수 → 처리 완료 · **구조 추천**: list — 건수가 많아 찾기·걸러 보기가 먼저다
- **증거 예**: 배송 완료 사진 · 반송 처리 표시 · 고객 확인 · **막히는 곳**: 문제 배송을 따라가기 어렵다 · 기사별로 처리 상황이 흩어진다

**1차 세부**
1. "하루 물량은 수십·수백·수천 중 어느 쪽인가요?"
2. "구역이 나뉘어 있나요?"

**2차 흐름**
1. "문제 배송(반송·파손·분실)은 어떻게 알게 되세요?" [문제 배송 · 시작]
2. "누가 받아서 처리하세요?" [문제 배송 · 담당] — 이어서: "처리 상황은 어디에 적어 두세요?" [문제 배송 · 도구]
3. "처리는 어떤 순서로 하세요? 회사에서 부르시는 이름 그대로요." [문제 배송 · 단계]
4. "처리가 끝났다는 건 무엇으로 남기세요?" [문제 배송 · 끝·증거]
5. "재배송은 언제, 누가 나가세요?" [재배송 · 담당]
6. "주소가 틀린 건은 어떻게 확인하세요?" [문제 배송 · 되돌리기] — 이어서: "받는 분과 연락이 안 되는 건은 어떻게 하세요?" [문제 배송 · 안 되는 날]
7. "기사님들 하루 마감은 무엇으로 확인하세요?" [마감 · 증거]

**3차 화면·항목 제안**
1. "문제 배송 목록 한 줄에 접수일·송장 번호·문제 종류·기사·지금 단계를 보이면 될까요?" [3-1]
2. "한 건에는 접수일·송장 번호·문제 종류·구역·기사·처리 내용·처리일을 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 처리할 반송·재배송이 보이면 될까요?" [3-2]
4. "택배사 시스템에서 자동으로 가져오는 것은 만들지 않아도 될까요?" [3-7]

### 9.3 창고·보관

예: 물류 창고 · 보관 대행 · 3자 물류

- **이 업종의 말**: 한 건 → 입고·출고 요청 · 고객 → 화주(맡기는 회사) · 꺼내기 → 피킹 · 끝 → 출고 완료 · 맞춰 보기 → 재고 조사
- **관리 단위**: 출고 요청 · 입고. 두 층: 품목·화주(계속 있음) / 입출고(매번 생김) → 출고 요청이 관리 단위, 품목·화주는 고르기 칸.
- **첫 흐름 후보**: 출고 요청 → 출고 완료 · 입고 예정 → 입고 확인 · **구조 추천**: list — 품목·수량 비교와 검색이 핵심이다
- **증거 예**: 요청서 · 꺼내기(피킹) 체크 · 출고 확인 · 입고 검수 · **막히는 곳**: 실제 재고와 장부가 다르다 · 출고 요청이 메일·전화로 섞여 들어온다

**1차 세부**
1. "맡기는 회사(화주)가 몇 곳인가요?"
2. "재고 조사는 얼마나 자주 하세요?"

**2차 흐름**
1. "출고 요청은 어떻게 들어오나요?" [출고 · 시작]
2. "꺼내기(피킹)는 누가, 무엇을 보고 하세요?" [출고 · 담당·단계]
3. "꺼낸 것이 맞는지는 무엇으로 확인하세요?" [출고 · 증거]
4. "출고가 끝났다는 건 무엇으로 남기세요?" [출고 · 끝]
5. "입고가 오면 무엇을 검수하세요?" [입고 · 단계]
6. "재고가 모자라 출고를 못 할 때는 어떻게 하세요?" [출고 · 안 되는 날]
7. "잘못 나간 물건은 어떻게 되돌리세요?" [출고 · 되돌리기]
8. "재고 조사에서 숫자가 다르면 어떻게 하세요?" [재고 · 되돌리기]

**3차 화면·항목 제안**
1. "출고 요청 목록 한 줄에 요청일·화주·품목 요약·수량·지금 단계를 보이면 될까요?" [3-1]
2. "출고 한 건에는 요청일·화주·품목과 수량·받는 곳 구분·꺼낸 사람·확인 체크·출고일을 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 출고·입고 예정과 재고가 모자란 요청이 보이면 될까요?" [3-2]
4. "품목별 재고 계산은 다음으로 미뤄도 될까요?" [3-7]

### 9.4 승객 운송 (통학·대절)

예: 통학 차량 · 전세 버스 · 행사 대절

- **이 업종의 말**: 한 건 → 운행·대절 예약 · 길 → 노선 · 사람 → 기사님·차량 · 점검 → 차량 점검·보험 날짜
- **관리 단위**: 운행 · 대절 예약. 두 층: 차량·노선(계속 있음) / 운행(매번 생김).
- **첫 흐름 후보**: 대절 예약 → 운행 완료 · 차량 점검 → 완료 · **구조 추천**: list — 날짜와 차량 기준으로 훑는다
- **증거 예**: 예약 확정 · 운행 일지 · 점검표 · **막히는 곳**: 차량 점검·보험 날짜를 놓친다 · 탑승 명단 변경이 늦게 전달된다

**1차 세부**
1. "정해진 노선을 도시나요, 행사 때 빌려 드리나요?"
2. "차량이 몇 대인가요?"

**2차 흐름**
1. "대절 문의는 어떻게 들어오나요?" [운행 · 시작]
2. "차량과 기사님은 누가 배정하세요?" [운행 · 담당] — 이어서: "운행 일정은 어디에 적어 두세요?" [운행 · 도구]
3. "운행 날 출발 전에 무엇을 확인하세요?" [운행 · 단계]
4. "운행이 끝났다는 건 무엇으로 남기세요? 운행 일지인가요?" [운행 · 끝·증거]
5. "탑승 명단이 바뀌면 누가 기사님께 알리세요?" [운행 · 되돌리기]
6. "차량 점검·보험 날짜는 어디에 적고 누가 챙기세요?" [점검 · 도구·담당]
7. "차가 고장 나면 대신 갈 차는 어떻게 정하세요?" [운행 · 안 되는 날]

**3차 화면·항목 제안**
1. "운행 목록 한 줄에 날짜·출발 시간·차량·기사·지금 단계를 보이면 될까요?" [3-1]
2. "운행 한 건에는 날짜·출발 구분·도착 구분·차량·기사·탑승 인원·운행 일지를 적으면 될까요?" [3-3]
3. "아침 첫 화면에 오늘 운행과 점검 날짜가 가까운 차량이 보이면 될까요?" [3-2]
4. "탑승자 명단 관리는 두 번째 흐름 단계로 미뤄도 될까요?" [3-7]
