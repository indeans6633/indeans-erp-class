# 인디언즈 돈 흐름

돈 흐름 단계(선택) 실습. 첫 흐름이 돌고 권한이 나뉜 앱에 **돈**을 담는다. 두 번째 흐름으로 돈을 고른 회사가 쓰고, 고르지 않았으면 건너뛴다.

돈은 다른 데이터와 다르다. 화면이 틀리면 다시 고치면 되지만, **잘못 들어간 금액은 그것을 믿고 한 일(청구·지급·신고)까지 틀리게 만든다.** 그래서 이 스킬은 기능보다 규칙이 먼저다. 인디언즈가 자체 앱의 돈 흐름을 운영하며 굳힌 규칙을 업종 무관하게 옮겼다.

1. **두 축을 섞지 않는다.** 받을 돈(들어오는 돈)과 줄 돈(나가는 돈·원가)은 다른 표·다른 합계다. 새 돈 흐름이 생기면 **어느 축인지부터** 정한다.
2. **금액은 한 가지 기준으로 적는다.** 공급가와 부가세를 따로 적고, 합계는 계산으로 만든다. 어떤 줄은 부가세 포함, 어떤 줄은 빼고 적으면 차감·합계가 조용히 어긋난다.
3. **증빙 종류는 금액과 따로 적는다.** 세금계산서·현금영수증·카드 같은 "무엇으로 받았나"는 금액 칸이 아니라 증빙 칸에.
4. **계산과 금지는 서버가 한다.** 합계·남은 돈·초과 금지는 데이터베이스 함수·제약에 둔다. 화면 계산만 있으면 두 화면의 합계가 달라지는 날이 온다.
5. **고치지 않고 쌓는다.** 잘못 넣은 금액은 지우거나 덮어쓰지 않고 **취소 기록**을 한 줄 더한다(사유와 함께). 그래야 언제 무엇이 바뀌었는지 남는다.
6. **돈이 들어가는 길은 하나.** "이미 받음" 같은 지름길 버튼이나 자동 연결이 같은 기록을 따로 만들면 같은 돈이 두 번 들어간다.
7. **금액을 볼 수 있는 역할을 제한한다.** 기본은 대표만. 화면에서 숨기는 것이 아니라 데이터베이스 규칙으로.

이 스킬은 **세무 판단을 하지 않는다.** 세율·신고·반올림 규칙은 회사의 세무 담당에게 확인해 `company/money.md` 에 적고, 앱은 그 규칙을 지키기만 한다.

## 언제 쓰나

- 인터뷰에서 "돈 계산"으로 미뤄 둔 항목을 앱에 담을 때.
- "이 건은 얼마 받았고 얼마 남았지"를 엑셀·수첩이 아니라 앱에서 보고 싶을 때.
- 나눠 받는 돈(계약금·중도금·잔금, 선금·잔금, 월 정기)의 받을 날을 놓치지 않고 싶을 때.

쓰지 않는 경우: 권한이 아직 안 나뉘었다(→ 먼저 `indeans-erp-people` — 돈은 볼 사람이 정해져야 담는다), 세금 신고·장부 작성 자체(이 앱이 대신하지 않는다), 급여 계산(이 과정 밖), 단계·상태만의 일(→ `indeans-erp-workflow`).

## 시작 전 상태 진단

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` · `.owner/progress.json` | 미해결 문제, `app.roles`(역할이 나뉘었나) |
| `company/structure.md` | **"이번에 만들지 않을 것"의 돈 계산 줄**과 대표가 말한 이유·바람 |
| `company/roadmap.md`(있으면) · `company/profile.md` | 돈 항목 · **돈이 들어오는 방식**(한 번에 / 나눠서 / 매달 / 판매 즉시) |
| `company/people.md` | 역할·노출 표 — 금액을 볼 수 있는 사람의 출발점 |
| `company/workflow.md` | 단계 코드 — 돈을 받는 때를 단계에 이을 수 있나 |
| `company/data.md` · `supabase/migrations/` | 관리 단위 표 이름, 이미 금액 칸이 있나(있으면 어느 표에 누가 읽나) |
| `company/backup.md` | 되돌리는 순서와 **복구를 해 본 날짜** |
| `company/money.md` | 있으면 두 번째 — 아래 분기 |

**상태 문서가 코드와 다르면 문서를 믿지 않는다.**

판정과 분기 — **넷을 모두 통과해야 시작한다.**

1. 역할이 나뉘었다(판정 함수와 역할별 규칙이 실제로 실행됨 — `company/data.md` 실행 기록). 아니면 → `indeans-erp-people` 먼저. "돈은 볼 사람을 정한 뒤에 담습니다."
2. `.owner/state.md` 미해결 문제에 데이터가 잘못 저장되는 문제가 없다.
3. `company/backup.md` 에 되돌리는 순서가 있다. 복구를 해 본 날짜가 없으면 시작은 하되 **실제 금액을 넣기 전에 복구 실습을 마친다**(조건으로 적는다).
4. 대표가 돈 흐름을 이번에 담기로 정했다(두 번째 흐름으로 돈을 골랐거나 직접 요청).

- **처음** — `company/money.md` 없음 → 절차 0부터.
- **두 번째** — 받을 돈이 이미 돈다 → 「앞선 수강생 분기」(줄 돈 축 등).
- 이미 업무 표에 금액 칸이 있으면 → 그 칸을 누가 읽는지부터 본다. 직원이 읽는 표에 있으면 **이번 작업의 1번은 그 칸을 별도 표로 옮기는 것**이다(옮기기 전 백업).

판정을 한 문장으로 알린다. 예: "역할은 나뉘어 있고 금액 칸은 아직 없습니다. 인터뷰 때 미뤄 두신 '계약금·잔금 관리'부터 담겠습니다. 질문 여섯 개 드리겠습니다."

## 절차

### 0. 되돌릴 지점

```bash
git add -A && git commit -m "돈 흐름 작업 전 상태"
```

### 1. 원리 (3분, 네 문장)

> 돈은 들어오는 돈과 나가는 돈을 다른 장부에 적습니다. 섞으면 합계가 거짓말을 합니다.
> 금액은 부가세를 뺀 금액과 부가세를 따로 적고, 무엇으로 받았는지(세금계산서·카드 등)는 또 따로 적습니다.
> 계산은 화면이 아니라 데이터베이스가 합니다. 그래야 어느 화면을 봐도 같은 숫자가 나옵니다.
> 잘못 넣은 돈은 지우지 않고 "취소" 기록을 더합니다. 언제 무엇이 바뀌었는지가 남아야 나중에 맞춰 볼 수 있습니다.

### 2. 미뤄 둔 것부터 꺼낸다

`company/structure.md` 의 "이번에 만들지 않을 것"에서 돈 계산 줄을, `roadmap.md`·`profile.md` 에서 돈 이야기를 찾아 **대표의 말 그대로** 읽어 준다.

> "인터뷰 때 '돈 계산'으로 미뤄 두신 것이 이것입니다: ○○. 그때 '△△ 때문에 필요하다'고 하셨습니다. 오늘은 이 중 **하나의 돈 흐름**만 담습니다. 어느 것부터 할까요?"

**한 번에 한 축, 한 흐름.** 대개 받을 돈(고객에게서)이 먼저다. 줄 돈(거래처 지급)은 받을 돈이 안정된 뒤 같은 방식으로 한 번 더 한다.

### 3. 인터뷰 — 한 번에 하나씩

질문 원문은 아래 그대로. 되묻기와 업종별 예는 `references/money-patterns.md`.

- **3-1 축** — "이 돈은 **회사로 들어오는 돈**입니까, **회사에서 나가는 돈**입니까?" → 둘이 섞인 답이면 나눈다("그럼 둘을 따로 적겠습니다").
- **3-2 나눠 받는 구조** — "한 건의 돈을 **몇 번에 나눠** 받으십니까? 각각을 회사에서 뭐라고 부르십니까?" → 회차 표(계약금·중도금·잔금 / 선금·잔금 / 월 정기 / 한 번에). 회차마다 "언제 받나"를 **단계**(예: 확정될 때·끝날 때)나 **날짜**로 받는다.
- **3-3 증빙** — "돈을 받을 때 남는 서류는 무엇입니까? 세금계산서, 현금영수증, 카드 전표, 간이영수증, 없음 중에서요." → 증빙 종류 목록. 그리고: "금액을 적을 때 **부가세를 빼고** 적으십니까, **포함해서** 적으십니까?" → 앱은 언제나 공급가·부가세를 따로 받는다. 합계만 아는 습관이면 "서류에 찍힌 합계와 부가세를 그대로 옮기면 공급가는 앱이 계산합니다"라고 안내한다. 반올림·면세 여부는 세무 담당 확인 사항으로 적는다.
- **3-4 볼 사람** — "금액을 **볼 수 있는** 사람은 누구입니까? **넣는** 사람은요? 잘못 넣은 것을 **취소**하는 사람은요?" → 기본은 셋 다 대표. 직원이 넣어야 하면 "넣기만 하고 합계는 못 보게"가 되는지 묻는다 — 되면 그렇게 나눈다.
- **3-5 바로잡기** — "잘못 넣은 금액은 지금 어떻게 바로잡으십니까?" → 앱에서는 **취소 기록 + 사유**로만 바로잡는다고 알려 주고 동의를 받는다.
- **3-6 맞춰 보는 숫자** — "한 달에 한 번 **맞춰 보는 숫자**가 있습니까? 예를 들어 이번 달 받은 돈 합계와 통장 입금 합계요." → 감사(`erp-auditor`)와 주간 점검에서 볼 확인 항목이 된다.

받은 답을 표 한 장으로 되읽어 확인한다. **금액 값은 받지 않는다** — 구조와 이름만 적는다.

### 4. `company/money.md` 로 남긴다

`assets/money.template.md` 를 채워 `company/money.md` 로 저장한다. 축 정의 · 회차 표 · 증빙 목록 · 금액 적는 기준 · 볼 사람 · 바로잡는 법 · 서버가 지킬 규칙 · 맞춰 볼 숫자. `structure.md` 의 돈 계산 줄은 "언제" 칸을 `진행 중(money.md)` 으로 바꾼다.

### 5. 표 설계 — `assets/money-tables.template.sql`

다음 번호 파일로 옮겨 `<꺾쇠>` 를 `money.md` 대로 바꾼다. 들어 있는 것:

- **받을 돈 일정**(`money_in_plan`) — 건마다 회차 한 줄씩. 회차는 영문 코드로 저장하고 화면 글자는 앱이 갖는다.
- **받은 돈 기록**(`money_in`) — 받을 때마다 한 줄. 공급가·부가세·증빙 종류·받은 날. **고치기·지우기 규칙이 없다**(쌓이기만 한다). 취소 기록은 원래 줄 번호를 가리키고, 한 줄은 한 번만 취소된다.
- **서버가 지키는 규칙** — 0원 이하 금지 · 한 줄 10조 원 미만(합계는 서버가 넘치지 않게 더한다) · 취소 기록은 원래 금액을 그대로 따르고 사유가 반드시 있음 · **받은 돈 합계가 받을 돈 일정 합계를 넘지 못함**(추가로 받기로 했으면 일정을 먼저 더한다) · 이미 받은 것보다 일정을 작게 줄이지 못함 · 같은 건에 동시에 온 일은 한 줄씩 차례로(그 건의 `money_version` 을 고쳐 세운다). 이 검사는 모든 줄을 봐야 해서 권한 높은 함수로 돌고, 가드 세 줄이 들어 있다. 금액을 못 보는 사람이 막히면 이유 없이 "접수할 수 없습니다 — 대표에게 확인하세요"만 나온다(오류 문구로 남은 돈을 알아낼 수 없게).
- **건별 합계**(`money_in_by_job`) — 일정 합계·받은 합계·남은 돈. 잠금을 그대로 따르는 뷰(`security_invoker`)라 금액을 못 보는 역할에게는 줄이 안 나온다.
- **볼 사람 규칙** — 기본은 대표만 읽기·넣기. `money.md` 3-4 답대로 `money_can_read()`(보기)·`money_can_write()`(넣기) 두 함수만 고친다 — 규칙과 서버 검사가 같은 함수를 쓴다.

금액은 **원 단위 정수**(`bigint`)다. 소수 자리 숫자·실수를 쓰지 않는다. 화면에서도 금액끼리 곱하고 나누지 않는다(부가세·합계는 서버 결과를 표시만).

### 6. 실행 전 — 게이트와 롤백 시뮬

1. `npm run check` — 막힘이 없어야 한다.
2. **롤백 시뮬 두 번** — `indeans-erp-check` 의 `references/rollback-sim.md`:
   - 틀 1(정책): 직원 계정 0줄 · 대표 계정 일정 줄 수 · 로그인 안 함 막힘.
   - 틀 2(제약): 맞는 값(일정 안의 금액) 들어감 · 틀린 값(일정을 넘는 금액, 0원, 이미 취소된 줄을 또 취소) 막힘.
3. 적용 → `company/data.md` 실행 기록 한 줄.

### 7. 화면 — 계산은 표시만

1. 건 상세 화면에 **돈 칸 한 덩어리**: 받을 돈 일정(회차·받을 때·금액) · 받은 기록 · 남은 돈. 숫자는 `money_in_by_job` 에서 읽기만 한다.
2. 받은 돈 넣기 — 회차 고르기 · 공급가 · 부가세 · 증빙 종류 · 받은 날. 입력은 숫자만, 쉼표는 보이기만. 서버가 막으면(초과 등) 그 문장을 그대로 보여 준다.
3. **취소 기록 남기기** 버튼 — 사유 필수, 확인 한 번. 원래 줄 옆에 "취소됨" 표시.
4. 대표가 아니면 돈 칸이 **아예 그려지지 않는다**(화면 편의 — 방어선은 5단계 규칙).
5. 목록에 금액을 싣지 않는다. 필요하면 "받을 날 지난 건 3건"처럼 **건수**로.

### 8. 확인 — 손계산과 가장 권한 낮은 자리

`erp-verifier` 에게 맡기고, 손계산은 대표가 직접 한다.

- **실제 1건을 계산기로 맞춘다** — 일정 합계 − 받은 합계 = 남은 돈. 화면 숫자와 1원까지 같아야 한다.
- 취소 기록을 하나 넣고 남은 돈이 원래대로 돌아오는지.
- 일정을 넘는 금액을 넣어 보고 **막히는지**(서버 문장이 보이는지).
- 직원 계정으로 상세 화면·표 직접 읽기 → 금액이 하나도 안 나온다. 로그인 안 한 상태도.
- 다른 화면(목록·운영 보고)에 금액이 새지 않는지.

### 9. 검수·감사·상태 문서

## 하지 않는 것

- 받을 돈과 줄 돈을 한 표·한 합계에 섞지 않는다. 부가세 포함·불포함을 줄마다 다르게 적지 않는다.
- 금액 계산을 화면 코드에만 두지 않는다. 금액을 덮어쓰거나 지워서 바로잡지 않는다.
- 같은 돈을 만드는 두 번째 길(지름길 버튼·자동 연결)을 만들지 않는다. 필요하면 원래 길을 그대로 부른다.
- 권한이 나뉘기 전에 금액을 담지 않는다. 직원이 읽는 업무 표에 금액 칸을 두지 않는다.
- 세율·신고·반올림을 정해 주지 않는다(세무 담당 확인 사항으로 적는다). 실제 금액을 대화창·채널·문서에 적지 않는다.
- 롤백 시뮬·손계산 없이 "맞습니다"라고 보고하지 않는다.

## 앞선 수강생 분기

받을 돈이 안정적으로 돌면 하나만 고른다.

1. **줄 돈 축** — 거래처 지급·외주비를 같은 모양의 **다른 표**(`money_out_plan`·`money_out`)로. 건에 묶이지 않는 회사 공통 비용(사무실·소모품)은 가짜 건을 만들지 말고 '공통' 표시로 받아 건별 합계·목록에서 빠지게 한다. `references/money-patterns.md` 7절.
2. **월 마감 대조** — 3-6의 맞춰 볼 숫자를 질의 한 덩어리로 만들어 주간 점검 넷째 주에 돌린다(감사 M 항목과 함께).
3. **받을 날 놓침 신호** — 받을 단계·날짜가 지났는데 받은 기록이 없는 일정을 건수로 운영 보고에 한 줄.

## 자주 막히는 지점

- **"그냥 금액 칸 하나만 있으면 되는데요"** — 금액 칸 하나는 언젠가 부가세 포함·불포함이 섞이고, 바로잡을 때 이전 값이 사라진다. 일정·기록 두 표가 오히려 덜 헷갈린다고 설명하고, 화면은 한 덩어리로 단순하게 만든다.
- **넣으려는데 "받을 돈 계획보다 많이 받을 수 없습니다"** — 규칙이 맞게 돈 것이다. 추가 금액이 생겼으면 일정에 한 줄 더한 뒤 넣는다.
- **직원도 받은 돈을 넣어야 한다** — `money_can_write()` 에 직원을 더하고 `money_can_read()` 는 그대로 둔다(넣기만). 넣은 직후 화면이 합계를 다시 읽지 못하는 것, 막혔을 때 이유 없이 "접수할 수 없습니다 — 대표에게 확인하세요"만 나오는 것, 취소는 못 하는 것이 정상이다(이유는 대표 화면의 남은 돈에서 본다).
- **부가세가 1원 다르다** — 서류의 반올림과 계산 방식이 다르다. 서류에 찍힌 값을 그대로 넣고, 규칙은 세무 담당 확인 뒤 `money.md` 에 적는다. 감사가 1원 넘는 차이만 알린다.
- **옛 엑셀의 받은 기록을 옮기고 싶다** — 한 번에 다 옮기지 않는다. 진행 중인 건만 옮기고, 옮긴 건마다 손계산으로 남은 돈을 맞춘다. 옮기기 전 백업.
