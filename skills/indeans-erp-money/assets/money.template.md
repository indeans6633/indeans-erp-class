## 2. 두 축 — 받을 돈과 줄 돈을 섞지 않는다

| 돈 흐름(회사 말) | 축 | 표 | 이번에 담나 |
|---|---|---|---|
| <고객에게 받는 대금> | 받을 돈(들어오는 돈) | `money_in_plan` · `money_in` | 예 |
| <거래처에 주는 대금> | 줄 돈(나가는 돈·원가) | `money_out_plan` · `money_out`(다음에) | 다음에 |

- 새 돈 흐름이 생기면 **이 표에 축부터 정해 적은 뒤** 만든다.
- 두 축을 한 합계로 더하지 않는다(받을 돈 − 줄 돈 같은 "남은 이익" 계산은 이 앱의 범위 밖 — 하게 되면 따로 정한다).

## 3. 나눠 받는 구조 (회차)

| 회차 코드(저장 값) | 회사에서 부르는 말 | 기준 | 언제 받나 |
|---|---|---|---|
| `deposit` | <계약금> | <일정 금액 / 비율 — 금액 값은 적지 않는다> | <단계 '확정' 때 / 계약일> |
| `balance` | <잔금> | | <단계 '완료' 때> |

- 회차 코드는 영문으로 저장하고 화면 글자는 앱이 갖는다. 회사 말을 바꿔도 지난 기록은 그대로다.
- 월 정기·건별 즉시처럼 회차가 없는 회사는 `monthly` / `once` 한 줄로.

| 증빙 코드(저장 값) | 회사 말 | 쓰나 |

| `card` | 카드 | |

- 금액은 **공급가와 부가세를 따로** 적는다. 합계는 서버가 만든다.
- 서류에 합계만 있으면: 합계와 부가세를 그대로 넣고 **공급가는 서버가 합계 − 부가세로 계산**한다.
- 세금 구분(과세 / 면세 / 부가세 없음): <  >
- 부가세 반올림 규칙: <세무 담당 확인 — 확인한 날 YYYY-MM-DD> (이 앱은 세무 판단을 하지 않는다)
- 금액 단위: 원(정수). 소수 자리 없음.

## 5. 볼 사람

| 할 일 | 누가 | 데이터베이스 규칙 이름 |
|---|---|---|
| 금액 보기(일정·기록·합계) | <대표> | `money_can_read()` → `money_in_plan_read` · `money_in_read` |
| 받은 돈 넣기 | <대표 / 대표와 직원> | `money_can_write()` → `money_in_insert` |
| 취소 기록 남기기 | <대표> | 볼 수 있고 넣을 수 있는 사람만(넣기만 하는 사람은 못 함) |
| 일정 만들기·고치기 | <대표> | `money_in_plan_insert` · `money_in_plan_update` |

- 화면에서 숨기는 것이 아니라 위 규칙이 막는다. 직원 계정으로 실측한 날: <YYYY-MM-DD>
- 금액을 못 보는 사람이 넣다가 막히면 이유 없이 "접수할 수 없습니다 — 대표에게 확인하세요"만 본다. 이유는 대표가 화면의 남은 돈에서 본다.
- 목록·운영 보고에는 금액이 아니라 **건수**만 싣는다.

## 6. 바로잡는 법

- 받은 돈 기록은 **고치지도 지우지도 않는다.** 잘못 넣었으면 **취소 기록**(원래 줄 번호 + 사유)을 한 줄 더한다.
- 한 줄은 한 번만 취소된다. 취소 기록은 원래 금액을 그대로 따른다.
- 받을 돈 일정을 바꾸면(추가 계약 등) 일정을 더하거나 고친다. 이미 받은 것보다 작게는 못 줄인다.
- 돈이 들어가는 길은 하나: 앱은 `record_money_in` · `cancel_money_in` 두 함수만 부른다.

## 7. 서버가 지키는 규칙 (데이터베이스에 있다)

| 규칙 | 어디에 | 롤백 시뮬로 확인한 날 |
|---|---|---|
| 0원 이하 금지 · 한 줄 10조 원 미만 | 제약(check) | |
| 받은 돈 합계 ≤ 받을 돈 일정 합계 | `money_in_guard` | |
| 취소 기록은 원래 금액 그대로 · 한 번만 · 사유 필수 | `money_in_guard` · unique · check | |
| 이미 받은 것보다 일정을 줄이지 못함 · 다른 건으로 못 옮김 | `money_in_plan_guard` | |
