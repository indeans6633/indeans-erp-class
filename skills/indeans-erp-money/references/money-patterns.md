# 돈 흐름 — 패턴·흔한 실수·검사 질의

`indeans-erp-money` 가 읽는 참고 자료. 대표에게 통째로 읽어 주지 않는다. 인터뷰에서 되물을 때와 감사·검사 질의를 만들 때 쓴다.
인디언즈가 자체 앱의 돈 흐름에서 실제로 겪은 사고를 **업종 무관한 형태로** 옮겼다. 회사 이름·금액·사례 번호는 없다.

---

## 1. 두 축 — 왜 섞으면 안 되나

| 업종 | 받을 돈(들어오는 돈) | 줄 돈(나가는 돈·원가) |
|---|---|---|
| 제조 | 납품 대금 | 원자재 매입·외주 가공비 |
| 유통 | 판매 대금·도매 결제 | 매입 대금·배송비 |
| 서비스(수리·점검) | 수리비·점검비 | 부품비·협력 기사 비용 |
| 예약업 | 예약금·이용 대금 | 대행 수수료·소모품 |

한 표에 둘을 섞고 부호(+/−)로 나누면, 어느 날 "부호를 반대로 넣은 한 줄" 때문에 받을 돈 합계와 원가 합계가 **둘 다** 틀린다. 두 축은 표부터 나눈다. 같은 돈이 두 축에 다 걸려 보일 때(고객이 낸 돈 중 일부를 거래처에 바로 넘기는 경우)도 **받은 기록 한 줄 + 준 기록 한 줄**로 각각 적는다.

**되묻기** — "이 돈은 회사 통장에 들어옵니까, 나갑니까?" 답이 "둘 다"면 들어오는 순간과 나가는 순간을 나눠 묻는다.

## 2. 나눠 받는 구조 — 회사 말로

| 업종 | 흔한 구조(회사 말 예) | 받는 때를 무엇에 잇나 |
|---|---|---|
| 제조 | 선금 · 잔금 | 단계(수주 확정 / 출하) |
| 유통 | 월말 결제 | 날짜(매월 말일) |
| 서비스 | 한 번에 | 단계(작업 완료) |
| 예약업 | 예약금 · 방문 당일 결제 | 단계(예약 확정 / 이용) |
| 주문 제작·프로젝트처럼 기간이 긴 일 | 계약금 · 중도금 · 잔금 | 단계 |

**되묻기** — "각각을 회사에서 뭐라고 부르십니까?" (회사 말 그대로 받는다) · "그 돈은 일이 어디까지 왔을 때 받습니까?" (단계 코드에 잇는다 — 날짜보다 단계가 덜 틀린다).

## 3. 증빙과 금액 — 한 가지 기준

- **공급가와 부가세를 따로** 적는다. "어떤 줄은 부가세 포함 금액, 어떤 줄은 뺀 금액"이 섞이는 것이 돈 데이터 오염의 가장 흔한 시작이다. 섞이면 "계약 금액에서 받은 돈을 빼는" 계산이 줄마다 다른 기준으로 돌아 조용히 어긋난다.
- 서류에 합계만 크게 찍혀 있으면 **합계와 부가세를 그대로** 옮기고 공급가는 서버가 계산한다(합계 − 부가세). 사람이 나눗셈(÷1.1)을 하지 않는다 — 반올림 때문에 1원씩 틀린다.
- **증빙 종류는 금액과 다른 칸.** "카드 결제분"을 금액 칸 메모로 적으면 증빙별로 세지 못한다.
- 반올림·면세·세율은 이 앱이 정하지 않는다. 세무 담당 확인 사항으로 `money.md` 에 적는다.

## 4. 계산은 서버에서

화면 코드에서 합계를 계산하면, 화면이 둘이 되는 날(목록 합계와 상세 합계) 계산식이 두 벌이 되고, 한쪽만 고치는 날 숫자가 갈린다. **합계·남은 돈은 데이터베이스의 한 곳(건별 합계 뷰)** 에서 만들고 화면은 읽기만 한다. "넘으면 안 되는 금액"도 화면의 입력 검사가 아니라 데이터베이스의 제약·가드가 막는다 — 화면 검사만 있으면 버튼을 거치지 않는 길(다른 화면·자동 연결·직접 요청)로 그대로 들어간다.

## 5. 되돌리기 기록 — 지우지 않고 쌓는다

| 하고 싶은 것 | 하지 않는 것 | 하는 것 |
|---|---|---|
| 금액을 잘못 넣었다 | 그 줄 고치기 | 취소 기록(원래 줄 + 사유) → 맞는 금액으로 새 줄 |
| 받은 줄 알았는데 안 받았다 | 그 줄 지우기 | 취소 기록 |
| 계약이 늘었다 | 받은 기록을 늘리기 | 받을 돈 일정에 한 줄 더하기 |
| 환불했다 | 받은 기록 지우기 | 취소 기록(전액) 또는 줄 돈 축에 환불 기록(회사 방식대로 money.md 에 정한다) |

취소 기록은 원래 금액을 그대로 따르고, 한 줄은 한 번만 취소된다. 그래야 "몇 번 고쳤는지"와 "왜 고쳤는지"가 남는다.

## 6. 돈이 들어가는 길은 하나

"이미 받음" 같은 지름길 버튼이나 "증빙을 등록하면 받은 돈이 자동으로 생기는" 연결은 편하지만, **같은 돈을 만드는 두 번째 길**이 된다. 두 길이 각자 받은 돈을 만들면 같은 돈이 두 번 들어가고, 계약 금액에서 두 번 빠진다.

- 지름길이 필요하면 **원래 길(`record_money_in`)을 그대로 부르는** 버튼으로 만든다. 로직을 다시 쓰지 않는다.
- 자동 연결을 만들면 "이미 만들어졌으면 건너뛰기" 검사를 **다른 모든 검사보다 먼저** 둔다. 권한 검사 뒤에 두면, 권한 검사가 먼저 실패하거나 통과하는 경로에 따라 건너뛰기가 실행되지 않는 순서가 생긴다.

## 7. 줄 돈 축과 회사 공통 비용

- 줄 돈은 받을 돈과 **같은 모양의 다른 표**(`money_out_plan`·`money_out`)로 만든다. 받는 쪽 대신 주는 쪽(거래처 — 이름은 회사 말로, 실명 대신 거래처 표의 번호)을 잇는다.
- **건에 묶이지 않는 돈**(사무실 임대·소모품)은 가짜 건을 만들어 붙이지 않는다. 건 칸을 비우고 '공통' 표시(`scope = 'common'`)를 두어, 건별 합계·업무 목록·운영 보고에서 빠지게 한다. 가짜 건을 만들면 업무 목록에 "사무실"이라는 건이 섞여 건수가 거짓말을 한다.
- 줄 돈을 받을 돈으로 바꾸는 전환(거래처에 줄 돈을 고객에게 청구로 돌리기)이 필요하면 그 경로는 대표만, 기록과 함께.

## 8. 흔한 실수 패턴

| 증상 | 원인 | 막는 법 |
|---|---|---|
| 같은 돈이 두 번 들어감 | 지름길·자동 연결이 따로 기록을 만듦 | 길은 하나(6절), 건너뛰기 검사 먼저 |
| 받은 돈 합계가 계약보다 큼 | 화면에서만 막음 | 서버 가드(초과 금지) |
| 합계가 화면마다 다름 | 계산식이 화면마다 있음 | 서버 합계 뷰 한 곳 |
| 1원씩 어긋남 | 사람이 ÷1.1 계산 | 서류 값 그대로 + 서버 뺄셈 |
| 금액이 직원 화면에 보임 | 직원이 읽는 업무 표에 금액 칸 | 돈은 별도 표 + 대표만 읽기 |
| 고친 이력이 없음 | 금액 덮어쓰기 | 취소 기록 |
| 어느 증빙으로 받았는지 모름 | 메모에 적음 | 증빙 종류 칸 |
| 받을 돈·줄 돈 합계가 둘 다 틀림 | 한 표에 부호로 섞음 | 두 축을 다른 표로 |
| 사무실 비용이 업무 목록에 섞임 | 가짜 건 | '공통' 표시 |

## 9. 검사 질의 — 한 덩어리 (읽기 전용)

SQL Editor 에 통째로 붙여 넣고 Run. 결과 표의 `건수` 가 모두 0이어야 한다. **금액 값·고객 정보는 나오지 않는다** — 건수와 행 번호만. 감사관(`erp-auditor`)이 같은 항목을 이 회사 표에 맞춰 만든다.

```sql
select 'M1 초과 수납' as 항목, count(*) as 건수, string_agg(job_id::text, ',') as 예시
  from (select job_id from public.money_in_by_job where remaining < 0 limit 5) x
union all
select 'M2 취소 기록 고아·이중', count(*), string_agg(id::text, ',')
  from (select m.id from public.money_in m
         where m.reverses_id is not null
           and not exists (select 1 from public.money_in o where o.id = m.reverses_id and o.reverses_id is null)
         limit 5) x
union all
select 'M3 중복 입력 의심(같은 건·날·금액·증빙)', count(*), string_agg(k, ',')
  from (select min(id::text) as k from public.money_in
         where reverses_id is null
         group by job_id, received_on, supply_amount, vat_amount, evidence_type
        having count(*) > 1 limit 5) x
union all
select 'M4 증빙 누락', count(*), string_agg(id::text, ',')
  from (select id from public.money_in where evidence_type is null or evidence_type = '' limit 5) x
union all
select 'M6 0원 이하', count(*), string_agg(id::text, ',')
  from (select id from public.money_in where supply_amount <= 0 or vat_amount < 0 limit 5) x
union all
select 'M7 부가세 1원 넘게 어긋남(세금계산서)', count(*), string_agg(id::text, ',')
  from (select id from public.money_in
         where evidence_type = 'tax_invoice' and reverses_id is null
           and abs(vat_amount * 10 - supply_amount) > 10 limit 5) x;
```

- 건수는 "예시 5개까지"를 센 것이다. 5가 나오면 더 있을 수 있다 — 감사관에게 전체 건수를 세게 한다.
- M7 은 부가세가 공급가의 10분의 1과 1원 넘게 다른 줄이다. 면세·부가세 없는 거래는 빼고 본다(`money.md` 4절). 세율이 다른 회사는 이 줄을 고친다.
- M5(축 섞임)는 줄 돈 축을 만든 뒤 두 축의 연결 칸을 보고 감사관이 만든다.
