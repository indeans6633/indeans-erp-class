# 우리 회사 사람과 권한

> 이 파일은 `indeans-erp-people` 스킬이 인터뷰 답변으로 채운다. 절 제목과 표 형식은 바꾸지 않는다 — 감독(`erp-supervisor`)·감사(`erp-auditor`)·알림 스킬이 이 표를 읽는다.
> **실제 직원·고객 이름은 적지 않는다.** 역할 이름으로만 적는다. 비밀번호·접속 키도 적지 않는다.

- 작성일: YYYY-MM-DD
- 이 앱을 쓰는 사람 종류 수:
- 로그인 방식: 이메일 + 비밀번호 (가입 화면 없음 — 대표가 계정을 만들어 준다)

## 2. 보면 안 되는 것 (실측 체크리스트)

| 역할 | 절대 보이면 안 되는 것 | 지금은 무엇으로 막고 있나 | 앱에서 막은 방법(규칙 이름) | 확인함 |
|---|---|---|---|---|
|  |  |  |  | [ ] |
|  |  |  |  | [ ] |

- 확인 칸은 세 값 중 하나다: `[ ]` 아직 / `[x]` 실측함 / `[-]` **아직 앱에 그 칸·기능이 없음**. 빈칸으로 두면 "안 막았다"와 구분이 안 된다.
- "앱에서 막은 방법"에는 **데이터 규칙 이름**을 적는다. "화면에서 숨김"만 적혀 있으면 아직 안 막은 것이다.

## 3. 노출 표 — 정책의 설계도 (코드보다 먼저 채운다)

칸마다 `전부` / `자기 것만` / `안 됨`. 정책 한 줄은 이 표의 한 칸이다. 표에 없는 정책을 만들지 않는다.

|---|---|---|---|---|---|---|
| `<업무 표>` 목록·상세 | 전부 | 전부 | 전부 | 전부 | 전부 | 안 됨 |
| `<업무 표>` 사진·파일 |  |  |  |  |  |  |
| 내보내기(CSV) |  |  |  |  |  |  |
| 알림·운영 보고 본문 |  |  |  |  |  |  |
| `app_users`(사람 명단) | 전부 | 전부 | 안 됨 | 자기 것만 | 안 됨 | 안 됨 |

## 5. 들어오고 나가는 절차

- 새 사람 추가: (누가 계정을 만드나 / 역할은 누가 정하나)

- 그만둘 때: **차단**(기본) / 삭제
- 차단할 때 같이 할 일:
  - [ ] 활성(`active`)을 끈다 — 판정 함수가 활성을 보므로 데이터가 바로 안 나간다
  - [ ] 그 사람의 로그인 기록(`auth.sessions`)을 정리한다 — 이미 받아 간 출입증은 만료까지 남을 수 있다
