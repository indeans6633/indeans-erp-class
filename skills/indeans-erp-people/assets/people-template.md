# 우리 회사 사람과 권한

> 이 파일은 `indeans-erp-people` 스킬이 인터뷰 답변으로 채운다. 절 순서와 표 형식은 바꾸지 않는다.
> **실제 직원·고객 이름은 적지 않는다.** 역할 이름으로만 적는다. 비밀번호·접속 키도 적지 않는다.

- 작성일: YYYY-MM-DD
- 이 앱을 쓰는 사람 종류 수:
- 로그인 방식: 이메일 + 비밀번호 (가입은 대표가 초대)

| 저장 값 | 회사에서 부르는 이름 | 누가 해당되나 | 로그인 직후 첫 화면 |
|---|---|---|---|
| `owner` | 대표 |  |  |
| `staff` |  |  |  |

- **기본은 이 두 개**다. 저장 값은 바꾸지 않고, 화면에 보이는 이름만 회사 말로 바꾼다.
- 역할을 더 만들지 않는다. 보는 범위가 같으면 합친다. 확인해야 할 조합이 역할 수만큼 늘어난다.

## 2. 보면 안 되는 것 (확인 체크리스트)

| 역할 | 절대 보이면 안 되는 것 | 지금은 무엇으로 막고 있나 | 앱에서 막은 방법 | 확인함 |
|---|---|---|---|---|
|  |  |  |  | [ ] |
|  |  |  |  | [ ] |
|  |  |  |  | [ ] |

- 확인 칸은 세 값 중 하나다: `[ ]` 아직 확인 안 함 / `[x]` 확인함 / `[-]` **아직 앱에 그 칸·기능이 없음**. 빈칸으로 두면 "안 막았다"와 구분이 안 된다.
- "앱에서 막은 방법"에는 **데이터 규칙 이름**을 적는다. "화면에서 숨김"만 적혀 있으면 아직 안 막은 것이다.
- 확인은 그 역할 계정으로 **직접 로그인해서** 한다. 목록뿐 아니라 상세·검색·사진·파일까지 열어 본다.

## 3. 기록을 남기는 행동

| 무슨 일 | 남기는 내용 | 누가 볼 수 있나 |
|---|---|---|
|  | 누가 / 언제 / 무엇에서 무엇으로 |  |
|  |  |  |

- 두세 개만 고른다. 전부 남기면 아무도 안 본다.
- 기록은 고치거나 지울 수 없게 둔다.

## 4. 들어오고 나가는 절차

- 새 사람 추가: (누가 만드나 / 역할은 누가 정하나)
- 역할 변경: (누가 바꾸나 / 기록 남기나)
- 그만둘 때: 차단 / 삭제 — 기본은 **차단**
- 차단할 때 같이 할 일:
  - [ ] 활성 여부를 데이터 규칙 안에서 본다(출입증이 남아 있어도 데이터가 안 나가게)
  - [ ] 접속 기록(세션)을 정리한다
  - [ ] 알림·메일 수신 목록에서 뺀다

## 5. 만든 것

- [ ] 이메일 로그인 (가입 화면은 열어 두지 않음)
- [ ] 역할 표 (역할 칸 비워 둘 수 없음 · 활성 여부 있음)
- [ ] 역할 판정 함수 (**실행 권한 회수하지 않음**)
- [ ] 모든 표에 행 단위 보안 켬
- [ ] 표별 역할 규칙 (허용 목록 방식)
- [ ] 역할별 첫 화면 분기
- [ ] 변경 기록 — **앱이 실제로 기록을 넣는 자리까지 있어야 체크한다.** 표와 규칙만 만들고 체크하면 아무 기록도 안 남는데 남는다고 믿게 된다. 3절에 적은 행동을 하나 실제로 해 보고 기록이 한 줄 늘어난 것을 본 뒤 체크한다.

## 6. 확인한 것

- [ ] 역할별 계정으로 각각 로그인해 첫 화면을 봤다 (캡처 3장)
- [ ] 2절 체크리스트를 한 줄씩 대조했다
- [ ] 역할이 빈 계정으로 로그인해 보니 아무것도 안 보였다
- [ ] 로그인 안 한 상태로 열어 보니 아무것도 안 보였다
- [ ] 권한을 붙이기 전에 잘 되던 화면들이 지금도 그대로 된다
