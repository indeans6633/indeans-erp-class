# 인디언즈 작업 보고서

> **1일 차 라이브 판(11-17 리허설 반영)** — 공개 번들 v3.2 원본에서 회차 말(1일 차 카드 B3 보고서에서 씀)만 바꿨다. 비교용 원본: `proposed-skills/_원본/`.

**이 스킬의 역할은 "방금 한 작업을 대표에게 보여 주는 것"이다.** 잘 만들었는지 판정받는 일은 `indeans-erp-check`가 한다.

보고서는 `reports/<날짜>-<제목>.html` 파일 한 장이다. **내 컴퓨터 안에서만 만들어지고 어디로도 전송되지 않는다.** Claude Code와 Codex 양쪽에서 같은 방법으로 만든다.

## 언제 쓰나

- 작업을 끝낼 때마다(계정 가입·인터뷰·디자인 선택·초안 생성·개선·저장 연결·배포·권한·운영 보고 — 무엇이든). **작업 하나에 보고서 하나다.**
- 1일 차 끝(카드 B3)에 "오늘 무엇을 했는지" 한 장으로 남길 때.
- `indeans-erp-check`가 감독 판정·실측을 마친 뒤(그 결과를 보고서에 더한다).

수업 시간에 따로 배우는 주제가 아니다. **다른 스킬이 끝나면서 부르는 기본 동작**이다.

## 시작 전 상태 진단

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` · `.owner/progress.json` | 이번에 무엇을 하려 했는지(다음 행동)·미해결 문제 |
| `git status` · `git log --oneline -5` | 방금 무엇이 바뀌었는지. **추측하지 않고 실제 변경을 본다** |
| `reports/` | 오늘 날짜 보고서가 이미 있는지 |
| `company/structure.md` | 화면 이름·회사에서 쓰는 말·"이번에 만들지 않을 것" |
| `company/screens.md` · `company/design.md` | 화면별 설계 선언(목적·주 사용자·가장 중요한 행동·쓰지 않을 것)·고른 디자인 |
| `package.json` | 앱을 띄우는 명령(보통 `npm run dev`). 없으면 아직 앱이 없는 작업이다 |
| `.owner/hooks/report.mjs` · `capture.mjs` | 보고서 생성기와 캡처 도구가 설치돼 있는지 |

판정과 분기:

- **바뀐 것 없음** — 커밋도 변경도 없다 → 보고서를 만들지 않는다. "보고할 변경이 없습니다"라고 한 줄로 알리고 멈춘다.
- **오늘 보고서 있음** — 같은 작업의 연장이면 **같은 제목·같은 `--slug`로 다시 만들어** 그 파일을 갱신한다(파일이 하나로 유지된다). 다른 작업이면 새 제목으로 만든다.
- **화면이 없는 작업**(계정 가입·인터뷰·디자인 선택·문서·설정) → 캡처 없이 글만으로 만든다. 없는 사진을 만들지 않는다. 디자인 선택이 끝났으면 고른 것(구조·스타일·색·밝기)과 고른 이유(대표의 말)를 "무엇이 달라졌나"에 쓴다.
- **생성기 없음** — `.owner/hooks/report.mjs`가 없다 → 설치기를 다시 돌리게 안내한다.

판정을 한 문장으로 먼저 알린다. 예: "오늘 초안 앱을 만든 변경이 있습니다. 초안 보고서를 만들겠습니다."

## 절차

### 1. 무엇이 바뀌었는지 확인

```
git status --porcelain
git log --oneline -5
git diff --stat HEAD~1
```

- 대화 기억이 아니라 **실제 변경 목록**을 근거로 쓴다. 기억과 다르면 실제를 따른다.
- 바뀐 것을 대표의 말로 묶는다. 예: 파일 세 개가 바뀌었어도 대표에게는 "목록 화면 한 곳"이다.
- **일부러 손대지 않은 것**도 같이 정리한다(절차 3의 "바꾸지 않은 것"). 변경 목록에 없는 화면·문서 중 대표가 "그것도 바뀌었나?" 하고 물을 만한 것이다.

### 2. 화면 사진 찍기 (화면이 바뀐 작업만 — 기능당 한 번)

앱을 다른 창에서 띄운 뒤 찍는다.

```
npm run dev
```

터미널에 찍힌 주소를 그대로 쓴다(5173이 쓰이고 있으면 5174로 뜬다 — 짐작하지 않는다). 아래 예시는 **PowerShell 기준**이다.

```
# 첫 화면
node .owner/hooks/capture.mjs --url http://localhost:5173 --name list

# 버튼·탭을 눌러야 나오는 화면 — 화면에 보이는 글자를 그대로 준다
node .owner/hooks/capture.mjs --url http://localhost:5173 --click "오늘 현황" --name today

# 두 번 눌러 들어가는 화면(상세) — 적은 순서대로 누른다
node .owner/hooks/capture.mjs --url http://localhost:5173 --click "목록" --click "<목록 한 줄에 보이는 이름>" --name detail

# 주소가 따로 있는 화면(라우터를 쓰는 앱·가져온 앱)
node .owner/hooks/capture.mjs --url http://localhost:5173 --path "/orders" --name orders

# 내 컴퓨터의 파일(디자인 선택창처럼 dev 서버 없이 여는 화면) — --path 를 같이 쓰지 않는다
node .owner/hooks/capture.mjs --url "file:///<프로젝트>/.owner/design/index.html" --name design
```

- **`--click`** — 초안 앱은 화면 전환을 주소가 아니라 버튼으로 하므로 상세·오늘 현황은 `--path`로 못 찍는다. 화면에 보이는 버튼·탭·줄의 글자를 **회사 말 그대로** 준다. 여러 번 쓰면 적은 순서대로 누른다. 못 누르면 그 사진은 빠지고 `"…" 를 누르지 못했습니다`와 이유가 찍힌다 — 실제로 보이는 글자로 다시 준다.
- **파일 주소** — `<프로젝트>` 자리는 `git rev-parse --show-toplevel`이 알려 주는 경로를 그대로 쓴다(윈도우도 `/`로 나온다). 예: 윈도우 `file:///C:/work/my-erp/.owner/design/index.html`, 맥 `file:///Users/<이름>/work/my-erp/.owner/design/index.html`. 사진 이름은 `--name`을 주지 않으면 파일 이름(`index`)으로 만들어진다.
- **Git Bash 주의** — Git Bash에서 `--path "/orders"`를 주면 셸이 그것을 컴퓨터 폴더 경로로 바꿔 버린다. `--path "//orders"`처럼 `/`를 하나 더 붙이거나 PowerShell에서 실행한다(`capture.mjs`가 알아보고 되돌리며 그 사실을 알려 준다).
- **폭** — 새 기능은 휴대폰(375)·PC(1280) 두 장이 기본이다. 고친 뒤 다시 찍을 때는 바뀐 화면만 `--widths "375"`로 찍는다. 사진은 `reports/shots/<날짜>/`에 쌓인다.
- **보고서에 넣는 것은 1~3장.** 많이 넣으면 대표가 안 본다. 바뀐 화면만 고른다.
- 이 스크립트는 화면이 낸 오류도 함께 알려 준다. **오류가 있으면 보고서의 "남은 문제"에 적는다** — 조용히 넘기지 않는다.
- 캡처 도구가 없다고 나오면(종료 코드 3) 사진 없이 진행하고, 마지막에 설치 방법을 한 줄로 안내한다.

### 3. 본문 쓰기

`assets/report.template.md`를 채워 임시 파일 `.owner/tmp/report-body.md`에 쓴다. 따옴표·줄바꿈이 섞이므로 **명령에 본문을 직접 붙여 넣지 않고 파일로 넘긴다.**

문장 규칙(이 스킬의 핵심이다):

- **전엔 / 후엔 / 왜** 세 줄로 쓴다. 바뀐 것마다 이 세 줄.
- 화면은 **회사에서 부르는 이름**으로 쓴다(`structure.md`·`screens.md`의 이름).
- **설계 선언 요약** — 화면이 새로 생겼거나 그 화면의 목적·가장 중요한 행동이 바뀐 작업이면, `company/screens.md`에서 그 화면의 선언을 한두 줄로 옮긴다: 누가·어디서 여는 화면인지, 가장 중요한 행동 하나, 일부러 넣지 않은 것. 선언이 없는 화면이면 "선언 없음"이라고 쓰고 "남은 문제"에 올린다.
- **바꾸지 않은 것** — 이번에 일부러 손대지 않은 것을 2~4줄로 쓴다(예: 고른 디자인, 저장 방식, "이번에 만들지 않을 것"의 항목, 다른 화면). 대표가 범위를 한눈에 안다.
- **쓰지 않는 말**: 컴포넌트, 함수, 변수, 상태(state), 커밋, 리팩터링, 마이그레이션, 라우팅, 타입, 배열, 훅, API. 파일 경로(`src/screens/…`)와 커밋 번호도 쓰지 않는다.
- 바꿔 쓰는 말: "화면", "목록", "입력 칸", "저장해 두는 곳", "되돌릴 지점", "정리했습니다".
- 대표가 한 말을 인용하면 그대로 쓴다. 요약하지 않는다.
- 안 된 것·못 한 것을 반드시 적는다.
- 분량은 화면 한 눈에 읽히는 정도. 한 절에 다섯 줄을 넘기지 않는다.

### 4. 보고서 만들기

PowerShell은 줄을 이을 때 줄 끝에 `` ` ``(백틱)을 쓴다. 한 줄로 이어 써도 된다.

```
node .owner/hooks/report.mjs --title "오늘 현황 화면 추가" --body .owner/tmp/report-body.md `
  --shot reports/shots/2026-10-15/today-375.png --caption "휴대폰에서 본 오늘 현황" `
  --shot reports/shots/2026-10-15/today-1280.png --caption "PC에서 본 오늘 현황"
```

맥·Git Bash는 줄 끝에 `\`를 쓴다.

- `--title`은 대표가 목록에서 보고 알아볼 제목이다. 회사 말로, 열 자 안팎.
- 사진 경로는 **실제로 찍힌 파일 이름**을 쓴다(캡처 명령이 끝에 목록을 찍어 준다).
- 같은 파일을 갱신하려면 `--slug`를 처음과 같게 준다.
- 만들어지면 브라우저가 열린다. 안 열리면 나온 경로를 대표에게 알려 주고 직접 열게 한다(`node .owner/hooks/open.mjs <경로>`).
- 만든 뒤 임시 본문 파일(`.owner/tmp/report-body.md`)은 지운다.

### 5. 대표에게 보여 주고 한 줄 받기

보고서가 열리면 묻는다(질문 1개): **"여기 적힌 것 중에 사실과 다른 데가 있을까요?"**

- 다르다고 하면 본문을 고쳐 **같은 제목·같은 `--slug`로 다시 만든다.**
- 대표가 새 요청을 하면 그것은 다음 작업이다. 이 보고서에 넣지 않는다 — "미해결 문제"나 "다음 행동"에 한 줄로 적어 둔다.

### 6. 상태 문서 갱신과 커밋

`.owner/state.md`와 `.owner/progress.json`을 갱신한다.

- `state.md` → "현재 기능"에 이번에 된 것, "미해결 문제"에 보고서의 남은 문제, "다음 행동"에 다음 스킬. 끝난 일의 자세한 내용은 보고서에 있으니 `state.md`에는 한 줄만 둔다.
- `progress.json` → 해당 값과 `updated_at`. 없는 키를 새로 만들지 않는다.

```
git add -A
git commit -m "작업 보고서 — 오늘 현황 화면 추가"
```

**`.owner/last-check.json`은 건드리지 않는다.** 그 표식은 `indeans-erp-check`가 감독 판정·실측까지 마친 뒤에만 갱신한다. 보고서만 만들고 표식을 갱신하면 검수를 건너뛴 것이 된다.

마지막 한 줄: **"다음 작업은 새 대화에서 ○○ 스킬로 시작합니다."** 검수 훅이 검수를 요구하면 그것이 먼저다(`indeans-erp-check`는 같은 대화에서 이어 한다 — 같은 작업의 마무리다).

## 산출물

| 경로 | 내용 |
|---|---|
| `reports/<날짜>-<제목>.html` | 작업 보고서 한 장(브라우저로 열린다) |
| `reports/shots/<날짜>/…` | 화면 사진(휴대폰·PC) |
| `.owner/state.md`·`.owner/progress.json` | 갱신 |
| 커밋 1개 | `작업 보고서 — {제목}` |

보고서는 작업마다 `reports/`에 쌓인다.

## 하지 않는 것

- 판정. 승인·반려는 감독 에이전트가 한다(`indeans-erp-check`).
- 코드 수정. 보고서를 쓰다가 문제를 발견하면 보고서에 적고, 고치는 것은 다음 작업으로 둔다.
- `.owner/last-check.json` 갱신.
- 사진 없는데 있는 것처럼 쓰기. 못 찍었으면 "사진은 못 찍었습니다"라고 적는다.
- 잘된 것만 적기. 안 된 것·남은 문제를 같은 무게로 적는다.
- 설계 선언을 보고서에서 새로 지어내기. 선언은 `company/screens.md`에만 있고, 보고서는 옮겨 적기만 한다.
- 코드 용어·파일 경로·커밋 번호 쓰기.
- 고객 실명·연락처·금액이 보이는 화면 캡처. 예시 데이터 화면으로 찍는다.
- 보고서를 어디로 보내기(메일·메신저·업로드). 이 스킬은 파일 한 장만 만든다. 정해진 시각에 채널로 받는 보고는 운영 보고 단계의 `indeans-erp-digest`다.
- 한 보고서에 여러 작업 몰아 넣기. 작업 하나에 보고서 하나다.

## 앞선 수강생 분기

보고서를 이미 여러 장 만들어 본 대표에게는 아래 중 하나를 제안한다.

1. **직원에게 보여 줄 판** — 같은 내용을 "이번 주부터 이렇게 하세요" 문장으로 다시 써서 직원용 보고서를 한 장 만든다. 화면 사진만 그대로 쓴다.
2. **전·후 나란히** — 바꾸기 전 사진을 미리 찍어 두고(`--name before`) 같은 화면의 전·후를 나란히 넣는다. 대표가 가장 빨리 이해하는 형태다.

## 자주 막히는 지점

- **본문에 따옴표·줄바꿈이 많아 명령이 깨진다** → 본문은 항상 파일로 넘긴다(`--body <파일>`). 명령 줄에 본문을 붙여 넣지 않는다.
- **상세·오늘 현황 사진이 첫 화면으로 찍힌다** → `--path`로는 버튼으로 넘어가는 화면에 못 간다. `--click "<화면에 보이는 글자>"`를 쓴다.
- **`--click`이 "찾지 못했습니다"로 끝난다** → 글자가 화면과 다르다(띄어쓰기·회사 말). 앱을 열어 버튼에 보이는 글자를 그대로 복사해 준다. 화면이 늦게 뜨면 `--wait 3000`.
- **사진이 보고서에 안 나온다** → 경로가 틀렸다. 캡처 명령이 끝에 찍어 준 파일 목록을 그대로 복사해 쓴다. 없는 경로는 건너뛰고 만들어지므로 조용히 빠진다.
- **배포한 주소를 찍으려니 막힌다** → 캡처는 내 컴퓨터 주소가 기본이다. 꼭 필요하면 `--allow-remote`를 붙이되, 실제 고객 정보가 보이는 화면이면 찍지 않는다.
- **브라우저가 안 열린다** → 나온 경로를 `node .owner/hooks/open.mjs <경로>`로 다시 열거나, 파일을 두 번 눌러 열게 안내한다.
- **보고서가 계속 새 파일로 쌓인다** → 같은 작업의 갱신이면 `--slug`를 같게 준다.
- **무엇을 적을지 모르겠다** → `git diff --stat`을 보고 "이 변경이 대표에게 어떤 차이로 느껴지나"만 쓴다. 파일 이름을 나열하지 않는다.
- **대표가 "무슨 말인지 모르겠다"고 한다** → 코드 용어가 남아 있는 것이다. 그 문장을 지우고 화면에서 무엇이 달라 보이는지로 다시 쓴다.
