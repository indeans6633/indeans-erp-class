# 디자인 감사 — 찾기만 한다

> **1일 차 라이브 판(11-17 리허설 반영)** — 공개 번들 v3.2 원본에서 찾은 곳 번호(①②…)만 바꿨다. 비교용 원본: `proposed-skills/_원본/`.

`indeans-erp-review` 절차 3의 다섯째 묶음이다. 가져온 앱(다른 도구로 만들었거나 수업 뒤에 여러 번 고쳐 온 앱)에서 **AI가 만든 티가 나는 곳, 글자 위계·여백이 흐트러진 곳, 회사 말과 다른 문구**를 찾는다.

**이 감사는 찾기만 한다. 고치지 않는다.** 찾은 것은 개선 계획서의 "디자인 감사" 표에 적고 검수(`indeans-erp-check`)로 넘긴다. 무엇을 고칠지는 화면 감독(`erp-design-supervisor`)이 판정하고, 고치는 것은 그 검수 절차(지적 → 고침 → 다시 판정) 안에서 한다. 여기서 겸사겸사 고치면 대표가 고른 1~2건과 섞여, 무엇 때문에 무엇이 바뀌었는지 아무도 모르게 된다.

---

## 보는 순서

1. 앱을 띄워 폰(375)·PC(1280)로 세 화면을 한 번씩 본다. 이번에 찍어 둔 사진이 있으면 그것으로 본다(사진은 기능당 한 번 — 감사하려고 새로 다 찍지 않는다).
2. 아래 네 묶음을 위에서부터 본다. "코드에서 찾는 법"이 있는 항목은 찾아서 `파일:줄`을 적는다.
3. 같은 문제가 여러 군데면 대표 자리 하나와 "외 n곳"으로 한 줄에 적는다.
4. 표는 열 줄을 넘기지 않는다. 넘으면 사람이 매일 여는 화면(목록·오늘 현황)의 것부터 남긴다.
5. 기준은 그 앱이 고른 디자인이다 — `company/design.md`의 "바꾸면 안 되는 것"과 `src/styles/tokens.css`. 토큰에 그림자가 없는 디자인인데 그림자가 있으면 걸리고, 토큰에 있는 값을 쓴 것은 걸리지 않는다.

## 1. AI 티 패턴 — 어느 앱에나 있을 법한 모양

| 항목 | 어떻게 보이나 | 코드에서 찾는 법 |
|---|---|---|
| 왼쪽 색 막대 | 카드·알림 상자·목록 줄 왼쪽에 굵은 색 띠 | `border-left`에 강조색·상태색(`var(--primary)`·`#…`). 중립 회색의 얇은 구분선은 해당 없음 |
| 카드 안 카드 | 테두리 상자 안에 또 테두리 상자, 그림자 위에 그림자 | 테두리·그림자가 있는 상자 안에 같은 모양 상자가 겹친 곳 |
| 과한 그림자·그라데이션 | 떠 보이는 두꺼운 그림자, 색이 번지는 바탕 | `box-shadow`의 개수와 크기, `linear-gradient`·`radial-gradient` |
| 장식 이모지 | 제목·버튼·빈 화면 문장 앞의 그림 문자 | 화면 파일 안의 이모지 글자 |
| 뭉뚱그린 오류 문구 | "오류가 발생했습니다"·"입력값을 확인하세요"·"문제가 생겼습니다", 느낌표로 끝나는 성공 문구 | 그 문장들을 찾는다 |
| 큰 숫자 + 작은 라벨 칸 셋 | 첫 화면 맨 위에 같은 모양의 숫자 칸 세 개가 나란히 있고, 정작 해야 할 일은 그 아래 | 첫 화면 위쪽에 같은 모양 칸이 3~4개 반복 |
| 같은 모양 카드 셋 | 내용과 상관없이 같은 크기 카드 세 장이 가로로 | — |
| 가짜 같은 예시 | 홍길동·ABC상사·뜻 없는 영문 글·딱 떨어지는 숫자(100,000·50%)만 | 예시 데이터 파일 |

## 2. 타이포 위계 — 무엇이 먼저 읽히나

| 항목 | 기준 |
|---|---|
| 글자 크기 종류 | 한 화면에 4종 이하(`--fs-title`·`--fs-body`·`--fs-label`·`--fs-meta`). 입력 칸 글자(`--fs-input`)는 셈에서 뺀다 — 읽는 크기가 아니라 폰에서 화면 확대를 막는 기준이다 |
| 굵기 종류 | 3종 이하. 전부 굵으면 아무것도 굵지 않은 것과 같다 |
| 라벨과 값 | 라벨이 값보다 크거나 진하면 걸린다(예: "건수"라는 글자가 "12"보다 크다) |
| 직접 적은 크기 | 화면 파일의 `font-size: 15px` 같은 숫자 — 토큰(`var(--fs-…)`) 밖의 크기 |
| 긴 글 폭 | 상세 화면의 글이 PC에서 가로로 끝없이 이어진다(폭을 묶지 않았다) |
| 숫자 열 | 수량 같은 숫자 열의 자릿수가 들쭉날쭉해 위아래로 비교가 안 된다(숫자용 글꼴 `--font-num`이나 `tabular-nums`가 빠졌다) |

## 3. 여백 일관성 — 관계가 간격으로 보이나

| 항목 | 기준 |
|---|---|
| 토큰 밖의 간격 | `margin`·`padding`·`gap`에 `var(--sp-…)` 대신 숫자(`13px`·`1.1rem`) |
| 같은 것 다른 간격 | 같은 종류(목록 줄·입력 칸·카드) 사이의 간격이 화면마다 다르다 |
| 관계가 거꾸로 | 묶음 안의 간격이 묶음 사이의 간격보다 넓다 — 관련 있는 것이 더 멀리 있다 |
| 줄 높이 들쭉날쭉 | 목록 줄·카드 높이가 내용 따라 제각각이라 버튼 자리가 줄마다 다르다 |
| 버튼 줄 | 나란한 카드의 버튼이 서로 다른 높이에 있다 |
| 누르는 곳 간격 | 누를 것끼리 붙어 있어(`--sp-2` 미만) 잘못 누른다 |

## 4. 회사 말 일치 — 문장

절차 3의 넷째 묶음(이름 불일치)이 **라벨 이름**을 본다면, 여기서는 **문장**을 본다.

| 항목 | 기준 |
|---|---|
| 버튼 | 동작을 말한다("납품 건 저장"). "확인"·"제출"·"OK"만 있는 버튼은 걸린다 |
| 오류 | 무엇이 문제이고 무엇을 하면 되는지 말한다. 그 칸 바로 아래에 나온다 |
| 빈 화면 | "아직 없음 + 다음에 할 일 + 그 버튼"이 있다 |
| 개발 말 노출 | `undefined`·`null`·`NaN`·영문 상태 코드(`pending`)·`Error:`가 화면에 보인다 |
| 조사 괄호 | `을(를)`·`이(가)`·`(으)로`가 화면에 그대로 보인다 |
| 문장 속 회사 말 | 라벨은 고쳤는데 안내 문장·확인 창에는 옛 말이 남아 있다(`company/profile.md`의 용어와 대조) |

설계 선언(`company/screens.md`)이 있으면 하나 더 본다: 선언의 "쓰지 않을 것"이 화면에 들어가 있지 않은가, "가장 중요한 행동"이 엄지 자리(폰 아래쪽)에 있는가. 어긋나면 AI 티 묶음에 적는다.

## 5. 기록하는 법

개선 계획서(`company/improve-plan.md`)의 "디자인 감사" 표에 한 줄씩 적는다.

찾은 곳 번호는 **①②③…** 로 붙인다(대표에게도 같은 번호). **D1·D5 처럼 영문자+숫자로 붙이지 않는다** — 수업 카드 이름(D1 테마 고르기 · D5 AI 티 점검)과 겹쳐 헷갈린다.

| 번호 | 묶음 | 어디(화면 · `파일:줄`) | 무엇이 보이나(대표의 말로) | 검수 결과 |
|---|---|---|---|---|
| ① | AI 티 | 목록 · `src/screens/ListScreen.tsx:40` | 줄마다 왼쪽에 파란 띠가 있어 어느 줄이 급한지 오히려 안 보인다 | (검수 뒤 — 고침 / 그대로 둠 — 이유) |

- "검수 결과" 칸은 비워 두고 검수가 끝난 뒤 채운다.
- 대표에게는 3줄 이내로 요약해 보여 준다: "화면 모양에서 n가지가 눈에 띄었습니다. 고칠지는 검수에서 화면 감독이 정합니다."
- 대표가 그중 하나를 **오늘의 1~2건으로 직접 고르면** 그때는 개선 항목(절차 4~7)으로 올려 고친다. 대표가 고른 것은 감사 목록이 아니라 개선이다.

## 6. 검수에서 고치기로 정해졌을 때 쓰는 말 (참고)

화면 감독이 고치라고 한 항목을 `indeans-erp-check` 안에서 고칠 때 쓰는 지시 문장이다. 감사 단계에서는 쓰지 않는다. `<꺾쇠>`만 회사 말로 바꾼다.

- 왼쪽 색 막대 → "<목록> 줄 왼쪽의 색 띠를 없애고, 눈에 띄어야 하는 줄은 은은한 바탕색(`var(--primary-soft)`)으로만 구분해 줘."
- 카드 안 카드 → "<상세> 화면 안쪽 상자의 테두리를 없애고 선 한 줄과 여백으로 나눠 줘."
- 그림자·그라데이션 → "그림자와 색 번짐을 모두 없애 줘. 구분은 선과 여백으로."
- 큰 숫자 칸 셋 → "첫 화면 맨 위 숫자 칸 세 개를 빼고 오늘 할 일 목록을 맨 위로 올려 줘. 단계별 개수는 그 아래 한 줄로, 누르면 그 목록으로 가게."
- 뭉뚱그린 문구 → "'오류가 발생했습니다'를 무엇이 실패했고 무엇을 하면 되는지 말하는 문장으로 바꿔 줘. 오류는 그 칸 바로 아래에 나오게."
- 토큰 밖의 크기·간격 → "화면 파일에 숫자로 적은 글자 크기와 간격을 가장 가까운 토큰(`var(--fs-…)`·`var(--sp-…)`)으로 바꿔 줘. 화면 모양이 달라지면 바꾸기 전과 나란히 보여 줘."
