# 우리 회사 판례집 양식

판례집은 **같은 실수를 두 번 하지 않기 위한 기록**입니다. 잘한 일을 남기는 곳이 아니라, 한 번 당한 일을 적어 두는 곳입니다. 3건쯤 쌓이면 새 개선을 계획할 때 먼저 읽게 됩니다.

## 언제 한 건 남기나

아래 중 하나면 남깁니다. 아니면 주간 기록 한 줄로 충분합니다.

- 잘못된 데이터가 저장됐거나, 못 봐야 할 사람에게 화면이 보였다.
- 되돌려야 했다(커밋을 되돌리거나 백업으로 복구).
- 고친 줄 알았는데 안 고쳐져 있었다.
- 같은 문제가 두 번째 나왔다.
- "다음엔 이렇게 하자"가 한 문장으로 정리됐다.

## 파일 이름

`company/casebook/001-목록에-최근-건이-안-보임.md`

번호는 세 자리, 뒤는 **증상**을 짧게. 원인이 아니라 증상으로 이름을 답니다(다음에 같은 증상을 만났을 때 찾기 위해서).

## 양식

```markdown
# 판례 <NNN> — <증상 한 줄>

날짜 <YYYY-MM-DD> · 연-주 <YYYY-WW> · 등급 <데이터 / 권한 / 화면 / 비용>

## 무슨 일이 있었나
<세 줄 이내. 대표가 무엇을 하려다 무엇을 봤는지>

## 어떻게 알았나
<직원이 말했다 / 화면에서 봤다 / 주간 점검에서 나왔다 / 고객이 물었다>

## 원인
<확인한 것만 적는다. 추측이면 "추정"이라고 쓴다>

## 어떻게 고쳤나
<한 줄. 되돌린 커밋이 있으면 번호>

## 다음부터 이렇게 한다
<한 문장. 실행할 수 있는 형태로>
- 나쁨: "조심한다"
- 좋음: "목록 화면을 새로 만들 때는 정렬 기준과 가져오는 개수를 먼저 정한다"

## 기계가 대신 볼 수 있나
<가능 — 점검 항목으로 추가함 / 불가능 — 사람이 볼 항목>

## 같은 유형
<다른 판례 번호 / 없음>
```

## 쓸 때의 규칙

- 고객 실명·연락처·계좌·실제 금액을 적지 않습니다. "고객 한 건", "금액 항목"으로 씁니다.
- 누구 탓인지 적지 않습니다. 무엇이 그렇게 되도록 놔뒀는지를 적습니다.
- 길게 쓰지 않습니다. 열 줄이면 충분합니다. 길어지면 다음에 안 읽습니다.
- **'다음부터 이렇게 한다'가 가장 중요한 줄**입니다. 이 줄이 안 써지면 아직 원인을 모르는 것이고, 그러면 원인 칸에 "모름"이라고 적고 관찰 대상으로 남깁니다.

## 판례가 쌓이면

- 새 기능을 계획할 때 같은 등급(데이터·권한 등)의 판례를 먼저 읽습니다.
- 같은 유형이 두 번 나오면 **사람이 조심하는 대신 매주 돌리는 점검 항목이나 작은 확인 스크립트로 바꿉니다.** 조심하는 것은 세 번째에 또 실패합니다.
- 직원이 늘면 판례집이 인수인계 문서가 됩니다.

## 첫 판례 예시 (형식 참고용 — 지어낸 상황입니다)

```markdown
# 판례 001 — 목록에 오늘 넣은 건이 안 보임

날짜 2026-09-21 · 연-주 2026-38 · 등급 데이터

## 무슨 일이 있었나
새 건을 저장했는데 목록 맨 위에 안 보였다. 검색하면 나왔다.

## 어떻게 알았나
직원이 "저장이 안 되는 것 같다"고 말했다.

## 원인
목록이 오래된 순서로 나오고 있었고, 한 번에 가져오는 개수 안에 새 건이 들어가지 않았다.

## 어떻게 고쳤나
목록 정렬을 최근 순으로 바꾸고 가져오는 개수를 지정했다.

## 다음부터 이렇게 한다
목록 화면을 만들 때는 정렬 기준과 한 번에 가져오는 개수를 먼저 정하고, 저장 직후 목록에 보이는지 확인한다.

## 기계가 대신 볼 수 있나
가능 — 주간 점검에 "가장 최근 저장 건이 목록 첫 화면에 보이는가"를 넣었다.

## 같은 유형
없음
```
