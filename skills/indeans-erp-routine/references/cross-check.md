# 두 AI 교차 검토 — 명령과 요청 문장

만든 AI에게 "잘 됐냐"고 물으면 거의 "잘 됐다"고 합니다. 자기가 만든 것을 자기가 채점하기 때문입니다. 그래서 **다른 AI가, 읽기만 하는 상태로, 요구 원문과 결과를 대조**하게 합니다. 인디언즈도 중요한 판단에서 다른 계열 모델의 독립 의견을 이렇게 받습니다.

## 원칙 네 가지

1. **검토자에게 결론을 주지 않는다.** 요구 원문과 바뀐 파일 목록만 줍니다. "이렇게 고쳤는데 괜찮지?"라고 물으면 따라 말합니다.
2. **읽기만 하게 한다.** 검토 중에 파일을 고치면 검토가 아니라 두 번째 작업이 됩니다.
3. **판정은 세 가지로 받는다.** 맞음 / 빠짐 / 바뀜.
4. **결과가 갈리면 앱을 직접 연다.** 어느 AI가 맞냐고 다시 묻지 않습니다.

## 준비물 — 검토자에게 줄 세 가지

1. 요구 원문 (대표가 한 말 그대로)
2. 바뀐 파일 목록 — 아래 명령으로 뽑습니다.
   ```bash
   git diff --name-only HEAD~1 HEAD
   ```
3. 확인 기준 (무엇이 되면 끝인지)

## Claude Code 로 만들었을 때 → Codex 가 검토

프로젝트 폴더에서 실행합니다. `--sandbox read-only` 는 파일을 고치지 못하게 하는 설정입니다(2026-09 기준 Codex CLI 공식 문서 확인).

```bash
codex exec --sandbox read-only "아래 요구와 이 저장소의 최근 변경을 대조해라. 파일은 고치지 마라.
요구 원문: \"<대표의 말 그대로>\"
바뀐 파일: <파일 목록>
확인할 것만 답해라. (1) 요구 중 구현에 빠진 것 (2) 요구와 다르게 해석한 것
(3) 돈 계산이나 누가 무엇을 보는지에 영향이 가는 변경이 있는지.
더 나은 방법을 제안하지 말고, 빠진 것과 어긋난 것만 목록으로 말해라.
각 항목 끝에 판정을 맞음/빠짐/바뀜 중 하나로 붙여라."
```

긴 요구는 파일로 넘깁니다.

```bash
cat 요구.txt | codex exec --sandbox read-only -
```

## Codex 로 만들었을 때 → Claude Code 가 검토

Claude Code를 **새 대화**로 열고(이전 대화를 이어받지 않습니다) 이 문장을 붙여 넣습니다.

```text
이 프로젝트의 최근 변경을 검토만 해 줘. 파일은 고치지 마.
요구 원문: "<대표의 말 그대로>"
바뀐 파일: <git diff --name-only HEAD~1 HEAD 결과>
(1) 요구 중 빠진 것 (2) 요구와 다르게 해석한 것 (3) 돈 계산이나 권한에 영향이 가는 변경
이 세 가지만 목록으로 알려 줘. 더 좋은 방법은 제안하지 마.
각 항목에 맞음/빠짐/바뀜 판정을 붙여 줘.
```

## 도구가 하나뿐일 때

같은 도구의 **새 대화**를 열고 위 문장을 씁니다. 이전 대화 내용은 붙여 넣지 않습니다. 만든 과정을 모르는 상태에서 코드만 보게 하는 것이 목적입니다. 효과는 절반쯤이지만 안 하는 것보다 낫습니다.

## 검토 결과 처리

| 판정 | 뜻 | 처리 |
|---|---|---|
| 맞음 | 요구대로 됐다 | 주간 기록에 "맞음"만 적고 끝 |
| 빠짐 | 요구 중 안 된 것이 있다 | 이번 주에 마저 하거나, 못 하면 다음 주 1순위 + 대표에게 보고 |
| 바뀜 | 요구와 다르게 됐다 | **반드시 대표에게 알린다.** 바뀐 채로 두려면 대표의 답을 받는다 |

돈 계산·권한에 영향이 간다는 지적이 나오면 배포를 멈추고 먼저 확인합니다.

## 비용

- Claude Code · Codex 모두 구독 사용량을 씁니다. 주 1회 한 번이면 부담이 크지 않습니다.
- 검토 요청에 **코드 전체를 붙여 넣지 않습니다.** 바뀐 파일 목록만 주면 도구가 알아서 읽습니다.
- 고객 실명·연락처·계좌·실제 금액을 프롬프트에 넣지 않습니다. 검토에 필요 없습니다.

## 자주 막히는 지점

- **검토자가 "전체적으로 잘 되어 있습니다"만 말한다** — 요구 원문을 문장 단위로 쪼개서 한 문장씩 대조시킵니다. "이 문장은 어디서 처리되나?"
- **검토자가 파일을 고쳐 버렸다** — 읽기 전용 설정을 빠뜨린 것입니다. 되돌린 뒤 다시 합니다.
- **지적이 너무 많다** — 이번 요구와 무관한 것은 목록으로만 남기고 다음으로 미룹니다. 한 주에 한 건 원칙은 유지합니다.
- **명령이 실행되지 않는다** — 설치·로그인 상태를 먼저 확인합니다(1회차 `indeans-erp-setup`). 안 되면 그 주는 같은 도구 새 대화 방식으로 대체하고 기록에 남깁니다.
- **검토자가 "파일을 읽지 못했다·확인할 수 없다"고 답한다** — 그건 검토가 된 것이 아닙니다. 회사 노트북의 보안 설정 때문에 검토자가 저장소를 스스로 못 읽는 경우가 있습니다(명령이 실행은 되고 답도 오지만 내용이 "판정할 수 없습니다"입니다). 그때는 바뀐 내용을 **글로 만들어** 넘깁니다.

  ```bash
  git diff HEAD~1 HEAD > 바뀐내용.txt
  # 요구.txt 에 요구 원문 + 확인 기준 + 바뀐내용.txt 를 이어 붙인 뒤
  cat 요구.txt | codex exec --sandbox read-only -
  ```

  바뀐 부분(diff)만 붙이는 것은 "코드 전체를 붙여 넣는 것"이 아닙니다.
