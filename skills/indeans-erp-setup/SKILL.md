# 인디언즈 ERP 시작 점검

## 언제 쓰나

- 번들을 막 설치하고 처음 연 자리에서(1회차 첫 실습).
- 회차를 시작할 때 "오늘 준비됐나" 30초 점검.
- 앱이 안 켜지거나 스킬·감독 에이전트가 안 불릴 때, 원인이 도구·설치 쪽인지 먼저 가르는 자리.
- 사전 안내(0회차)를 못 하고 온 대표가 **당일 60분 안에 따라잡아야 할 때**(절차 12).

이 스킬은 **확인과 기록**만 한다. 앱 코드는 만들지 않는다.

## 시작 전 상태 진단

아래를 순서대로 읽고 판정한 뒤 분기한다. 읽기 전에 대표에게 말을 걸지 않는다.

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` · `.owner/progress.json` | 지난 점검 결과("미해결 문제"에 남은 미설치·미확인 항목)·다음 행동. 둘 다 없으면 설치가 안 된 것이다 |
| `.owner/install-state.json` | 설치기가 남긴 기록 — `version`·`target`·설치한 파일 목록 |
| `.claude/skills/` · `.agents/skills/` | 스킬이 도구 쪽에 들어왔는지 |
| `.claude/agents/` · `.codex/agents/` | 감독 에이전트 3종이 생성됐는지 |
| `.owner/hooks/` · `.owner/design/` | 검수 훅 4개·디자인 이미지 세트가 있는지 |
| `company/profile.md` | 인터뷰를 이미 했는지 |
| `package.json` · `src/` | 초안 앱이 이미 있는지 |

판정과 분기:

- **설치 전** — `.owner/install-state.json`이 없다 → 절차 1~2를 하고 **절차 6(번들 설치)**부터 챙긴다. 설치가 안 된 폴더에서는 다른 스킬이 뜨지 않는다.
- **처음** — 설치는 됐고 상태 문서에 점검 기록이 없다 → 절차 1~11 전부.
- **진행 중** — `.owner/state.md`의 "미해결 문제"에 미설치·미확인 항목이 남아 있다 → 그 항목만 다시 확인한다.
- **완료** — 도구·계정·설치가 다 확인되고 `company/profile.md`가 있다 → **30초 점검 모드**(절차 13). 남는 시간은 「앞선 수강생 분기」로.

판정을 한 문장으로 먼저 알린다. 예: "지난 회차 점검 기록이 있고 도구는 다 확인돼 있습니다. 30초 점검만 하겠습니다."

## 절차

### 1. 되돌릴 지점 만들기

프로젝트 폴더에서 확인하고, 아직 git이 없으면 만든다.

```
git rev-parse --show-toplevel
```

나온 경로가 **지금 프로젝트 폴더와 같은지** 확인한다. 다르거나 오류가 나면 이 폴더에는 아직 되돌릴 지점이 없는 것이다 — 문서 폴더·수업 자료 폴더 안에 프로젝트를 만들면 상위 폴더의 저장소가 잡혀 "있음"처럼 보인다. 그럴 때는:

```
git init
git add -A
git commit -m "시작 지점"
```

대표에게 한 줄로 설명한다: "지금 상태를 사진 찍어 두는 것입니다. 잘못되면 여기로 돌아옵니다."

### 2. 어떤 컴퓨터인지 확인

질문 1개: **"지금 쓰시는 노트북이 윈도우인가요, 맥인가요?"**

- 윈도우 → `references/install-windows.md`를 읽고 그 절차를 따른다.
- 맥 → `references/install-mac.md`를 읽고 그 절차를 따른다.

설치 명령 원문은 참고 파일에 있다. 여기서는 순서만 관리한다.

### 3. Node.js와 Git 확인

```
node -v
npm -v
git --version
```

- `node -v`가 `v22` 미만이거나 "찾을 수 없다"로 나오면 → 참고 파일의 Node.js LTS 설치 절차. nodejs.org 첫 화면의 **LTS** 버튼을 받으면 된다.
- `git --version`이 안 나오면 → 참고 파일의 Git 설치 절차.
- 설치 후에는 **터미널 창을 닫고 새로 연다.** 이걸 안 해서 "설치했는데 없다"가 되는 경우가 가장 많다.

### 4. 도구 2종 확인 (Claude Code · Codex)

```
claude --version
claude doctor
```

```
codex --version
codex login status
codex doctor
```

- 버전 숫자가 나오면 설치된 것이다. `doctor`의 경고는 문장을 그대로 대표에게 보여 준다.
- Claude Code는 **유료 구독(Pro 이상)**, Codex는 **ChatGPT Plus 이상**이 필요하다. 로그인은 `claude`를 실행해 대화가 열리는지, `codex login status`가 "Logged in"으로 나오는지로 확인한다.
- **둘 중 하나만 있어도 수업은 진행된다.** 없는 쪽은 "나중에 해도 됩니다"로 넘기고 **`.owner/state.md`의 "미해결 문제"에 한 줄로 적는다**(예: "Codex 미설치 — 회차 사이에"). 여기서 시간을 다 쓰지 않는다.

### 5. 계정 3종 확인

묻기 전에 한 줄로 먼저 말한다: **"Supabase는 앱에 넣은 내용이 사라지지 않게 보관하는 창고, Vercel은 그 앱을 인터넷 주소로 띄우는 곳입니다. 오늘은 가입만 합니다."**

그다음 한 번에 하나씩 묻는다. 이미 있다고 하면 "어디서 확인하나"만 알려 주고 넘어간다.

| 계정 | 왜 필요한가(대표에게 하는 말) | 확인하는 곳 |
|---|---|---|
| GitHub | 만든 앱을 안전하게 보관하고 되돌리는 창고 | github.com 로그인 → 오른쪽 위 내 아이콘이 보이면 됨 |
| Supabase | 2회차부터 실제 데이터를 넣어 둘 곳 | supabase.com 로그인 → 대시보드가 열리면 됨 |
| Vercel | 앱을 실제 주소로 띄우는 곳 | vercel.com 로그인 → 대시보드가 열리면 됨 |

- 셋 다 무료로 시작한다. **GitHub 계정으로 Supabase·Vercel에 가입하면** 계정이 하나로 묶여 관리가 쉽다 — 이 순서를 권한다.
- **계정 3종은 2회차 시작 전까지 필수다.** 1회차에 실제로 쓰는 것은 없지만, **없으면 2·3·4회차의 필수 완료 결과에 도달할 수 없다**(2회차 저장·주소, 3회차 정해진 시각 보고, 4회차 그 위의 검수·복구). **3회차는 계정 없이 진행할 대안 경로가 없다.**
- 가입 도중 막히면 붙잡지 말고 **"미해결 문제"에 미확인으로 적고** 넘어간다. 다만 넘길 때 위 문장을 **그대로 같이 말한다**: "오늘은 안 쓰지만 2회차 시작 전까지는 꼭 만들어 오셔야 합니다. 없으면 2·3·4회차에서 끝내야 할 것을 못 끝냅니다." 말없이 `미확인`으로만 적지 않는다.

### 6. 번들이 다 들어왔는지 확인

설치기가 한 번에 넣는 것은 다섯 묶음이다. 아래 다섯 줄을 **직접 확인**한다(파일이 있는지 본다).

| 묶음 | 어디에 | 몇 개 |
|---|---|---|
| 스킬 | `.claude/skills/` · `.agents/skills/` | 14개 폴더(각 폴더에 `SKILL.md`) |
| 감독 에이전트 | `.claude/agents/*.md` · `.codex/agents/*.toml` | 3개 (`erp-supervisor`·`erp-design-supervisor`·`erp-verifier`) |
| 검수 훅·도구 | `.owner/hooks/` | 4개 (`erp-check.mjs`·`open.mjs`·`capture.mjs`·`report.mjs`) |
| 디자인 이미지 세트 | `.owner/design/` | `index.html` + PNG 12장 + `tokens/` 12개 |
| 회차 자료 | `course/` | `session-01`~`session-04` + `final` |

**감독 에이전트는 두 가지로 확인한다.** 목록을 내주는 명령이 따로 있는 것이 아니다.

1. `.claude/agents/` (Codex 는 `.codex/agents/`)에 **파일 3개가 있는지 눈으로 본다.**
2. AI에게 **`erp-supervisor 에이전트로 이 변경을 검토해 줘.`** 라고 시켜 **실제로 떠지는지** 본다. 판정이 돌아오면 된 것이다. "그런 에이전트가 없다"고 하면 1번으로 돌아간다.

빠진 묶음이 있으면 저장소 폴더에서 설치기를 다시 돌리게 안내한다(재설치는 안전하다 — 대표가 고친 파일은 `.new`로 옆에 저장된다).

```
node install.mjs --project <내 프로젝트 폴더 경로> --target both
```

- **회차 자료(`course/`)만 비어 있으면 설치기를 다시 돌리라고 하지 않는다.** 저장소에 그 폴더가 아직 없으면 설치기는 몇 번을 돌려도 같은 결과를 내고, 대표는 같은 명령을 반복하게 된다. 설치기가 "회차 자료가 아직 없어 건너뜁니다"라고 안내했다면 **강사에게 알린다**(자료가 아직 배포되지 않았을 수 있다)고 한 줄로 말하고, 1회차 실습은 그대로 진행한다 — 회차 자료는 실습에 필수가 아니다. `.owner/state.md`의 "미해결 문제"에 "회차 자료 미도착 — 강사 확인"으로 적어 둔다.
- 나머지 묶음(스킬·감독 에이전트·검수 훅·디자인 이미지)이 비었을 때만 설치기를 다시 돌린다. 다시 돌려도 같은 것이 빠지면 저장소를 제대로 내려받았는지(폴더에 `install.mjs`·`skills/`가 있는지) 확인한다.
- 한쪽 도구에만 들어왔으면 `--target both`로 다시 돌린다.
- Codex는 파일이 바뀐 걸 대개 알아서 잡지만, 안 보이면 Codex를 껐다 켠다.
- `.owner/install-state.json`의 `version`을 대표에게 한 줄로 알린다("번들 2.0.0이 설치돼 있습니다").

### 7. 검수 훅이 등록됐는지 확인

파일이 있는 것과 **도구가 부르는 것**은 다르다. 등록은 설정 파일에 들어 있다.

| 도구 | 설정 파일 | 들어 있어야 하는 것 |
|---|---|---|
| Claude Code | `.claude/settings.json` | `hooks.Stop`에 `node .owner/hooks/erp-check.mjs --tool claude` |
| Codex | `.codex/hooks.json` | `hooks.Stop`에 `node .owner/hooks/erp-check.mjs --tool codex` |

등록이 없으면 설치기를 다시 돌린다. 그래도 안 되면(설정 파일의 다른 내용이 깨져 있을 때) 설치기가 낸 안내대로 손으로 한 줄 넣는다. **대표가 넣어 둔 다른 설정을 지우지 않는다.**

등록된 훅이 실제로 도는지 한 번 실행해 본다.

```
node .owner/hooks/erp-check.mjs --tool claude --debug
```

"판정: 통과" 또는 "판정: 검수 필요"와 바뀐 파일 목록이 나오면 정상이다. **바뀐 것이 없으면 `판정: 통과` 한 줄만 나온다 — 그것도 정상이다.** 목록이 안 나왔다고 고장으로 읽지 않는다(방금 커밋했으면 바뀐 것이 없는 게 맞다).

대표에게 한 줄로 설명한다: "작업을 끝낼 때마다 이게 먼저 돌아서, 화면·저장·권한이 바뀌었으면 검수를 받으라고 알려 줍니다."

**Codex 를 쓰면 한 가지를 더 확인한다 — 훅 신뢰 승인.** Codex 는 프로젝트에 있는 훅을 **신뢰 승인 전까지 조용히 건너뛴다**(경고도 없다). 처음 한 번은 **대화형으로**(`codex` 를 그냥 실행해서) 열어 승인해야 검수가 돈다. 확인법: 아무 작업이나 한 번 끝내고 화면에 `hook: Stop` 이 **두 줄**(개인 설정 것 + 이 프로젝트 것) 나오는지 본다. 한 줄만 나오면 아직 승인 전이다. 승인이 안 됐으면 `.owner/state.md` 의 "미해결 문제"에 `Codex 훅 신뢰 승인 — 대화형으로 한 번 열기` 로 적는다.

### 8. 화면 캡처 도구(playwright) 확인

보고서에 넣을 화면 사진을 찍는 도구다. 이 도구는 **프로젝트 안에** 설치한다(설치기가 대신 설치하지 않는다).

```
npm ls playwright
```

- 버전이 나오면 된 것이다.
- `package.json`이 아직 없으면(초안 앱을 만들기 전) **지금 설치하지 않는다.** "미해결 문제"에 `화면 사진 도구 — 앱 만든 뒤 설치`로 적고 넘어간다 — `indeans-erp-draft`가 앱을 만든 뒤에 설치한다.
- `package.json`이 있고 playwright가 없으면 아래 두 줄을 실행한다. 한 번만 하면 된다(두 번째 줄은 브라우저를 받아 2~4분 걸린다).

```
npm i -D playwright
npx playwright install chromium
```

- 회사 네트워크가 브라우저 내려받기를 막으면 붙잡지 않는다. 캡처 없이도 수업은 진행된다 — 캡처가 필요한 자리에서 "사진은 없이 진행"으로 적는다.

### 9. 프로젝트 폴더 규약

프로젝트 폴더가 아래 모양인지 확인하고, 없는 폴더는 만든다.

```
my-erp/                   ← 회사 이름으로 지어도 된다(영문·하이픈 권장)
  company/                ← 회사 문서(인터뷰 결과). 다음 회차 스킬들이 읽는다
  src/                    ← 앱 코드
  course/session-01/      ← 회차 자료
  reports/                ← 작업 보고서(회차마다 쌓인다)
  .owner/                 ← 설치 기록·상태 문서·검수 훅·디자인 이미지
  .owner/tmp/             ← 스킬이 쓰고 버리는 임시 파일(보고서 본문 등). 커밋하지 않는다
  .claude/skills/         ← Claude Code가 읽는 스킬
  .agents/skills/         ← Codex가 읽는 스킬
```

- **`.gitignore` 에 `.env.local` 과 `.owner/tmp/` 두 줄이 있는지 확인한다.** 없으면 대표에게 "이 두 줄을 넣겠습니다"라고 알린 뒤 넣는다. `.owner/tmp/` 는 스킬이 쓰고 버리는 자리라 저장소에 올라갈 이유가 없고, `.env.local` 은 한 번 올라가면 지워도 기록에 남는다. **설치기는 `.gitignore` 를 건드리지 않는다** — 대표의 파일이라 손대지 않는 것이 규약이다.
- 폴더 이름에 한글·공백·괄호를 쓰지 않는다. 나중에 배포 주소와 명령에서 문제가 된다.
- 바탕화면이나 다운로드 폴더가 아니라, 문서 폴더 아래 고정된 자리에 둔다. 클라우드 동기화 폴더(OneDrive·iCloud 데스크톱) 안은 피한다 — 파일이 잠기거나 반쯤 내려받아진 상태에서 오류가 난다.

### 10. 상태 문서 확인

`.owner/state.md`와 `.owner/progress.json`은 **회차를 잇는 기억**이다. 모든 스킬이 시작할 때 읽고 끝날 때 고친다.

- 둘 중 하나라도 없으면 설치기를 다시 돌린다(있는 파일은 건드리지 않는다). 손으로 새로 만들지 않는다.
- 있으면 열어서 **실제와 맞는지** 본다. 문서에 "배포 완료"인데 주소가 없거나, "화면 3개"인데 `src/screens/`가 비어 있으면 **문서를 믿지 않고** 실제에 맞게 고친다.
- `.owner/`에는 금액·고객 실명·연락처·비밀값을 적지 않는다.

### 11. 기록하고 커밋

점검 결과를 두 곳에 남긴다. **파일의 구조는 그대로 두고 값만 바꾼다**(다음 스킬들이 이 구조를 읽는다. 없는 키를 새로 만들지 않는다).

- `.owner/state.md` → "미해결 문제"에 미설치·미확인 항목을 한 줄씩(무엇이 없고 언제 하기로 했는지), "다음 행동"에 `indeans-erp-interview`.
- `.owner/progress.json` → `open_problems`에 같은 항목을 짧게, `next_action`에 다음 행동, `updated_at`에 지금 시각, `updated_by`에 지금 쓰는 도구(`claude` 또는 `codex`).

```
git add -A
git commit -m "1회차 시작 점검"
```

마지막으로 대표에게 3줄로 보고한다: 된 것 / 안 된 것 / 지금 당장 필요한지 여부.

### 12. 사전 안내를 못 한 대표 — 당일 60분 따라잡기

사전 안내(0회차)에는 도구 2종·계정 3종·Node·프로젝트 폴더·번들 설치가 들어 있다. 하나도 안 된 상태로 왔으면 **이 순서대로만** 한다. 순서를 바꾸지 않는다 — 뒤 항목은 앞 항목이 있어야 된다.

| 분 | 무엇을 | 안 되면 |
|---|---|---|
| 0~10 | Node.js LTS + Git 설치, 터미널 새로 열기 | 여기서 막히면 옆자리 화면을 같이 보며 진행. 이건 건너뛸 수 없다 |
| 10~25 | **도구 하나만** 설치·로그인(대표가 이미 결제한 쪽으로) | 결제가 안 되어 있으면 강사 계정 화면으로 따라만 보고, 집에서 설치 |
| 25~30 | GitHub 가입·로그인 | 메일 인증이 늦으면 `미확인`으로 두고 진행 |
| 30~35 | 프로젝트 폴더 만들기(영문 이름) | — |
| 35~45 | 번들 설치(절차 6) + 등록 확인(절차 7) | 설치가 실패하면 강사가 그 자리에서 본다. 여기까지는 반드시 끝낸다 |
| 45~60 | 인터뷰 시작(`indeans-erp-interview`) | — |

- **미루는 것**: 두 번째 도구 · Supabase·Vercel 가입 · playwright. 셋 다 1회차에 쓰지 않는다. `미확인`으로 적고 회차 사이에 하게 안내한다.
- 60분을 넘기면 인터뷰 시간을 깎게 된다. 남은 것은 `.owner/state.md`의 "미해결 문제"에 적고 다음 회차 시작 때 처리한다.

### 13. 30초 점검 모드 (회차를 시작할 때)

"완료" 판정이거나 대표가 "점검만"이라고 하면 이것만 한다.

1. `node -v`, `git --version`, `claude --version`(또는 `codex --version`) — 한 번에 실행하고 결과만 본다.
2. `.owner/install-state.json`의 `version`과 저장소 `manifest.json`의 `version`을 비교한다. 다르면 설치기를 다시 돌리라고 한 줄 안내한다.
3. `.owner/progress.json`의 `open_problems`와 `.owner/state.md`의 "미해결 문제"를 읽어 지난 회차 대비 빠진 것이 있는지 본다.
4. `git status`로 저장 안 된 변경이 있는지 본다. 있으면 커밋할지 묻는다(질문 1개).
5. 결과를 표 한 줄로 보고하고 끝낸다. 질문을 더 하지 않는다.

## 산출물

- `.owner/progress.json` — `open_problems`·`next_action`·`updated_at` 갱신(설치기가 만든 구조 그대로, 값만 바꾼다)
- `.owner/state.md` — 미해결 문제(미설치·미확인 항목)·다음 행동 갱신
- 점검 보고(대화창에만): 된 것 / 안 된 것 / 다음 행동 3줄
- 커밋 1개(`1회차 시작 점검`)

## 하지 않는 것

- 앱 코드·화면 생성. 그건 `indeans-erp-draft`가 한다.
- 인터뷰 질문. 그건 `indeans-erp-interview`가 한다.
- 구독 결제 대행·계정 생성 대행. 로그인 화면까지 안내하고 입력은 대표가 한다.
- 상태 문서를 손으로 새로 만들기. 없으면 설치기를 다시 돌린다.
- 설치기가 넣지 않은 설정(대표가 직접 넣은 훅·설정)을 지우거나 덮기.
- 안 되는 도구를 끝까지 붙들기. 5분 안에 안 되면 `미설치`로 적고 진행한다. 수업은 도구 하나로도 굴러간다.
- 대표 컴퓨터의 다른 프로그램 설치·설정 변경. 이 목록 밖의 것은 손대지 않는다.

## 앞선 수강생 분기

이미 점검이 끝나 있으면 30초 점검 뒤 아래 중 하나를 제안한다(고르는 것은 대표).

1. **두 도구 비교** — 같은 요청을 Claude Code와 Codex에 각각 넣고 결과가 어떻게 다른지 본다. 어느 쪽이 내 말투를 잘 알아듣는지 감을 잡는 연습.
2. **감독 에이전트 한 번 불러 보기** — 지금 있는 화면 하나를 `erp-design-supervisor`에게 검토받아 본다. 검수 체계가 어떻게 말하는지 미리 겪어 두면 4회차가 쉬워진다.
3. **되돌리기 연습** — 일부러 파일 하나를 고쳐 놓고 `git status`·`git restore`로 되돌려 본다. 과정 내내 가장 많이 쓰게 될 안전장치다.
4. **다른 폴더에서도 쓰기** — 다음에 만들 폴더에서도 같은 스킬이 뜨게 개인 자리에 둔다. 방법은 `references/troubleshooting.md`의 "스킬을 다른 폴더에서도 쓰고 싶다" 항목.

## 자주 막히는 지점

자세한 증상·해결·"AI에게 그대로 말할 문장"은 `references/troubleshooting.md`에 정리돼 있다. 오류가 나면 **추측하지 말고 그 파일을 먼저 읽는다.**

특히 자주 나오는 넷:

- **설치했는데 "찾을 수 없다"** → 터미널을 닫고 새로 연다. 그래도 안 되면 참고 파일의 PATH 항목.
- **스킬은 뜨는데 감독 에이전트가 안 불린다** → 에이전트 파일이 도구 쪽에 없는 것이다(절차 6). 파일 3개를 눈으로 확인하고, `erp-supervisor 에이전트로 이 변경을 검토해 줘.`로 한 번 불러 본 뒤, 그래도 안 되면 설치기를 `--target both`로 다시 돌린다.
- **폴더 이름에 한글·공백** → 나중에 반드시 터진다. 지금 영문 폴더로 옮기고 다시 연다.
- **회사 노트북 보안 프로그램이 설치를 막음** → 개인 노트북으로 진행하거나, 참고 파일의 "대표가 IT 담당자에게 보낼 문장"을 쓴다.
