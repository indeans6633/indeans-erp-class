# 인디언즈 ERP 시작 점검

> **1일 차 라이브 판(11-17 리허설 반영)** — 공개 번들 v3.2 원본에서 수업 단위 말·1일 차 순서·버전 비교·마지막 안내만 바꿨다. 비교용 원본: `proposed-skills/_원본/`.

## 언제 쓰나

- 번들을 막 설치하고 처음 연 자리에서(1일 차 첫 실습). 1일 차는 **설치 점검(이 스킬) → 인터뷰 1·2·3차(`indeans-erp-interview`, 차수마다 새 대화) → 테마 고르기(`indeans-erp-design`) → 초안 계획(Plan)·초안·보고서** 순서다. **1차 인터뷰 끝에는 디자인 선택창이 열리지 않는다** — 디자인은 3차가 끝난 뒤다.
- 수업을 시작할 때 "오늘 준비됐나" 30초 점검.
- 앱이 안 켜지거나 스킬·감독 에이전트가 안 불릴 때, 원인이 도구·설치 쪽인지 먼저 가르는 자리.
- 사전 안내(사전 안내)를 못 하고 온 대표가 **당일 60분 안에 따라잡아야 할 때**(절차 12).

이 스킬은 **확인·가입 안내·기록**만 한다. 앱 코드는 만들지 않는다.

## 시작 전 상태 진단

아래를 순서대로 읽고 판정한 뒤 분기한다. 읽기 전에 대표에게 말을 걸지 않는다.

| 읽을 것 | 무엇을 보나 |
|---|---|
| `.owner/state.md` · `.owner/progress.json` | 미해결 문제·다음 행동, **`interview.round`(인터뷰를 몇 차까지 했나)·`design.code`(고른 디자인의 코드)·`app.deploy_url`(배포 주소)**. 둘 다 없으면 설치가 안 된 것이다 |
| `.owner/install-state.json` | 설치기가 남긴 기록 — `version`·`target`·설치한 파일 목록 |
| `.owner/accounts.md` | 가입한 계정(서비스·아이디·만든 날). 없으면 가입 안내를 아직 안 한 것이다 |
| `.claude/skills/` · `.agents/skills/` · `.claude/agents/` · `.codex/agents/` | 스킬과 감독 에이전트가 도구 쪽에 들어왔는지 |
| `.owner/hooks/` · `.owner/design/` | 검수 훅·도구와 디자인 선택창이 있는지 |
| `company/profile.md` · `company/design.md` | 인터뷰·디자인 결과 문서가 **실제로** 있는지 |
| `package.json` · `src/` | 초안 앱이 이미 있는지 |
| **가져온 앱 감지** — `package.json` · `src/`(`app/`·`pages/`) · `company.name` · `imported_app.detected` | 다른 도구로 만들어 온 앱인지. 기준은 `indeans-erp-rebuild` 의 「기존 앱 감지 기준」(`src/styles/` 만 있는 설치 골격은 앱이 아니다) |

판정과 분기:

- **가져온 앱** — 감지 기준이 맞는다(또는 `imported_app.detected` true) → 점검(절차 1~11)만 마치고 마지막 안내를 교재 B1 문장으로 바꿔 넘긴다(절차 11). **앱은 건드리지 않는다** — `.gitignore` 에 `.env`·`.env.local`·`.owner/tmp/` 줄이 없으면 알리고 넣는 것까지만. **이미 기록에 들어 있는 `.env` 는 추적 해제(`git rm --cached`)하지 않는다** — 리빌딩 진단이 '커밋된 .env' 를 치명으로 올리고 대표가 제안서에서 고른 뒤 처리한다(여기서 빼 두면 진단이 '현재 추적 중'을 못 본다). `.env` 계열 파일은 열지 않는다 — 키 이름만 보려는 `sed`·`cat` 도 포함(결과 표에는 `git ls-files` 로 "기록에 들어 있음/없음"만 적는다). 결과 표의 첫 행은 **'가져온 앱 감지 — 감지됨'** 이다(문장으로만 알리지 않는다).
- **설치 전** — `.owner/install-state.json`이 없다 → 절차 1~2를 하고 **절차 6(번들 설치)**부터 챙긴다. 설치가 안 된 폴더에서는 다른 스킬이 뜨지 않는다.
- **1일 차 처음** — 설치는 됐고 점검 기록이 없다 → 절차 1~11 전부(계정 가입은 오늘 필수가 아니다 — 절차 5).
- **1일 차 진행 중** — `interview.round` 가 3보다 작거나 `design.code` 가 비어 있다 → 남은 항목만 확인하고 빠진 자리로 보낸다(인터뷰 → `indeans-erp-interview`, 3차가 끝났으면 디자인 → `indeans-erp-design`).
- **1일 차 끝** — `interview.round` 3 + `design.code` 있음(그리고 `company/design.md`·`.owner/design/choice.json` 이 실제로 있음) → 30초 점검(절차 13) 뒤 초안 계획(새 대화 · Plan · `indeans-erp-draft`). 초안이 이미 있으면 `.owner/state.md` 의 "다음 행동".
- **다음 단계(저장·배포) 끝** — 배포 주소(`app.deploy_url`)가 있고 **그 주소가 실제로 열린다** → 30초 점검 뒤 `.owner/state.md` 의 "다음 행동"을 따른다.
- 그 사이 → 30초 점검 뒤 "다음 행동"을 따른다.

값이 있어도 실제가 다르면 믿지 않는다 — `design.code`가 있는데 `company/design.md`가 없거나, 배포 주소가 안 열리면 끝나지 않은 것으로 본다.

판정을 한 문장으로 먼저 알린다. 예: "인터뷰 세 번과 테마 고르기가 끝나 있습니다. 30초 점검 뒤 초안 계획으로 가겠습니다."

## 절차

### 1. 되돌릴 지점 만들기

```
git rev-parse --show-toplevel
```

나온 경로가 **지금 프로젝트 폴더와 같은지** 확인한다. 다르거나 오류가 나면 이 폴더에는 아직 되돌릴 지점이 없는 것이다 — 문서 폴더·수업 자료 폴더 안에 프로젝트를 만들면 상위 폴더의 저장소가 잡혀 "있음"처럼 보인다. 그럴 때는 `git init` → `git add -A` → `git commit -m "시작 지점"`.

대표에게 한 줄로 설명한다: "지금 상태를 사진 찍어 두는 것입니다. 잘못되면 여기로 돌아옵니다."

### 2. 어떤 컴퓨터인지 확인 (묻지 않고 본다)

도구가 알려 주는 환경 정보나 `node -p process.platform`(`win32` = 윈도우, `darwin` = 맥)으로 직접 확인한다. 둘 다 안 되면 그때 한 번 묻는다: **"지금 쓰시는 노트북이 윈도우인가요, 맥인가요?"**

- 윈도우 → `references/install-windows.md`, 맥 → `references/install-mac.md`를 읽고 그 절차를 따른다. 설치 명령 원문은 참고 파일에 있다. 여기서는 순서만 관리한다.

### 3. Node.js와 Git 확인

```
node -v
npm -v
git --version
```

- `node -v`가 `v22` 미만이거나 "찾을 수 없다"로 나오면 → 참고 파일의 Node.js LTS 설치 절차(nodejs.org 첫 화면의 **LTS** 버튼).
- `git --version`이 안 나오면 → 참고 파일의 Git 설치 절차.
- 설치 후에는 **터미널 창을 닫고 새로 연다.** 이걸 안 해서 "설치했는데 없다"가 되는 경우가 가장 많다.

### 4. 도구 2종 확인 (Claude Code · Codex)

```
claude --version
claude doctor
codex --version
codex login status
codex doctor
```

- 버전 숫자가 나오면 설치된 것이다. `doctor`의 경고는 문장을 그대로 대표에게 보여 준다.
- Claude Code는 **유료 구독(Pro 이상)**, Codex는 **ChatGPT Plus 이상**이 필요하다. 로그인은 `claude`를 실행해 대화가 열리는지, `codex login status`가 "Logged in"으로 나오는지로 확인한다.
- **둘 중 하나만 있어도 수업은 진행된다.** 없는 쪽은 "나중에 해도 됩니다"로 넘기고 **`.owner/state.md`의 "미해결 문제"에 한 줄로 적는다**(예: "Codex 미설치 — 수업 뒤에"). 여기서 시간을 다 쓰지 않는다.

### 5. 계정 가입 지원 (GitHub·Supabase·Vercel 필수, 디스코드·텔레그램 선택)

먼저 한 줄로 말한다: **"GitHub는 만든 앱을 보관하는 창고, Supabase는 앱에 넣은 내용이 사라지지 않게 두는 곳, Vercel은 그 앱을 인터넷 주소로 띄우는 곳입니다. 오늘은 가입하고 이름까지만 만들어 둡니다."**

`references/accounts.md`의 그 서비스 절을 읽고 **아래 순서대로 하나씩** 돕는다. 가입 화면의 입력과 인증은 대표가 하고, AI는 화면 순서를 한 단계씩 불러 준다. 이미 있다고 하면 "어디서 확인하나"만 알려 주고 넘어간다.

| 순서 | 서비스 | 오늘 만드는 것 | 처음 쓰는 때 |
|---|---|---|---|
| 1 | GitHub | 계정 + **비공개(Private) 빈 저장소** 1개(이름 = 프로젝트 폴더 이름) | 다음 단계 — 올리기 |
| 2 | Supabase | 계정(GitHub로 로그인) + 조직(Free). **프로젝트는 다음 단계에** 만든다 | 다음 단계 — 저장 연결 |
| 3 | Vercel | 계정(GitHub로 로그인, Hobby). 팀은 자동으로 생긴다. 가져오기는 다음 단계에 | 다음 단계 — 배포 |
| 4 | 디스코드(선택) | 계정 + 내 서버 + 보고 받을 채널 | 운영 보고 단계 |
| 5 | 텔레그램(선택) | 폰 앱 가입(휴대폰 번호). 봇은 그 단계에 | 운영 보고 단계 |

- **GitHub로 Supabase·Vercel에 가입한다.** 로그인이 하나로 묶여 비밀번호가 늘지 않고, 저장·배포 단계에서 저장소를 가져올 때 연결이 이미 돼 있다.
- 다 만들면 `assets/accounts.template.md`를 `.owner/accounts.md`로 만들어 **서비스 · 계정 식별자(아이디·저장소·조직·팀·서버 이름) · 만든 날만** 적는다. **비밀번호·토큰·키·웹후크 주소·복구 코드·메일 주소·휴대폰 번호는 적지 않는다.** 비밀값은 쓸 때 그 스킬이 `.env.local`과 서비스의 비밀 저장 칸에 넣는다.
- 흔히 막히는 곳 넷: **인증 메일이 안 온다**(스팸함·프로모션함, 2분 뒤 한 번만 재전송) · **휴대폰 인증을 요구한다**(대표 본인 폰으로) · **요금제 고르기**(전부 무료 — GitHub Free·Supabase Free·Vercel Hobby. 카드 입력 화면이 나오면 멈추고 한 화면 뒤로) · **Vercel을 메일로 가입했다**(계정 설정의 로그인 연결에서 GitHub를 붙인다). 자세한 것은 `references/accounts.md`.
- Vercel 무료(Hobby)는 개인·비상업 용도로 정해져 있다. 실습은 무료로 하고, 직원이 매일 쓰기 시작할 때 요금제를 **대표가** 판단한다(`references/accounts.md` 3절).
- **계정 3종(GitHub·Supabase·Vercel)은 저장·배포 단계를 시작하기 전까지만 있으면 된다.** 오늘(1일 차)은 내 컴퓨터에서 초안까지라 계정이 없어도 막히지 않는다 — 시간이 남을 때 같이 만든다.
- 한 서비스에서 5분 넘게 막히면 붙잡지 말고 "미해결 문제"에 `미가입 — ○○(막힌 화면)`으로 적고 다음으로 간다. 넘길 때 한 줄만: "오늘은 없어도 됩니다. 저장·배포 단계 전까지만 만들어 두시면 돼요."
- 디스코드·텔레그램은 오늘 시간이 남을 때만 한다. 운영 보고 단계에서 그 스킬이 둘 다 만든다.

### 6. 번들이 다 들어왔는지 확인

설치기가 한 번에 넣는 것은 다섯 묶음이다. **직접 확인**한다(파일이 있는지 본다). 개수가 아래와 다르면 저장소의 `manifest.json` 목록이 기준이다.

| 묶음 | 어디에 | 몇 개 |
|---|---|---|
| 스킬 | `.claude/skills/` · `.agents/skills/` | 17개 폴더(각 폴더에 `SKILL.md`) |
| 감독 에이전트 | `.claude/agents/*.md` · `.codex/agents/*.toml` | 4개 (`erp-supervisor`·`erp-design-supervisor`·`erp-verifier`·`erp-auditor`) |
| 검수 훅·도구 | `.owner/hooks/` | 7개 — `erp-check.mjs`(검수)·`open.mjs`(열기)·`capture.mjs`(화면 사진)·`report.mjs`(보고서)·`design-pick.mjs`(디자인 선택창) + 배포 전 점검·정기 점검 훅 2개(이름은 `manifest.json`) |
| 디자인 선택창 | `.owner/design/` | `index.html`(선택창)·`app/`·`fonts/`(글꼴·라이선스)·`src/`(구조별 목업·뼈대 CSS) — 빠진 것은 아래 점검 명령이 센다 |
| 수업 자료 | `course/` | `session-01`~`session-04` + `final` |

디자인 선택창은 명령 한 줄로 점검한다(브라우저는 열리지 않는다). `선택창 점검 통과`가 나오면 된 것이다. `문제 n건`과 `없음: …` 줄이 나오면 아래처럼 설치기를 다시 돌린다. 빈 포트를 열지 못했다는 문제 한 줄만 나오면 설치는 된 것이다 — 보안 프로그램 탓이고, 그때는 `.owner/design/index.html`을 직접 열어 고를 수 있다.

```
node .owner/hooks/design-pick.mjs --check
```

**감독 에이전트는 두 가지로 확인한다.** 목록을 내주는 명령이 따로 있는 것이 아니다. ① 에이전트 폴더에 **파일 4개가 있는지 눈으로 본다.** ② AI에게 **`erp-supervisor 에이전트로 이 변경을 검토해 줘.`** 라고 시켜 **실제로 떠지는지** 본다. "그런 에이전트가 없다"고 하면 ①로 돌아간다.

빠진 묶음이 있으면 저장소 폴더에서 설치기를 다시 돌리게 안내한다(재설치는 안전하다 — 대표가 고친 파일은 `.new`로 옆에 저장된다).

```
node install.mjs --project <내 프로젝트 폴더 경로> --target both
```

- **수업 자료(`course/`)만 비어 있으면 설치기를 다시 돌리라고 하지 않는다.** 저장소에 그 폴더가 아직 없으면 몇 번을 돌려도 같은 결과다. 설치기가 "수업 자료가 아직 없어 건너뜁니다"라고 했다면 **강사에게 알린다**고 한 줄로 말하고 1일 차 실습은 그대로 진행한다. "미해결 문제"에 "수업 자료 미도착 — 강사 확인"으로 적는다.
- 나머지 묶음이 비었을 때만 다시 돌린다. 다시 돌려도 같은 것이 빠지면 저장소를 제대로 내려받았는지(폴더에 `install.mjs`·`skills/`가 있는지) 본다. 한쪽 도구에만 들어왔으면 `--target both`로 다시 돌린다. Codex에서 안 보이면 Codex를 껐다 켠다.
- `.owner/install-state.json`의 `version`을 대표에게 한 줄로 알린다("번들 {version}이 설치돼 있습니다"). 커밋 이름(v3.2 등)과 견주지 않는다.

### 7. 검수 훅이 등록됐는지 확인

파일이 있는 것과 **도구가 부르는 것**은 다르다. 등록은 설정 파일에 들어 있다.

| 도구 | 설정 파일 | 들어 있어야 하는 것 |
|---|---|---|
| Claude Code | `.claude/settings.json` | `hooks.Stop`에 `node "${CLAUDE_PROJECT_DIR}/.owner/hooks/erp-check.mjs" --tool claude` |
| Codex | `.codex/hooks.json` | `hooks.Stop`에 `node "<이 프로젝트의 절대 경로>/.owner/hooks/erp-check.mjs" --tool codex` |

상대 경로(`node .owner/hooks/…`)로 적힌 옛 등록이면 설치기를 다시 돌려 바꾼다 — AI 가 다른 폴더로 옮겨 가 있으면 그 훅이 조용히 안 돈다. 손으로 넣을 때도 상대 경로로 쓰지 않는다.

등록이 없으면 설치기를 다시 돌린다. 그래도 안 되면(설정 파일의 다른 내용이 깨져 있을 때) 설치기가 낸 안내대로 손으로 한 줄 넣는다. **대표가 넣어 둔 다른 설정을 지우지 않는다.** 등록된 훅이 실제로 도는지 한 번 실행해 본다.

```
node .owner/hooks/erp-check.mjs --tool claude --debug
```

"판정: 통과" 또는 "판정: 검수 필요"와 바뀐 파일 목록이 나오면 정상이다. **바뀐 것이 없으면 `판정: 통과` 한 줄만 나온다 — 그것도 정상이다.** **1일 차 첫 검수 때 바뀐 파일 목록이 길게 나오는 것도 정상이다** — 아직 검수를 마친 적이 없어(`.owner/last-check.json` 없음) 기준점이 번들을 설치한 시점의 커밋이기 때문이다. 한 번 검수를 마치면 그 뒤에 바뀐 것만 나온다.

대표에게 한 줄로 설명한다: "작업을 끝낼 때마다 이게 먼저 돌아서, 화면·저장·권한이 바뀌었으면 검수를 받으라고 알려 줍니다."

**Codex를 쓰면 하나 더 — 훅 신뢰 승인.** Codex는 프로젝트에 있는 훅을 **신뢰 승인 전까지 조용히 건너뛴다**(경고도 없다). 처음 한 번은 **대화형으로**(`codex`를 그냥 실행해서) 열어 승인해야 검수가 돈다. 확인법: 아무 작업이나 한 번 끝내고 화면에 `hook: Stop`이 **두 줄**(개인 설정 것 + 이 프로젝트 것) 나오는지 본다. 한 줄이면 아직 승인 전이다 — "미해결 문제"에 `Codex 훅 신뢰 승인 — 대화형으로 한 번 열기`로 적는다.

### 8. 화면 캡처 도구(playwright) 확인

보고서에 넣을 화면 사진을 찍는 도구다. 이 도구는 **프로젝트 안에** 설치한다(설치기가 대신 설치하지 않는다). `npm ls playwright`로 버전이 나오면 된 것이다.

- `package.json`이 아직 없으면(초안 앱을 만들기 전 — 1일 차는 대개 이 상태다) **지금 설치하지 않는다.** "미해결 문제"에 `화면 사진 도구 — 앱 만든 뒤 설치`로 적는다 — 다음 단계에 `indeans-erp-draft`가 앱을 만든 뒤 설치한다.
- `package.json`이 있고 playwright가 없으면 `npm i -D playwright`와 `npx playwright install chromium` 두 줄을 실행한다(한 번만, 두 번째 줄은 2~4분). 회사 네트워크가 막으면 붙잡지 않는다 — 캡처가 필요한 자리에서 "사진은 없이 진행"으로 적는다.

### 9. 프로젝트 폴더 규약

프로젝트 폴더가 아래 모양인지 확인하고, 없는 폴더는 만든다.

```
my-erp/                 ← 회사 이름으로 지어도 된다(영문·하이픈 권장)
  company/              ← 회사 문서(인터뷰·디자인 결과). 다음 스킬들이 읽는다
  src/                  ← 앱 코드(다음 단계에 생긴다)
  course/session-01/    ← 수업 자료
  reports/              ← 작업 보고서(작업마다 쌓인다)
  .owner/               ← 설치 기록·상태 문서·계정 기록(accounts.md)·검수 훅·디자인 선택창
  .owner/tmp/           ← 스킬이 쓰고 버리는 임시 파일. 커밋하지 않는다
  .claude/skills/       ← Claude Code가 읽는 스킬
  .agents/skills/       ← Codex가 읽는 스킬
```

- **`.gitignore`에 `.env.local`과 `.owner/tmp/` 두 줄이 있는지 확인한다.** 없으면 "이 두 줄을 넣겠습니다"라고 알린 뒤 넣는다. `.env.local`은 한 번 올라가면 지워도 기록에 남는다. **설치기는 `.gitignore`를 건드리지 않는다** — 대표의 파일이라 손대지 않는 것이 규약이다.
- 폴더 이름에 한글·공백·괄호를 쓰지 않는다. 나중에 배포 주소와 명령에서 문제가 된다.
- 바탕화면·다운로드 폴더가 아니라 문서 폴더 아래 고정된 자리에 둔다. 클라우드 동기화 폴더(OneDrive·iCloud 데스크톱) 안은 피한다 — 파일이 잠기거나 반쯤 내려받아진 상태에서 오류가 난다.

### 10. 상태 문서 확인

`.owner/state.md`와 `.owner/progress.json`은 **대화를 잇는 기억**이다. 모든 스킬이 시작할 때 읽고 끝날 때 고친다.

- 둘 중 하나라도 없으면 설치기를 다시 돌린다(있는 파일은 건드리지 않는다). 손으로 새로 만들지 않는다.
- 있으면 열어서 **실제와 맞는지** 본다. "배포 완료"인데 주소가 없거나, "화면 3개"인데 `src/screens/`가 비어 있으면 **문서를 믿지 않고** 실제에 맞게 고친다.
- `.owner/`에는 금액·고객 실명·연락처·비밀값을 적지 않는다.

### 11. 작업 습관 읽어 주기, 기록하고 커밋

아래 「작업 습관」 여섯 줄을 대표에게 한 번 읽어 준다. 묻지 않는다 — 다 읽고 "앞으로 이렇게 하겠습니다" 한 줄로 끝낸다.

그다음 점검 결과를 두 곳에 남긴다. **파일의 구조는 그대로 두고 값만 바꾼다**(없는 키를 새로 만들지 않는다).

- `.owner/state.md` → "미해결 문제"에 미설치·미가입 항목을 한 줄씩(무엇이 없고 언제 하기로 했는지), "다음 행동"에 `새 대화에서 indeans-erp-interview(1차) — 끝나면 새 대화에서 2차·3차, 그다음 테마 고르기`.
- `.owner/progress.json` → `open_problems`에 같은 항목을 짧게, `next_action`에 다음 행동, `updated_at`에 지금 시각, `updated_by`에 지금 쓰는 도구(`claude` 또는 `codex`).

```
git add -A
git commit -m "1일 차 시작 점검"
```

마지막으로 대표에게 3줄로 보고한다: 된 것 / 안 된 것(언제까지) / 다음 행동. 끝에 한 줄: "다음은 새 대화를 열고 「1차 인터뷰 시작해 줘.」라고 말씀해 주세요." — 프로젝트 `CLAUDE.md` 의 짧은 말 사전이 이 말을 `indeans-erp-interview` 로 잇는다. 교재 쪽수·긴 문장을 안내하지 않는다.

가져온 앱이면 끝 한 줄이 다르다: "다음 작업(리빌딩)은 새 대화에서 시작합니다. 교재 앞선 트랙 B1 문장을 그대로 넣어 주세요." 하고 그 세 줄을 **글자 그대로** 보여 준다(줄여 쓰지 않는다 — 되돌릴 지점·백업·진단·제안 지시가 다 들어 있다). `.owner/state.md` 의 "다음 행동"도 `새 대화에서 indeans-erp-rebuild — 되돌릴 지점·백업·진단·제안` 으로 적는다.

```
indeans-erp-rebuild 스킬을 읽고 시작해 주세요.
이 폴더의 앱은 제가 다른 도구로 만들어 온 것입니다. 먼저 되돌릴 지점과 백업을 만들고,
앱을 진단해서 개선 방향을 제안해 주세요. 제가 고르기 전에는 아무것도 고치지 마세요.
```

### 12. 사전 안내를 못 한 대표 — 당일 60분 따라잡기

사전 안내(사전 안내)에는 도구·Node·Git·프로젝트 폴더·번들 설치·계정 가입이 들어 있다. 하나도 안 된 상태로 왔으면 **이 순서대로만** 한다. 뒤 항목은 앞 항목이 있어야 된다.

| 분 | 무엇을 | 안 되면 |
|---|---|---|
| 0~10 | Node.js LTS + Git 설치, 터미널 새로 열기 | 옆자리 화면을 같이 보며 진행. 건너뛸 수 없다 |
| 10~25 | **도구 하나만** 설치·로그인(대표가 이미 결제한 쪽) | 결제가 안 돼 있으면 강사 화면으로 따라 보고 집에서 설치 |
| 25~30 | 프로젝트 폴더 만들기(영문 이름) | — |
| 30~40 | 번들 설치(절차 6) + 등록 확인(절차 7) | 실패하면 강사가 그 자리에서 본다. 여기까지는 반드시 끝낸다 |
| 40~55 | GitHub → Supabase → Vercel 가입(절차 5) | 인증이 늦으면 `미가입`으로 두고 진행 — 다음 단계 전까지 필수 |
| 55~60 | 1차 인터뷰 시작(새 대화에서 `indeans-erp-interview`) | — |

- **미루는 것**: 두 번째 도구 · 디스코드·텔레그램 · playwright. 셋 다 1일 차에 쓰지 않는다. `미확인`으로 적고 수업 뒤에 하게 안내한다.
- 60분을 넘기면 인터뷰·디자인 선택 시간을 깎게 된다. 남은 것은 "미해결 문제"에 적고 다음 단계 시작 때 처리한다.

### 13. 30초 점검 모드 (수업을 시작할 때)

"1일 차 끝"·"다음 단계 끝"·그 사이 판정이거나 대표가 "점검만"이라고 하면 이것만 한다.

1. `node -v`, `git --version`, `claude --version`(또는 `codex --version`) — 한 번에 실행하고 결과만 본다.
2. `.owner/install-state.json`의 `version`과 저장소 `manifest.json`의 `version`**만** 비교한다. 다르면 설치기를 다시 돌리라고 한 줄 안내한다. **커밋 이름·태그(v3.2 같은 것)와는 비교하지 않는다** — 둘은 이름 붙이는 법이 달라 숫자가 달라 보여도 정상이다. 대표에게 그 차이를 말하지 않는다.
3. `open_problems`와 "미해결 문제"를 읽어 지난번 대비 빠진 것을 본다. 다음 단계를 시작하는 날이면 `.owner/accounts.md`의 GitHub·Supabase·Vercel 세 줄이 채워졌는지 **반드시** 본다 — 비었으면 절차 5부터 한다.
4. `git status`로 저장 안 된 변경이 있는지 본다. 있으면 커밋할지 묻는다(질문 1개).
5. 결과를 표 한 줄로 보고하고, 진단에서 정한 다음 스킬을 알린 뒤 끝낸다. 질문을 더 하지 않는다.

## 작업 습관 (모든 날 공통)

AI와 일하는 방식이다. 1일 차에 한 번 같이 읽고(절차 11), AI는 모든 스킬에서 이것을 스스로도 지킨다.

1. **작업 하나 = 새 대화 하나.** 화면 하나 만들기·저장 연결처럼 작업 하나가 보고서·커밋까지 끝나면 대화를 닫고 다음 작업은 새 대화에서 연다(1차 인터뷰 → 디자인 선택처럼 스킬이 이어서 여는 것은 한 작업이다). 이어 갈 것은 대화 기억이 아니라 `.owner/state.md`의 "다음 행동"에서 읽는다. 긴 대화는 앞에서 정한 것을 놓치고 사용량도 빨리 닳는다. AI는 작업을 끝낼 때 "다음 작업은 새 대화에서 ○○ 스킬로" 한 줄을 남긴다.
2. **기록은 한 곳.** 한 일은 `reports/`(작업 보고서), 지금 상태는 `.owner/state.md`에만 둔다. 메모장·대화창·다른 문서에 흩지 않는다. `state.md`에는 지금 되는 것·미해결 문제·다음 행동만 두고, 끝난 일의 자세한 내용은 보고서에 맡긴다(`company/`의 회사 문서는 기록이 아니라 앱의 설계도라 따로 둔다).
3. **화면 사진은 기능당 한 번.** 새 기능을 만들면 폰(375)·PC(1280) 한 번씩. 고친 뒤 다시 찍을 때는 바뀐 화면만 폰 폭으로. 글자 몇 개·조건 한 줄 바꾼 것은 찍지 않고 빌드·새로고침으로 확인한다.
4. **결정은 대표가, AI는 권장안 하나.** AI가 고를 것을 여러 개 늘어놓으면 "권하는 것 하나와 이유만 말해 줘"라고 한다. AI는 돈·권한·지우기·되돌리기 어려운 것만 묻고, 나머지는 권장안으로 진행한 뒤 보고에 한 줄로 적는다(틀리면 대표가 바로잡는다).
5. **"아직 만들지 마세요"를 같이 말한다.** 확인이나 계획만 원할 때는 하지 말 것을 같이 말한다. 계획을 먼저 보고 "그대로 해 주세요"로 시작한다.
6. **오류는 원문 그대로.** 요약하지 않고 화면의 글자를 그대로 붙여 넣는다. 형식은 `references/troubleshooting.md` 16번(하려던 것·기대한 것·실제·오류 원문).

- 비밀번호·인증 코드·복구 코드·키·토큰·웹후크 주소를 받아 적거나 대화에 옮기기. 대표가 불러 주려 하면 "그건 저에게 주지 않으셔도 됩니다"라고 막는다.
- Supabase 프로젝트·Vercel 프로젝트를 1일 차에 만들기. 다음 단계에 만든다.
- 상태 문서를 손으로 새로 만들기. 없으면 설치기를 다시 돌린다.
- 설치기가 넣지 않은 설정(대표가 직접 넣은 훅·설정)을 지우거나 덮기.
- 안 되는 도구·가입을 끝까지 붙들기. 5분 안에 안 되면 `미설치`·`미가입`으로 적고 진행한다.
- 대표 컴퓨터의 다른 프로그램 설치·설정 변경. 이 목록 밖의 것은 손대지 않는다.

## 앞선 수강생 분기

이미 점검이 끝나 있으면 30초 점검 뒤 아래 중 하나를 제안한다(고르는 것은 대표).

1. **두 도구 비교** — 같은 요청을 Claude Code와 Codex에 각각 넣고 결과가 어떻게 다른지 본다. 어느 쪽이 내 말투를 잘 알아듣는지 감을 잡는 연습.
2. **감독 에이전트 한 번 불러 보기** — 고른 디자인 문서(`company/design.md`)를 `erp-design-supervisor`에게 검토받아 본다. 검수 체계가 어떻게 말하는지 미리 겪어 두면 실사용 준비 단계가 쉬워진다.
3. **되돌리기 연습** — 일부러 파일 하나를 고쳐 놓고 `git status`·`git restore`로 되돌려 본다. 과정 내내 가장 많이 쓰게 될 안전장치다.
4. **선택 계정 미리** — 디스코드 서버·채널과 텔레그램 가입(`references/accounts.md` 4·5절). 운영 보고 단계에서 시간을 번다.
5. **다른 폴더에서도 쓰기** — 다음에 만들 폴더에서도 같은 스킬이 뜨게 개인 자리에 둔다. 방법은 `references/troubleshooting.md`의 "스킬을 다른 폴더에서도 쓰고 싶다" 항목.

## 자주 막히는 지점

자세한 증상·해결·"AI에게 그대로 말할 문장"은 `references/troubleshooting.md`(설치·도구)와 `references/accounts.md`(가입)에 있다. 오류가 나면 **추측하지 말고 그 파일을 먼저 읽는다.**

- **설치했는데 "찾을 수 없다"** → 터미널을 닫고 새로 연다. 그래도 안 되면 참고 파일의 PATH 항목.
- **스킬은 뜨는데 감독 에이전트가 안 불린다** → 에이전트 파일이 도구 쪽에 없는 것이다(절차 6). 파일 4개를 눈으로 확인하고, `erp-supervisor 에이전트로 이 변경을 검토해 줘.`로 한 번 불러 본 뒤, 그래도 안 되면 설치기를 `--target both`로 다시 돌린다.
- **인증 메일·문자가 안 온다** → 스팸함·프로모션함, 2분 뒤 재전송 한 번. 그래도 안 오면 `미가입`으로 적고 다음 서비스로 간다.
- **폴더 이름에 한글·공백** → 나중에 반드시 터진다. 지금 영문 폴더로 옮기고 다시 연다.
- **회사 노트북 보안 프로그램이 설치를 막음** → 개인 노트북으로 진행하거나, 참고 파일의 "대표가 IT 담당자에게 보낼 문장"을 쓴다.
