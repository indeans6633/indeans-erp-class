> **1일 차 라이브 판(11-17 리허설 반영)** — 공개 번들 v3.2 원본에서 수업 단위 말만 바꿨다. 비교용 원본: `proposed-skills/_원본/`.

> 작성: indeans-erp-setup · 1일 차. 가입할 때마다 그 줄을 채운다. 절 제목을 바꾸지 않는다 — 다음 단계 저장·배포 스킬과 운영 보고 단계 스킬이 이 표를 읽는다.

**이 파일은 저장소에 같이 올라간다.** 그래서 남이 봐도 괜찮은 것만 적는다: **서비스 · 계정 식별자 · 만든 날** 세 가지뿐이다.

## 가입한 계정

| 서비스 | 계정 식별자 (아이디·저장소·조직·팀·서버 이름, 로그인 방식) | 만든 날 |
|---|---|---|
| GitHub (필수) | 아이디 `{아이디}` · 비공개 저장소 `{저장소 이름}` | {YYYY-MM-DD 또는 (아직)} |
| Supabase (필수) | GitHub 로 로그인 · 조직 `{조직 이름}` · 프로젝트는 다음 단계에 | {YYYY-MM-DD 또는 (아직)} |
| Vercel (필수) | GitHub 로 로그인 · 팀 `{팀 이름}` · 요금제 Hobby | {YYYY-MM-DD 또는 (아직)} |
| 디스코드 (선택) | 서버 `{서버 이름}` · 채널 `{채널 이름}` | {YYYY-MM-DD 또는 (안 함)} |
| 텔레그램 (선택) | 사용자 이름 `{@이름 — 없으면 '앱 가입함'}` | {YYYY-MM-DD 또는 (안 함)} |

- 아직 못 만든 줄은 `(아직)` 으로 두고, 이유를 `.owner/state.md` 의 "미해결 문제"에 한 줄로 적는다(예: `미가입 — Supabase(인증 메일 안 옴), 다음 단계 전까지`).
- **GitHub·Supabase·Vercel 세 줄은 다음 단계 시작 전까지 채워져 있어야 한다.** 다음 단계에 이 셋으로 저장과 배포를 한다.

## 여기에 적지 않는 것

- 비밀번호, 2단계 인증 복구 코드
- 키·토큰·열쇠(Supabase 키, 데이터베이스 비밀번호, 봇 열쇠, 접속 토큰)
- 웹후크 주소
- 메일 주소, 휴대폰 번호

비밀값은 쓸 때 그 스킬이 `.env.local`(커밋하지 않는 파일)과 서비스의 비밀 저장 칸에만 넣는다. 비밀번호·복구 코드는 대표 본인만 보는 곳(비밀번호 관리 앱·종이)에 둔다.
