# 계정 가입 안내 (1회차)

`indeans-erp-setup` 절차 5가 읽는다. **위에서부터 한 서비스씩** 끝내고 다음으로 간다. 가입 화면의 입력과 인증(메일·문자 코드)은 **대표가 직접** 하고, AI 는 화면 순서를 한 단계씩 불러 준다.

기준일 2026-10. 가입 화면의 글자·버튼 이름은 자주 바뀐다. 이 문서와 화면이 다르면 **지금 화면에 보이는 글자를 그대로 읽어 달라고 해서** 거기에 맞춘다. 짐작으로 누르게 하지 않는다.

## 공통 — 시작 전에 말해 둘 것

- **대표 본인 명의·본인 메일**로 만든다. 직원 메일이나 남의 계정으로 만들면 그 사람이 회사를 떠날 때 앱도 같이 잠긴다.
- 메일 주소는 하나로 정해 다섯 곳 모두 그 메일을 쓴다. 대표가 오래 쓸 메일(회사 메일 권장)이다.
- **GitHub 를 먼저** 만든다. Supabase·Vercel 은 "GitHub 로 계속(Continue with GitHub)"으로 가입한다 — 비밀번호가 늘지 않고, 2회차에 저장소를 가져올 때 연결이 이미 돼 있다.
- **결제 카드를 넣는 화면이 나오면 멈춘다.** 이 과정의 가입은 전부 무료 요금제로 된다. 카드를 요구하면 유료 요금제를 고른 것이니 한 화면 뒤로 간다.
- 비밀번호·복구 코드·인증 앱은 **대표 본인만 보는 곳**(비밀번호 관리 앱·종이)에 둔다. 프로젝트 폴더·대화창·회사 문서에 쓰지 않는다. AI 에게 불러 주지도 않는다.
- 한 서비스에서 5분 넘게 막히면 붙잡지 않는다. `미가입 — ○○(막힌 화면)` 으로 적고 다음 서비스로 간다(절차 5의 마지막 줄).

## 적어 두는 곳 — `.owner/accounts.md`

템플릿은 `assets/accounts.template.md`. 적는 것은 **세 가지뿐**이다: 서비스 · 계정 식별자 · 만든 날.

| 적는다 (계정 식별자) | 적지 않는다 |
|---|---|
| GitHub 아이디, 비공개 저장소 이름 | 비밀번호, 2단계 인증 복구 코드, 접속 토큰 |
| 로그인 방식("GitHub 로 로그인") | 메일 주소, 휴대폰 번호 |
| Supabase 조직 이름 | 데이터베이스 비밀번호, 키(`anon`·`publishable`·`service_role`·`secret`) |
| Vercel 팀 이름 | 접속 토큰 |
| 디스코드 서버·채널 이름 | 웹후크 주소(webhook URL) |
| 텔레그램 사용자 이름(@…) | 봇 열쇠(토큰) |

비밀값은 쓸 때가 되면(2회차 저장 연결, 운영 보고 단계) 그 일을 맡은 스킬이 `.env.local`(내 컴퓨터에만 있고 커밋하지 않는 파일)과 서비스의 비밀 저장 칸에만 넣는다. `.owner/accounts.md` 는 저장소에 같이 올라가는 파일이다 — 남이 봐도 괜찮은 것만 둔다.

## 1. GitHub — 만든 앱을 보관하는 창고 (필수)

대표에게 하는 말: "만든 앱을 날짜별로 보관하는 창고입니다. 2회차에 여기에 올리고, 인터넷 주소도 여기에 올린 것을 가져가서 띄웁니다."

순서:

1. github.com → **Sign up**.
2. 메일 → 비밀번호 → 아이디(영문 소문자·숫자·하이픈). 회사 이름을 바탕으로 짓는다(예: `hana-works`·`daon-parts`·`mirae-foods`). 아이디는 저장소 주소에 그대로 들어간다.
3. 사람 확인 퍼즐 → 메일로 온 숫자 코드를 넣는다.
4. 요금제를 물으면 **Free**.
5. **비공개 저장소 1개를 만든다.** 오른쪽 위 `+` → **New repository** →
   - 이름: 프로젝트 폴더 이름과 같게(예: `my-erp`).
   - **Private** 를 고른다. Public 으로 만들지 않는다 — 회사 업무 구조가 통째로 공개된다.
   - README·.gitignore·라이선스를 추가하는 칸은 **모두 비워 둔다.** 빈 저장소라야 2회차 첫 올리기가 한 번에 된다.
   - **Create repository**.
6. 만든 저장소의 주소(`https://github.com/<아이디>/<저장소>`)를 확인한다. **오늘은 올리지 않는다.** 올리는 것은 2회차에 `indeans-erp-data` 가 한다.

확인: 오른쪽 위에 내 아이콘이 보이고, 저장소 이름 옆에 `Private` 표시가 있다.

막히는 곳:

- **코드 메일이 안 온다** → 스팸함·프로모션함을 본다. 2분 뒤 다시 보내기를 한 번만 누른다.
- **아이디가 이미 있다** → 회사 이름에 지역·업종을 붙인다(`hana-works-seoul`).
- **2단계 인증(2FA)을 켜라고 한다** → 휴대폰 인증 앱으로 켠다. 마지막에 나오는 **복구 코드**를 내려받아 컴퓨터 밖(종이·개인 보관함)에 둔다. 폰을 잃었을 때 계정에 다시 들어가는 유일한 열쇠다. 정해진 기한 안에 켜지 않으면 로그인이 막힌다.
- **Public 으로 만들어 버렸다** → 저장소 Settings → 맨 아래 Danger Zone → 공개 범위 바꾸기(Change visibility) → Private.

## 2. Supabase — 앱에 넣은 내용을 두는 곳 (필수)

대표에게 하는 말: "앱에 넣은 내용이 사라지지 않게 두는 창고입니다. 오늘은 가입과 조직까지만 만들고, 실제 창고(프로젝트)는 2회차에 만듭니다."

순서:

1. supabase.com → **Start your project**(또는 Sign in) → **Continue with GitHub** → 허용(Authorize). 로그인에 쓰는 허용이다.
2. 조직(Organization)을 만들라는 화면이 나오면: 이름은 회사 영문 이름, 요금제는 **Free**. 조직이 자동으로 하나 만들어져 있으면 그 이름을 확인만 한다.
3. 이어서 **프로젝트 만들기 화면이 나오면 여기서 멈춘다.**
   - 왜: 무료 프로젝트는 **일주일 넘게 쓰지 않으면 잠시 멈춘다.** 대시보드에서 다시 켤 수 있지만 몇 분이 걸려, 1회차에 만들어 두면 2회차를 깨우는 일부터 시작하게 된다.
   - 무료 프로젝트는 **동시에 두 개까지**다. 연습용으로 여러 개 만들지 않는다.

확인: 대시보드 왼쪽 위에 조직 이름이 보인다.

알아 둘 것 — 무료로 시작한다. 무료 요금제의 한도는 세 가지다(대표에게 그대로 읽어 준다):

- **1주일 동안 쓰지 않으면 잠시 멈춘다.** 데이터는 그대로이고, 대시보드에서 그 프로젝트를 다시 켜면(Restore) 몇 분 뒤 돌아온다.
- **프로젝트는 2개까지다.**
- **자동 백업이 없다.** 수업에서 앱의 전체 내려받기로 직접 백업한다(2회차에 `indeans-erp-data` 가 백업 방법부터 정한다).

유료(Pro)로 바꿀지는 실사용을 시작할 때 다시 본다(`indeans-erp-routine` 세팅 모드). AI 가 대신 정하지 않는다.

막히는 곳:

- **메일로 가입해 버렸다** → 그대로 써도 된다. 메일의 확인 링크를 눌러야 로그인된다.
- **프로젝트를 이미 만들었다** → 지우지 않는다. 2회차 시작 전에 대시보드를 열어 멈춰 있으면 다시 켠다(Restore). 이름은 `.owner/accounts.md` 에 적어 둔다.

## 3. Vercel — 앱을 인터넷 주소로 띄우는 곳 (필수)

대표에게 하는 말: "만든 앱을 휴대폰에서도 열리는 주소로 띄우는 곳입니다. 오늘은 GitHub 로 가입만 합니다."

순서:

1. vercel.com → **Sign Up** → **Continue with GitHub** → 허용.
2. 요금제를 묻는 화면이 나오면 **Hobby**(무료). 이름을 물으면 대표 이름이나 회사 이름.
3. 가입이 끝나면 "저장소 가져오기(Import)" 화면이 나온다 → **오늘은 가져오지 않는다.** 대시보드로 나간다. 2회차에 1번에서 만든 저장소를 가져온다.
4. 왼쪽 위에 보이는 이름(팀 — 가입하면 하나가 자동으로 생긴다)을 확인해 적어 둔다.

확인: 대시보드가 열리고 왼쪽 위에 팀 이름이 보인다.

알아 둘 것 — 무료 요금제의 용도:

- Vercel 무료(Hobby)는 **개인·비상업 용도**로 정해져 있다. 수업은 무료로 배포한다.
- **회사에서 계속 쓰려면 Pro(월 $20)로 바꾸는 것이 약관상 맞다.** 바꿀지와 언제 바꿀지는 **대표가 정한다** — AI 가 대신 정하거나 결제하지 않는다. 실사용 준비 단계에서 다시 본다. 약관이 애매하면 Vercel 고객 지원에 묻는다.

막히는 곳:

- **메일로 가입해 버렸다** → 메일로 가입한 계정은 로그인할 때마다 메일 확인을 한다. 계정 설정(Settings) → Authentication 에서 GitHub 를 연결해 둔다.
- **카드 입력 화면이 나온다** → 유료(Pro)를 고른 것이다. 뒤로 가서 Hobby.
- (2회차에 막히는 곳, 미리) **가져오기 목록에 내 저장소가 안 보인다** → 그 화면의 GitHub 앱 권한 조정(Adjust GitHub App Permissions)에서 그 저장소를 허용한다.

## 4. 디스코드 — 보고가 쌓이는 창구 (선택, 운영 보고 단계)

대표에게 하는 말: "정해진 시각에 오는 운영 보고를 쌓아 두고 다시 찾아보는 곳입니다. 오늘 시간이 남을 때만 만듭니다."

순서:

1. discord.com 에서 가입(PC 프로그램·폰 앱 모두 같다) → 메일·사용자 이름·비밀번호·생년월일 → 메일 인증.
2. 서버 만들기: 왼쪽 `+` → 직접 만들기 → 나와 친구들을 위한 서버 → 서버 이름(예: 우리회사 운영).
3. 텍스트 채널 만들기: 이름 `운영보고`.
4. 웹후크(앱이 보고를 써 넣는 주소)는 **오늘 만들지 않는다.** 운영 보고 단계에서 `indeans-erp-channel` 이 만든다 — 그 주소는 비밀값이다.

막히는 곳: **휴대폰 인증을 요구할 때가 있다** → 대표 본인 폰으로 한다. 인증 메일이 안 오면 스팸함.

## 5. 텔레그램 — 바로 아는 창구 (선택, 운영 보고 단계)

대표에게 하는 말: "폰에 바로 뜨는 알림 창구입니다. 휴대폰 번호로만 가입됩니다."

순서:

1. 폰에 텔레그램 앱 설치 → 휴대폰 번호 → 문자로 온 코드 → 이름.
2. PC 에서도 받으려면 PC 앱을 열고, 폰 앱의 설정 → 기기 → 데스크톱 기기 연결로 PC 화면의 QR 을 찍는다.
3. 사용자 이름(@…)을 정했으면 그것만 적는다. 휴대폰 번호는 적지 않는다.
4. 보고를 보내는 봇은 **오늘 만들지 않는다.** 운영 보고 단계에서 `indeans-erp-channel` 이 만든다 — 봇 열쇠는 비밀값이다.

막히는 곳: **코드 문자가 늦다** → 다시 받기를 한 번만 누른다. 여러 번 누르면 한동안 막힌다.
