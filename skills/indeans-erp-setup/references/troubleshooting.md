# 자주 나는 오류

각 항목은 **증상 → 원인 → 해결 → 대표가 AI에게 그대로 말할 문장** 순이다. 마지막 문장은 복사해서 Claude Code나 Codex 대화창에 그대로 붙여 넣으면 된다.

읽는 순서: 증상 문구로 목차에서 찾는다. 안 맞으면 16번(못 찾았을 때)으로 간다. **계정 가입(인증 메일·문자·요금제·GitHub 연결)** 문제는 이 파일이 아니라 `accounts.md`의 서비스별 "막히는 곳"에 있다.

---

## 1. `node`(또는 `git`·`claude`·`codex`)를 찾을 수 없습니다

- 증상: `'node' is not recognized...` / `command not found: node`
- 원인: 방금 설치했는데 터미널이 예전 상태를 들고 있다. 열에 아홉은 이것이다.
- 해결: 터미널 창을 **완전히 닫고** 새로 연다. 그래도 안 되면 컴퓨터를 한 번 재시작한다. 그래도 안 되면 설치가 실제로는 실패한 것이니 설치 절차를 다시 한다.

> 이렇게 말하세요
> `터미널에서 node -v 를 쳤더니 "찾을 수 없다"고 나옵니다. 창을 닫고 새로 열어도 같습니다. 지금 설치가 어떻게 돼 있는지 확인하고, 다시 설치해야 하는지 알려 주세요. 제 컴퓨터는 윈도우(또는 맥)입니다.`

## 2. 권한이 없다 / Permission denied

- 증상: `EACCES`, `permission denied`, `액세스가 거부되었습니다`
- 원인: 시스템 폴더에 쓰려고 했거나, `sudo npm install -g`를 썼다.
- 해결: `sudo`를 붙이지 않는다. 공식 설치 명령(참고 파일)을 쓴다. 이미 `sudo`로 깐 적이 있으면 그 설치를 지우고 다시 깐다.

> 이렇게 말하세요
> `설치할 때 permission denied 오류가 납니다. 관리자 권한 없이 설치하는 방법으로 다시 안내해 주세요. 지금까지 실행한 명령은 이것입니다: (붙여넣기)`

## 3. 폴더 이름에 한글·공백이 있어서 명령이 깨진다

- 증상: 경로 중간에서 잘린 오류, `no such file or directory`, 한글이 `??`로 보임
- 원인: 폴더 이름에 한글·공백·괄호가 있다.
- 해결: 영문 소문자·하이픈만 쓰는 새 폴더(`my-erp`)를 만들고 파일을 옮긴 뒤 그 폴더에서 다시 연다.

> 이렇게 말하세요
> `제 프로젝트 폴더 이름에 한글과 공백이 들어 있습니다. 영문 폴더로 옮기고 싶은데, 옮기는 절차를 알려 주고 옮긴 뒤 무엇을 확인하면 되는지 알려 주세요.`

## 4. 로그인이 안 된다 / 무료 플랜이라 막힌다

- 증상: 로그인 창은 뜨는데 "이 플랜에서는 사용할 수 없습니다"
- 원인: Claude Code는 Pro 이상, Codex는 ChatGPT Plus 이상 구독이 필요하다.
- 해결: 구독 상태를 확인한다. 하나만 구독돼 있으면 그 도구로만 수업을 진행한다. 두 도구를 동시에 켤 필요는 없다.

> 이렇게 말하세요
> `로그인을 했는데 구독 플랜 때문에 막힙니다. 지금 제 계정으로 쓸 수 있는 도구가 무엇인지 확인하고, 그 도구 하나로 진행할 수 있게 다음 단계를 알려 주세요.`

## 5. 회사 노트북 보안 프로그램이 설치를 막는다

- 증상: 설치 파일이 자동 삭제됨, 관리자 승인 요구, 네트워크 차단
- 원인: 사내 보안 정책.
- 해결: 개인 노트북으로 진행하는 것이 가장 빠르다. 회사 장비를 써야 하면 아래 문장을 IT 담당자에게 보낸다.

> IT 담당자에게 보낼 문장
> `개발 교육 과정 수강으로 아래 프로그램 설치 허용을 요청드립니다. Node.js(LTS), Git for Windows, Claude Code(claude.ai), Codex(chatgpt.com). 모두 공식 배포처에서 내려받으며 관리자 권한 없이 사용자 폴더에 설치됩니다. 회사 시스템에 접속하지 않고, 교육용 개인 프로젝트 폴더에서만 사용합니다.`

## 6. 스킬이 한쪽 도구에만 보인다

- 증상: Claude Code에서는 스킬이 뜨는데 Codex에서는 안 뜬다(또는 반대)
- 원인: 설치기를 `--target both`로 돌리지 않았다. 두 도구는 읽는 폴더가 다르다 — Claude Code는 `.claude/skills/`, Codex는 `.agents/skills/`.
- 해결: 설치기를 `--target both`로 다시 돌린다. 이미 있는 파일은 건너뛰므로 여러 번 돌려도 안전하다. 그래도 안 보이면 Codex를 껐다 켠다.

> 이렇게 말하세요
> `스킬이 한쪽 도구에서만 보입니다. .claude/skills 와 .agents/skills 양쪽에 같은 폴더가 있는지 확인하고, 없는 쪽에 채워 주세요. 기존 파일은 덮어쓰지 마세요.`

## 7. 스킬을 설치했는데 AI가 안 쓴다

- 증상: 스킬 폴더는 있는데 대화에서 그 절차대로 안 움직인다
- 원인: 새 대화를 열지 않았거나, 요청 문장에 스킬 이름이 없다.
- 해결: 대화를 새로 열고 **스킬 이름을 직접 부른다.** 예: `indeans-erp-interview 스킬을 읽고 인터뷰를 시작해 줘.`

> 이렇게 말하세요
> `indeans-erp-setup 스킬을 읽고 그 절차대로 제 상태를 점검해 주세요. 스킬 파일은 .claude/skills/indeans-erp-setup/SKILL.md 에 있습니다.`

## 8. `npm install` 이 중간에 멈추거나 오래 걸린다

- 증상: 몇 분째 진행 표시가 멈춘 것처럼 보임, `ETIMEDOUT`, `ECONNRESET`
- 원인: 네트워크(사내망·공용 와이파이) 또는 클라우드 동기화 폴더 안에서 돌렸다.
- 해결: 다른 네트워크(휴대폰 테더링)로 바꿔 다시 한다. 프로젝트가 OneDrive·iCloud 동기화 폴더 안이면 동기화 밖으로 옮긴다. 처음 설치는 원래 2~5분 걸린다 — 1분 만에 취소하지 않는다.

> 이렇게 말하세요
> `npm install 이 중간에 멈춥니다. 오류 메시지는 이것입니다: (붙여넣기). 다시 시도하기 전에 확인할 것을 알려 주세요.`

## 9. 앱 주소(localhost)를 열었는데 아무것도 안 보인다

- 증상: `npm run dev`는 돌고 있는데 브라우저가 흰 화면
- 원인: 주소를 잘못 열었거나(포트 번호 다름), 코드 오류가 있다.
- 해결: 터미널에 찍힌 주소를 그대로 복사해 연다(`http://localhost:5173` 같은 형태, 숫자가 다를 수 있다). 흰 화면이면 브라우저에서 `F12`(맥은 `option+command+i`)를 눌러 빨간 글씨를 찾아 그대로 복사한다.

> 이렇게 말하세요
> `npm run dev 로 주소를 열었는데 화면이 하얗습니다. 브라우저 개발자 도구에 이런 빨간 글씨가 있습니다: (붙여넣기). 원인을 찾아 고쳐 주세요.`

## 10. 뭘 잘못 건드려서 되돌리고 싶다

- 증상: 파일이 이상해졌다, 앱이 갑자기 안 돈다
- 원인: 방금 고친 것이 문제다. 원인 찾기보다 되돌리기가 빠르다.
- 해결: 아직 커밋하지 않았다면 되돌릴 수 있다.

```
git status
git restore .
```

이미 커밋했다면 직전 커밋으로 돌아간다(AI에게 시키는 편이 안전하다).

> 이렇게 말하세요
> `방금 고친 것 때문에 앱이 안 됩니다. 마지막으로 잘 되던 커밋으로 되돌려 주세요. 되돌리기 전에 지금 상태를 따로 저장해 두고, 무엇이 지워지는지 먼저 알려 주세요.`

## 11. 감독 에이전트가 안 불린다

- 증상: 스킬은 뜨는데 `erp-supervisor`·`erp-design-supervisor`·`erp-verifier`·`erp-auditor` 를 불러도 "그런 에이전트가 없다"고 한다
- 원인: 에이전트 파일이 도구 쪽에 없다. 설치기가 만드는 자리는 Claude Code `.claude/agents/*.md`, Codex `.codex/agents/*.toml` 다.
- 해결: 설치기를 `--target both` 로 다시 돌린 뒤 대화를 새로 연다. Codex 는 껐다 켠다.

> 이렇게 말하세요
> `.claude/agents 와 .codex/agents 에 erp-supervisor, erp-design-supervisor, erp-verifier, erp-auditor 가 있는지 확인해 주세요. 없으면 번들 설치기를 다시 돌려야 하는지 알려 주세요.`

## 12. 작업이 끝났는데 검수 요구가 안 뜬다

- 증상: 화면이나 저장 구조를 바꿨는데 아무 말 없이 끝난다
- 원인: 검수 훅이 **등록**되지 않았다. 파일이 있는 것과 도구가 부르는 것은 다르다.
- 해결: `.claude/settings.json` 의 `hooks.Stop`(Codex 는 `.codex/hooks.json`)에 `node .owner/hooks/erp-check.mjs` 가 들어 있는지 본다. 없으면 설치기를 다시 돌린다. 직접 돌려 확인하려면:

```
node .owner/hooks/erp-check.mjs --tool claude --debug
```

"판정: 통과" 또는 "판정: 검수 필요"가 나오면 훅 자체는 정상이다.

> 이렇게 말하세요
> `검수 훅이 등록됐는지 확인해 주세요. 설정 파일의 다른 내용은 그대로 두고, 빠진 항목만 넣어 주세요.`

## 13. 검수 요구가 계속 뜬다

- 증상: 끝내려 할 때마다 "검수가 필요한 변경이 있습니다"가 반복된다
- 원인: 검수를 마친 표식(`.owner/last-check.json`)이 갱신되지 않았다. 또는 정말로 검수가 안 끝났다.
- 해결: `indeans-erp-check` 스킬로 감독 판정 → 검증 → 보고서까지 한 번 끝낸다. 같은 작업에서 두 번 요구한 뒤에는 막지 않고 경고만 낸다.
- 표현(문구·색)만 고친 것이면 그 이유를 한 줄로 말하고 표식을 갱신하면 된다. **훅을 지우지 않는다.**
- **1회차 첫 검수 때 바뀐 파일 목록이 길게 나온다** → 정상이다. 아직 검수를 마친 적이 없어(`.owner/last-check.json` 없음) 기준점이 번들을 설치한 시점의 커밋이라, 그 뒤 바뀐 파일이 다 나온다. 한 번 검수를 마치면 그다음부터는 그 뒤에 바뀐 것만 나온다.

## 14. 화면 사진을 못 찍는다

- 증상: `node .owner/hooks/capture.mjs` 가 "화면을 찍는 도구(playwright)가 없습니다"로 끝난다
- 원인: 프로젝트에 playwright 가 설치되지 않았다(설치기는 이것을 대신 설치하지 않는다).
- 해결: 프로젝트 폴더에서 아래 두 줄을 한 번만 실행한다. `package.json` 이 아직 없으면(초안 앱 생성 전) 지금 하지 않는다.

```
npm i -D playwright
npx playwright install chromium
```

- 앱을 먼저 띄워 두어야 찍힌다(`npm run dev` 가 알려 준 주소를 `--url` 로 준다).
- 회사 네트워크가 브라우저 내려받기를 막으면 사진 없이 진행한다. 보고서는 글만으로도 만들어진다.

## 15. 스킬을 다른 폴더에서도 쓰고 싶다

- 증상: 다른 회사 폴더·새 프로젝트에서 같은 스킬이 안 뜬다
- 원인: 스킬은 설치한 프로젝트 폴더 안에만 있다.
- 해결: 개인(전역) 자리에 복사한다. 두 도구의 자리가 다르다.

| 도구 | 개인 스킬 자리 |
|---|---|
| Claude Code | `~/.claude/skills/<스킬이름>/` (윈도우 `%USERPROFILE%\.claude\skills\`) |
| Codex | `~/.agents/skills/<스킬이름>/` (윈도우 `%USERPROFILE%\.agents\skills\`) |

맥·리눅스:

```
mkdir -p ~/.claude/skills ~/.agents/skills
cp -R .claude/skills/indeans-erp-setup ~/.claude/skills/
cp -R .claude/skills/indeans-erp-setup ~/.agents/skills/
```

윈도우 PowerShell:

```
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills","$env:USERPROFILE\.agents\skills"
Copy-Item -Recurse -Force ".claude\skills\indeans-erp-setup" "$env:USERPROFILE\.claude\skills\"
Copy-Item -Recurse -Force ".claude\skills\indeans-erp-setup" "$env:USERPROFILE\.agents\skills\"
```

- 개인 자리에 둔 스킬은 **어느 폴더에서나 뜬다.** 회사 앱과 상관없는 작업 중에도 불릴 수 있으니, 여러 프로젝트를 섞어 쓸 계획이 아니면 프로젝트 안에 두는 쪽이 낫다.

## 16. 여기에 없는 오류일 때 — 전달하는 법

오류를 그대로 옮기는 것만으로 대부분 해결된다. 네 가지를 함께 적는다.

1. **무엇을 하려 했나** — "초안 앱을 실행하려고 했습니다"
2. **무엇을 기대했나** — "브라우저에 목록 화면이 뜨기를 기대했습니다"
3. **실제로 무엇이 됐나** — "빨간 글씨가 나오고 멈췄습니다"
4. **오류 원문** — 화면의 글자를 그대로 복사(요약하지 않는다)

> 이렇게 말하세요
> `(1) 하려던 것: ○○ (2) 기대한 결과: ○○ (3) 실제 결과: ○○ (4) 오류 원문: (붙여넣기). 원인을 찾아 고치기 전에, 무엇 때문인지 한 줄로 먼저 알려 주세요.`

화면을 캡처해 붙여 넣어도 된다. 다만 **고객 이름·금액·연락처가 보이는 화면은 캡처하지 않는다.**
