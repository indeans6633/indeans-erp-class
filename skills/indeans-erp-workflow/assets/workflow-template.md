# 우리 회사 업무 흐름

> 이 파일은 `indeans-erp-workflow` 스킬이 인터뷰 답변으로 채운다. 절 순서와 표 형식은 바꾸지 않는다(다음 주 스킬이 읽는다).
> 빈칸은 비워 두지 말고 "미정"이라고 적는다. 고객 실명·금액은 적지 않는다.

- 작성일: YYYY-MM-DD
- 관리 단위(일 한 건을 부르는 말): (예: 주문 / 프로젝트 / 접수 건)
- 이 흐름이 다루는 일의 종류: (예: 신규 주문. 정기 점검은 별도 흐름)

| 순서 | 회사에서 부르는 이름 | 저장 값 | 끝났다는 증거 | 다음 담당(역할) | 기한 | 고객에게 보임 |
|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  | 보임 / 안 보임 |
| 2 |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |
| 4 |  |  |  |  |  |  |

- 저장 값은 영문 소문자·밑줄(예: `inquiry`, `in_progress`). 화면 글자를 바꿔도 저장 값은 그대로 둔다.
- 기한은 "이 단계에 며칠 이상 머물면 늦은 것인가". 모르면 "미정".

## 2. 끝나는 방법

| 끝나는 상태 | 저장 값 | 이럴 때 | 집계에 포함 |
|---|---|---|---|
| 정상 완료 | `done` |  | 포함 |
| 취소 | `canceled` |  | 제외 |
| 보류 | `on_hold` |  | 제외 |

- 취소·보류에는 이유 한 줄을 같이 받는다. (예 / 아니오)
- 저장 값은 회사 단계 이름에 맞춰 정한다(예: 정상 완료를 `closed` 로 부르는 회사도 있다). **위 표의 값을 그대로 쓰지 않아도 된다.**

## 6. 화면에 반영한 것

- [ ] 상태 값과 화면 글자를 분리해 한 파일에 정의
- [ ] 전이 규칙을 코드 한 곳에 표로 정의
- [ ] 데이터에 상태 칸 추가(기본값 있음·빈칸 금지)
- [ ] 목록에 상태별 필터(기본은 "끝난 것 빼고")
- [ ] 상세 화면 맨 위에 "다음 할 일" 한 줄과 넘기는 버튼
- [ ] 목록 조회에 정렬과 개수 제한

## 7. 확인한 것

- [ ] 실제 건 하나를 첫 단계부터 마지막까지 옮겨 봤다
- [ ] 한 번 되돌려 봤다
- [ ] 금지된 이동을 눌러 보니 막혔다
- [ ] 상태별 버튼을 누르니 건수가 바뀌었다
